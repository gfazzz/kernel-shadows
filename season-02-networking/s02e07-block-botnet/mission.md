## Обстановка

Лишние разрешения закрыты, но атака идёт мимо них: флуд с 847 адресов, все —
выходные узлы Tor и адреса VPN-провайдеров. Вносить их по одному нереально.

Список составлен не тобой. Применять его напрямую из скрипта нельзя: один
неверный адрес, применённый автоматически, отрезает команду от сервера в разгар
инцидента.

## Приказ

Собрать `block_botnet.sh` — читает список адресов и **генерирует** файл правил,
готовый к осознанному применению:

```
$ ./block_botnet.sh botnet_ips.txt block_rules.sh
Правил сгенерировано: 3 → block_rules.sh
```

Использование: `./block_botnet.sh IP_LIST [OUTPUT_FILE]`.
Применяется результат отдельно и вручную: `sudo bash block_rules.sh`.

## Данные

| Что | Как |
|---|---|
| список / выходной файл | `"${1:?…}"`, `"${2:-block_rules.sh}"` |
| проверка входа | `[ -f "$list" ]`, иначе stderr и `exit 1` |
| фильтры цикла | пропускать пустые строки и строки с `#` |
| адрес | `ip="${line%% *}"` — комментарий сбоку отбрасывается |
| проверка формата | `case "$ip" in *.*.*.*) ;; *) continue ;; esac` |
| правило | `echo "ufw deny from $ip"` |
| сборка файла | `{ … } > "$out"` — одно перенаправление на группу (s01e12) |
| ноль правил | сообщение в stderr и ненулевой код |

Сгенерированный файл начинается с shebang и комментария об источнике и времени —
через месяц никто не вспомнит, откуда он взялся.

## Критерии приёмки

- [ ] `artifacts/block_botnet.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] На каждый валидный адрес списка генерируется правило `ufw deny from <ip>`.
- [ ] Комментарии, пустые строки и комментарий сбоку от адреса в правила не попадают.
- [ ] Строка, не похожая на адрес, правилом не становится.
- [ ] Сгенерированный файл проходит `bash -n` при любом входе.
- [ ] В файле есть shebang и пометка об источнике.
- [ ] Скрипт **не применяет** правила — `ufw` во время генерации не вызывается.
- [ ] Сводка о числе правил совпадает с содержимым файла.
- [ ] Пустой результат (ноль правил) → сообщение в stderr и ненулевой код возврата.
- [ ] Отсутствующий список → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 15 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — правила генерируются, применение отдельно и вручную |
| ОС | любая с bash |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | фикстура-список во временном каталоге; `ufw` подменён заглушкой-ловушкой |

Заглушка `ufw` в тесте не блокирует, а фиксирует факт вызова: скрипт, применяющий
правила вместо генерации, будет пойман.

Перед применением проверь сгенерированный файл на отсутствие своих адресов:

```bash
grep -E '10\.50\.|172\.20\.' artifacts/block_rules.sh   # должно быть пусто
grep -E 'ufw deny from [^0-9]' artifacts/block_rules.sh # мусор — тоже пусто
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| в правиле лишние слова | не отрезан комментарий сбоку | `ip="${line%% *}"` |
| правило `ufw deny from #` | не пропущены комментарии | фильтр `case "$line" in \#*) continue ;; esac` |
| правило из строки-мусора | нет проверки формата | `case "$ip" in *.*.*.*) ;; *) continue ;; esac` |
| файл правил пуст, код 0 | нулевой результат считается успехом | `[ "$count" -eq 0 ]` → stderr и `exit 1` |
| счётчик не сходится с файлом | считается не там, где пишется | увеличивать рядом с `echo` правила |
| скрипт что-то заблокировал | вызывается `ufw` вместо генерации | правила только печатать в файл |
