## 1. Два формата миссии

### `QGC WPL 110` — текстовый

```
QGC WPL 110
0	1	0	16	0	0	0	0	22.5410000	114.0520000	0	1
```

Табуляции, двенадцать полей, одна строка — одна команда. Старый формат, читаемый глазами и обрабатываемый `awk`. Поддерживается всеми станциями до сих пор.

### `.plan` — JSON

```json
{
  "fileType": "Plan",
  "mission": {
    "cruiseSpeed": 15,
    "items": [
      { "command": 16, "frame": 3, "params": [0,0,0,null,22.541,114.052,60] }
    ]
  },
  "geoFence": { "polygons": [] },
  "rallyPoints": { "points": [] }
}
```

Богаче: хранит геозону, точки сбора, скорости. Разбирается `jq`, а не `awk`. Проверки по смыслу — те же самые; меняется только способ достать поля.

## 2. Системы отсчёта высоты

`MAV_FRAME` определяет, относительно чего считается `ALT`:

| Значение | Имя | Отсчёт |
|---|---|---|
| 0 | `GLOBAL` | над средним уровнем моря (AMSL) |
| 3 | `GLOBAL_RELATIVE_ALT` | над точкой взлёта |
| 10 | `GLOBAL_TERRAIN_ALT` | над рельефом (нужны данные высот) |
| 6 | `GLOBAL_INT` | то же, что 0, координаты целыми |

Смешивание — классическая причина происшествий. Площадка на 40 м над уровнем моря; точка с `frame=3, alt=60` — это 100 м AMSL, а соседняя с `frame=0, alt=60` — 20 м над площадкой. Разница в 40 метров возникает из одного поля, которое никто не смотрел.

Отдельно опасен `GLOBAL_TERRAIN_ALT`: он требует загруженной карты высот. Без неё автопилот либо откажется, либо (хуже) подставит нули. **Проверять надо не только значение высоты, но и то, относительно чего оно задано.**

## 3. Команды миссии

Из сотен `MAV_CMD` в обычном маршруте встречается десяток:

| Код | Имя | Смысл |
|---|---|---|
| 16 | `NAV_WAYPOINT` | лететь в точку |
| 17 | `NAV_LOITER_UNLIM` | кружить бесконечно |
| 18/19 | `NAV_LOITER_TURNS`/`TIME` | кружить N витков / N секунд |
| 20 | `NAV_RETURN_TO_LAUNCH` | вернуться домой |
| 21 | `NAV_LAND` | посадка |
| 22 | `NAV_TAKEOFF` | взлёт |
| 177 | `DO_JUMP` | перейти к точке N, повторить M раз |
| 178 | `DO_CHANGE_SPEED` | сменить скорость |
| 183 | `DO_SET_SERVO` | дёрнуть сервоприводом (сброс груза, камера) |
| 206 | `DO_SET_CAM_TRIGG_DIST` | снимать каждые N метров |

`DO_JUMP` заслуживает отдельного внимания валидатора: он превращает линейный список в граф с циклами. План с `DO_JUMP` на самого себя и бесконечным числом повторов — это аппарат, который никогда не вернётся. Проверка «последняя команда — посадка» на таком плане проходит и ничего не значит: до последней команды дело не дойдёт.

Общий приём: **как только в данных появляются переходы, линейных проверок мало — нужна проверка достижимости.** Та же задача решалась в [`s04e07`](../../season-04-devops-automation/s04e07-ci-pipeline/), где по графу `needs` проверялось, что до этапа развёртывания вообще можно добраться.

## 4. Координаты

### Форматы записи

| Формат | Пример |
|---|---|
| десятичные градусы | `22.5410000` |
| градусы-минуты-секунды | `22°32'27.6"N` |
| целые (1e7) — как в MAVLink | `225410000` |

`GLOBAL_POSITION_INT` передаёт координаты умноженными на 10⁷ и высоту в миллиметрах — так они помещаются в целые и не теряют точность при передаче. Забыть поделить — верный способ получить координаты за пределами планеты.

### Точность

| Знаков после точки | Точность на экваторе |
|---|---|
| 3 | ~110 м |
| 5 | ~1.1 м |
| 7 | ~1.1 см |

Семь знаков — предел осмысленного для гражданского GPS. Больше — иллюзия: сам приёмник даёт метры.

### Точка Нуль

`0,0` — точка в Гвинейском заливе, на пересечении экватора и нулевого меридиана. Это самое частое значение «незаполненных координат» в мире, и именно поэтому оно опасно: в отличие от `NULL`, ноль — валидное число, и любая система примет его как настоящие координаты.

Отсюда общее правило работы с числовыми данными: **у величины, для которой ноль допустим, нужен отдельный признак «не задано».** Если такого признака нет — валидатор обязан считать ноль подозрительным.

## 5. Что проверяет сам автопилот

ArduPilot и PX4 делают предполётные проверки (`arming checks`), не давая взлететь при проблемах:

| Проверка | Что смотрит |
|---|---|
| GPS | тип решения, число спутников, HDOP |
| компас | калибровка, расхождение с GPS-курсом |
| барометр | стабильность показаний |
| батарея | напряжение выше порога |
| RC | приёмник живой, каналы в норме |
| EKF | оценка положения сошлась |
| миссия | точки заданы, дом установлен |

Соблазн отключить их («мешают») велик и стоит дорого: почти каждый разбор происшествия с любителями содержит фразу «проверки были отключены».

Важно понимать границу: **автопилот проверяет своё состояние, а не осмысленность твоего плана.** Он не знает, хватит ли батареи на маршрут, не задевает ли маршрут аэродром и не уйдёт ли аппарат за пределы связи. Это и есть та проверка, которую пишут в этой серии.

## 6. Геозона

Геозона (`geofence`) — граница, за которую аппарат не летит. Настраивается как радиус вокруг дома, потолок и (в новых прошивках) произвольный многоугольник.

| Действие при нарушении | Поведение |
|---|---|
| только предупреждение | сообщение оператору |
| удержание | не выпускать за границу |
| возврат | `RTL` при пересечении |
| посадка | сесть немедленно |

Важное различие: **валидатор проверяет план заранее, геозона действует в полёте.** Одно не заменяет другого. План может быть корректным, а аппарат унесёт ветром; геозона сработает. Геозона может быть настроена, а маршрут проходит впритирку к её границе — тогда каждый порыв ветра вызывает срабатывание, и полёт превращается в серию возвратов.

Разумная практика: проверять маршрут против границы **с запасом**, а не по факту пересечения. В валидаторе этой серии запас закладывается в `geofence_radius_m`: туда пишут не саму границу, а границу минус разумный резерв.

## 7. Где проверять до полигона

```bash
# SITL: автопилот целиком в программной модели
sim_vehicle.py -v ArduCopter --console --map
```

Порядок отладки, экономящий аппараты:

1. **валидатор** — план как текст, за секунды, без всего;
2. **SITL** — тот же план в симуляторе: видно траекторию и реакцию на отказы;
3. **стенд** — реальный автопилот без винтов, проверка команд и телеметрии;
4. **полигон** — полёт.

Каждый следующий шаг дороже предыдущего примерно на порядок. Это та же пирамида, что в [`s04e07`](../../season-04-devops-automation/s04e07-ci-pipeline/): много дешёвых быстрых проверок внизу, мало дорогих наверху.
