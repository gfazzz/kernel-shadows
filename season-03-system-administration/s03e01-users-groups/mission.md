## Обстановка

На `shadow-server-01` найден бэкдор. Анна сняла три файла учётных записей до
того, как на машине что-либо трогали, — это вещественное доказательство, и
разбирать надо копии, а не живую систему.

Известно, что в системе есть учётная запись `devops` с UID 0. Неизвестно,
единственная ли она и что ещё успели завести.

## Приказ

Составить список жильцов и **сдать отчёт** — заполненный
`artifacts/users_report.txt`: сколько учётных записей, сколько служебных,
сколько человеческих, у кого полные права, кто входит без пароля, кто
заблокирован и какие служебные записи умеют входить в систему.

```bash
cp starter/users_report.txt artifacts/users_report.txt
bash tests/test.sh
```

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/passwd_shadow-01.txt`](../data/passwd_shadow-01.txt) | снимок `/etc/passwd` |
| [`data/group_shadow-01.txt`](../data/group_shadow-01.txt) | снимок `/etc/group` |
| [`data/shadow_shadow-01.txt`](../data/shadow_shadow-01.txt) | снимок `/etc/shadow`, хеши обрезаны |

У всех трёх файлов есть шапка с комментариями — её надо отбросить перед
разбором. Разделитель полей везде один: двоеточие.

## Чем добывать

| Что нужно | Как |
|---|---|
| отбросить шапку | `grep -vE '^[[:space:]]*(#\|$)' "$F"` |
| поля строки | `awk -F: '{print $1, $3, $7}'` |
| все UID 0 | `awk -F: '$3 == 0 {print $1}'` |
| системные | `awk -F: '$3 < 1000'` |
| человеческие | `awk -F: '$3 >= 1000 && $3 != 65534'` |
| состав группы | `awk -F: '$1=="sudo" {print $4}'` |
| поле пароля | `awk -F: '{print $1, $2}'` по `shadow` |
| список через запятую | `sort \| paste -sd, -` |

Поле пароля читается так: `$6$…` — пароль задан, `*` — вход по паролю
невозможен, `!` в начале — учётная запись заблокирована, **пусто** — пароля нет.

## Критерии приёмки

- [ ] `artifacts/users_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Число учётных записей, системных и человеческих посчитано по UID, а не на глаз.
- [ ] Перечислены **все** записи с UID 0, а не только `root`.
- [ ] Указан состав группы `sudo` из `/etc/group`.
- [ ] Найдена запись с пустым полем пароля и найдены заблокированные.
- [ ] Служебные записи с интерактивной оболочкой перечислены; `sync` в их число не попал.
- [ ] Названа учётная запись, которой на машине быть не должно.
- [ ] `bash tests/test.sh` → 17 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбираются копии файлов |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из тех же снимков, констант в тесте нет |

Тест дополнительно проверяет, что ловушки в данных на месте: вторая запись
с UID 0, учётка `sync` с оболочкой `/bin/sync`, служебная запись с `bash`.

## Выполнение

```bash
cd season-03-system-administration/s03e01-users-groups
cp starter/users_report.txt artifacts/users_report.txt
D=../data
grep -vE '^[[:space:]]*(#|$)' $D/passwd_shadow-01.txt | awk -F: '{print $3, $1, $7}' | sort -n
bash tests/test.sh
```

На своей машине посмотри то же самое вживую: `getent passwd`, `id`, `groups`.
Разница между `getent passwd max` и `grep max /etc/passwd` разобрана
в [`theory.md`](theory.md) — она заметна не всегда, но когда заметна, объясняет
многое.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| в списке UID 0 только `root` | поиск шёл по имени | `awk -F: '$3 == 0'` |
| число учётных записей больше на 3–5 | не отброшена шапка файла | `grep -vE '^[[:space:]]*(#\|$)'` |
| в человеческих оказался `nobody` | не исключён UID 65534 | добавить условие |
| в служебных с оболочкой появился `sync` | фильтр «не nologin» слишком широкий | спрашивать про `bash`, `sh`, `zsh` |
| состав `sudo` пустой | взято не то поле | члены группы — четвёртое поле |
| `passwordless` совпал с `locked` | перепутаны пустое поле и `!` | пусто — нет пароля, `!` — блокировка |

## После выполнения

Зелёный тест означает, что список жильцов составлен и сверен с тем, каким он
должен быть. Подсадок в снимке две: одна очевидная, вторая — сделанная в расчёте
на то, что после первой искать перестанут.

Дальше — вопрос, что именно учётная запись может делать: какие файлы читать,
куда писать и что запускать от чужого имени. Это права на файлы и специальные
биты, из-за которых обычная программа выполняется с правами root.

## Кумулятивность

Разбор полей по разделителю — `awk -F` из s01e11; сверка «что есть» против
«что должно быть» — та же линия, что инвентаризация портов в s02e02 и правил
фаервола в s02e06. Меняется объект, метод один.
