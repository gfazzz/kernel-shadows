## Теория: `sed` + Type B (один концепт: собрать отчёт из инструментов)

**`sed`** — потоковый редактор: заменяет и удаляет по шаблону, вывод идёт в stdout (файл не меняется без `-i`):

```bash
sed 's/error/ERROR/g' file        # заменить все вхождения (g)
sed '/^$/d' file                  # удалить пустые строки
awk '{print $4}' log | sed 's/[][]//g'   # вычистить скобки из [таймстампа]
```

**Type B** — это про то, КАК собран капстоун: тело отчёта — из one-liner'ов, которые ты уже знаешь:

```bash
echo "Всего запросов: $(wc -l < "$log")"
awk '{print $1}' "$log" | sort | uniq -c | sort -rn | head -10   # топ IP
awk '{print $9}' "$log" | sort | uniq -c | sort -rn             # статусы
```

bash здесь — только клей (собрать вывод в файл через `{ … } > report`). Детали `sed` и философия Type B — в [`theory.md`](theory.md).

> **LILITH:** *«Это Type B episode. 70% инструменты, 30% bash. Так работают настоящие Linux-администраторы — не пишут скрипт там, где хватает пяти команд в конвейере.»*

## Проверка «в мире сюжета»

**Ольга:** *«Почему `log_analyzer.sh` на bash — это нормально, а „перепиши grep на чистом bash" — нет?»*

<details>
<summary>Подумай 30 секунд</summary>

Bash здесь — оркестратор: он вызывает специализированные инструменты (`grep`, `awk`, `sort`) и собирает их вывод. Переписывать их логику на bash — значит изобретать медленный и багованный велосипед. Type B: используй готовое, склеивай минимумом кода.
</details>

**Ольга:** *«`sed -i 's/x/y/g' prod.log` — что здесь опасного?»*

<details>
<summary>Ответ</summary>

`-i` меняет файл **на месте**, без подтверждения. Ошибся в шаблоне — испортил боевой лог без возможности отката. Безопаснее сначала прогнать без `-i` (посмотреть на stdout), а для правки использовать `-i.bak`, чтобы остался бэкап.
</details>
