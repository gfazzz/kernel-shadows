## Обстановка

Серверы разворачивались в три захода за полгода, последняя инвентаризация была в
июле. Никто в команде не может перечислить, какие сервисы подняты на машине и
какие из них видны из сети.

Одновременно снаружи идёт медленный перебор портов — по несколько за час, чтобы
не сработали пороги обнаружения. Кто-то ищет забытую открытую дверь, и найдёт он
её быстрее, чем команда вспомнит, что её открывала.

Дмитрий снял с одного из серверов состояние сокетов. Разобраться в нём — твоя
задача.

## Приказ

Провести разведку по снимку и **сдать отчёт** — заполненный
`artifacts/ports_report.txt`. Не инструмент, а находки: сколько портов, какие из
них видны снаружи, какие только локально, чего нет в согласованном списке и что
на машине вообще никто из команды не поднимал.

```bash
cp starter/ports_report.txt artifacts/ports_report.txt
# заполнить каждое значение, добывая его командами
bash tests/test.sh
```

## Объект разведки и источники

| Файл | Что это |
|---|---|
| [`data/ss_listen_moscow1.txt`](../data/ss_listen_moscow1.txt) | снимок `ss -tuln` — предмет разбора |
| [`data/allowed_ports.txt`](../data/allowed_ports.txt) | согласованный allowlist портов операции |
| [`data/known_services.txt`](../data/known_services.txt) | что команда разворачивала сама: порт → сервис |

Формат отчёта: `ключ=значение`, числа цифрами, списки портов через запятую без
пробелов, по возрастанию. Строки с `#` игнорируются.

## Чем добывать

| Что нужно | Как |
|---|---|
| колонка привязок | `awk '/^LISTEN/{print $4}' "$SNAP"` |
| номер порта | `sed 's/.*://'` — после **последнего** двоеточия (иначе `[::]:80` сломается) |
| только числа | `grep -E '^[0-9]+$'` |
| уникальные по возрастанию | `sort -un` |
| список через запятую | `paste -sd, -` |
| публичные привязки | `grep -E '^(0\.0\.0\.0|\[::\]):'` |
| локальные привязки | `grep -E '^127\.0\.0\.'` |
| сверка со списком | `grep -qxF "$p" файл` — совпадение строки целиком |

Чувствительными считаем `3306 5432 6379 9200 27017 11211` — СУБД, кеши и поиск.

## Критерии приёмки

- [ ] `artifacts/ports_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Число строк `LISTEN` и число уникальных портов указаны отдельно и **не совпадают**.
- [ ] Список всех портов полон и упорядочен по возрастанию.
- [ ] Публичные порты (`0.0.0.0`, `[::]`) отделены от локальных (`127.0.0.x`).
- [ ] Порт, привязанный к адресу интерфейса, не попал ни в один из этих двух списков.
- [ ] Перечислено, чего нет в `allowed_ports.txt`.
- [ ] Указаны чувствительные сервисы, доступные снаружи.
- [ ] Найден порт, отсутствующий в `known_services.txt`, — тот, который никто не поднимал.
- [ ] `bash tests/test.sh` → 13 passed, 0 failed.

## Выполнение

```bash
cd season-02-networking/s02e02-ports-sockets
cp starter/ports_report.txt artifacts/ports_report.txt
SNAP=../data/ss_listen_moscow1.txt
awk '/^LISTEN/{print $4}' "$SNAP" | sed 's/.*://' | sort -un   # с этого удобно начать
bash tests/test.sh
```

На своей машине посмотри то же самое вживую: `ss -tuln`, а под `sudo` — `ss -tulnp`,
чтобы увидеть, какой процесс держит каждый порт.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| порт из `[::]:80` потерялся | режется по первому `:` | `sed 's/.*://'` |
| строк и портов поровну | посчитаны дубли IPv6 | считать `sort -un` |
| `9100` попал в публичные | привязка к `10.50.1.100` принята за `0.0.0.0` | шаблон `^(0\.0\.0\.0|\[::\]):` |
| `53` не попал в локальные | шаблон `^127\.0\.0\.1` вместо `^127\.0\.0\.` | резолвер слушает на `127.0.0.53` |
| в неожиданных нет `9100` | сверка не по всем портам | сверять весь список, а не только публичные |
| порт `44` «нашёлся» в списке | сверка по подстроке | `grep -qxF` |
| тест «значение не заполнено» | ключ переименован или потерян `=` | брать шаблон из `starter/` без правок |

## После выполнения

Зелёный тест означает, что состояние машины известно из наблюдения, а не из
предположений: одиннадцать портов, из них семь видны снаружи, два — базы, которые
там быть не должны, и один — который никто не поднимал.

Отчёт — инвентаризация поверхности `netshield` (см. [`PROJECTS.md`](../../docs/PROJECTS.md)).
В [`s02e06`](../s02e06-firewall-ufw/) к нему добавится вторая половина картины:
что из этого действительно доступно снаружи по правилам фаервола.

Дальше — уровнем ниже. Порт может слушать, но машина не отвечать; между тобой и ею
десяток маршрутизаторов, и любой способен пакет не пропустить.
