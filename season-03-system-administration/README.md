из одних скриптов, как того требует «курс про Linux, а не про bash».

**Отклонение от первоначального плана:** `s03e12` задумывалась как второй
`.timer` (расписание бэкапа). Таймеры целиком разобраны в `s03e06`, и повтор
не дал бы ничего нового, поэтому серия отдана `logrotate`. Причина не только
в дублировании: конфигурация ротации — прямая причина находки `s03e08`
(десять гигабайт, занятых файлом без имени), и это единственное место, где
её можно закрыть. Тип серии (**B**) и баланс сезона не изменились.

**Линия C:** в `s03e04` появляется первое знакомство с системными вызовами —
`strace` на простой программе и объяснение, почему `ls` — это `getdents64`.

Учебные данные сезона лежат в [`data/`](data/) — одиннадцать снимков со
скомпрометированного `shadow-server-01`: учётные записи, права, SUID-файлы,
таблица процессов, `/proc`, журнал за вечер атаки, дисковое состояние, LVM,
`blkid`. Разбираются копии, поэтому ни root, ни живая система, ни сеть не нужны
ни одной серии.

Старые `episode-09..12` удалены после аудита потерь: `limits.conf` и PAM
перенесены в теорию `s03e03`, атрибуты `chattr` — в `s03e02`, разметка дисков
и квоты — в `s03e08`, RAID и `mdadm` — в `s03e09`.

Прогнать тесты сезона: `make test SEASON=season-03-system-administration`.

**Сквозная линия сезона.** Все тринадцать серий разбирают одну и ту же машину и
один и тот же инцидент: подсаженная учётка `devops` с UID 0 (`s03e01`) →
SUID-копия оболочки в её домашнем каталоге (`s03e02`) → строка `%sudo`, через
которую это стало возможно (`s03e03`) → процессы, выдающие себя за `sshd`
(`s03e04`) → юнит, который их запускает (`s03e05`) → пропущенная проверка
целостности (`s03e06`) → хронология вечера 14 октября по журналу (`s03e07`) →
десять гигабайт, занятых удалённым файлом (`s03e08`) → расширение тома
(`s03e09`) → таблица монтирования с `nosuid` и `noexec` (`s03e10`) → копии
(`s03e11`) → ротация, которая и создала ту дыру (`s03e12`) → проверка
восстановления (`s03e13`).

### Дни 19–20: службы и журнал (s03e04–s03e07)

является. Хронология восстанавливается по журналу — та же техника, которой в

### Дни 21–22: Таллин, диски (s03e08–s03e10)

Kristjan Tamm и эстонская электронная государственность. Разделы, LVM,
монтирование по идентификатору вместо имени устройства. Место кончается не
там, где кажется: `du` и `df` расходятся, и причина — удалённый файл, который
держит открытым процесс.

### Дни 23–24: Liisa Kask и бэкапы (s03e11–s03e13)

Резервное копирование, которое проверяется восстановлением, а не наличием
архива. `rsync`, инкремент через жёсткие ссылки, план восстановления с
измеренным временем. Финал сезона — не «бэкап настроен», а «восстановление
проверено и заняло столько-то».

**From Season 1-2:**
- Bash scripting → automation для user management

**To Season 4-8:**
- Users/permissions → Docker containers, Kubernetes RBAC
- Systemd services → microservices orchestration
- LVM → cloud storage, Kubernetes persistent volumes
- Backup → CI/CD, disaster recovery в production

**Философия:** System Administration — это фундамент. Без понимания users, processes, disks невозможно администрировать cloud/containers/Kubernetes.

**Акцент сезона — конфигурирование системы, а не bash-скрипты:**
- учётные записи и права: `/etc/sudoers.d/`, `/etc/security/limits.conf`, PAM
- службы: юниты systemd с ограничениями (`User=`, `ProtectSystem=`)
- диски: `/etc/fstab` по UUID, наблюдение за местом
- регламент: таймеры systemd и `logrotate` вместо самописных обёрток

**Правило:** Используй готовые инструменты (systemd, PAM, logrotate), не переписывай их bash скриптами.

## Важные напоминания

### Security:
- ⚠️ **НИКОГДА не давай полный sudo всем**
- ⚠️ **Проверяй /etc/sudoers через visudo** (защита от syntax errors)
- ⚠️ **Используй `/etc/sudoers.d/` для модульности**
- ⚠️ **Permissions на /etc/shadow должны быть 640 или 600**
- ⚠️ **Systemd services: включай security hardening** (NoNewPrivileges, ProtectSystem)
- ⚠️ **Systemd timers: используй Persistent=true** (не пропустишь запуски)
- ⚠️ **Тестируй backup recovery, а не только backup creation**
- ⚠️ **"Untested backup = no backup"** — тестируй restore каждый месяц

### LILITH подход:
- "Root — это оружие. Используй мудро."
- "Процессы не врут про PID. Но врут про имя."
- "Диски как жизнь. Места всегда мало."
- "Untested backup = no backup. Test restore every month."
- "Systemd timers > cron. Persistent = надёжность."
- "Используй готовые инструменты. Не переписывай systemd bash скриптом."
