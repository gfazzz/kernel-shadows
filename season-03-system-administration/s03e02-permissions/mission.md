## Обстановка

Учётные записи разобраны, две подсадки найдены. Но закрыть учётку мало: если
злоумышленник успел оставить программу, выполняющуюся с правами root, она
переживёт любую блокировку — права у файла свои, к учётной записи отношения
не имеющие.

Анна сняла два снимка: права на ключевые пути и полный список файлов с битами
SUID и SGID.

## Приказ

Провести аудит прав и **сдать отчёт** — заполненный
`artifacts/perms_report.txt`: что доступно на запись всем, где общие каталоги
без sticky, какие приватные ключи читаются посторонними, сколько в системе
SUID- и SGID-файлов и какие из них стоят не на своём месте.

```bash
cp starter/perms_report.txt artifacts/perms_report.txt
bash tests/test.sh
```

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/perm_audit_shadow-01.txt`](../data/perm_audit_shadow-01.txt) | вывод `ls -l` по ключевым путям |
| [`data/suid_scan_shadow-01.txt`](../data/suid_scan_shadow-01.txt) | результат `find / -perm -4000 -o -perm -2000` |

В обоих файлах есть шапка и заголовки секций. Строки прав начинаются с `-`,
`d` или `l` — по этому признаку их и отбирают.

## Чем добывать

| Что нужно | Как |
|---|---|
| только строки прав | `grep -E '^[-dl]' "$F"` |
| доступные всем на запись файлы | `awk '$1 ~ /^-.{7}w/ {print $NF}'` |
| то же для каталогов | `awk '$1 ~ /^d.{7}w/ {print $NF}'` |
| наличие sticky | десятый символ строки прав — `t` или `T` |
| SUID | четвёртый символ — `s`: `awk '$1 ~ /^-..s/'` |
| SGID | седьмой символ — `s`: `awk '$1 ~ /^-.....s/'` |
| владелец и группа | третье и четвёртое поля строки `ls -l` |

Восьмеричная запись считается из троек: `r`=4, `w`=2, `x`=1. Специальные биты
дают четвёртую цифру впереди: SUID 4, SGID 2, sticky 1.

## Критерии приёмки

- [ ] `artifacts/perms_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Восьмеричные права трёх путей посчитаны верно, включая специальный бит там, где он есть.
- [ ] Файлы и каталоги, доступные всем на запись, перечислены отдельно.
- [ ] Каталоги без sticky выделены из общего списка (у `/tmp` sticky есть — он не в их числе).
- [ ] Найден приватный ключ с правами шире `600`.
- [ ] Посчитаны SUID- и SGID-файлы **раздельно**: `s` в позиции владельца и в позиции группы — разные вещи.
- [ ] Перечислены SUID-файлы вне `/usr` — их два.
- [ ] Назван тот из них, что лежит в домашнем каталоге и принадлежит root.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбираются копии вывода команд |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из тех же снимков, констант в тесте нет |

Тест дополнительно проверяет, что ловушки на месте: каталог `777` со sticky
рядом с каталогами без него, два SUID вне `/usr` (не всякий из них атака),
и присутствие SGID-файлов.

## Выполнение

```bash
cd season-03-system-administration/s03e02-permissions
cp starter/perms_report.txt artifacts/perms_report.txt
D=../data
grep -E '^[-dl]' $D/perm_audit_shadow-01.txt | awk '{print $1, $NF}'
grep -E '^[-dl]' $D/suid_scan_shadow-01.txt  | awk '$1 ~ /^-..s/ {print $NF}'
bash tests/test.sh
```

На своей машине прогони настоящий поиск — он занимает секунды и стоит того,
чтобы увидеть список SUID своей системы хотя бы раз:

```bash
find / -xdev -perm -4000 -type f -ls 2>/dev/null
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `/tmp` попал в небезопасные | не проверен sticky | десятый символ строки прав |
| SUID и SGID дали одно число | шаблон ловит `s` в любой позиции | `^-..s` против `^-.....s` |
| права `/tmp` вышли `777` | не учтён специальный бит | sticky добавляет `1` впереди: `1777` |
| в списке путей появились заголовки секций | не отфильтрованы строки | брать только начинающиеся с `-`, `d`, `l` |
| `world_writable_files` содержит каталоги | шаблон не различает тип | первый символ строки: `-` файл, `d` каталог |
| ключ `max` попал в незащищённые | сравнение не с `600` | у него `-rw-------`, это и есть 600 |

## После выполнения

Зелёный тест означает, что аудит прав проведён и закладка найдена. Полезнее
самой находки — понимание, что почти всё в этом списке возникло не от атаки:
`666` на `/etc/hosts` кто-то поставил, чтобы не набирать `sudo`, а ключ потерял
режим при копировании. Намеренно сделан ровно один файл.

и она станет капстоуном эпизода.
