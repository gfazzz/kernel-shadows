## Обстановка

Пароль, найденный вчера в истории, уже поменяли. Ханс задаёт следующий
вопрос: что помешает отправить такой же завтра.

Ответ «внимательность» его не устраивает: «если защита требует, чтобы человек
каждый раз помнил, — это не защита, а пожелание».

## Приказ

Написать `artifacts/prepush_check.sh` — проверку, которая смотрит на коммиты,
которых нет в базовой ветке, и отказывает, если среди них есть то, что
отправлять нельзя.

```bash
cp starter/prepush_check.sh artifacts/prepush_check.sh
bash ../data/build_shadow_iac.sh /tmp/shadow_iac
bash artifacts/prepush_check.sh --repo /tmp/shadow_iac --base main
bash tests/test.sh
```

## Что должен ловить скрипт

| Нарушение | Признак |
|---|---|
| работа прямо в основной ветке | текущая ветка совпадает с базовой |
| секрет в содержимом файла | `PASSWORD=`, `SECRET=`, `API_TOKEN=`, `BEGIN … PRIVATE KEY`, `ghp_…` |
| запрещённое имя файла | `.env`, `*.pem`, `*.key`, `id_rsa`, `id_ed25519` |
| слишком большой файл | предел в килобайтах, ключ `--max-size` |
| конфликтные маркеры | строки из семи `<`, `=` или `>` |

Каждая находка называет **коммит и файл**. Код возврата: `0` — можно
отправлять, `1` — нельзя, `2` — ошибка вызова.

## Требования

| Что | Почему |
|---|---|
| смотреть на диапазон `база..HEAD` | ругаться на отправленное бессмысленно: отправка этого не изменит |
| пропускать удалённые файлы | их содержимого в этом коммите нет |
| ничего не менять в репозитории | проверка только читает |
| ключи `--repo`, `--base`, `--max-size` | скрипт вызывают и вручную, и хуком |
| сообщения об отказе — в stderr | хук смотрит на код, человек читает поток ошибок |

## Чем добывать

| Что нужно | Как |
|---|---|
| текущая ветка | `git -C "$R" rev-parse --abbrev-ref HEAD` |
| коммиты к отправке | `git rev-list "${BASE}..HEAD"` |
| файлы коммита | `git show --pretty=format: --name-only "$c"` |
| содержимое файла в коммите | `git show "$c:$f"` |
| размер объекта | `git cat-file -s "$c:$f"` |
| существует ли файл в коммите | `git cat-file -e "$c:$f" \|\| continue` |
| короткий хеш | `git rev-parse --short=7 "$c"` |

## Критерии приёмки

- [ ] `artifacts/prepush_check.sh` создан на основе `starter/`, с шебангом и `set -euo pipefail`.
- [ ] Чистый репозиторий проходит с кодом 0.
- [ ] Работа из основной ветки отклоняется, причина названа.
- [ ] Секрет в содержимом отклоняется; названы файл и коммит.
- [ ] Файл `*.pem` отклоняется по имени; файл назван.
- [ ] Файл больше предела отклоняется; `--max-size` меняет решение.
- [ ] Конфликтные маркеры отклоняются; файл назван.
- [ ] То, что уже есть в базовой ветке, **не** вызывает отказа.
- [ ] Репозиторий после проверки не изменён.
- [ ] Каталог без репозитория отвергается, сообщение — в stderr.
- [ ] Решение не зависит от локали и часового пояса.
- [ ] `bash tests/test.sh` → 20 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils |
| Сеть | не нужна |
| Внешние пакеты | **`git`** |
| Изоляция теста | тест сам создаёт шесть репозиториев во временном каталоге: чистый и пять с одним нарушением в каждом |

Тест дополнительно проверяет, что скрипт ничего не изменил: хеш `HEAD` и
`git status --porcelain` до и после совпадают.

## Выполнение

```bash
cd season-04-devops-automation/s04e02-branches-prepush
cp starter/prepush_check.sh artifacts/prepush_check.sh
$EDITOR artifacts/prepush_check.sh
bash tests/test.sh
```

Поставить проверку себе (на своей машине, в своём репозитории):

```bash
cp artifacts/prepush_check.sh .git/hooks/pre-push
chmod +x .git/hooks/pre-push
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «ругается на то, что уже есть в базовой ветке» | проверяется вся история | диапазон `${BASE}..HEAD` |
| «секрет пропущен» | ищется только по именам файлов | нужно и содержимое |
| «файл не назван» | печатается только счётчик | называть коммит и файл |
| падает на удалённом файле | `git show` не находит содержимое | `git cat-file -e … \|\| continue` |
| `--max-size` не влияет | предел зашит числом | брать из ключа |
| код 0 при находках | итог не влияет на `exit` | `exit 1`, если найдено хоть что-то |
| `set -e` роняет на `grep` без совпадений | `grep` возвращает 1 | `|| true` там, где отсутствие — норма |

## После выполнения

Зелёный тест означает, что следующий пароль не уедет молча. И стоит сразу
понимать границу: хук лежит в `.git`, а `.git` не отправляется. Это защита
для вас, не для команды.

Для команды нужна та же проверка, но выполняемая на чужой машине, которую
нельзя отключить локально. Этим займёмся в `s04e07`.

хватало одной строки, которую никто не помнил написать.
