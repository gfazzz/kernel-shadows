## Обстановка

На стене ЦОД висит карта сети операции: сотни адресов, сгруппированных по стойкам
и сегментам. Часть из них — внутренние машины, часть видна из интернета, часть
принадлежит партнёрам.

Правила фильтрации построены на различии «свой — чужой», и различие это делается
по адресу. Ошибка в границе диапазона означает, что чужой адрес считается своим —
и проходит без проверок.

## Приказ

Собрать `ipinfo.sh` — принимает IPv4-адрес и печатает три вещи: сам адрес, его
исторический класс и тип.

```
$ ./ipinfo.sh 10.50.1.100
IP: 10.50.1.100
Класс: A
Тип: private (10.0.0.0/8)
```

Невалидный вход — сообщение в stderr и ненулевой код возврата.

## Данные

| Что | Как |
|---|---|
| адрес | первый аргумент — `"${1:?…}"` |
| разбор на октеты | `IFS='.' read -r -a oct <<< "$ip"` |
| проверка формы | ровно 4 элемента; каждый — только цифры (`case "$o" in *[!0-9]*)`) |
| проверка диапазона | каждый октет `0`–`255` |
| класс | по первому октету: A `<128`, B `<192`, C `<224`, дальше D/E |
| loopback | первый октет `127` (весь `/8`, не только `127.0.0.1`) |
| private | `10.*`; `172.16`–`172.31`; `192.168.*` |
| broadcast | ровно `255.255.255.255` |

Форму проверяют **до** сравнения чисел: `[ "abc" -le 255 ]` — не ложь, а ошибка.

## Критерии приёмки

- [ ] `artifacts/ipinfo.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] `10.50.1.100`, `172.16.5.20`, `192.168.1.100` → private.
- [ ] `172.32.5.20` и `192.169.1.1` → public (границы диапазонов соблюдены).
- [ ] `172.31.255.255` → private (верхняя граница `/12` включительно).
- [ ] `127.0.0.1` и `127.10.20.30` → loopback.
- [ ] `255.255.255.255` → broadcast.
- [ ] Класс определяется верно: `8.8.8.8` → A, `128.0.0.1` → B, `192.168.1.1` → C.
- [ ] `999.1.1.1`, `1.2.3`, `10.0.0.256`, `10.0.0.a`, пустая строка → ненулевой код и сообщение в stderr.
- [ ] `bash tests/test.sh` → 16 passed, 0 failed.

Проверь соседние адреса по обе стороны каждой границы — именно там живут ошибки,
а не в середине диапазона.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `172.32.x` считается private | нет проверки второго октета | `[ "$b" -ge 16 ] && [ "$b" -le 31 ]` |
| `192.169.x` считается private | сравнивается только первый октет | проверять `b -eq 168` |
| ошибка «integer expression expected» | сравнение нечисловой строки | сначала `case "$o" in *[!0-9]*)`, потом сравнение |
| `1.2.3` принят за адрес | не проверено число октетов | `[ "${#oct[@]}" -eq 4 ]` |
| `10.0.0.` проходит валидацию | пустой октет считается нулём | пустая строка тоже не цифры — отсекается тем же `case` |
| пустой аргумент → непонятная ошибка | нет `${1:?}` | добавить подсказку по использованию |

## После выполнения

Зелёный тест означает, что карта на стене перестала быть набором чисел: ты видишь,
что внутреннее, что внешнее и где проходят границы доверия.

`ipinfo.sh` — первый инструмент сезонного проекта **`netshield`**
(см. [`PROJECTS.md`](../../docs/PROJECTS.md)).

Дальше — следующий слой. Адрес отвечает на вопрос «кто», а разговоры в сети идут
через порты: на каждой машине открыты двери, за которыми ждут сервисы. Их и надо
пересчитать раньше, чем это сделает кто-то другой.
