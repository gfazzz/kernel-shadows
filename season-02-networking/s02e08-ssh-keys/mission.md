## Обстановка

Атака была прикрытием: Анна нашла следы перехвата трафика на транзитном участке.
Команда переходит на аутентификацию по ключам — секрет, который не покидает
машину и не может быть перехвачен по дороге.

Ключи у большинства давно заведены. Как они лежат на диске, не смотрел никто, а
приватный ключ с правами `644` SSH просто откажется использовать — и это лучший
исход из возможных.

## Приказ

Собрать `ssh_key_check.sh` — проходит по каталогу ключей и проверяет права и тип:

```
  ✓ id_ed25519 — права 600 (ок)
     тип: ed25519 (рекомендуется)
  ⚠️ id_rsa — права 644 (НЕБЕЗОПАСНО, нужно 600)
     тип: rsa (ок для старых серверов; ed25519 лучше)
---
Ключей проверено: 3 | Проблем: 2
```

Использование: `./ssh_key_check.sh SSH_DIR` — обычно `~/.ssh`.

## Данные

| Что | Как |
|---|---|
| каталог | `"${1:?…}"`, проверить `[ -d … ]` |
| перебор ключей | `for key in "$keydir"/id_*` |
| пропустить публичные | `case "$key" in *.pub) continue ;; esac` |
| права кроссплатформенно | `stat -c '%a' "$f" 2>/dev/null \|\| stat -f '%Lp' "$f"` |
| безопасные права | `600` или `400` |
| тип | по имени файла: `id_ed25519`, `id_rsa`, `id_dsa` |
| счётчики | найдено ключей и число проблем |

`stat -c` есть в GNU coreutils, `stat -f` — в BSD и macOS. Пара с `||` покрывает обе.

## Критерии приёмки

- [ ] `artifacts/ssh_key_check.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Приватный ключ с правами `600` признаётся корректным.
- [ ] Права `400` тоже признаются корректными (строже — не хуже).
- [ ] Ключ с правами `644` помечается как небезопасный.
- [ ] Публичные ключи (`*.pub`) не проверяются как приватные.
- [ ] `id_dsa` помечается как устаревший тип.
- [ ] Посторонние файлы каталога (`config`, `known_hosts`) ключами не считаются.
- [ ] Счётчик проверенных ключей совпадает с числом приватных ключей в каталоге.
- [ ] Счётчик проблем согласован с числом выданных предупреждений.
- [ ] Несуществующий каталог → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 13 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash и `stat` (Linux / macOS / WSL) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | фикстура-каталог ключей во временном каталоге |

Фикстура содержит: `id_ed25519` с правами `600`, `id_ed25519_backup` с `400`,
`id_rsa` с `644`, устаревший `id_dsa`, публичные ключи и файлы `config`
и `known_hosts`. Ожидаемые числа тест считает по самой фикстуре.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| все ключи «безопасны», права пустые | `stat` вызван в чужом варианте | пара `stat -c … \|\| stat -f …` |
| `.pub` помечен небезопасным | не отфильтрованы публичные | `case "$key" in *.pub) continue ;; esac` |
| `config` посчитан ключом | перебор по всему каталогу | брать только `id_*` |
| ключ с `400` объявлен проблемой | проверяется только `600` | разрешить оба значения |
| счётчик проблем не сходится | увеличивается не в той ветке | считать там же, где печатается предупреждение |
| каталога нет → «Проверено: 0» | нет проверки входа | `[ -d "$keydir" ]`, иначе `exit 1` |

## После выполнения

Зелёный тест означает, что состояние ключей команды известно из наблюдения. На
реальных машинах проверка найдёт три ключа из семи с правами `644` — один из них
на общей машине, где есть учётные записи других людей.

`ssh_key_check.sh` — модуль доступа `netshield` (см. [`PROJECTS.md`](../../PROJECTS.md)).

Дальше — вторая половина задачи: пока сервер принимает пароли и пускает root
напрямую, ключи остаются просто удобным способом входа, а не защитой. Финал
сезона — конфигурация `sshd` и шифрованные туннели.
