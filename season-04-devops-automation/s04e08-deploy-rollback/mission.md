## Обстановка

В 15:47 выкат положил боевой контур: пятьдесят серверов отдавали пятисотую.
Откат сделан вручную и занял пять минут, из которых четыре ушли на вопрос
«а на какую версию откатываться».

Строка перед текущей — неудачный утренний выкат, который в бой не пошёл.
Ханс это знал; скрипт этого знать не может, пока ему не объяснить.

## Приказ

Написать `artifacts/rollback.sh` — откат одной командой, по журналу.

```bash
cp starter/rollback.sh artifacts/
bash tests/test.sh
```

```
rollback.sh --journal FILE --host HOST --image IMAGE
            [--to ВЕРСИЯ] [--force] [--dry-run] [--health URL]
```

Журнал (`data/releases_prod.log`) — строки вида:

```
время                 версия    состояние миграция [комментарий]
2025-10-29T11:31:57Z  b0c4d5e6  failed    no       готовность не подтвердилась
```

Состояние: `healthy` или `failed`. Версия встречается несколько раз;
**последняя запись о ней побеждает** — как присваивание в юните systemd.

## Требования

| Что | Почему |
|---|---|
| цель — последняя версия, чьё последнее состояние `healthy` | строка перед текущей может быть неудачным выкатом |
| миграция после цели → отказ, код 3, ничего не тронуто | откат кода не отменяет изменения схемы |
| миграции раньше цели не мешают | они уже были в бою, когда цель работала |
| `--force` снимает оба отказа | решение принимает человек, но явно и в истории команд |
| выкат точным тегом версии, по `ssh` на `--host` | `latest` — это «сломанное, что сейчас» |
| проверка готовности после выката | «команда выполнена» ≠ «служба отвечает» |
| готовность не подтвердилась → код 1 | молчаливый успех хуже честного отказа |
| журнал дописывается: снятая → `failed`, восстановленная → `healthy` | иначе повторный откат вернёт в бой сломанное |
| `--to ВЕРСИЯ` — явная цель, с проверкой по журналу | под давлением полезно уметь назвать версию руками |
| `--dry-run` печатает план и не меняет ничего | сначала увидеть, что произойдёт |
| ни одного зашитого имени, хоста и версии | тест подставит другой журнал |

Коды возврата: `0` — откат подтверждён, `1` — выполнен, но служба молчит,
`2` — ошибка вызова или откатываться некуда, `3` — миграция на пути.

## Чем добывать

| Что нужно | Как |
|---|---|
| значащие строки журнала | `grep -vE '^[[:space:]]*(#\|$)'` |
| последнее состояние версии | `awk -v v=… '$2==v {s=$3} END{print s}'` |
| версии по последнему упоминанию | `awk '{last[$2]=NR} END{…}' \| sort -rn` |
| миграции после цели | запомнить номер строки цели, смотреть `NR > n` |
| выкат | `ssh "${HOST}" "docker pull ${IMAGE}:${TARGET}"` |
| проверка готовности | `curl -fsS --max-time 5 "${HEALTH}"` в цикле |
| дописать журнал | `printf '%s  %s  %-8s %-3s %s\n' … >> "${JOURNAL}"` |

## Критерии приёмки

- [ ] `artifacts/rollback.sh` создан на основе `starter/`, синтаксис проходит `bash -n`.
- [ ] Включены строгие режимы (`set -euo pipefail`).
- [ ] На журнале инцидента цель отката — `3f8ba110`, а не `b0c4d5e6`.
- [ ] Выкат идёт точным тегом; `latest` не используется.
- [ ] Миграция раньше цели откату не мешает.
- [ ] Миграция после цели даёт код 3, `ssh` не вызывается, журнал не изменён.
- [ ] `--force` разрешает такой откат.
- [ ] Проверка готовности выполняется **после** выката.
- [ ] Не подтвердилась — ненулевой код и запись `failed` в журнале.
- [ ] Журнал дописан: снятая версия `failed`, восстановленная `healthy`.
- [ ] Повторный запуск уходит глубже, а не возвращает снятую версию.
- [ ] `--dry-run` не трогает ни хост, ни журнал, но называет цель.
- [ ] Единственная версия в журнале → код 2, ничего не тронуто.
- [ ] `--to` работает; на неизвестную и на `failed` версию — отказ.
- [ ] Пустые строки, комментарии и табуляции в журнале разбираются верно.
- [ ] На другом журнале, хосте и образе все ответы пересчитываются.
- [ ] `bash tests/test.sh` → 31 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils |
| Сеть | **не нужна** |
| `docker`, `ssh` | **не нужны** — подменяются заглушками |
| Внешние пакеты | нет |
| Изоляция теста | `ssh`, `curl`, `docker` и `sleep` заменяются заглушками в `PATH` |

Заглушки записывают вызовы в файл, поэтому предметом проверки становится не
результат, а **что скрипт собирался сделать и в каком порядке**: сходил ли на
хост до проверки готовности, каким тегом, не запускал ли `docker` у себя.
Подменённый `sleep` делает ожидание бесплатным — цикл повторов не замедляет
тест. Локальный `docker` — сигнал ошибки: откат делается на машине из
`--host`.

Ожидаемых значений в тесте не зашито: последний сценарий подставляет журнал
с другими версиями, другим хостом и другим образом, и ответы обязаны
измениться вместе с ним.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «цель выбрана неверно» | берётся предпоследняя строка | искать последнюю с состоянием `healthy` |
| «версия со статусом failed выбрана» | состояние не проверяется | смотреть **последнюю** запись о версии |
| «миграция раньше цели не мешает» — красное | проверяются все миграции журнала | только строки после цели |
| «миграция не остановила откат» | проверки нет | код 3 и выход до `ssh` |
| «журнал не дописан» | скрипт только читает | дописать две записи |
| «повторный откат вернул a1b2c3d4» | снятая версия не помечена | записывать её как `failed` |
| «служба не отвечает, а код 0» | результат `curl` не влияет на выход | вернуть 1 |
| «локальный docker не вызывается» — красное | `docker` запускается на своей машине | всё через `ssh "${HOST}"` |
| «в выводе всплыли значения из другого журнала» | что-то зашито | все значения — из аргументов и файла |

## После выполнения

Зелёный тест означает, что откат перестал быть текстом в вики и стал
командой: цель выбирается по записанному факту, а не по памяти, а
односторонние двери скрипт замечает раньше, чем в них войдут.

Стоит запомнить формулировку, которая переносится дальше всего: **у любой
отмены есть граница**. Откат возвращает код, но не данные; `git revert` — не
то, что уже забрали другие; удаление секрета — не факт утечки. Знать эту
границу заранее — работа на десять минут. Выяснять во время инцидента —
именно то, из-за чего пять минут простоя превращаются в сорок.

## Кумулятивность

Откат возможен только потому, что конвейер из
[`s04e07`](../s04e07-ci-pipeline/) метит каждую сборку хешем коммита: у
предыдущей версии есть имя. Разница между «процесс запущен», «служба
отвечает» и «служба отвечает правильно» продолжает
[`s04e06`](../s04e06-compose/), где `Up` отличался от `Up (healthy)`. Чтение
журнала по правилу «последняя запись побеждает» — та же семантика, что в
юните systemd из
[`s03e05`](../../season-03-system-administration/s03e05-systemd-service/), и
пятая из названных в курсе. Порядок «сначала появляется новое, потом
исчезает старое» — тот же, что при смене способа входа в
[`s02e09`](../../season-02-networking/s02e09-ssh-hardening/). Граница
отмены — прямое продолжение
[`s04e03`](../s04e03-gitignore-secrets/): удалить секрет из репозитория
можно, сделать его неутёкшим — нельзя.
