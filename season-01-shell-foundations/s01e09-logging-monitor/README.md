## Теория: логирование (один концепт: сохранить историю)

Вывод по умолчанию идёт на экран (`stdout`). **Перенаправление** отправляет его в файл:

```bash
echo "строка"  > file      # перезаписать (опасно для логов!)
echo "строка" >> file      # дописать в конец (append — для логов)
echo "строка" | tee -a file  # и на экран, И в лог
```

Лог без времени бесполезен — добавляем **таймстамп** через `date`:

```bash
ts() { date '+%Y-%m-%d %H:%M:%S'; }
echo "[$(ts)] [UP] ${host}" >> "${log}"
# [2025-10-04 16:23:45] [UP] shadow-server-01
```

Функция `ts()` держит формат единым по всему логу. Разница `>`/`>>`/`2>`/`2>&1` и коды `date` — в [`theory.md`](theory.md).

> **LILITH:** *«Перепутал `>` и `>>` — стёр production-логи. `>` опасен, `>>` безопасен для логов. Запомни.»*

## Проверка «в мире сюжета»

**Дмитрий:** *«В чём разница между `echo x > log` и `echo x >> log` для файла логов?»*

<details>
<summary>Подумай 30 секунд</summary>

`>` **затирает** файл целиком при каждой записи — от лога останется одна последняя строка. `>>` **дописывает** в конец, сохраняя историю. Для логов всегда `>>`. Перепутать — значит потерять всю историю мониторинга.
</details>

**Дмитрий:** *«Зачем таймстамп, если статус и так виден?»*

<details>
<summary>Ответ</summary>

Статус без времени не отвечает на главный вопрос инцидента: «когда упало и как долго лежало?». Таймстамп превращает набор строк в хронологию, по которой можно расследовать сбой и считать SLA.
</details>
