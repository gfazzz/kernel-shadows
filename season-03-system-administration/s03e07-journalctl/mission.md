## Обстановка

Шесть дней разбирали следствия: учётные записи, права, процессы, юниты,
расписание. Осталось единственное, чего ещё не читали, — сам журнал за тот
вечер, когда всё это появилось.

Записей об «атаке» в нём нет. Есть семьдесят строк, из которых часть
складывается в неё.

## Приказ

Восстановить хронологию и **сдать отчёт** — заполненный
`artifacts/journal_report.txt`: как вошли, под кем, что выполнили через
`sudo`, когда появилась учётная запись `devops`, когда служба была включена
и когда запущена, сколько машина простояла.

```bash
cp starter/journal_report.txt artifacts/journal_report.txt
bash tests/test.sh
```

Время записывается ровно в том виде, как в журнале, но **без часового
пояса**: `2025-10-14T22:07:02`.

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/journal_shadow-01.txt`](../data/journal_shadow-01.txt) | `journalctl --since … --until … -o short-iso` |
| [`data/journal_err_shadow-01.txt`](../data/journal_err_shadow-01.txt) | то же окно с `-p err` |

Формат `short-iso`: `ВРЕМЯ ХОСТ ИСТОЧНИК[PID]: СООБЩЕНИЕ`. В обоих файлах
есть шапка с описанием.

## Чем добывать

| Что нужно | Как |
|---|---|
| только записи | `grep -vE '^[[:space:]]*#\|^[[:space:]]*$' "$J"` |
| время без пояса | `sed -E 's/^([0-9-]+T[0-9:]+).*/\1/'` |
| попытки входа | `grep -E 'Failed\|Accepted\|Invalid'` |
| команды через sudo | `grep 'COMMAND='` — **не** `grep sudo` |
| перебранные имена | `grep -oE 'Invalid user [a-z]+' \| awk '{print $3}' \| sort -u` |
| включение юнита | `grep 'Created symlink'` |
| запуск юнита | `grep 'Started '` |
| разрыв в мониторинге | `grep 'ops-check\['` и посмотреть на колонку времени |
| скачок часов | `grep 'clock jumped'` |

Несколько значений собираются в одну строку через запятую, без пробелов,
по алфавиту.

## Критерии приёмки

- [ ] `artifacts/journal_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Адрес, с которого шли попытки, определён по частоте, а не по первой попавшейся строке.
- [ ] Неудачные попытки посчитаны по `Failed password`, а не по слову `invalid`.
- [ ] В списке перебранных имён нет существующих учётных записей.
- [ ] Названа учётная запись, под которой вошли, — и это **не** та, которую создали позже.
- [ ] Команды `sudo` посчитаны по `COMMAND=`.
- [ ] Различены включение (`Created symlink`) и запуск (`Started`) службы.
- [ ] Границы провала в мониторинге найдены, длительность посчитана в минутах.
- [ ] Скачок часов выписан и сходится с длительностью провала.
- [ ] Посчитаны записи уровня `err` и выше — и видно, что записей об атаке среди них нет.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбирается копия вывода `journalctl` |
| ОС | любая с bash + awk + sed + coreutils (systemd не требуется) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из тех же снимков, констант в тесте нет |

Тест дополнительно проверяет, что ловушки на месте: парные строки
`Invalid user`, строки `pam_unix` вокруг каждой команды `sudo`, попытка под
существующим `root` и отсутствие записей об атаке в выборке по приоритету.

## Выполнение

```bash
cd season-03-system-administration/s03e07-journalctl
cp starter/journal_report.txt artifacts/journal_report.txt
J=../data/journal_shadow-01.txt
grep -vE '^[[:space:]]*#|^[[:space:]]*$' $J | grep -E 'Failed|Accepted|Invalid|COMMAND='
bash tests/test.sh
```

На своей машине стоит проверить главное — сохраняется ли твой журнал между
перезагрузками:

```bash
ls -d /var/log/journal 2>/dev/null || echo "журнал живёт в /run и исчезнет при перезагрузке"
journalctl --disk-usage
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| неудачных попыток получилось 6 | посчитаны парные строки `Invalid user` | считать по `Failed password` |
| в списке имён появился `root` | root существует, это не перебор | брать только из строк `Invalid user` |
| команд `sudo` получилось 17 | посчитаны строки `pam_unix` | считать по `COMMAND=` |
| `compromised_account=devops` | учётка создана **после** входа | смотреть строку `Accepted` |
| `helper_enabled` = время `Started` | перепутаны включение и запуск | `Created symlink` — это enable |
| время не принято | попал часовой пояс `+0300` | формат `2025-10-14T22:07:02` |
| длительность провала на минуту меньше | посчитаны секунды | по минутам: `22:10` → `23:45` = 95 |
| `err_records` большое | посчитаны все строки файла вместе с шапкой | шапка начинается с `#` |

## После выполнения

Зелёный тест означает, что хронология восстановлена по секундам. Стоит
задержаться на двух наблюдениях, которые важнее самих значений.

Первое: всё, что произошло, заняло десять минут и не породило ни одной
ошибки. Система работала штатно и честно записывала, что делает.

Второе: разбор занял больше времени, чем сама атака, — и это нормально.
Ненормально другое: журнал лежал шесть дней, и его никто не открыл.
