## Обстановка

Три поломки, разобранные утром в [`s07e01`](../s07e01-cluster-recon/), живут
в одном файле: предел памяти ниже пика, запрос памяти такой, что пятая
реплика не влезает ни на один узел, и переменная окружения, которой нет.
Плюс предел процессора, поставленный ниже измеренного максимума, — этого
утром не было видно, потому что троттлинг не порождает событий.

Кластер исполнит написанное буквально. Значит, каждое число в файле должно
иметь происхождение.

## Приказ

Написать `artifacts/deployment.yaml` так, чтобы пять реплик поднялись и
остались живыми.

```bash
cp starter/deployment.yaml artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `current_deployment.yaml` | манифест как он есть сейчас — не образец |
| `usage.txt` | p50, p95 и максимум памяти и процессора за неделю |
| `capacity.txt` | сколько памяти свободно на каждом узле |
| `startup.txt` | журнал холодного старта |
| `endpoints.txt` | какая ручка что спрашивает; обязательные переменные |
| `registry_tags.txt` | какие теги образа существуют |

## Чем добывать

| Что нужно | Как |
|---|---|
| свободно на узле | `memory_allocatable_Mi - memory_others_Mi` |
| сколько реплик встанет | сумма целых частей `свободно / requests` по узлам |
| потолок памяти | `memory_max_Mi` плюс `memory_headroom_pct` |
| длительность старта | разница меток времени от `pid 1` до `listening` |
| бюджет `startupProbe` | `periodSeconds × failureThreshold` |
| ручка для пробы живости | та, у которой `depends_on` пуст |

## Критерии приёмки

- [ ] `spec.replicas` — столько же, сколько заказано сейчас.
- [ ] Тег образа явный, не `latest`, и существует в реестре.
- [ ] `requests.memory` покрывает обычное потребление, `limits.memory` — пик с запасом, и они **не равны**.
- [ ] Пять реплик размещаются по узлам: считать по узлам, а не по сумме.
- [ ] `limits.cpu` либо отсутствует, либо не ниже измеренного пика.
- [ ] Заданы три пробы; бюджет `startupProbe` — не меньше полутора холодных стартов.
- [ ] Проба живости не ходит во внешние системы; пути живости и готовности разные.
- [ ] `AURORA_DB_DSN` приходит ссылкой на `Secret`, а не значением.
- [ ] Запись блочная, отступ два пробела.
- [ ] `bash tests/test.sh` → 31 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep + sed |
| Сеть | не нужна |
| **кластер** | **не нужен** — измерения и снимки в `data/` |
| `kubectl` | не нужен |
| Внешние пакеты | нет |
| Изоляция теста | пороги вычисляются из `data/`, во временный каталог пишется только разбор |

Тест не содержит зашитых чисел: он берёт p50, максимум, запас, свободное
место и длительность старта из `data/` и сравнивает с ними. Отдельно
проверяется, что данные не выродились: что нынешний предел действительно
ниже пика и что размещение действительно зависит от размера `requests`.
Без этих двух свойств серия свелась бы к переписыванию образца.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «встают только 4 из 5» | `requests` великоваты | считать места по узлам: `int(свободно / requests)` |
| «вернётся 137» | предел памяти ниже пика | `memory_max_Mi` плюс запас |
| «requests=limits» | поля заполнены одним числом | это два разных вопроса |
| «тега нет в реестре» | тег придуман | взять из `registry_tags.txt` |
| «бюджет старта меньше» | считали по `initialDelaySeconds` | бюджет — произведение периода на порог |
| «живость смотрит /ready» | пробы перепутаны | `/ready` ходит в базу, живость — нет |
| «задана значением» | DSN вписан в манифест | `valueFrom.secretKeyRef` |
| «потоковая запись» | использованы `{}` или `[]` | развернуть в отступы |

## После выполнения

Зелёный тест означает, что в файле не осталось чисел, выбранных по
привычке. Пять реплик встают, потолок покрывает пик, медленный старт
защищён от пробы живости, а пароль остался вне git.

Главное, что стоит унести: **`requests` и `limits` отвечают на разные
вопросы, и равенство их — не выбор, а его отсутствие.** Тот же приём
различения уже встречался в курсе: «сколько заказано» и «сколько работает»
в [`s07e01`](../s07e01-cluster-recon/), «описано» и «накоплено» в
[`s04e11`](../../season-04-devops-automation/s04e11-iac-audit/).

## Кумулятивность

Числа берутся из измерения, а не из привычки — это продолжение
[`s05e06`](../../season-05-security-pentesting/s05e06-pam-passwords/),
где длина пароля обосновывалась расчётом, и
[`s03e09`](../../season-03-system-administration/s03e09-lvm/), где размер
тома считался, а не назначался.

Проверка «что изменится, если применить» — тот же вопрос, что задавал
режим `--check` в
[`s04e10`](../../season-04-devops-automation/s04e10-ansible-check/);
здесь его задаёт `kubectl diff` и `--dry-run=server`.

Секрет, которого нет в репозитории, — прямое продолжение
[`s04e03`](../../season-04-devops-automation/s04e03-gitignore-secrets/):
там его не пускали в git правилами игнорирования, здесь — ссылкой на
`Secret`.
