## Обстановка

Дмитрий завёл учётную запись на московском сервере и прислал снимок:
четыре команды, выполненные от вашего имени. С припиской «посмотри заранее,
чтобы не удивляться. Это не твой ноутбук».

В снимке есть строка, которой вы не ждали: попытка прочитать чужой файл
через `sudo` закончилась отказом — и попала в журнал.

## Приказ

Разобрать снимок и **сдать отчёт** — заполненный `artifacts/access_answers.txt`:
кто вы на этой машине, что сможете прочитать, что нет, и что вам разрешено
через `sudo`.

```bash
cp starter/access_answers.txt artifacts/access_answers.txt
bash tests/test.sh
```

## Объект разведки

| Раздел файла | Что это |
|---|---|
| `=== whoami ===` | имя пользователя |
| `=== id ===` | номер и все группы |
| `=== ls -l /srv/ops ===` | девять записей рабочего каталога операции |
| `=== sudo -l ===` | что именно вам разрешено |
| `=== журнал sudo за 8 октября ===` | что происходило на самом деле |

Всё в одном файле: [`data/moscow_server_access.txt`](../data/moscow_server_access.txt).

## Чем добывать

| Что нужно | Как |
|---|---|
| вырезать раздел | `awk -v s='id' '$0=="=== "s" ===" {f=1; next} /^=== /{f=0} f' "$D"` |
| номер пользователя | `grep -oE 'uid=[0-9]+'` |
| список групп | всё после `groups=`, через запятую |
| только строки прав | `grep -E '^[-dl]'` |
| права в цифрах | по тройкам: `r`=4, `w`=2, `x`=1 |
| владелец и группа файла | третья и четвёртая колонки `ls -l` |
| SUID | буква `s` вместо `x` в позиции владельца (четвёртый символ) |
| разрешённые команды | строки после «may run the following commands» |
| успешные вызовы | строки журнала, где есть `COMMAND=` и нет пометки об отказе |

## Критерии приёмки

- [ ] `artifacts/access_answers.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Группы посчитаны по одному списку: основная не учтена дважды.
- [ ] Различены три уровня доступа: читаемое всеми, читаемое через группу, недоступное совсем.
- [ ] Найден каталог, доступный всем на запись.
- [ ] Права двух файлов переведены в цифры верно.
- [ ] Найден файл с битом SUID (`s` вместо `x` у владельца).
- [ ] Посчитано, сколько команд разрешено через `sudo` и от чьего имени.
- [ ] Успешные вызовы `sudo` отделены от отказа.
- [ ] Названа команда, которую `sudo` запретил.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбирается копия вывода команд |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из того же снимка, констант в тесте нет |

Тест дополнительно проверяет, что ловушки на месте: основная группа
перечислена и в `gid=`, и в `groups=`; в журнале три строки с вашим именем
при двух успешных вызовах.

## Выполнение

```bash
cd season-01-shell-foundations/s01e16-sudo-basics
cp starter/access_answers.txt artifacts/access_answers.txt
D=../data/moscow_server_access.txt
awk -v s='ls -l /srv/ops' '$0=="=== "s" ===" {f=1; next} /^=== /{f=0} f' $D
bash tests/test.sh
```

На своей машине те же три команды занимают секунду и почти всегда
показывают что-нибудь неожиданное:

```bash
id
sudo -l
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| групп получилось 4 | основная посчитана дважды | считать по одному списку `groups=` |
| «файл, читаемый через группу» не тот | смотрели только права | нужна ещё колонка группы: `adm` |
| «недоступный совсем» — не тот | взят файл с правами группы | нужны `-rw-------` **и** чужой владелец |
| права вышли неверно | сложены не те тройки | владелец / группа / остальные, по три буквы |
| SUID не найден | искали букву `s` где угодно | четвёртый символ строки прав |
| успешных вызовов 3 | посчитаны все строки с именем | одна из них — отказ |
| `sudo_denied` не принят | указано `cat` вместо пути | в журнале записан полный путь |

## После выполнения

Зелёный тест означает, что вы читаете чужую машину: видите, кто вы на ней,
что вам доступно и почему.

Обратите внимание на `plan.txt`. Он не читается — и это не ошибка настройки.
Виктор так и хотел. Правильная реакция на такой отказ — не искать обход,
а понять, что решение было принято заранее и осознанно.

Через два сезона вы окажетесь по другую сторону и будете писать этот список
сами.

## Кумулятивность

Девять букв прав прочитаны в [`s01e15`](../s01e15-permissions-basics/) —
здесь они впервые применяются к чужой машине, где владелец не вы. Ошибка
`Permission denied` из [`s01e01`](../s01e01-terminal-awakening/) и замечание
из [`s01e03`](../s01e03-cd-cat-navigate/) о том, что это не повод тянуться
к `sudo`, здесь закрываются окончательно. Команды `sudo apt update` и
`sudo apt install` из [`s01e13`](../s01e13-apt-dpkg/) получают объяснение:
именно они и стоят в списке разрешённых. Разбор колонок через `awk` —
из [`s01e11`](../s01e11-awk-stats/), вырезание разделов по заголовку —
приём, который дальше используется во всём курсе.
