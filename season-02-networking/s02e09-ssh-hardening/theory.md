## SSH-туннели — шифрованные каналы

SSH умеет пробрасывать порты внутри своего шифрованного соединения:

```bash
# Local forward (-L): локальный порт → сервис на удалённой стороне
ssh -L 8080:localhost:80 user@server
# теперь localhost:8080 ведёт на 80-й порт server через шифрованный туннель

# Remote forward (-R): удалённый порт → сервис на твоей стороне
ssh -R 9000:localhost:3000 user@server
# server:9000 ведёт на твой localhost:3000

# Dynamic forward (-D): SOCKS-прокси, весь трафик через сервер
ssh -D 1080 user@server
# настрой браузер на SOCKS 127.0.0.1:1080 — трафик пойдёт зашифрованно через server
```

Туннель прячет трафик от DPI: снаружи видно только SSH-соединение, а не то, что внутри.

## Hardening sshd_config

Файл `/etc/ssh/sshd_config`. Ключевые директивы:

| Директива | Безопасно | Почему |
|-----------|-----------|--------|
| `PermitRootLogin` | `no` | не пускать root напрямую (только `sudo` от юзера) |
| `PasswordAuthentication` | `no` | только ключи (пароли брутфорсятся) |
| `PermitEmptyPasswords` | `no` | очевидно |
| `X11Forwarding` | `no` | не нужен на сервере, лишняя поверхность атаки |
| `Protocol` | `2` | SSHv1 сломан (в новых OpenSSH только 2) |
| `AllowUsers`/`AllowGroups` | явный список | пускать только кого нужно |
| `MaxAuthTries` | `3` | меньше попыток подбора |
| `Port` | нестандартный (опц.) | меньше шума от сканеров (не защита, а гигиена) |

**Важно:** sshd берёт **первое** вхождение директивы; закомментированные (`#`) —
игнорируются (это дефолт). Правило применения: изменил конфиг → `sudo sshd -t` (проверка
синтаксиса!) → перезапуск службы. Перезапуск — это systemd (`systemctl restart ssh`),
его разбираем в **Season 3**; здесь — только аудит конфига.

> Не заблокируй себя: перед `PasswordAuthentication no` убедись, что ключ работает,
> и держи вторую сессию открытой.

## VPN (WireGuard) — шифрование всего трафика

SSH-туннель шифрует один канал; VPN — **весь** трафик машины. Современный выбор —
**WireGuard** (шифр ChaCha20-Poly1305, простой конфиг, быстрый). Против DPI Крылова:
он видит только зашифрованный поток, содержимое недоступно. Настройка WireGuard —
это конфиги + ключи (та же логика, что SSH), с systemd-сервисом (S3).
