## Обстановка

Виктор подключил к серверу диск на 500 ГБ. Ядро его видит, `lsblk` показывает,
`df` — нет и не покажет: диск не размечен под LVM и не входит в группу томов.
`VFree` в группе равен нулю.

Расширять `/var/log` предстоит на работающем сервере, не останавливая ни базу,
ни сбор журналов.

## Приказ

Написать `artifacts/lvm_plan.sh` — скрипт, который читает снимок состояния и
**печатает** последовательность команд для расширения тома.

```bash
cp starter/lvm_plan.sh artifacts/lvm_plan.sh
bash artifacts/lvm_plan.sh
bash tests/test.sh
```

**Скрипт ничего не выполняет.** `lvreduce` на смонтированном томе уничтожает
файловую систему, `pvcreate` на чужом диске стирает разметку — единственная
защита от опечатки в имени устройства состоит в том, чтобы человек прочитал
план до его выполнения. Тест проверяет это отдельно: команды LVM подменены
заглушками, и любой их вызов означает провал.

## Объект разведки

| Файл | Что в нём |
|---|---|
| [`data/lvm_shadow-01.txt`](../data/lvm_shadow-01.txt) | разделы `pvs`, `vgs`, `lvs`, `lsblk -dn` |
| [`data/disk_shadow-01.txt`](../data/disk_shadow-01.txt) | оттуда берутся точка монтирования и тип ФС (`s03e08`) |

Пути по умолчанию скрипт знает сам; тест подменяет их ключами `--snapshot`
и `--fs-snapshot`.

## Что должен уметь скрипт

| Требование | Почему |
|---|---|
| определять группу томов и `VFree` из снимка | имена меняются от сервера к серверу |
| находить свободный диск как «есть в `lsblk`, нет в `pvs`» | `pvcreate` на чужом PV стирает метаданные |
| брать размер и имя целевого тома из `lvs` | том задаётся ключом `--target` |
| выбирать команду растягивания по типу ФС | `resize2fs` для ext4, `xfs_growfs` для xfs |
| печатать шаги по порядку: диск → группа → том → ФС | каждый шаг безопасен, остановка не ломает систему |
| завершаться с ненулевым кодом на несуществующем томе | молчаливая ошибка хуже громкой |
| ничего не выполнять | см. выше |

## Чем добывать

| Что нужно | Как |
|---|---|
| вырезать раздел снимка | `awk -v s='vgs' '$0=="=== "s" ===" {f=1; next} /^=== /{f=0} f' "$F"` |
| группа и `VFree` | раздел `vgs`, первая строка данных: `$1` и `$NF` |
| размер тома | раздел `lvs`: `$1` — имя, `$4` — размер |
| устройства группы | раздел `pvs`, колонка `$1` |
| диски | раздел `lsblk -dn -o NAME,SIZE,TYPE` |
| точка монтирования и тип ФС | разделы `df -h` и `lsblk -f` второго снимка |
| имя тома в `/dev/mapper` | дефис в имени группы удваивается: `ops-vg` → `ops--vg-log` |

## Критерии приёмки

- [ ] `artifacts/lvm_plan.sh` создан на основе `starter/`, начинается с шебанга и `set -euo pipefail`.
- [ ] Скрипт отрабатывает без аргументов и печатает непустой план.
- [ ] Ни одна команда LVM не выполняется — только печатается.
- [ ] В плане есть все четыре шага в правильном порядке.
- [ ] Команда растягивания соответствует типу файловой системы из снимка.
- [ ] Имя группы и устройство взяты из снимка, а не вписаны в текст скрипта.
- [ ] Диск, уже входящий в группу, не предлагается размечать заново.
- [ ] Ключ `--target` переключает целевой том.
- [ ] Несуществующий том вызывает ошибку с ненулевым кодом.
- [ ] Вывод не меняется от локали и часового пояса.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Выполнение

```bash
cd season-03-system-administration/s03e09-lvm
cp starter/lvm_plan.sh artifacts/lvm_plan.sh
$EDITOR artifacts/lvm_plan.sh
bash artifacts/lvm_plan.sh
bash artifacts/lvm_plan.sh --target var
bash tests/test.sh
```

На своей машине стоит посмотреть, есть ли у тебя LVM вообще, — на многих
десктопных установках Ubuntu он есть, а владелец об этом не знает:

```bash
sudo pvs; sudo vgs; sudo lvs
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «скрипт ВЫПОЛНИЛ команду» | команда вызвана, а не напечатана | обернуть в `echo` |
| «в выводе нет kx-vg» | имя группы вписано в текст | читать из раздела `vgs` |
| «в выводе нет /dev/vdz» | устройство вписано в текст | искать как «есть в `lsblk`, нет в `pvs`» |
| «для xfs нужен xfs_growfs» | команда выбрана заранее | ветвление по типу ФС из снимка |
| «порядок шагов нарушен» | `vgextend` раньше `pvcreate` | диск → группа → том → ФС |
| «--target не влияет» | имя тома вписано в текст | подставлять переменную |
| размер тома вышел `-wi-ao----` | взята колонка `Attr` | в `lvs` размер — четвёртая колонка |
| план предлагает `pvcreate` на `/dev/vdb` | не проверено вхождение в группу | сверить со списком `pvs` |

## После выполнения

Зелёный тест означает, что скрипт читает состояние, а не помнит его. Разница
проверяется буквально: тест подсовывает снимок другого сервера, и план должен
измениться целиком.

Отдельно стоит посмотреть на получившийся план глазами и задать по каждому
шагу один вопрос: «что будет, если остановиться здесь». У правильной
последовательности ответ на всех четырёх шагах — «ничего страшного».

## Кумулятивность

Тип файловой системы и точка монтирования берутся из снимка
[`s03e08`](../s03e08-disks-fs/) — того же, по которому найдены удалённый файл
и исчерпание inode. Разбор разделов через `awk` и вырезание секций по
заголовку — оттуда же. Дисциплина скрипта (`set -euo pipefail`, ключи,
ненулевой код при ошибке) — из
[`s01e09`](../../season-01-shell-foundations/s01e09-logging-monitor/), моки в
`PATH` как способ поймать «выполнил вместо того, чтобы напечатать» — из
[`s02e06`](../../season-02-networking/s02e06-firewall-ufw/).
