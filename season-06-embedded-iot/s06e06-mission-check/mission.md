## Обстановка

Вчерашний план прошёл загрузку в наземную станцию без единой жалобы — и
содержал незаполненную точку с координатами `0,0`, точку в другой системе
отсчёта высоты, заход в зону аэродрома и маршрут в полтора раза длиннее
запаса батареи. Станция проверяет синтаксис; смысл не проверил никто.

Нужен валидатор, который делает это на земле — за секунду и без аппарата.

## Приказ

Написать `artifacts/check_mission.sh`.

```bash
cp starter/check_mission.sh artifacts/
bash tests/test.sh
```

```
check_mission.sh [--limits ФАЙЛ] [--nofly ФАЙЛ] ПЛАН.waypoints
```

| Файл в `data/` | Что в нём |
|---|---|
| `mission_ok.waypoints` | корректный план: на нём не должно быть ни одного срабатывания |
| `mission_bad.waypoints` | вчерашний план со всеми находками |
| `limits.txt` | пределы аппарата и площадки (`ключ=значение`) |
| `nofly.txt` | запретные зоны: `имя lat lon радиус_м` |

Формат плана — `QGC WPL 110`, поля через табуляцию:

```
INDEX CURRENT FRAME COMMAND P1 P2 P3 P4 LAT LON ALT AUTOCONTINUE
  $1     $2     $3     $4               $9 $10 $11     $12
```

## Требования

| № | Правило | Что предотвращает |
|---|---|---|
| 1 | индексы подряд с нуля | пропущенную или задвоенную строку |
| 2 | первая точка — дом: команда `16`, `current=1` | план без точки старта |
| 3 | последняя команда — `20` или `21` | зависание в воздухе в конце маршрута |
| 4 | нет координат `0,0` | полёт в точку Нуль |
| 5 | единый `FRAME` у путевых точек | необъявленное снижение |
| 6 | высота в `[alt_min_m, alt_max_m]` | нарушение регламента, полёт по земле |
| 7 | точки вне запретных зон | заход на аэродром |
| 8 | точки внутри `geofence_radius_m` от дома | уход за пределы связи |
| 9 | плечо ≤ `leg_max_m` | перелёт вне зоны приёма |
| 10 | маршрут ≤ `total_max_m` | посадку на разряженной батарее |

Дополнительно:

- заголовок `QGC WPL` проверяется **до** разбора;
- ни одного числового предела в коде — только из `--limits` и `--nofly`;
- по строке на нарушение, с номером точки; в конце — `Нарушений: N`;
- нулевые точки исключаются из расчёта длины и называются отдельно.

Коды возврата: `0` — чисто, `1` — аргументы, `2` — не читается или не тот
формат, `3` — есть нарушения.

## Чем добывать

| Что нужно | Как |
|---|---|
| ограничения | `getline line < LIM` в `BEGIN`, разбор `ключ=значение` |
| зоны | `split(line, f)` — имя, широта, долгота, радиус |
| точки | `idx[++m]=$1; frame[m]=$3; cmd[m]=$4; lat[m]=$9; lon[m]=$10; alt[m]=$11` |
| расстояние | гаверсинус — заготовка в комментарии стартера |
| внутри зоны | расстояние до центра ≤ радиуса |

## Критерии приёмки

- [ ] `artifacts/check_mission.sh` создан на основе `starter/`, `bash -n` чист.
- [ ] `mission_ok` → `Нарушений: 0`, код `0`: ни одного ложного срабатывания.
- [ ] `mission_bad` → код `3`; названы номера точек с высотой вне пределов, с нулевыми координатами и с чужим `FRAME`.
- [ ] Сказано про отсутствие посадки и названа запретная зона по имени.
- [ ] Ослабление пределов в `--limits` убирает геометрические нарушения.
- [ ] Ужесточение `alt_max_m` делает корректный план негодным.
- [ ] Пустой файл зон убирает нарушение по зоне.
- [ ] Файл не в формате `QGC WPL` даёт код `2` без разбора.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | не нужна |
| **дрон** | **не нужен** — планы лежат в `data/` |
| Внешние пакеты | нет |
| Изоляция теста | вердикты сверяются с независимым расчётом и подменой пределов |

Тест не содержит зашитых вердиктов. Для простых правил он сам вычисляет из
плана, какие точки нарушают высоту, содержат нули и выбиваются по `FRAME`, и
требует, чтобы валидатор назвал именно эти номера.

Геометрические правила проверяются подменой данных: с ослабленными пределами
нарушения по высоте, плечу, дальности и геозоне обязаны **исчезнуть**, с
ужесточённым `alt_max_m` — появиться даже на корректном плане, а с пустым
файлом зон — пропасть нарушение по зоне. Валидатор с зашитыми числами эти
проверки не пройдёт.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| ложные срабатывания на `mission_ok` | правило слишком строгое | сверить с таблицей: у посадки высота 0 — это норма |
| «ослабление пределов ничего не изменило» | числа зашиты в коде | все пределы читать из `--limits` |
| «геометрические нарушения остались» | часть правил игнорирует файл | проверить каждое обращение к `L[...]` |
| точка не названа | в сообщении нет номера | печатать `точка N: …` |
| чужой формат разбирается | нет проверки заголовка | `head -1 | grep QGC WPL` до всего |
| абсурдная длина маршрута | нулевая точка попала в цепочку | исключать её из расчёта |
| вывод меняется при `LC_ALL=C` | десятичный разделитель локали | в `awk` числа печатать через `%d`/`%s` |

## После выполнения

Зелёный тест означает, что план полёта проверяется за секунду, до вылета и
без аппарата — а десять правил закрывают десять способов потерять дрон.

Стоит запомнить принцип, который работает далеко за пределами авиации:
**проверка формата не заменяет проверку смысла.** «Файл разобрался» говорит
только о том, что в нём нужное число полей. Осмысленность требует внешних
знаний — про батарею, площадку, зоны, — и эти знания надо принести и
применить самому. Второй принцип рядом: **знания о конкретной технике живут
в данных, логика проверки — в коде.** Иначе через месяц у тебя пять копий
скрипта с одинаковым именем и разными числами.

## Кумулятивность

Проверка достижимости и «десять дешёвых проверок вместо одного дорогого
запуска» — прямое продолжение
[`s04e07`](../../season-04-devops-automation/s04e07-ci-pipeline/) с его
пирамидой тестов и графом `needs`. Зазор между «разобралось» и «правильно» —
та же мысль, что в
[`s04e10`](../../season-04-devops-automation/s04e10-ansible-check/): проверка
режимом `--check` показывает, что сделает playbook, но не отвечает, надо ли
это делать.

Вынос пределов в данные — тот же приём, что карта гребёнки в
[`s06e02`](../s06e02-gpio-sysfs/), список датчиков в
[`s06e03`](../s06e03-boot-config/) и замеры записи в
[`s06e04`](../s06e04-readonly-root/). Формат отчёта «нарушение + объект + итог
числом» — из
[`s05e12`](../../season-05-security-pentesting/s05e12-cis-check/), где
защищённость превращалась в «X из Y».

Разбор вчерашнего полёта в
[`s06e05`](../s06e05-mavlink-telemetry/) ответил на вопрос «что случилось»;
эта серия отвечает на вопрос «почему это стало возможно» — и закрывает его
проверкой, а не расследованием.
