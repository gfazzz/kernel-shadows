## Обстановка

Пять реплик `aurora-api` готовы и не получают ни одного запроса. Служба
существует восемьдесят семь дней со списком адресов `<none>`: селектор
содержит `pod-template-hash`, который менялся при каждом выкате. Ни одного
события, ни одной записи в журнале — несовпадение меток кластер не считает
происшествием.

Заодно надо развести настройки: `AURORA_MESH_URL` и остальные обычные
значения сейчас вписаны в манифест `Deployment`, то есть правка уровня
журнала требует выката.

## Приказ

Написать `artifacts/service.yaml` и `artifacts/config.yaml`.

```bash
cp starter/service.yaml starter/config.yaml artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `pods.txt` | `kubectl get pods --show-labels` — какие метки на самом деле |
| `deployment_excerpt.yaml` | метки шаблона и имя порта контейнера |
| `current_service.yaml` | черновик службы — не образец |
| `endpoints.txt` | `kubectl get endpoints` и `describe svc` |
| `app_config.txt` | какие настройки бывают, какие секретны, что согласовано |
| `services.txt` | службы кластера, их порты и как работает DNS |

## Чем добывать

| Что нужно | Как |
|---|---|
| метки подов | последняя колонка `--show-labels`, через запятую |
| кого найдёт селектор | под подходит, если у него есть **все** пары селектора |
| `targetPort` | имя порта из `deployment_excerpt.yaml` |
| состав `ConfigMap` | строки `key … plain` из `app_config.txt` |
| значения | строки `value …` оттуда же |
| `AURORA_MESH_URL` | имя и порт службы из `services.txt` |

## Критерии приёмки

- [ ] Селектор находит все пять подов приложения и не содержит меток, меняющихся при выкате.
- [ ] `type: ClusterIP`, `nodePort` не задан.
- [ ] `targetPort` совпадает с портом контейнера; порт службы назван.
- [ ] `ConfigMap` содержит все настройки, помеченные `plain`, и ни одной `secret`.
- [ ] Значения совпадают с согласованными в тикете.
- [ ] Все значения `ConfigMap` — строки, включая числа и `true`.
- [ ] В `AURORA_MESH_URL` имя службы, а не адрес пода; порт совпадает с портом службы.
- [ ] `ConfigMap` в том же пространстве имён, что и служба.
- [ ] `bash tests/test.sh` → 26 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep + sed |
| Сеть | не нужна |
| **кластер** | **не нужен** — снимки в `data/` |
| `kubectl` | не нужен |
| Внешние пакеты | нет |
| Изоляция теста | разбор пишется во временный каталог, снимки только читаются |

Тест не сверяет текст с образцом: он считает, сколько подов найдёт **твой**
селектор по реальным меткам из снимка, и сравнивает с тем, сколько подов
приложения там есть. Отдельно проверяется, что данные не выродились: что
селектор черновика действительно не находит никого и что список адресов в
снимке действительно пуст.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «не находит ни одного пода» | селектора нет или он лишний | сверить с колонкой LABELS |
| «в селекторе pod-template-hash» | скопировано из вывода `get pods` | оставить метку из шаблона |
| «находит N из 5» | в селекторе лишняя пара | селектор — это «и», а не «или» |
| «targetPort=80» | взято из черновика | контейнер слушает свой порт |
| «порт без имени» | не задан `name` | пригодится для сбора метрик |
| «в ConfigMap попало секретное» | скопирован весь список | колонка `kind` в `app_config.txt` |
| «без кавычек» | `300` и `true` записаны как есть | в `data` бывают только строки |
| «в адресе IP» | взято из `endpoints.txt` | там адреса, а нужны имена |

## После выполнения

Зелёный тест означает, что служба находит все пять реплик, внутренняя
служба не открыта на узлах, а настройки живут отдельно от образа и от
секретов.

Главное, что стоит унести: **пустой результат не сообщает о себе.** Ошибку
покажет и `apply`, и событие, и журнал; ноль найденных подов не покажет
никто. Поэтому у службы проверяют не факт создания, а список адресов — и
делают это сразу, а не при разборе аварии.

## Кумулятивность

Колонка `READY` из [`s07e01`](../s07e01-cluster-recon/) здесь получает
смысл: в список адресов службы попадают только готовые поды, то есть
проба готовности — это выключатель, которым под сам выводит себя из-под
трафика.

Имя вместо адреса — та же мысль, что в
[`s02e04`](../../season-02-networking/s02e04-dns-lookup/) и
[`s02e05`](../../season-02-networking/s02e05-dns-spoofing-guard/): адрес
меняется, имя остаётся, и разрешать его надо каждый раз заново.

Разделение «настройки отдельно от секретов» продолжает
[`s07e02`](../s07e02-deployment-manifest/) и
[`s04e03`](../../season-04-devops-automation/s04e03-gitignore-secrets/);
разделение «настройки отдельно от образа» — [`s04e05`](../../season-04-devops-automation/s04e05-dockerfile/),
где то же самое решалось переменными сборки.

Балансировка правилами ядра — прямое продолжение
[`s02e06`](../../season-02-networking/s02e06-firewall-ufw/): те же
цепочки, только пишет их не человек.
