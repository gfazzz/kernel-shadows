## Блокировка IP

```bash
sudo ufw deny from 185.220.101.47             # заблокировать один IP (ufw)
sudo iptables -A INPUT -s 185.220.101.47 -j DROP   # то же на iptables
sudo ufw deny from 185.220.0.0/16             # заблокировать подсеть (CIDR)
```

**Почему генерировать, а не применять на лету.** Скрипт, который сам дёргает `ufw`
на каждый IP из списка, при ошибке в данных может заблокировать не то (включая твой
SSH). Безопаснее: сгенерировать **читаемый** файл правил, глазами проверить, и применить
осознанно (`sudo bash block_rules.sh`). Плюс файл версионируется и повторяем.

## Масштаб: ipset вместо тысяч правил

847 отдельных правил iptables — медленно (каждый пакет проверяется по списку сверху вниз).
Для больших списков — **ipset** (хеш-таблица IP, проверка за O(1)):

```bash
sudo ipset create botnet hash:ip
sudo ipset add botnet 185.220.101.47
sudo iptables -A INPUT -m set --match-set botnet src -j DROP   # одно правило на весь список
```

## DDoS-митигация (шире блокировки)

Блокировка IP помогает против известного ботнета, но у атакующего IP много и они меняются.
Дополнительно:

- **Rate limiting:** `ufw limit 22/tcp`, `iptables ... -m limit` — ограничить частоту.
- **SYN cookies:** `sysctl net.ipv4.tcp_syncookies=1` — против SYN-флуда (подробно — S5/S8).
- **Upstream/CDN:** большой объёмный DDoS гасят провайдер/Cloudflare выше по потоку —
  один хост его не переварит.

## fail2ban (превью, полноценно — Season 5)

`fail2ban` читает логи (`/var/log/auth.log`) и **автоматически** банит IP при
подозрительной активности (перебор паролей, много ошибок):

```bash
sudo apt install fail2ban     # сервис мониторит логи → ufw/iptables ban
```

Это автоматизация того, что здесь делаем вручную. Управляется через systemd —
поэтому полноценно разбираем в **Season 5** (security), а не сейчас.
