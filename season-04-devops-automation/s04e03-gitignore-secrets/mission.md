## Обстановка

Первые два уровня защиты стоят: секрет в истории найден
([`s04e01`](../s04e01-git-history/)), проверка перед отправкой написана
([`s04e02`](../s04e02-branches-prepush/)). Оба ловят секрет, который **уже
в коммите**.

Третий уровень — сделать так, чтобы `git add .` его вообще не видел.
В репозитории Дмитрия для этого есть одна строка: `*.log`, добавленная после
того, как журналы уже засорили историю.

## Приказ

Написать два файла в `artifacts/`:

- `gitignore` — то, что лежало бы в репозитории как `.gitignore`;
- `env.example` — перечень нужных переменных **без значений**.

```bash
cp starter/gitignore starter/env.example artifacts/
bash tests/test.sh
```

Имена без точки в начале — чтобы файлы было видно в списке и чтобы они не
влияли на сам курс. В репозитории они назывались бы `.gitignore` и
`.env.example`.

## Что должно получиться

| Должно игнорироваться | Должно **остаться** |
|---|---|
| `.env`, `.env.local` | `.env.example` |
| `secrets/db.key`, `keys/id_ed25519`, `deploy.pem` | `README.md`, `deploy.sh` |
| `ansible/vault_pass.txt` | `roles/common/tasks/main.yml` |
| `terraform.tfstate`, `.terraform/plugin.so` | `hosts/servers.txt` |
| `logs/run.log`, `deep/nested/debug.log` | `docs/keys.md` |
| `node_modules/`, `__pycache__/`, `.DS_Store`, `tmp/` | `docs/secrets-policy.md` |

Правый столбец — не украшение, а проверка на то, что правила не шире, чем
нужно. `*key*` вместо `*.key` выбросит документацию, и никто этого не заметит.

`env.example` должен содержать те же четыре переменные, что были в `.env`,
и **ни одного заполненного значения**.

## Чем добывать

| Что нужно | Как |
|---|---|
| шаблон на любой глубине | без слэша внутри: `*.log` |
| только каталог | слэш в конце: `secrets/` |
| только от корня | слэш в начале: `/build` |
| отмена игнорирования | `!путь` — **после** шаблона, который его захватил |
| проверить результат | `git check-ignore -v путь` |
| посмотреть, что попадёт в индекс | `git add -n .` |
| что уже отслеживается | `git ls-files` |

## Критерии приёмки

- [ ] `artifacts/gitignore` и `artifacts/env.example` созданы на основе `starter/`.
- [ ] Нет строк с ведущими пробелами и нет правила, игнорирующего всё подряд.
- [ ] Игнорируются все четырнадцать путей из левого столбца.
- [ ] **Не** игнорируется ни один путь из правого столбца.
- [ ] Пара «`.env` прячем, `.env.example` оставляем» работает — то есть `!` стоит после шаблона.
- [ ] `docs/keys.md` и `docs/secrets-policy.md` остаются в репозитории.
- [ ] В примере не меньше четырёх переменных и ни одного заполненного значения.
- [ ] После `git add -A` в индекс попадает `.env.example` и не попадает `.env`.
- [ ] `bash tests/test.sh` → 21 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils |
| Сеть | не нужна |
| Внешние пакеты | **`git`** |
| Изоляция теста | тест создаёт репозиторий во временном каталоге, кладёт твой файл как `.gitignore` и спрашивает у самого git через `git check-ignore` |

Проверяется **поведение**, а не текст правил: порядок строк, отмена через
`!` и ширина шаблонов видны только по результату.

## Выполнение

```bash
cd season-04-devops-automation/s04e03-gitignore-secrets
cp starter/gitignore starter/env.example artifacts/
$EDITOR artifacts/gitignore
bash tests/test.sh
```

Проверить своё правило руками, до теста:

```bash
cd /tmp && rm -rf t && mkdir t && cd t && git init -q
cp ~/…/artifacts/gitignore .gitignore
mkdir -p docs && touch .env .env.example docs/keys.md
git check-ignore -v .env .env.example docs/keys.md
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «из репозитория выпадет `.env.example`» | `!` стоит выше шаблона | побеждает последнее совпавшее правило |
| «`docs/keys.md` игнорируется» | шаблон `*key*` вместо `*.key` | сузить |
| «`docs/secrets-policy.md` игнорируется» | шаблон `*secret*` | то же |
| «не игнорируется `deep/nested/debug.log`» | шаблон привязан к корню | без слэша внутри — на любой глубине |
| «не игнорируется `secrets/db.key`» | нет правила на каталог | `secrets/` |
| строка с ведущим пробелом | пробел — часть шаблона | убрать |
| в примере осталось значение | пример сделан копированием рабочего файла | оставить только имена переменных |

## После выполнения

Зелёный тест означает, что `git add .` больше не увидит секрет — и при этом
не потеряет ничего нужного. Второе проверяется реже первого и стоит дороже:
лишний файл в репозитории заметят, отсутствующий — нет.

Стоит помнить границу этого уровня защиты. `.gitignore` действует только на
то, что git ещё не отслеживает, и не трогает историю. Порядок при инциденте
неизменный: **сначала сменить секрет, потом прятать.**

## Кумулятивность

Пароль, ради которого всё это пишется, найден в
[`s04e01`](../s04e01-git-history/) и не прошёл бы проверку из
[`s04e02`](../s04e02-branches-prepush/) — здесь он не попадает в коммит
вовсе, то есть закрывается третий и последний уровень. Правило «побеждает
последнее совпавшее» уже встречалось в
[`s03e03`](../../season-03-system-administration/s03e03-sudo/) для `sudoers`;
в `sshd_config` ([`s02e09`](../../season-02-networking/s02e09-ssh-hardening/))
оно обратное, и путать их дорого. Проверка командой вместо чтения глазами —
`git check-ignore -v` — того же рода, что `ssh -G` из
[`s02e10`](../../season-02-networking/s02e10-ssh-tunnels/) и `sudo -l` из
[`s01e16`](../../season-01-shell-foundations/s01e16-sudo-basics/).
