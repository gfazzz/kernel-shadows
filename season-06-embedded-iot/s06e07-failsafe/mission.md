## Обстановка

В параметрах вчерашнего аппарата нашлись три способа его потерять:
выключенный отказ по связи, критический порог батареи выше низкого и
высота возврата, заданная в метрах там, где ждут сантиметры. Ни одна из
трёх ошибок не помешала загрузке — автопилот принял всё.

Нужен набор параметров, в котором согласованы не только значения, но и
связи между ними.

## Приказ

Собрать `artifacts/failsafe.params` — 18 параметров.

```bash
cp starter/failsafe.params artifacts/
bash tests/test.sh
```

Формат ArduPilot: `ИМЯ,ЗНАЧЕНИЕ`, по параметру на строку.

| Файл в `data/` | Что в нём |
|---|---|
| `param_reference.txt` | обязательные параметры, единицы, диапазоны |
| `airframe.txt` | батарея аппарата: банки, химия, минимум на банку |
| `site_limits.txt` | радиус маршрута, регламентный потолок, высота препятствия |
| `rc_calibration.txt` | калибровка каналов пульта в единицах PWM |

## Требования

| Блок | Требование |
|---|---|
| набор | заданы все параметры из справочника, ни одного неизвестного, без дублей |
| диапазоны | каждое значение внутри границ справочника |
| отказы | `FS_THR_ENABLE`, `FS_GCS_ENABLE`, `FS_EKF_ACTION`, `FENCE_ENABLE` не равны нулю |
| порог газа | `FS_THR_VALUE` ниже минимума канала `throttle` |
| батарея | `BATT_CRT_VOLT` < `BATT_LOW_VOLT`; оба не ниже банок × `cell_min_volt` |
| реакции | низкий заряд → `2` (возврат), критический → `1` (посадка) |
| геозона | `FENCE_TYPE` содержит биты `1` и `2`; `FENCE_RADIUS` больше маршрута с запасом |
| высоты | препятствие ≤ `RTL_ALT` ≤ `FENCE_ALT_MAX` ≤ регламент (с учётом единиц!) |
| возврат | `RTL_ALT_FINAL` = 0 |
| комментарии | сохранены: набор должен объяснять сам себя |

## Чем добывать

| Что нужно | Как |
|---|---|
| список обязательных | `awk '!/^#/ && NF>=5 {print $1}' data/param_reference.txt` |
| единицы и диапазон | колонки 2–4 того же файла |
| физический низ батареи | `battery_cells × cell_min_volt` из `airframe.txt` |
| минимум канала газа | `awk '$2=="throttle" {print $3}' data/rc_calibration.txt` |
| радиус маршрута, потолок, препятствие | `site_limits.txt` |
| перевод высот | `RTL_ALT` в см, `FENCE_ALT_MAX` в м |

## Критерии приёмки

- [ ] `artifacts/failsafe.params` создан на основе `starter/`, 18 параметров заданы.
- [ ] Ни одного имени вне справочника: опечатка молча игнорируется автопилотом.
- [ ] Ни один параметр отказа не равен нулю.
- [ ] `FS_THR_VALUE` ниже минимума канала газа из калибровки.
- [ ] `BATT_CRT_VOLT` строго ниже `BATT_LOW_VOLT`, оба выше физического низа.
- [ ] `FENCE_TYPE` — маска с битами потолка и радиуса.
- [ ] Цепочка высот выдержана после перевода единиц.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | не нужна |
| **дрон** | **не нужен** — параметры проверяются как текст |
| Внешние пакеты | нет |
| Изоляция теста | все пороги вычисляются из `data/` |

Тест не содержит зашитых значений. Список обязательных параметров и их
диапазоны он берёт из справочника, физический низ батареи считает из
характеристик аппарата, радиус геозоны сверяет с маршрутом, порог газа — с
калибровкой пульта.

Главное, что проверяется, — **связи**: порядок порогов батареи, вложенность
цепочки высот, соответствие радиуса маршруту, биты маски геозоны. Каждое
значение по отдельности при этом может быть совершенно нормальным.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «неизвестные параметры» | опечатка в имени | сверить со справочником посимвольно |
| «ноль означает продолжать полёт» | реакция не задана | выбрать действие, а не оставить 0 |
| «критический не ниже низкого» | пороги перепутаны | мягкий раньше, жёсткий позже |
| «ниже физического низа» | порог взят ниже банок | `cells × cell_min_volt` |
| «нужна маска с битами 1 и 2» | `FENCE_TYPE` понят как номер варианта | это сумма битов |
| «ниже препятствия — проверь единицы» | `RTL_ALT` задан в метрах | параметр в сантиметрах |
| «возврат нарушит геозону» | `RTL_ALT` выше `FENCE_ALT_MAX` | выстроить цепочку высот |
| «радиус мал против маршрута» | геозона уже утверждённого маршрута | радиус больше с запасом на ветер |

## После выполнения

Зелёный тест означает, что у аппарата есть заранее заданные ответы на все
отказы, которые могут случиться в воздухе, и что эти ответы не противоречат
друг другу.

Стоит запомнить два принципа. Первый: **реакция на отказ должна опираться
только на то, что ещё работает.** Возвращаться домой, потеряв представление
о своём положении, — это вторая авария вместо реакции на первую. Второй:
**проверка полей по одному пропускает именно те ошибки, ради которых её
писали.** Схема отсекает мусор; неверными бывают осмысленные комбинации
корректных значений, и для них нужны правила о связях.

## Кумулятивность

Логика «реагировать тем, что ещё исправно» — та же, что `nofail` в
[`s06e04`](../s06e04-readonly-root/): узел поднимается без раздела данных,
раз данных всё равно нет. Проверка связей между параметрами продолжает
[`s06e04`](../s06e04-readonly-root/) (сумма `tmpfs` против объёма памяти) и
[`s06e03`](../s06e03-boot-config/) (параметр в правильной секции).

Отказ по связи с наземной станцией — тот самый механизм, который вернул
аппарат в разборе [`s06e05`](../s06e05-mavlink-telemetry/); радиус маршрута
для геозоны посчитан валидатором из
[`s06e06`](../s06e06-mission-check/). Молчаливое игнорирование неизвестного
имени параметра — тот же класс, что незамеченная опечатка в конфигурации из
[`s04e10`](../../season-04-devops-automation/s04e10-ansible-check/).

Хранение набора параметров в системе контроля версий и сравнение с
аппаратом (`param diff`) — прямое продолжение
[`s04e11`](../../season-04-devops-automation/s04e11-iac-audit/): состояние
сверяется с описанным, расхождение — находка.
