## 2. Девять бит

```
rwx rwx rwx
 │   │   └ other  — все остальные пользователи машины
 │   └ group      — члены группы-владельца
 └ user           — владелец файла
```

| Буква | На файле | Значение |
|---|---|---|
| `r` | читать содержимое | 4 |
| `w` | изменять содержимое | 2 |
| `x` | выполнять | 1 |

Цифры складываются внутри тройки: `rwx` = 4+2+1 = 7, `r-x` = 4+1 = 5, `rw-` = 4+2 = 6. Отсюда `750` = `rwxr-x---`.

Смотреть можно двумя способами:

```bash
ls -l файл                 # символьно
stat -c '%a %U %G %n' файл # цифрами + владелец и группа (GNU)
stat -f '%Lp %Su %Sg %N' файл   # то же в macOS
```

## 3. Каталог — не файл

Те же три буквы означают на каталоге совсем другое:

| Бит | На файле | На каталоге |
|---|---|---|
| `r` | читать содержимое | получить список имён (`ls`) |
| `w` | изменять содержимое | **создавать и удалять** записи внутри |
| `x` | выполнять | войти внутрь, обратиться к файлу по имени |

Три следствия, которые стоит осознать один раз:

- **Каталог с `r`, но без `x`:** `ls` покажет имена, а открыть нельзя ничего — даже файл с правами `777`.
- **Каталог с `x`, но без `r`:** список не получить, но если имя известно — файл откроется. Так делают «доступно по ссылке, но не листается».
- **Удаление определяется каталогом, а не файлом.** Файл с правами `444`, принадлежащий кому-то другому, удалится, если у тебя есть `w` на каталог.

Проверка идёт **по всему пути**: чтобы открыть `/srv/ops/logs/day.txt`, нужен `x` на `/srv`, на `/srv/ops`, на `/srv/ops/logs` — и только потом `r` на сам файл. Отсюда загадка «права на файл правильные, а не читается».

## 4. `chmod`

```bash
chmod 600 secrets/.env        # цифрами: задать всё сразу
chmod u+x collect.sh          # символьно: добавить одно право
chmod go-rwx secrets/         # отнять всё у группы и остальных
chmod a+r README              # всем читать
chmod -R u+rwX,go-rwx ops/    # рекурсивно
```

Символьная запись читается как предложение: **кому** (`u` владелец, `g` группа, `o` остальные, `a` все) — **что делать** (`+` добавить, `-` отнять, `=` установить ровно) — **какие права** (`rwx`).

**Заглавная `X`** — важное отличие от строчной: она ставит `x` только каталогам и тем файлам, у которых бит выполнения уже был. Рекурсивный `chmod -R 755` без неё делает исполняемыми все `.txt` подряд, и потом это никто не откатывает.

**Цифрами или буквами?** Цифрами — когда задаёшь состояние целиком и знаешь, каким оно должно быть (`chmod 600 ключ`). Буквами — когда меняешь одно свойство, не трогая остального (`chmod u+x скрипт`).

## 5. `umask`: откуда берутся права новых файлов

Новый файл получает `666` минус маска, новый каталог — `777` минус маска:

```bash
umask         # 0022 — обычное значение
umask -S      # u=rwx,g=rx,o=rx — то же словами
```

| umask | файл | каталог | где встречается |
|---|---|---|---|
| `022` | 644 | 755 | по умолчанию почти везде |
| `027` | 640 | 750 | ужесточённая политика |
| `077` | 600 | 700 | многопользовательская машина |

Именно поэтому созданный тобой файл читают все, хотя ты об этом не просил, — и почему скрипт, который «просто создаёт каталоги», отдаёт их с правами `755`. Маска — свойство процесса, и в скрипте её можно задать одной строкой: `umask 077`.

## 6. Владелец и группа

```bash
id                       # кто я и в каких группах
groups                   # только группы
ls -l                    # третья и четвёртая колонки: владелец и группа
chown max файл           # сменить владельца — только root
chgrp ops-logs файл      # сменить группу — владелец, если состоит в ней
```

**Владельца может сменить только root** — иначе можно было бы «подарить» файл чужому пользователю и обойти квоты и учёт. Группу владелец сменить может, но только на ту, в которой сам состоит.

Группа — это способ дать доступ нескольким людям, не открывая файл всем: `chgrp ops-logs journal && chmod 640 journal` означает «читаем я и те, кто в `ops-logs`».

## 7. Почему `chmod 777` — не решение

Это самая частая команда в ответах на форумах и самая вредная. Она не «чинит права» — она **выключает вопрос**:

- ты перестаёшь видеть, какого бита не хватало на самом деле;
- писать в каталог сможет любой пользователь машины;
- если это каталог, куда что-то загружают, туда рано или поздно положат чужое.

Правильный порядок отладки доступа занимает на минуту больше:

```bash
ls -ld /путь /путь/каталог /путь/каталог/файл   # права по всему пути
id                                              # кто я на самом деле
sudo -u другой_пользователь ls /путь            # посмотреть его глазами
```

Последняя строка отвечает на настоящий вопрос — на каком шаге путь обрывается.

## 8. Типовые значения, которые стоит помнить

| Что | Права | Почему |
|---|---|---|
| приватный ключ | `600` | иначе программа откажется его использовать |
| каталог с ключами | `700` | посторонним нечего даже перечислять |
| файл с паролями, `.env` | `600` | секрет |
| свой скрипт | `700` или `755` | нужен `x`; `755` — если запускают и другие |
| отчёт, документ | `644` | читать всем, менять владельцу |
| общий каталог команды | `770` | своя группа работает, посторонние нет |

## 9. Метанавык: права как утверждение, а не как препятствие

Права воспринимаются новичком как то, что мешает: команда не сработала, надо что-то поменять, чтобы заработало. При таком взгляде естественный ход — расширять их, пока препятствие не исчезнет.

Полезнее прочитать права как **утверждение о намерении**: «этот файл предназначен вот кому». Тогда `Permission denied` перестаёт быть препятствием и становится сообщением: файл не для тебя — либо потому, что так задумано, либо потому, что кто-то ошибся.

Разница видна на одном вопросе, который стоит задавать себе перед каждым `chmod`: **кому именно я сейчас открываю доступ и зачем ему он**. Если ответа нет — команда, скорее всего, лишняя.
