## Обстановка

На трёх узлах в Цюрихе работают процессы, которых туда никто не ставил. Они
пережили перезагрузку — значит, их что-то запускает, и это «что-то» записано
в файле.

Анна сняла каталоги, где такое записывают. Восемнадцать файлов, все выглядят
обычно. Есть перечень с чистого узла того же образа, снятый 49-го дня.

Узлов пятьдесят. Смотреть глазами — не вариант, поэтому артефакт этой серии —
скрипт.

## Приказ

Написать `artifacts/hunt_persistence.sh`: принимает корень снимка и эталонный
перечень, печатает всё, что на узле запускается само.

```bash
cp starter/hunt_persistence.sh artifacts/
$EDITOR artifacts/hunt_persistence.sh
bash artifacts/hunt_persistence.sh data/node_snapshot data/baseline_manifest.txt
bash tests/test.sh
```

## Договор

```
hunt_persistence.sh <корень-снимка> <эталонный-перечень>

PERSIST <категория> <путь> <почему>
TOTAL <n>

код возврата: 0 — чисто, 1 — есть находки, 2 — вход не разобран
```

Путь — относительно корня снимка. Категории: `cron`, `systemd`,
`shell-profile`, `ssh-key`, `account`, `sudoers`, `preload`, `rc-local`.
Строки отсортированы.

## Дано

| Файл в `data/` | Что в нём |
|---|---|
| `node_snapshot/` | снимок узла: каталоги автозапуска, 18 файлов |
| `baseline_manifest.txt` | путь и контрольная сумма каждого файла на чистом узле |
| `persistence_map.txt` | места закрепления и что в них смотрят |

## Что здесь легко пропустить

**Одного сравнения с эталоном мало.** Эталон снят 49-го дня. Если гость
пришёл раньше, его закрепление уже в эталоне, и разница будет нулевой. Нужны
признаки, видные сами по себе: учётная запись с нулевым uid кроме root,
существование `/etc/ld.so.preload`, `NOPASSWD: ALL`. Тест проверяет это
отдельно — прогоном, где эталон снят **после** проникновения.

**Ложные срабатывания считаются наравне с пропусками.** На чистом дереве
скрипт обязан напечатать `TOTAL 0`.

**Скрипт только читает.** Дерево после прогона обязано совпадать с деревом до
прогона побайтово.

**Тест не проверяет снимок из `data/`.** Он строит собственные деревья во
временном каталоге. Ответы, выписанные руками, там не подойдут.

## Критерии приёмки

- [ ] Договор вызова соблюдён, коды возврата 0/1/2 различаются по смыслу.
- [ ] Неверный вызов и отсутствующие файлы дают код 2, а не трассировку.
- [ ] На чистом дереве — `TOTAL 0` и код 0.
- [ ] На дереве с закреплениями найдены все восемь мест, лишнего не названо.
- [ ] Категория каждой находки соответствует месту.
- [ ] Есть проверка, не зависящая от эталона.
- [ ] Вывод отсортирован и не зависит от текущего каталога.
- [ ] Дерево после прогона не изменено.
- [ ] `bash tests/test.sh` → 35 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + find |
| Контрольные суммы | `sha256sum`, `shasum` или `openssl` — любой из трёх |
| Сеть | не нужна |
| Живой узел | **не нужен** — снимок в `data/` |
| Изоляция теста | свои деревья в `mktemp -d`, `data/` только читается |

Если ни одной программы для контрольных сумм в системе нет, тест честно
сообщает `SKIP` и завершается успешно: это отсутствие окружения, а не отказ.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «ложные срабатывания» на чистом дереве | сравниваются все файлы подряд | только места из `persistence_map.txt` |
| пропущен `root/.ssh/authorized_keys` | проверяется только появление файла | файл был, изменилось содержимое |
| пропущен `etc/passwd` | то же самое | сравнение сумм, а не наличия |
| «скрипт не находит ничего» в разделе 5 | есть только сравнение с эталоном | нужны независимые признаки |
| «порядок строк зависит от обхода» | нет сортировки | `LC_ALL=C sort` перед печатью |
| «из другого каталога вывод другой» | относительный путь внутри скрипта | все пути строить от аргумента |
| «скрипт изменил дерево» | временные файлы создаются внутри снимка | `mktemp -d` и уборка в `trap` |
| код 1 на чистом дереве | код возврата не связан с числом находок | 0 при `TOTAL 0` |

## После выполнения

Зелёный тест означает, что у вас есть инструмент, который можно применить ко
всем пятидесяти узлам, а не только к тому, который принесла Анна.

Главное, что стоит унести: **ищут не плохое, а новое.** Имя файла и его
содержимое выбирает тот, кто закрепляется; момент появления — нет. Поэтому
сравнение с известным состоянием сильнее любого списка признаков.

И второе: **у метода сравнения есть слепая зона размером с дату эталона.**
Всё, что случилось раньше, для него не существует. Закрывается она не лучшим
эталоном, а второй проверкой другой природы — по состояниям, которые
неправильны сами по себе.
