# Теория — s03e08

## 1. Вечер, потраченный на удаление нужного

> *Диск под логами кончился в пятницу вечером. Я сделал ровно то, что делают все: пошёл в `/var/log` и стал удалять самое старое. Освободил гигабайт — `df` показал тот же процент. Удалил ещё три — то же самое.*
>
> *К тому моменту, когда пришёл Палыч, я успел снести архивы за полгода.*
>
> — Сколько ты удалил?
> — Гигабайт пять.
> — А место?
> — Не изменилось.
> — Тогда почему ты продолжал?
>
> *Ответить было нечего. Я продолжал, потому что не мог придумать ничего другого, а надо было что-то делать.*
>
> *Он набрал одну команду:*
>
> ```
> $ sudo lsof +L1
> COMMAND   PID USER  FD  TYPE  SIZE/OFF NLINK NAME
> java     4021 app   12w REG  9663676416    0 /var/log/app/app.log (deleted)
> ```
>
> — Девять гигабайт. Приложение пишет в файл, у которого нет имени: кто-то удалил его руками вместо ротации. Твои пять гигабайт архивов к этому отношения не имели.
>
> *Он перезапустил приложение, место вернулось.*
>
> — Запомни порядок, — сказал он. — Сначала выясняешь, куда делось место. Потом освобождаешь. Не наоборот. «Что-то удалить» — это не действие, это паника с правами root.

## 2. Как устроен файл

```
имя в каталоге ──► inode ──► блоки данных
                    │
                    ├ права, владелец, время
                    ├ размер
                    └ счётчик ссылок
```

Имя — это запись в каталоге, указывающая на inode. Их может быть несколько (жёсткие ссылки), и все равноправны:

```bash
ln файл другое_имя      # жёсткая ссылка: тот же inode
ln -s файл символ       # символьная: отдельный файл с путём внутри
ls -li                  # первая колонка — номер inode
stat файл               # счётчик ссылок в поле Links
```

`rm` вызывает `unlink()`: убирает имя и уменьшает счётчик. Данные освобождаются, когда счётчик стал нулём **и** файл никем не открыт. Открытый дескриптор — это тоже ссылка, просто не видимая в каталогах.

Практическое следствие, из-за которого и существует эта серия: **удалённый, но открытый файл занимает место и не виден никакому обходу дерева.**

```bash
lsof +L1                       # NLINK=0 — есть дескриптор, нет имени
ls -l /proc/PID/fd | grep deleted
cp /proc/709/fd/7 /tmp/спасённое.log    # содержимое ещё доступно
: > /proc/709/fd/7             # обнулить, не ломая дескриптор
```

## 3. `du`: чем считать

```bash
du -sh /var/log                # итог по каталогу
du -h --max-depth=1 /var/log | sort -h
du -xh --max-depth=1 /        # -x: не пересекать точки монтирования
du -sh --apparent-size файл   # «сколько в файле» вместо «сколько блоков»
ncdu /var                     # интерактивно, если пакет доступен
```

Две тонкости, которые регулярно сбивают:

- **`sort -h` вместо `sort -n`.** Обычная числовая сортировка сравнит `120M` и `4.2G` как 120 и 4.2 — и поставит мегабайты выше гигабайтов.
- **`du` считает блоки, а не байты.** Тысяча файлов по 10 байт занимает не 10 КБ, а тысячу блоков — обычно 4 МБ. На каталогах с мелкими файлами разница с `--apparent-size` в сотни раз.

`du` без `-x` уходит в примонтированные файловые системы, включая сетевые. На сервере с NFS это превращается из «посмотрю, что занимает место» в получасовое ожидание.

## 4. Что показывает `lsblk` и `blkid`

```bash
lsblk                      # дерево устройств
lsblk -f                   # + файловые системы, UUID, точки монтирования
lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,ROTA   # ROTA=1 — вращающийся диск
blkid                      # UUID и типы всех разделов
findmnt /var/log           # чем и с какими опциями смонтировано
```

Имена устройств (`/dev/vdb`) **не стабильны**: порядок обнаружения дисков меняется от загрузки к загрузке. Поэтому монтируют по `UUID=` — об этом в серии про `fstab`.

Тома LVM видны как `/dev/mapper/группа-том` и в `lsblk` показаны вложенными в физическое устройство с типом `LVM2_member`.

## 5. Файловые системы

| | ext4 | xfs | btrfs |
|---|---|---|---|
| Уменьшение размера | да (только размонтированной) | **нет** | да |
| Увеличение «на ходу» | да | да | да |
| Число inode | фиксируется при `mkfs` | динамическое | динамическое |
| Снимки | нет (только через LVM) | нет | да |
| Где по умолчанию | Debian/Ubuntu | RHEL/CentOS/Fedora | openSUSE, Fedora (корень) |

«xfs нельзя уменьшить» — то, что стоит знать **до** разметки, а не после. Если раздел может понадобиться сжать, выбор сделан за вас.

```bash
mkfs.ext4 -m 1 -L log /dev/mapper/ops--vg-log   # -m: резерв root в процентах
tune2fs -l /dev/mapper/ops--vg-log              # все параметры существующей ФС
tune2fs -m 1 /dev/mapper/ops--vg-log            # изменить резерв без пересоздания
resize2fs /dev/mapper/ops--vg-log               # растянуть на весь том
xfs_growfs /var/log                             # то же для xfs, по точке монтирования
```

**Резерв root** (5 % по умолчанию) существует, чтобы при заполнении ФС система осталась управляемой: демоны под root допишут журнал, администратор войдёт. На 20-гигабайтном томе это гигабайт, на двухтерабайтном — сто, и вот там его уже уменьшают.

## 6. Разметка и квоты

Прежде чем на диске появится файловая система, на нём обычно создают разделы:

```bash
lsblk -o NAME,SIZE,TYPE,PTTYPE            # есть ли таблица разделов
parted -s /dev/vdc mklabel gpt            # таблица GPT (не MBR: MBR — до 2 ТБ, 4 раздела)
parted -s /dev/vdc mkpart data 1MiB 100%  # один раздел на весь диск
partprobe /dev/vdc                        # перечитать таблицу без перезагрузки
fdisk -l /dev/vdc                          # то же интерактивно, старым инструментом
sgdisk --backup=vdc.gpt /dev/vdc           # копия таблицы разделов
```

**Разделы не обязательны.** Диск целиком можно отдать под LVM или под файловую систему (`mkfs.ext4 /dev/vdc`) — так делают на виртуальных машинах, где диск и так виртуальный, а его размер меняется на уровне гипервизора. Именно это сделано с `/dev/vdb` и `/dev/vdc` в снимке этой серии: `TYPE="LVM2_member"` без единого раздела.

`parted` в неинтерактивном режиме (`-s`) применяет изменения **немедленно и без подтверждения**. На чужом диске это одна команда до потери разметки, поэтому перед ней смотрят `lsblk` и `blkid`, а не полагаются на память об именах устройств.

**Квоты** ограничивают место на пользователя или группу внутри одной файловой системы:

```bash
mount -o remount,usrquota,grpquota /home
quotacheck -cugm /home          # создать файлы учёта
quotaon /home
edquota -u max                  # мягкий и жёсткий предел
repquota -a                     # отчёт по всем
```

Мягкий предел можно превысить на время отсрочки, жёсткий — нельзя. На серверах квоты применяют редко (обычно проще отдельный том), но на многопользовательских машинах и общих хранилищах это единственный способ не дать одному каталогу занять всё.

## 7. Проверка и обслуживание

```bash
fsck -n /dev/vda1          # проверка без изменений; на смонтированной ФС только так
tune2fs -c 30 /dev/vda1    # проверять каждые 30 монтирований
fstrim -av                 # сообщить SSD об освобождённых блоках
smartctl -a /dev/sda       # здоровье диска (пакет smartmontools)
```

`fsck` на смонтированной файловой системе **разрушителен** — отсюда правило: либо `-n`, либо размонтировать, либо загрузиться с другого носителя. Современные дистрибутивы запускают проверку при загрузке, до монтирования, и это единственный безопасный момент.

## 8. Когда место кончается: порядок действий

1. `df -h` — где именно и насколько.
2. `df -i` — не в inode ли дело. Занимает секунду и снимает целый класс тупиков.
3. `lsof +L1` — не держит ли кто удалённый файл. Тоже секунда, и часто на этом всё.
4. `du -xh --max-depth=1 /том | sort -h` — спуститься по дереву до источника.
5. И только теперь что-то удалять или переносить.

Первые три шага занимают меньше минуты и в большинстве случаев отвечают на вопрос целиком. Четвёртый — самый долгий и почему-то всегда первый.

## 9. Метанавык: сначала измерение, потом действие

Кончившееся место — редкий случай, когда есть и срочность, и полная возможность разобраться: сервер работает, данные на месте, ничего не горит по-настоящему. И почти всегда именно здесь начинают удалять наугад.

Причина не в незнании команд, а в том, что «удалять» ощущается как действие, а «смотреть» — как бездействие. На самом деле наоборот: удаление без диагноза обратимо только из бэкапа, а минута измерений обратима полностью.

Тот же порядок работает за пределами дисков: сначала выяснить, куда делся ресурс — память, дескрипторы, соединения, время ответа, — потом трогать. Разница между администратором и человеком с правами root примерно в этом и состоит.
