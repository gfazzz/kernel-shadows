## Обстановка

Проверка списка работает и считает верно. Но её результат живёт до первого
`clear` — а разбор инцидента начинается через сутки после инцидента.

На вопрос «когда узел упал и сколько пролежал» ответить нечем: скрипт знает
только «сейчас». Нужна история — файл, который растёт от запуска к запуску
и в котором у каждой строки есть время.

## Приказ

Собрать `server_monitor.sh` — капстоун второго эпизода. Обходит список,
проверяет каждый узел, **пишет каждую строку в журнал с меткой времени**,
печатает итог и поднимает тревогу, если кто-то молчит.

```
[2025-10-04 16:47:03] [UP]   shadow-server-01
[2025-10-04 16:47:05] [DOWN] shadow-server-31
[2025-10-04 16:47:07] SUMMARY: UP=2 DOWN=1
[2025-10-04 16:47:07] ALERT: 1 server(s) DOWN!
```

Использование: `./server_monitor.sh SERVERS_FILE [LOG_FILE]`.
По умолчанию журнал — `monitor.log`.

## Данные

| Что | Как |
|---|---|
| список / журнал | `list="${1:?…}"`, `log="${2:-monitor.log}"` |
| метка времени | `ts() { date '+%Y-%m-%d %H:%M:%S'; }` — вызывать при каждой записи |
| запись в журнал | `>> "$log"` — **никогда** `>` |
| экран + журнал | `echo "…" \| tee -a "$log"` |
| тревога | `echo "…" \| tee -a "$log" >&2` — в журнал и в stderr |
| обход списка | `while IFS= read -r line; … done < "$list"` (из s01e08) |
| имя узла | `host="${line%% *}"` — `awk` появится в s01e11 |

Формат `%Y-%m-%d %H:%M:%S` обязателен: он сортируется как текст и однозначен.
`04.10.2025` не подходит ни по тому, ни по другому.

## Критерии приёмки

- [ ] `artifacts/server_monitor.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Журнал создаётся и содержит метки формата `ГГГГ-ММ-ДД ЧЧ:ММ:СС`.
- [ ] Каждый проверенный узел попадает в журнал со своим статусом.
- [ ] Пустые строки и комментарии в список не попадают в журнал как узлы.
- [ ] `SUMMARY: UP=<n> DOWN=<m>` соответствует реальным результатам.
- [ ] При `DOWN > 0` выдаётся `ALERT` — **и на экран, и в журнал**.
- [ ] Повторный запуск **дописывает** журнал; записи первого прогона на месте.
- [ ] Отсутствующий список → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 11 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils (Linux / macOS / WSL) |
| Сеть | **не нужна** — тест подменяет `ping` |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | `date`, `tee` (coreutils); в реальном запуске `ping` |
| Изоляция теста | мок-`ping`, фикстура-список и журнал во временном каталоге |

Фикстура: два отвечающих узла, один молчащий, плюс комментарий и пустая строка.
Ожидаемые `UP`/`DOWN` тест **считает по самой фикстуре**, а не хранит константой.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| в журнале одна строка | `>` вместо `>>` (или `tee` без `-a`) | заменить на `>>` / `tee -a` |
| у всех строк одинаковое время | метка вычислена один раз до цикла | вызывать `ts()` в момент записи |
| журнал есть, экран пуст | использован только `>>` | `\| tee -a "$log"` |
| `ALERT` виден, но его нет в журнале | тревога ушла мимо `tee` | `\| tee -a "$log" >&2` |
| ошибки скрипта не попадают в журнал | пишется только stdout | `2>&1` **после** перенаправления вывода |
| `UP=0 DOWN=0` при верных строках | цикл в подоболочке | читать через `done < "$list"` |
| пустой журнал и код 0 при отсутствии списка | нет проверки входа | `[ -f "$list" ]` до цикла, иначе `exit 1` |

## После выполнения

Зелёный тест означает, что у мониторинга появилась память. С этого момента на
вопрос «когда упал» отвечает файл, а не человек — и отвечает одинаково точно
через час и через неделю.

Дальше по расписанию его поставит `cron` или `systemd timer` (Season 3), там же
разберём ротацию: журнал без неё однажды займёт весь раздел, и сервер перестанет
писать вообще что-либо. Пока достаточно двух вещей — писать со временем и не
затирать написанное.
