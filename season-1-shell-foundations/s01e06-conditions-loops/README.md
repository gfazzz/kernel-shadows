## Теория: условия + циклы (один концепт: решить и повторить)

**Условие** — развилка. `if` смотрит на exit code команды: `0` → одна ветка, иначе — другая.

```bash
if ping -c 1 -W 2 "$host" >/dev/null 2>&1; then
    status="UP"
else
    status="DOWN"
fi
```

Внутри `[ … ]` — операторы сравнения: числовые (`-eq`, `-gt`), строковые (`=`, `-z`), файловые (`-f`, `-d`). Полная таблица — в [`theory.md`](theory.md).

**Цикл** — конвейер. Читать файл построчно нужно **золотым паттерном**:

```bash
while IFS= read -r line; do
    host="${line%% *}"      # первое поле (имя) — без awk, чистым bash
    # ... проверить host ...
done < servers.txt
```

`for line in $(cat file)` — так **нельзя**: ломается на пробелах и спецсимволах. А `${line%% *}` отрезает всё от первого пробела — так мы берём имя хоста из строки «имя IP» без внешних утилит.

> **LILITH:** *«`while read` — золотой стандарт чтения файлов в bash. Запомни этот паттерн — будешь использовать постоянно.»*

## Проверка «в мире сюжета»

**Дмитрий:** *«Почему `for line in $(cat servers.txt)` — плохая идея для нашего списка?»*

<details>
<summary>Подумай 30 секунд</summary>

`$(cat …)` разбивает вывод по пробелам, а не по строкам: строка «shadow-01 185.192.45.118» превратится в два элемента. Плюс весь файл грузится в память и ломается на спецсимволах. `while IFS= read -r line` читает ровно по строке и ничего не портит.
</details>

**Дмитрий:** *«Скрипту передали путь к списку, но файла нет. Что должен сделать хороший скрипт?»*

<details>
<summary>Ответ</summary>

Проверить условием `[ -f "$list" ]`, сообщить об ошибке в stderr и выйти с ненулевым кодом — а не молча выдать «0 серверов, всё ОК». Ранняя проверка входных данных экономит часы отладки.
</details>

<details>
<summary>Подсказка (после попытки)</summary>

```bash
while IFS= read -r line; do
    [ -z "$line" ] && continue
    case "$line" in \#*) continue ;; esac
    host="${line%% *}"
    if ping -c 1 -W 2 "$host" >/dev/null 2>&1; then up=$((up+1)); else down=$((down+1)); fi
done < "$list"
```
