## Обстановка

Манифестов будет несколько — по одному на роль сервера, и наборы пересекаются.
Установка по одному пакету перестаёт иметь смысл: двенадцать вызовов `apt` — это
двенадцать независимых планов установки вместо одного.

Виктору нужен документ, а не строчка «всё поставилось»: что стоит, каких версий,
чего не хватает и какой командой это добрать. Такие отчёты складывают и через
месяц по ним видят, какая машина отстала.

## Приказ

Собрать `install_report_generator.sh` — читает манифест, проверяет каждый пакет и
пишет отчёт в файл:

```
=== PACKAGE INSTALLATION REPORT ===
Дата: 2025-10-07 17:12:44
Архитектура: amd64

--- ПАКЕТЫ ИЗ СПИСКА ---
  ✓ git (2.34.1-1)
  ✗ htop — НЕ установлен

--- СТАТИСТИКА ---
Установлено из списка: 3 / 5

--- УСТАНОВИТЬ НЕДОСТАЮЩЕЕ (batch, one-liner) ---
grep -v '^#' tools.txt | awk '{print $1}' | xargs sudo apt install -y
```

Использование: `./install_report_generator.sh TOOLS_FILE [REPORT_FILE]`.
Краткая сводка (сколько из скольких) дублируется на экран.

Установку скрипт **не выполняет**: она делается `apt` напрямую, одной batch-командой.

## Данные

| Что | Как |
|---|---|
| манифест / файл отчёта | `"${1:?…}"`, `"${2:-install_report.txt}"` |
| архитектура | `dpkg --print-architecture` |
| статус пакета | `dpkg -l "$pkg" 2>/dev/null \| grep -q '^ii'` |
| версия | `dpkg -l "$pkg" \| awk '/^ii/{print $3; exit}'` — `exit` обязателен |
| счётчики | увеличивать **в ветке проверки**, не по длине списка |
| сборка отчёта | `{ … } > "$report"` — фигурные скобки, не круглые |
| строка batch-установки | `grep -v '^#' … \| awk '{print $1}' \| xargs sudo apt install -y` |

## Критерии приёмки

- [ ] `artifacts/install_report_generator.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] В шапке отчёта есть дата запуска и архитектура.
- [ ] Установленный пакет выводится с **одной** точной версией из `dpkg`.
- [ ] Пакет в состоянии `rc` считается отсутствующим.
- [ ] Неизвестный пакет считается отсутствующим, скрипт не падает.
- [ ] `Установлено из списка: N / M` соответствует напечатанным строкам, а не длине манифеста.
- [ ] Краткая сводка на экране совпадает с отчётом (отчёт собран в `{ }`, а не в `( )`).
- [ ] В отчёте есть готовая команда пакетной установки недостающего.
- [ ] Комментарии и пустые строки манифеста не считаются пакетами.
- [ ] Отсутствующий манифест → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 15 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен (пакетная установка — с `sudo`, но она вне теста) |
| ОС | любая с bash + awk — Ubuntu не требуется |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `dpkg`; в тесте подменяется |
| Изоляция теста | мок-`dpkg` (включая `--print-architecture`) + фикстура-манифест во временном каталоге |

Мок отдаёт три состояния — `ii`, `rc` и «неизвестен». Ожидаемые числа и версию
тест получает прогоном мока по манифесту, а не хранит константами.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «Установлено: 5 / 5» всегда | счётчик берётся из длины манифеста | увеличивать внутри ветки `ii` |
| сводка на экране нулевая | отчёт собран в `( … )` — подоболочка | заменить на `{ … }` |
| в версии два номера подряд | `awk` без `exit` печатает все совпадения | `{print $3; exit}` |
| удалённый пакет в графе «установлено» | `grep` без якоря `^` | `grep -q '^ii'` |
| комментарий стал пакетом | нет фильтров цикла | пропускать пустые и `#` |
| `xargs` запустил `apt` без пакетов | пустой вход | `xargs -r` |
| нет манифеста → пустой отчёт, код 0 | нет проверки входа | `[ -f "$list" ]`, иначе `exit 1` |

## После выполнения

Зелёный тест закрывает Episode 04 и Season 1. Отчёт о готовности — это не
формальность: он фиксирует состояние машины на момент времени, и именно по таким
документам потом понимают, чем одна машина отличается от другой.

Дальше — сети: как эти машины видят друг друга и кто ещё их видит. Для полусотни
серверов ручной `apt` не годится, и в Season 4 появится Ansible — но человека,
который не понимает `apt`, к Ansible подпускать нельзя: он автоматизирует
непонимание.
