>

> dpkg -l "$pkg" 2>/dev/null | grep -q '^ii'
> ```
>
> — И запомни общий случай. Когда команда отвечает больше, чем ты спросил, ты обязательно прочитаешь только знакомую часть. Полчаса чужого времени — дешёвая цена за этот урок.

## 2. Два уровня: `apt` и `dpkg`

| | `dpkg` | `apt` |
|---|---|---|
| Уровень | низкий | высокий |
| Работает с | одним `.deb` файлом | репозиториями |
| Зависимости | **не** разрешает, только проверяет | разрешает и доустанавливает |
| Сеть | не нужна | нужна |
| Подписи | не проверяет | проверяет GPG |
| Типичное применение | «что установлено», установка локального `.deb` | повседневная установка и обновление |

```bash
# apt — повседневное
sudo apt update                 # обновить ИНДЕКС (не программы!)
sudo apt upgrade                # обновить сами программы
sudo apt full-upgrade           # обновить, разрешая удаление конфликтующих
apt search  nginx               # поиск по имени и описанию
apt show    nginx               # версия, размер, зависимости
apt list --installed            # что установлено
apt list --upgradable           # что можно обновить
sudo apt install nginx
sudo apt remove  nginx          # удалить, конфиги оставить
sudo apt purge   nginx          # удалить вместе с конфигами
sudo apt autoremove             # снять зависимости, ставшие ненужными

# dpkg — вопросы к базе
dpkg -l                         # все известные пакеты
dpkg -l nginx                   # состояние конкретного
dpkg -s nginx                   # подробный статус
dpkg -L nginx                   # какие файлы принёс пакет
dpkg -S /usr/sbin/nginx         # какому пакету принадлежит файл
sudo dpkg -i ./package.deb      # поставить локальный .deb (зависимости — сам)
sudo apt install -f             # …и доставить недостающие зависимости
```

**Коды состояния в `dpkg -l`.** Первый символ — желаемое состояние, второй — фактическое:

| Код | Значение |
|---|---|
| `ii` | установлен и настроен — единственное «да» |
| `rc` | удалён, конфигурационные файлы остались |
| `iU` | распакован, но не настроен (обычно прерванная установка) |
| `iF` | установлен наполовину, требуется `dpkg --configure -a` |
| `un` | системе неизвестен |

**`apt` против `apt-get`.** `apt` — интерфейс для человека: прогресс-бар, цвет, краткие сообщения; его вывод меняется между версиями и не предназначен для разбора. `apt-get`, `apt-cache`, `apt-mark` — стабильные интерфейсы для скриптов. Отсюда правило: в терминале — `apt`, в автоматизации — `apt-get` с `DEBIAN_FRONTEND=noninteractive` и явным `-y`.

## 3. Откуда берутся пакеты

Список источников — `/etc/apt/sources.list` и файлы в `/etc/apt/sources.list.d/`:

```
deb http://archive.ubuntu.com/ubuntu jammy main restricted universe multiverse
#    ^ URL                            ^ выпуск ^ компоненты
```

Компоненты Ubuntu различаются не техникой, а политикой: `main` — поддерживается Canonical, `universe` — сообществом, `restricted`/`multiverse` — несвободные лицензии. Отдельно существуют `-security`, `-updates`, `-backports` — они и делают систему обновляемой.

`apt update` скачивает индексы этих репозиториев и кладёт в `/var/lib/apt/lists/`. Именно поэтому на свежей системе `apt install` иногда говорит «пакет не найден»: индекс пуст или устарел, и `apt` честно не знает про пакет, который в репозитории есть.

**Подписи.** Каждый индекс подписан ключом репозитория; ключи лежат в `/etc/apt/keyrings/` (современный способ) или в устаревшем `apt-key`. Без доверенного ключа `apt` откажется ставить — это и есть основная защита от подмены пакета по пути. Инструкции вида «скачай ключ curl'ом и добавь» стоит читать внимательно: ты добавляешь того, кому доверяешь установку кода с правами root.

**Сторонние источники.** PPA (`add-apt-repository ppa:…`) и вендорские репозитории удобны, но каждый добавленный источник — это ещё один субъект, который может обновить пакет на твоей машине. Правило простое: добавляй ровно то, чем пользуешься, и знай, кто это сопровождает.

## 4. Экосистема шире Debian

| Семейство | Менеджер | Установка |
|---|---|---|
| Debian / Ubuntu | `apt` + `dpkg` | `apt install nginx` |
| RHEL / Fedora | `dnf` (`yum`) + `rpm` | `dnf install nginx` |
| Arch | `pacman` | `pacman -S nginx` |
| Alpine | `apk` | `apk add nginx` |
| openSUSE | `zypper` | `zypper install nginx` |
| macOS | `brew` | `brew install nginx` |

Различаются команды, а модель одинакова: репозиторий, индекс, пакет с метаданными и зависимостями, база установленного, подписи. Освоив одну, вторую читаешь по диагонали.

Отдельно стоят «универсальные» форматы — Snap, Flatpak, AppImage, — которые несут зависимости внутри себя. Они решают проблему совместимости ценой размера и изоляции; в серверной практике встречаются реже, чем на десктопе.

## 5. Почему это Type B

Курс размечает серии по тому, что производит студент: **A** — скрипт-оркестратор, **B** — конфигурация или инструмент, собранный из готовых, **C** — находки исследования, **D** — программа.

Управление пакетами — образцовый Type B, потому что соблазн написать код здесь максимален, а вреда от него больше всего. Установка пакета — это разрешение графа зависимостей, проверка подписей, порядок распаковки, обработка конфликтов файлов, откат при сбое и работа с базой состояния. Всё это в `apt` уже есть и отлажено на миллиардах установок.

Работа администратора начинается там, где `apt` заканчивается: сверить желаемый состав с фактическим, собрать отчёт, зафиксировать версии, повторить на пятидесяти машинах. Первое — эта серия, последнее — Ansible в Season 4.

## 6. Метанавык: сначала разница, потом действие

Список нужного — это описание желаемого состояния, а не последовательность команд. Между «должно быть установлено двенадцать пакетов» и «установить двенадцать пакетов» лежит разница, которую и надо вычислить: восемь уже есть, четырёх нет, а один стоит другой версии, чем нужно.

Такой порядок — сначала посчитать расхождение, потом закрыть только его — дальше в курсе встречается постоянно: `diff` перед правкой конфигурации, `--dry-run` перед синхронизацией, `terraform plan` перед `apply`, режим проверки в Ansible. Причина одна: действие, применённое к тому, что уже в порядке, не бесполезно, а опасно.
