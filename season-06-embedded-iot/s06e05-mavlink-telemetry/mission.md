## Обстановка

Дрон развернулся и вернулся домой, не долетев до точки съёмки. Оператор
утверждает, что ничего не нажимал. Бортовой журнал будет доступен вечером;
запись эфира есть сейчас — каждый кадр, прошедший по линии за шестьдесят
секунд полёта.

Задача — прочитать причину из потока, не вскрывая аппарат.

## Приказ

Заполнить `artifacts/telemetry_report.txt` — 23 значения.

```bash
cp starter/telemetry_report.txt artifacts/
```

## Чем добывать

| Что нужно | Как |
|---|---|
| байты кадра | `grep -v '^#' data/frame_sample.hex \| tr -cs '0-9A-Fa-f' ' '` |
| `msgid` из трёх байт | `b7 + b8*256 + b9*65536`, младший первым |
| кадры аппарата | `awk '!/^#/ && $2==1' data/telemetry.txt` |
| потери | `awk '$2==1 {s=$4; if(p!=""){d=(s-p-1)%256; if(d<0)d+=256; t+=d} p=s} END{print t}'` |
| разрыв связи | наибольшая разница соседних `t_ms` у кадров аппарата |
| поля сообщения | они в шестой колонке и дальше, вида `имя=значение` |
| имена | соединением со справочниками в `data/` |

## Критерии приёмки

- [ ] `artifacts/telemetry_report.txt` создан на основе `starter/`, 23 ключа заполнены.
- [ ] Поля кадра прочитаны по смещениям, а не угаданы; `frame_len` = заголовок + нагрузка + сумма.
- [ ] `msgid` собран из трёх байт с младшим первым.
- [ ] Потери посчитаны **только** по кадрам аппарата и **по модулю 256**.
- [ ] `worst_severity` — минимальное число: шкала обратная.
- [ ] `final_mode` — имя режима из таблицы, а не число.
- [ ] Комментарии в файле сохранены.
- [ ] `bash tests/test.sh` → 27 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep |
| Сеть | не нужна |
| **дрон** | **не нужен** — разбирается запись в `data/` |
| Внешние пакеты | нет |
| Изоляция теста | все значения пересчитываются из `data/` |

Тест не содержит зашитых значений. Заголовок кадра он разбирает по тем же
смещениям, что и студент, статистику считает из потока, имена берёт из
справочников.

Ключевая проверка — способ подсчёта потерь. Тест считает три «почти
правильных» варианта и различает их в сообщении об ошибке: пропуск убываний
`seq` даёт 66, счёт без разделения систем — 14601, верный ответ — 70.
Совпадение с неверным вариантом диагностируется прямым текстом, а не просто
как «не то число».

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `lost_frames`: «убывания пропущены» | `if (s>p)` вместо модуля | `(s-p-1) % 256` |
| `lost_frames`: «по всем кадрам сразу» | не отфильтрован `sysid` | считать отдельно по каждой системе |
| поля кадра «съехали» | взят разбор MAVLink 1 | у версии 2 заголовок 10 байт |
| `frame_msgid` не проходит | байты собраны в обратном порядке | младший байт первым |
| `worst_severity` = 6 | шкала прочитана как «больше — хуже» | минимальное число серьёзнее |
| `final_mode` = 6 | не сделано соединение с таблицей | имя — из `ardupilot_modes.txt` |
| `battery_min_v` не проходит | взято последнее, а не минимальное | минимум по всем `BATTERY_STATUS` |

## После выполнения

Зелёный тест означает, что причина возврата прочитана по эфиру: семь
процентов потерь, четыре секунды тишины, потеря навигационного решения на
28-й секунде и переход в `RTL` на 29-й. Оператор действительно ничего не
нажимал — аппарат принял решение сам.

Стоит запомнить два принципа. Первый: **разность кольцевых счётчиков
считается в арифметике их разрядности** — это верно для `seq` MAVLink,
номеров TCP-сегментов, счётчиков интерфейса и `jiffies` в ядре. Второй:
**«жив» и «здоров» — разные сигналы.** `HEARTBEAT` шёл ровно весь полёт, и
всё это время аппарат был неисправен; полезная информация лежала в полях, а
не в факте прихода сообщения.

## Кумулятивность

Формат Type C — отчёт из значений, добытых командами, — тот же, что в
[`s06e01`](../s06e01-board-recon/) и
[`s05e09`](../../season-05-security-pentesting/s05e09-forensics-snapshot/);
там же встречалось чтение двоичных данных по смещениям с младшим байтом
вперёд (декодирование адреса из `/proc/net/tcp`).

Разбор потока во времени и восстановление причинности по соседству событий —
прямое продолжение
[`s05e10`](../../season-05-security-pentesting/s05e10-timeline/), где
разрозненные находки выстраивались в одну линию. Различение «жив» и «здоров»
перекликается с
[`s03e05`](../../season-03-system-administration/s03e05-systemd-service/):
запущенный юнит и работающая служба — не одно и то же.

Справочник вместо памяти (`msgid` → имя, `custom_mode` → режим) — тот же
приём, что таблица ARM в [`s06e01`](../s06e01-board-recon/) и эталонный
список модулей в
[`s05e09`](../../season-05-security-pentesting/s05e09-forensics-snapshot/).
