## Обстановка

Брокер закрыт и разграничен, темы описаны. Осталось написать то, что
будет с ним разговаривать, — и оно должно выдержать три вещи, каждая из
которых уже случалась: битые показания с длинного провода, значение
`85.0` от датчика, который ещё не мерил, и четырёхминутный обрыв сети,
после которого двадцать семь узлов вернулись одновременно и положили
брокер снова.

Это первая серия курса, где сдаётся **программа**. Проверяется не текст,
а поведение: тест импортирует файл и вызывает функции напрямую.

## Приказ

Написать `artifacts/sensor.py`.

```bash
cp starter/sensor.py artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `w1_samples/` | образцы вывода `w1_slave`: годный, отрицательный, битый по CRC, `85.0`, мусор |
| `limits.txt` | диапазон правдоподобия, особое значение, ёмкость очереди, параметры задержки, единица |
| `topic_schema.txt` | схема тем — та же, под которую написан `acl` в `s06e09` |

## Требования

| Функция / класс | Требование |
|---|---|
| `parse_w1(text)` | CRC проверяется **до** разбора; `None` при любой негодности; значение в тысячных долях |
| `plausible(v, lo, hi, por)` | `None`, выход за диапазон и особое значение — не годятся; границы включительно |
| `topic_for(schema, node, sensor)` | схема приходит извне и в коде не дублируется |
| `build_message(...)` | JSON: `node`, `sensor`, `value` (число), `unit`, `ts` (целое), `seq`; результат детерминирован |
| `Backoff` | рост по `factor`, потолок `cap`, разброс `±jitter`, источник случайности параметром, `reset()` |
| `Spool` | ограничена `capacity`; при переполнении отбрасывает **старое**; считает `dropped`; `drain()` опустошает |
| `run_cycle(state, raw, publish, now)` | негодное не публикуется и не тратит `seq`; при `publish → False` остаток уходит в очередь по порядку |
| `read_device(path)` | единственное обращение к файловой системе; `None` при ошибке |
| `credentials(env)` | из окружения; отсутствие — `None`, не значение по умолчанию |
| модуль | импорт молчит и ничего не запускает |

## Чем добывать

| Что нужно | Как |
|---|---|
| пределы и параметры | `data/limits.txt` (`ключ=значение`) |
| схема тем | `data/topic_schema.txt`, поля `{node}` и `{sensor}` |
| образцы показаний | `data/w1_samples/*.txt` |
| задержка | `raw = min(base * factor**attempt, cap)`, затем разброс, затем снова обрезка по `cap` |

## Критерии приёмки

- [ ] `artifacts/sensor.py` создан на основе `starter/`, компилируется без ошибок.
- [ ] `parse_w1` возвращает `None` для строки с `CRC=NO`, хотя `t=` в ней есть.
- [ ] `None` не подменяется нулём: «нет показания» и «ноль градусов» различимы.
- [ ] `plausible` отсекает `85.0` — оно проходит CRC и выглядит настоящим.
- [ ] `topic_for` работает с любой схемой, а не только со схемой сети.
- [ ] `build_message` кладёт `value` числом и `ts` целым; повторный вызов даёт тот же результат.
- [ ] `Backoff` растёт, не превышает потолок, даёт разброс при разных `rand`, сбрасывается.
- [ ] `Spool` не растёт выше ёмкости и отбрасывает самое старое.
- [ ] `run_cycle` откладывает при обрыве и отдаёт накопленное после восстановления.
- [ ] Ни одного пароля в исходнике.
- [ ] `bash tests/test.sh` → 39 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| **Python** | **3.8+** (`python3` в `PATH`) |
| Сеть | не нужна |
| датчик | **не нужен** — образцы в `data/` |
| брокер | **не нужен** — `publish` передаётся тестом |
| Внешние пакеты | нет: только стандартная библиотека |
| Изоляция теста | время и случайность передаются параметрами |

Тест не содержит зашитых температур: ожидаемые значения вычисляются из
образцов в `data/w1_samples/` независимо от проверяемого кода. Пределы,
ёмкость очереди и параметры задержки берутся из `data/limits.txt`, схема
тем — из `data/topic_schema.txt`.

Отдельно проверяется, что импорт модуля ничего не печатает и ничего не
запускает: работа должна начинаться только под `if __name__ == "__main__"`.
Иначе тест, импортирующий файл, запустил бы бесконечный цикл.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `test_crc_fail_is_none` | ищется `t=` без проверки первой строки | CRC — первым действием |
| `test_none_is_not_zero` | при ошибке возвращается `0.0` | возвращать `None` |
| `test_power_on_reset_rejected` | не отсечено `85.0` | сравнить с `power_on_reset_c` |
| `test_topic_uses_schema_not_hardcode` | тема собрана строкой в коде | подставлять в переданную схему |
| `test_jitter_spreads` | нет разброса | `raw ± raw*jitter` |
| `test_cap` | разброс применён после обрезки | обрезать по `cap` ещё раз |
| `test_drops_oldest` | выбрасывается новое | `pop(0)` |
| `test_import_silent` | код верхнего уровня печатает | всё под `if __name__` |
| `test_seq_increases` | номер тратится на негодное показание | увеличивать после проверки |

## После выполнения

Зелёный тест означает, что программу проверили, не запуская её целиком:
у неё спросили, что она сделает с битой строкой, с восьмьюдесятью пятью
градусами, с обрывом на четвёртом сообщении и с часом без связи.

Стоит запомнить принцип, ради которого эта серия построена именно так:
**всё, что делает результат непредсказуемым, передаётся снаружи.** Время,
случайность, сеть, файловая система, окружение. Тогда ядро программы
становится обычной функцией, и проверять его можно как арифметику — точным
сравнением, а не «похоже на правду». Зависимость, переданная явно, видна в
сигнатуре; взятая изнутри — скрыта, и обнаруживается она обычно в
эксплуатации.

Второе: **у переполнения всегда есть политика.** Отбрасывать старое,
отбрасывать новое, блокировать источник, писать на диск — выбор делается
по смыслу данных. Очередь, которая просто растёт, тоже реализует политику:
худшую из возможных, и выбранную не тобой.

## Кумулятивность

Метка времени в сообщении — прямое следствие
[`s06e08`](../s06e08-mqtt-dump/), где `retained` отдавал состояние мёртвого
узла трое суток. Схема тем совпадает с `acl` из
[`s06e09`](../s06e09-mqtt-broker/) и потому вынесена в данные: разойтись с
брокером нельзя. Пароль из окружения, а не из кода, — та же мысль, что
`.gitignore` для секретов в
[`s04e03`](../../season-04-devops-automation/s04e03-gitignore-secrets/).

Разброс при переподключении решает ту же задачу, что и ограничение частоты
в [`s05e04`](../../season-05-security-pentesting/s05e04-fail2ban/), но с
другой стороны: там ограничивали чужие попытки, здесь — свои. Различие
«жив» и «здоров», из-за которого нужен `WatchdogSec`, — из
[`s06e05`](../s06e05-mavlink-telemetry/).

Идея «вынести решение из кода в данные» проходит через весь сезон: карта
гребёнки в [`s06e02`](../s06e02-gpio-sysfs/), список датчиков в
[`s06e03`](../s06e03-boot-config/), замеры записи в
[`s06e04`](../s06e04-readonly-root/), пределы полёта в
[`s06e06`](../s06e06-mission-check/). Здесь она же определяет, что
программа умеет работать не только на этом узле.
