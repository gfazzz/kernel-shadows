## Обстановка

Бэкап `shadow-server-01` делает скрипт Дмитрия: `cp -r` в каталог с датой,
на тот же сервер, каждую ночь. Копия занимает столько же, сколько оригинал,
проверить её нечем, и из неё ни разу не восстанавливались.

Лийза Каск задала три вопроса — когда, где и когда восстанавливались, —
и ответа не оказалось ни на один.

## Приказ

Написать `artifacts/backup.sh` — инкрементальный снимок каталога, из которого
можно восстановиться и о котором можно сказать, цел ли он.

```bash
cp starter/backup.sh artifacts/backup.sh
bash tests/test.sh
```

## Что должен уметь скрипт

| Требование | Почему |
|---|---|
| ключи `--source`, `--dest`, `--name`, `--exclude-from`, `--keep`, `--dry-run` | скрипт вызывают из расписания с разными параметрами |
| снимок через `rsync --archive --delete` | иначе теряются права, владельцы и время |
| `--link-dest` на предыдущий снимок | место занимает только разница, а снимок остаётся целым |
| символьная ссылка `latest` | восстанавливающий должен видеть, какой снимок свежий |
| манифест с `sha256` и **относительными** путями | иначе не с чем сверить восстановленную копию |
| блокировка от одновременного запуска | два `rsync` с `--delete` в один каталог портят копию |
| `--dry-run` ничего не создаёт | проверять план на живой системе |
| `--keep N` оставляет N снимков | иначе копии съедят тот самый том из `s03e09` |
| ошибки — в stderr, код возврата ненулевой | иначе служба в журнале выглядит успешной |

## Чем добывать

| Что нужно | Как |
|---|---|
| разбор ключей | `while [ $# -gt 0 ]; do case "$1" in … esac; done` |
| атомарная блокировка | `mkdir "${DEST}/.backup.lock"` — создание каталога атомарно |
| снять блокировку в любом случае | `trap 'rmdir …' EXIT` |
| сборка аргументов | массив: `args=(--archive); args+=(--link-dest=…)`; запуск `rsync "${args[@]}"` |
| контрольные суммы переносимо | `sha256sum` в GNU, `shasum -a 256` в macOS — выбрать через `command -v` |
| относительные пути в манифесте | считать суммы, находясь **внутри** снимка (`cd "${SNAP}"`) |
| устойчивый порядок | `LC_ALL=C sort` |
| самый старый снимок | имена в формате даты сортируются как строки |

## Критерии приёмки

- [ ] `artifacts/backup.sh` создан на основе `starter/`, с шебангом и `set -euo pipefail`.
- [ ] Снимок создаётся в каталоге с именем из `--name`.
- [ ] Файлы копируются с сохранением вложенности.
- [ ] `rsync` получает `--archive` и `--exclude-from`.
- [ ] На первом прогоне `--link-dest` не используется, на втором — используется и указывает на предыдущий снимок.
- [ ] `latest` — символьная ссылка, обновляется после каждого прогона.
- [ ] Манифест содержит `sha256` и относительные пути, включая вложенные файлы.
- [ ] `--dry-run` ничего не создаёт и передаётся самому `rsync`.
- [ ] При существующей блокировке запуск отклоняется с ненулевым кодом.
- [ ] Несуществующий источник отвергается, сообщение уходит в stderr.
- [ ] `--keep 2` оставляет два снимка, удаляя самый старый.
- [ ] Манифест одинаков при разной локали и часовом поясе.
- [ ] `bash tests/test.sh` → 27 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — работа во временном каталоге |
| ОС | любая с bash + coreutils + `sha256sum` или `shasum` |
| Сеть | не нужна |
| `rsync` | **не нужен**: тест подменяет его заглушкой |
| Внешние пакеты | нет |
| Изоляция теста | заглушка `rsync` записывает полученные аргументы и копирует дерево через `cp -p`, поэтому проверяются и ключи, и результат |

## Выполнение

```bash
cd season-03-system-administration/s03e11-backup-rsync
cp starter/backup.sh artifacts/backup.sh
$EDITOR artifacts/backup.sh
mkdir -p /tmp/bk-src /tmp/bk-dst && echo проба > /tmp/bk-src/f.txt
bash artifacts/backup.sh --source /tmp/bk-src --dest /tmp/bk-dst --name проба
bash tests/test.sh
```

На своей машине стоит увидеть эффект `--link-dest` своими глазами:

```bash
rsync -a ~/Documents/ /tmp/s1/
rsync -a --link-dest=/tmp/s1 ~/Documents/ /tmp/s2/
du -sh /tmp/s1 /tmp/s2 ; du -sh --total /tmp/s1 /tmp/s2 2>/dev/null | tail -1
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «каталога run1 нет» | имя снимка берётся из `date`, а не из `--name` | ключ должен переопределять умолчание |
| «rsync без --archive» | использован `-r` | `-a` сохраняет права, владельцев и время |
| «на первом прогоне использован --link-dest» | нет проверки существования `latest` | ссылки ещё нет — снимок полный |
| «--link-dest указывает не на предыдущий» | путь относительный от чужого каталога | указывать абсолютный путь к `latest` |
| «в манифесте абсолютные пути» | суммы считаются снаружи снимка | `cd "${SNAP}"` перед `find` |
| «--dry-run создал снимок» | каталог создаётся до проверки режима | в холостом режиме не создавать ничего |
| «запуск прошёл при блокировке» | `mkdir` без проверки кода возврата | `mkdir … || die` |
| «удалён не самый старый» | сортировка не по имени | `LC_ALL=C sort`, удалять из начала списка |

## После выполнения

Зелёный тест означает, что копия делается, занимает место только под изменения
и о ней можно сказать, цела ли она. Это ещё не бэкап в смысле 3-2-1-T: копия
лежит рядом с оригиналом, и из неё ни разу не восстанавливались.

Первое чинится одной строкой с `rsync -e ssh` на другую машину. Второе не
чинится настройкой вовсе — это отдельная процедура, и ей посвящён финал сезона.

## Кумулятивность

Каталог `/var/log/ops`, который копируется, — тот самый, где в
[`s03e08`](../s03e08-disks-fs/) нашлись десять гигабайт без имени, а
[`s03e07`](../s03e07-journalctl/) восстанавливал по нему хронологию. Том, на
котором лежат снимки, расширен в [`s03e09`](../s03e09-lvm/) — отсюда `--keep`:
копии не должны съесть то, что только что добавили. Дисциплина скрипта
(`set -euo pipefail`, ключи, `trap`, ненулевой код) — из
[`s01e09`](../../season-01-shell-foundations/s01e09-logging-monitor/), а
ограничение ключа SSH на приёмной стороне — та же логика наименьших
привилегий, что в [`s03e03`](../s03e03-sudo/).
