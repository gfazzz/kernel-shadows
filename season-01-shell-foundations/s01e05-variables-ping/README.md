## Теория: переменные + exit code (один концепт)

Скрипту нужна память — **переменные**. Это коробки с наклейками:

```bash
host="shadow-server-01"    # положили значение (НЕТ пробелов вокруг =)
echo "$host"               # достаём через $ (всегда в кавычках!)
```

Кавычки вокруг `"$host"` — не опция, а выживание: без них пробел в значении разорвёт команду на части. Границы имени задают фигурные скобки: `"${host}"`.

Чтобы узнать, жив ли сервер, — **`ping`**, а его вердикт читаем через **exit code**:

```bash
ping -c 1 -W 2 "$host" >/dev/null 2>&1   # -c 1 пакет, -W 2 таймаут
code=$?                                    # $? = exit code: 0 = дошло, иначе — нет
```

`$?` хранит код возврата **последней** команды, поэтому его сохраняют сразу в переменную. Таблица спец-переменных (`$1`, `$#`, `$@`…) и кросс-платформенные тонкости `ping` — в [`theory.md`](theory.md).

> **LILITH:** *«Exit codes — это возвращаемые значения команд. Без них ты слепой. Проверяй `$?` после критичных операций. Всегда.»*

## Проверка «в мире сюжета»

**Дмитрий:** *«Почему `rm $file` — потенциальная катастрофа, а `rm "$file"` — нет?»*

<details>
<summary>Подумай 30 секунд</summary>

Если `file="my document.txt"`, то без кавычек bash видит два аргумента (`my` и `document.txt`) и удалит не тот файл. Кавычки склеивают значение в один аргумент. Один пробел в имени — и без кавычек ты стёр не то.
</details>

**Дмитрий:** *«`ping` вернул `$? = 1`. Сервер точно мёртв?»*

<details>
<summary>Ответ</summary>

Не обязательно «мёртв»: ненулевой код значит «ICMP-ответ не пришёл за таймаут» — сервер может быть жив, но блокировать ICMP, или сеть подлагивает. Для мониторинга это «DOWN по ping», но настоящий вывод делают по совокупности проверок (дальше в курсе — порты, HTTP).
</details>

## Задача

Собери `check_host.sh`: пингует хост (аргумент `$1`), сохраняет exit code в переменную и печатает `HOST` / `STATUS` (`UP`/`DOWN`) / `EXIT_CODE`. Это `Type A` и первый кирпич будущего `server_monitor.sh`.

```bash
cp starter/check_host.sh ./check_host.sh
# заменить TODO (ping → $? → status), кавычки вокруг переменных
bash tests/test.sh
```

ТЗ и «Требования среды» — в [`mission.md`](mission.md). Тест (8 проверок) **подменяет `ping`** мок-версией: достижимые хосты `up-*` → 0, остальные → 1. Живая сеть не нужна, а «всегда UP» тест отвергает.

<details>
<summary>Подсказка (после попытки)</summary>

```bash
ping -c 1 -W 2 "${host}" >/dev/null 2>&1
code=$?
if [ "${code}" -eq 0 ]; then status="UP"; else status="DOWN"; fi
```

Эталон — в `solution/`, открывай после своей попытки.
</details>
