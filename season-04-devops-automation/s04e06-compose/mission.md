## Обстановка

Стек операции поднимается одной командой — и при этом база слушает на всех
интерфейсах машины с белым адресом, пароль лежит открытым текстом в файле,
который в репозитории, а данные исчезают при `docker compose down`.

Сборщик при старте иногда падает с «connection refused» и поднимается со
второй попытки. Это считалось особенностью сети.

## Приказ

Переписать `artifacts/compose.yaml`.

```bash
cp starter/compose.yaml artifacts/compose.yaml
bash tests/test.sh
```

## Требования

| Что | Почему |
|---|---|
| убрать `version:` | устарел с 2020 года и игнорируется |
| образы с точной версией | `latest` завтра означает другое |
| у базы **нет** `ports` | внутри сети её видно по имени `db` |
| публикуемый порт с префиксом `127.0.0.1:` | иначе слушает на всех интерфейсах хоста |
| пароль через `secrets` и переменную `*_FILE` | `environment` печатает `docker inspect` |
| именованный том для данных базы | иначе они исчезнут при `down` |
| `healthcheck` у базы + `condition: service_healthy` | «контейнер запущен» ≠ «база готова» |
| `user`, `read_only`, `tmpfs`, `cap_drop` | то же, что `User=` и `ProtectSystem=` в юните |
| сеть с `internal: true` | базе некуда ходить наружу |
| `restart` у всех служб | после перезагрузки хоста стек должен вернуться |
| убрать `privileged: true` и `docker.sock` | это выдача root на хосте |

## Чем добывать

| Что нужно | Как |
|---|---|
| проверка готовности postgres | `test: ["CMD-SHELL", "pg_isready -U ops -d ops"]` |
| ожидание готовности | `depends_on: {db: {condition: service_healthy}}` |
| секрет из файла | блок `secrets:` верхнего уровня + `secrets: [имя]` у службы |
| пароль внутри контейнера | `POSTGRES_PASSWORD_FILE: /run/secrets/db_password` |
| запись при `read_only` | `tmpfs: [/tmp]` |
| проверить результат | `docker compose config` (на своей машине) |

## Критерии приёмки

- [ ] `artifacts/compose.yaml` создан на основе `starter/`, ключа `version:` нет.
- [ ] Описано не меньше двух служб, у всех образы с точной версией.
- [ ] У базы нет публикуемых портов; все публикуемые порты привязаны к адресу.
- [ ] Паролей открытым текстом нет; есть блок `secrets:` и переменная `*_FILE`.
- [ ] Объявлены именованные тома, данные базы лежат в томе.
- [ ] У базы есть `healthcheck`, у зависящей службы — `condition: service_healthy`.
- [ ] `user` не root, `read_only: true`, `cap_drop` задан.
- [ ] `privileged` нигде не включён, `docker.sock` не монтируется.
- [ ] Сети объявлены явно, одна помечена `internal: true`.
- [ ] `restart` задан у всех служб.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| `docker` | **не нужен** — файл разбирается по отступам как текст |
| Внешние пакеты | нет |
| Изоляция теста | верхний уровень — колонка 0, службы — 2 пробела, их ключи — 4; этого достаточно, чтобы отвечать «что у какой службы задано» |

Тест дополнительно проверяет, что в стартере остались ловушки: устаревший
`version`, монтирование `docker.sock` и публикация порта базы.

## Выполнение

```bash
cd season-04-devops-automation/s04e06-compose
cp starter/compose.yaml artifacts/compose.yaml
$EDITOR artifacts/compose.yaml
bash tests/test.sh
```

Если docker есть на твоей машине, стоит увидеть разницу своими глазами:

```bash
docker compose config          # что понял compose, с подставленными переменными
docker compose ps              # STATUS: Up против Up (healthy)
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «ключ version устарел» | скопировано из старого примера | убрать строку |
| «база публикует порт наружу» | `ports` у `db` | убрать; внутри сети доступ по имени |
| «порт опубликован на всех интерфейсах» | `"8080:8080"` | `"127.0.0.1:8080:8080"` |
| «секрет прямо в файле» | пароль в `environment` | `secrets:` + `*_FILE` |
| «у базы нет именованного тома» | нет `volumes` у службы | `db_data:/var/lib/postgresql/data` |
| «depends_on без condition» | список вместо отображения | `condition: service_healthy` |
| «read_only не включён» | пропущено | плюс `tmpfs: [/tmp]`, иначе некуда писать |
| «ни одна сеть не помечена internal» | сети не объявлены | блок `networks:` с `internal: true` |

## После выполнения

Зелёный тест означает, что стек поднимается одной командой и при этом база
не видна из интернета, пароль не лежит в репозитории, данные переживают
пересоздание, а «поднялось» отличается от «работает».

Стоит задержаться на последнем. `docker compose ps` показывает `Up` у обоих
контейнеров и `Up (healthy)` только у того, кого кто-то проверил. Первое —
свойство процесса, второе — свойство службы, и вся эта серия про разницу
между ними.

[`s03e05`](../../season-03-system-administration/s03e05-systemd-service/), и

[`s03e06`](../../season-03-system-administration/s03e06-systemd-timers/), где
`Type=oneshot` отличался от `simple` ровно этим. Публикация порта только на
`127.0.0.1` — то же правило, что для `RemoteForward` в
[`s02e10`](../../season-02-networking/s02e10-ssh-tunnels/), а «база не должна
смотреть наружу» установлено ещё в
[`s02e02`](../../season-02-networking/s02e02-ports-sockets/).
