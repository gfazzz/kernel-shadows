## Теория: адрес и слои

### Что такое IPv4-адрес

Четыре числа от 0 до 255 — тридцать два бита, разделённые точками для читаемости:

```
10.50.1.100
│  │  │  └── хост: конкретная машина
│  │  └───── подсеть: стойка
│  └──────── подсеть: ЦОД
└─────────── сеть: 10.0.0.0/8, приватный диапазон
```

Где именно проходит граница между «сетью» и «хостом», определяет **маска**, а не сам адрес. Запись `10.50.1.0/24` означает: первые 24 бита — адрес сети, оставшиеся 8 — номера хостов внутри неё, то есть 254 машины плюс адрес сети и широковещательный.

### Приватный или публичный — главное различие

Три диапазона зарезервированы под внутренние сети и никогда не маршрутизируются в интернете (RFC 1918):

| Диапазон | Запись CIDR | Где встречается |
|---|---|---|
| `10.0.0.0` – `10.255.255.255` | `10.0.0.0/8` | крупные корпоративные сети, ЦОД |
| `172.16.0.0` – `172.31.255.255` | `172.16.0.0/12` | средние сети, Docker по умолчанию |
| `192.168.0.0` – `192.168.255.255` | `192.168.0.0/16` | домашние роутеры |

Плюс `127.0.0.0/8` — петля на самого себя, и `0.0.0.0` — «любой адрес», который в конфигурациях означает «слушать на всех интерфейсах».

Граница второго диапазона — место, где ошибаются чаще всего: приватны только `172.16`–`172.31`. Адрес `172.32.5.20` выглядит точно так же, но он **публичный** и принадлежит кому-то в интернете.

### Четыре слоя: зачем они

```
Application   ЧТО   HTTP, SSH, DNS — собственно данные
Transport     КАК   TCP (надёжно) / UDP (быстро), номера портов
Internet      КУДА  IP-адреса, маршрутизация, ICMP
Link          ЧЕМ   Ethernet/Wi-Fi, MAC-адреса, кабель
```

Отправляемые данные спускаются сверху вниз, и каждый слой добавляет свой заголовок — как конверт, вложенный в конверт. На приёме конверты вскрываются снизу вверх.

Практическая ценность модели — в диагностике: она превращает «интернет не работает» в конкретный вопрос. Не пингуется адрес — слой Internet. Пингуется, но порт не отвечает — Transport. Не видно соседа по кабелю — Link. Дальше в сезоне ты пройдёшь эти слои снизу вверх, и каждый инструмент встанет на свой.

> **Дмитрий:** *«Модель не для экзаменов. Она нужна, чтобы после звонка „у нас всё лежит" задать три вопроса вместо тридцати.»*

## Проверка: LILITH задаёт вопросы

**LILITH:** *«`172.16.5.20` и `172.32.5.20` — оба приватные?»*

<details>
<summary>Подумай 20 секунд</summary>

Нет. Приватный диапазон класса B — это `172.16.0.0/12`, то есть второй октет от 16 до 31 включительно. `172.16.5.20` приватный, `172.32.5.20` — публичный.

Цена ошибки конкретная: чужой публичный адрес, принятый за свой внутренний, спокойно проходит все правила «доверяем внутренней сети».
</details>

**LILITH:** *«Зачем модель из четырёх слоёв, если пакет можно просто отправить?»*

<details>
<summary>Ответ</summary>

Затем, что «просто отправить» перестаёт работать в тот момент, когда не отправляется. Слои дают порядок проверки от простого к сложному и не дают искать причину не там.

Плюс они объясняют, почему инструменты разные: `ping` работает на Internet, `ss` — на Transport, `dig` — на Application. Каждый видит свой слой и слеп к остальным.
</details>

## Задание: прочитать адрес

Собери `ipinfo.sh` — принимает адрес и говорит о нём главное:

```
$ ./ipinfo.sh 10.50.1.100
IP: 10.50.1.100
Класс: A
Тип: private (10.0.0.0/8)
```

Невалидный вход — сообщение в stderr и ненулевой код: `999.1.1.1`, `1.2.3`, `10.0.0.-1` адресами не являются.

```bash
cp starter/ipinfo.sh artifacts/ipinfo.sh
# заменить TODO (валидация октетов + класс + тип)
bash artifacts/ipinfo.sh 172.32.5.20
bash tests/test.sh
```

ТЗ и критерии — в [`mission.md`](mission.md). Тест целиком состоит из граничных случаев: `172.16` против `172.32`, `192.168` против `192.169`, октет `255` против `256`. Сеть не нужна — это чистый разбор.

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

```bash
IFS='.' read -r -a oct <<< "$ip"
[ "${#oct[@]}" -eq 4 ] || { echo "невалидный адрес" >&2; exit 1; }
for o in "${oct[@]}"; do
    case "$o" in ''|*[!0-9]*) exit 1 ;; esac
    [ "$o" -le 255 ] || exit 1
done
```

`IFS='.' read -a` режет строку по точкам в массив — тот же приём, что с чтением строк, только разделитель другой. Эталон — в `solution/`, открывай после попытки.
</details>

## Разбор типичных ошибок

**Проверять только диапазон, но не форму.** `[ "$o" -le 255 ]` на строке `abc` в bash вызовет ошибку сравнения, а на пустой строке поведёт себя непредсказуемо. Сначала убеждаются, что октет состоит только из цифр (`case "$o" in *[!0-9]*)`), и лишь потом сравнивают числа.

**Забыть про верхнюю границу второго диапазона.** Условие `[ "$a" -eq 172 ]` без проверки `b` в пределах 16–31 сделает приватным весь `172.x.x.x` — то есть шестнадцать с половиной миллионов чужих адресов.

**Считать классы актуальными.** Деление на A/B/C отменено в 1993 году, когда появился CIDR; сейчас оно живёт как удобная мнемоника и в старых конфигурациях. В скрипте класс печатать полезно (он встречается в документации), а вот принимать по нему решения — нет: решения принимают по маске.
