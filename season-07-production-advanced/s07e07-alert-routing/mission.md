## Обстановка

Ночью узел `verne-w2` ушёл в перезагрузку. Пять правил из
[`s07e06`](../s07e06-alert-rules/) сработали в течение сорока двух секунд,
и каждое стало отдельным звонком. Ещё три звонка — повторы одного и того
же с интервалом в пять минут. Итого восемь звонков за пятнадцать минут про
одну аварию; первый принят, остальные сброшены.

Три из пяти оповещений — следствия недоступности узла, а не
самостоятельные события. Знать об этом система не может: причинные связи
есть только у вас, и записать их можно только в настройку.

## Приказ

Написать `artifacts/alertmanager.yml` так, чтобы такая ночь дала один
звонок.

```bash
cp starter/alertmanager.yml artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `night.txt` | журнал телефона дежурного за ту ночь |
| `policy.txt` | о чём договорились после неё |
| `alert_labels.txt` | какие метки несут оповещения из `s07e06` |
| `current_alertmanager.yml` | настройка, которая действовала, — не образец |

## Чем добывать

| Что нужно | Как |
|---|---|
| разброс оповещений одной аварии | разница времён в `night.txt` |
| приёмник по умолчанию | `default_receiver` в `policy.txt` |
| метки склеивания | строки `group_by` оттуда же |
| минимальные выдержки | `min_group_wait`, `min_group_interval`, `min_repeat_interval` |
| что что подавляет | строки `inhibit` |

## Критерии приёмки

- [ ] У корневого маршрута задан приёмник, и это не телефон.
- [ ] `group_by` — по меткам из политики; `alertname` в него **не** входит.
- [ ] Три выдержки не меньше согласованных.
- [ ] Ветка `severity=page` уходит на телефон, `severity=ticket` — в трекер.
- [ ] Каждый упомянутый приёмник описан в `receivers`.
- [ ] У каждого приёмника есть хотя бы одна настройка доставки.
- [ ] Три правила подавления, и у каждого задан `equal`.
- [ ] В файле нет адреса с токеном: значение приезжает из `Secret`.
- [ ] `bash tests/test.sh` → 24 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep + sed |
| Сеть | не нужна |
| **Alertmanager** | **не нужен** |
| `amtool` | не нужен |
| Внешние пакеты | нет |
| Изоляция теста | разбор YAML пишется в `mktemp -d` |

Тест берёт требования из `policy.txt`, а не хранит их у себя. Отдельно
проверяется, что данные не выродились: что звонков в журнале действительно
больше четырёх, что разброс первой очереди укладывается в требуемое окно
склеивания и что подавлять действительно есть что.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «нет receiver у корня» | забыт приёмник по умолчанию | оповещение исчезнет молча |
| «в group_by попал alertname» | склеиваем одинаковые | склеивать надо разные оповещения одной аварии |
| «group_wait меньше требуемых» | взято 0s из прежней настройки | разброс в `night.txt` — сорок две секунды |
| «нет ветки для severity=…» | ветки не заведены | `route.routes`, у каждой свои `matchers` |
| «приёмника нет в receivers» | опечатка в имени | Alertmanager не запустится |
| «нет equal» | подавление без ограничения | одна цель заглушит весь кластер |
| «адрес с учётными данными» | ссылка вписана значением | `url_file` и `Secret` |

## После выполнения

Зелёный тест означает, что та же ночь дала бы один звонок: пять
оповещений склеены в одну группу, три из них подавлены источником, пятое
ушло в трекер, повтор — через четыре часа, а не через пять минут.

Главное, что стоит унести: **фильтровать надо доставку, а не
наблюдение.** Всё, что система заметила, стоит записать — подавленное
оповещение существует, видно в интерфейсе и попадает в историю, просто не
звонит. Решение о том, кого будить, — отдельный слой, и живёт он не в
правилах, а в описании того, кто дежурит и что из чего следует.

## Кумулятивность

Разделение «что случилось» и «кому сказать» продолжает границу, начатую в
[`s07e06`](../s07e06-alert-rules/): правило знает про метрики, настройка
доставки — про людей.

Подавление следствий — та же операция, что триаж в
[`s05e07`](../../season-05-security-pentesting/s05e07-pentest-triage/):
сначала выясняется, сколько здесь разных проблем, и только потом сколько
из них новости. Первый шаг тот же, что в
[`s07e01`](../s07e01-cluster-recon/).

Учётные данные, которых нет в файле, — прямое продолжение
[`s07e02`](../s07e02-deployment-manifest/) и
[`s04e03`](../../season-04-devops-automation/s04e03-gitignore-secrets/).

Выбор между «хотя бы раз» и «не более раза» при доставке — тот же, что
разбирался с `QoS` брокера в
[`s06e09`](../../season-06-embedded-iot/s06e09-mqtt-broker/).
