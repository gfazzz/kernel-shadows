# Теория — s01e11

## 1. Отчёт, в котором все числа были нулями

> *Третий курс, подрабатываю у Палыча. Меня просят посчитать, сколько трафика ушло на каждый факультет — есть выгрузка биллинга, поля через пробел.*
>
> *Пишу конвейер, запускаю, получаю красивую таблицу. Все значения — ноль.*
>
> *Проверяю файл: данные на месте. Проверяю поля: пятое — байты. Запускаю снова — нули. Меняю пятое на шестое — нули. Начинаю подозревать биллинг.*
>
> *Палыч подходит, читает мою команду вслух:*
>
> — `awk "{sum += $5} END {print sum}"`. Кавычки покажи.
> — Двойные, а что?
> — А то, что до `awk` эту строку читает **bash**. Он видит `$5`, думает «пятый аргумент скрипта», не находит его и подставляет пустоту. `awk` получает программу `{sum += } END {print sum}` — и складывает ничто с ничем.
> — Но он не ругается!
> — Конечно. С точки зрения `awk` программа синтаксически валидна. Ты попросил сложить пустоту — он сложил.
>
> *Он берёт мою распечатку и обводит двойные кавычки.*
>
> — Программа `awk` — это чужой язык внутри твоего. У него свои переменные, и они не должны проходить через bash. Одинарные кавычки. Всегда. А если нужно передать туда значение из оболочки — не склеивай строки, а отдай явно: `awk -v n="$n" '{print $n}'`.
>
> *Самое неприятное было не в ошибке. Отчёт с нулями я почти отправил — он выглядел совершенно нормально, просто цифры были грустные. Молчаливая неправильность страшнее падения: падение ты чинишь, а нули объясняешь.*

## 2. `awk` — это язык, а не флаг

Программа `awk` состоит из правил вида `условие { действие }`:

```bash
awk '{print $1}'              # нет условия → действие для каждой строки
awk '$9 != 200'               # нет действия → печатается вся строка ($0)
awk '$9 == 403 {print $1}'    # и то, и другое
awk 'NR <= 5'                 # первые 5 строк
awk 'END {print NR}'          # сколько всего строк
awk 'BEGIN {FS=":"} {print $1}'  # то же, что -F':'
```

| Переменная | Значение |
|---|---|
| `$0` | вся строка |
| `$1`…`$N` | поля |
| `NF` | количество полей в строке (`$NF` — последнее) |
| `NR` | номер текущей строки во всём вводе |
| `FS` / `OFS` | разделитель на входе / на выходе |
| `BEGIN` / `END` | блоки до первой и после последней строки |

Из этого набора собираются вещи, для которых иначе пришлось бы писать скрипт:

```bash
awk '{sum += $10} END {print sum}' access.log          # суммарный объём ответов
awk '{c[$9]++} END {for (s in c) print c[s], s}' access.log | sort -rn  # статусы
awk 'length($0) > 200' access.log                       # аномально длинные строки
awk -F: '$3 >= 1000 {print $1}' /etc/passwd             # обычные пользователи
```

Ассоциативные массивы (`c[$9]++`) делают `awk` самодостаточным: он умеет то же, что `sort | uniq -c`, за один проход и без сортировки. Идиому с `sort | uniq -c` всё равно знать нужно — она короче и её пишут чаще, — но когда файл большой, один проход `awk` заметно быстрее.

**`awk` против `cut`.** `cut -d' ' -f1` кажется проще, но он считает **каждый** пробел разделителем: два пробела подряд дадут пустое поле. `awk` схлопывает последовательности пробелов и табуляций — для логов с выравниванием это решающая разница.

**Диалекты.** `awk` в Linux обычно `gawk` или `mawk`, в macOS и BSD — `onetrue awk`. Базовый POSIX-набор одинаков; расширения `gawk` (`gensub`, `asort`, `--csv`) — нет. Пиши в POSIX-подмножестве, если скрипт поедет на чужую машину.

## 3. `sort`: чем сортируем и по чему

| Флаг | Действие |
|---|---|
| `-n` | по числу (без него `100 < 20` как текст) |
| `-r` | по убыванию |
| `-u` | оставить уникальные |
| `-k N` | по N-му полю (`-k2,2` — только по второму) |
| `-t 'X'` | разделитель полей |
| `-h` | «человеческие» размеры: `2K` < `1M` |
| `-V` | версии: `1.10` > `1.9` |
| `-s` | устойчивая сортировка (не переставлять равные) |

```bash
sort -t: -k3 -n /etc/passwd          # по UID
sort -k2 -rn stats.txt               # по второму полю, по убыванию
du -h /var/log/* | sort -h           # по размеру, читаемому глазом
```

**Локаль влияет на порядок.** В UTF-8-локали `sort` учитывает правила языка: регистр, диакритику, иногда игнорирует пробелы. В `LC_ALL=C` сравнение побайтовое и предсказуемое. Поэтому в тестах и в скриптах, где важна воспроизводимость, ставят `LC_ALL=C sort`.

## 4. `uniq`: считает только соседей

```bash
sort file | uniq        # убрать дубликаты
sort file | uniq -c     # с количеством
sort file | uniq -d     # только те, что встречались больше раза
sort file | uniq -u     # только уникальные
sort file | uniq -i     # без учёта регистра
```

`uniq` держит в памяти ровно одну предыдущую строку — отсюда и требование сортировки, и его главное достоинство: он работает на файлах любого размера.

Вывод `uniq -c` выровнен пробелами слева (`      5 66.66.66.66`). Это важно, если результат идёт дальше в конвейер: `awk '{print $1}'` возьмёт число корректно (лидирующие пробелы `awk` игнорирует), а `cut -d' ' -f1` вернёт пустоту.

Побочный эффект выравнивания: числа одинаковой ширины сортируются как текст в том же порядке, что и как числа, — поэтому на выводе `uniq -c` разница между `sort -r` и `sort -rn` часто не видна. Это удача, а не свойство: стоит числу выйти за ширину поля (или данным прийти из другого источника, без выравнивания) — и порядок разъедется. `-n` пишут всегда, а не «когда заметно».

## 5. Идиома целиком

```bash
grep -vE ' 200 ' access.log \
  | awk '{print $1}' \
  | sort \
  | uniq -c \
  | sort -rn \
  | head -20
```

Читается справа налево как вопрос и слева направо как ответ: «двадцать самых частых адресов среди запросов, не вернувших 200». Меняя одно поле в `awk`, получаешь топ URL (`$7`), топ статусов (`$9`), топ user-agent (`$NF`).

Отлаживают её всегда по частям: добавили звено — посмотрели `| head`, убедились, что на входе следующего то, что ожидалось. Собранный целиком и не работающий конвейер разбирать втрое дольше.

## 6. Когда конвейер перестаёт быть уместен

Идиома отлично работает до тех пор, пока задача — «посчитать одно измерение». Как только вопросов становится несколько (и статусы, и адреса, и объём — за один проход), конвейер начинает читать файл по разу на вопрос, а команда растёт в ширину экрана.

Признаки, что пора остановиться: больше пяти-шести звеньев; один и тот же файл читается несколько раз; в середине появился `sed`, который «чинит» формат. Тогда либо один `awk` с массивами, либо, если и этого мало, `python`/`jq` (для JSON-логов) — и это не поражение bash, а нормальная граница инструмента.

## 7. Метанавык: агрегат вместо перечня

Разница между «сотни подозрительных строк» и «один адрес с четырьмя тысячами запросов» — не в данных, данные те же. Разница в том, что первое человек читать не может, а второе понимает мгновенно.

Любой разбор данных сводится к одному движению: свернуть перечень в распределение. Сколько чего, кто чаще, что редко. Инструменты меняются — `uniq -c` в терминале, `GROUP BY` в SQL, сводная таблица в отчёте, гистограмма в мониторинге, — движение одно и то же. Освоив его на логах, ты узнаешь его везде.
