## Что это

101 серия в восьми сезонах, 98 часов 25 минут чистого времени на задачи.
Теория вплетена в сюжет: распределённая операция, восемь стран, 60 дней.

Единица курса — **серия**: один концепт, одна задача, один проверяемый
артефакт, 45–90 минут. Артефактом может быть скрипт, конфиг, отчёт о
разборе или программа — в зависимости от того, чему серия учит.

Курс про Linux целиком, а не про shell-скриптинг. Автоматизация — следствие
владения системой, а не его содержание: администратор, умеющий только писать
скрипты, беспомощен там, где ничего не надо автоматизировать.

Продолжение вселенной [OPERATION MOONLIGHT](https://github.com/gfazzz/moonlight-course):
там вы **создаёте программы**, здесь — **управляете системами, на которых они
работают**. Персонажи и сюжет общие.

## Быстрый старт

```bash
git clone https://github.com/gfazzz/kernel-shadows.git
cd kernel-shadows
make check                                    # 101 из 101 — всё на месте

cd season-01-shell-foundations/s01e01-terminal-awakening
less README.md                                # сцена, теория, задание
cp starter/whereami.sh artifacts/             # каркас с TODO
bash tests/test.sh                            # красный — так и задумано
```

Сразу после копирования каркаса тест **красный**: в `starter/` лежат `TODO`,
а не решение. Тест здесь не судья, а спецификация — его вывод говорит, чего
не хватает. Зелёным он станет, когда задание выполнено.

**Впервые с Linux?** Пошаговая установка и разбор типичных проблем —
в [docs/GETTING_STARTED.md](docs/GETTING_STARTED.md).

### Как проходить серию

| Файл | Зачем |
|---|---|
| `README.md` | сцена, теория одного концепта, задание, разбор типичных ошибок |
| `mission.md` | брифинг: что дано, критерии приёмки, требования среды, диагностика |
| `theory.md` | углубление: история вопроса, компромиссы, книги |
| `starter/` | каркас артефакта — копируется в `artifacts/` |
| `solution/` | рабочий эталон, открывать после своей попытки |
| `tests/test.sh` | проверка: без root, без сети, на фикстурах |
| `artifacts/` | ваша работа |

### Ask, а не Agent

Курс проходят в режиме **`Ask`**. В режиме `Agent` помощник правит файлы
сам: серия окажется решённой, а вы не напишете ни строки.

Первый раздел [`.cursorrules`](.cursorrules) это запрещает — не писать в
`artifacts/`, не выдавать решение серии, не пересказывать `solution/`, — но
режим переключаете вы, а не файл.

Что помощник делает вместо этого: объясняет концепт, показывает приём на
**другой** задаче, разбирает сообщение об ошибке, задаёт наводящий вопрос.

### Ваша работа и git

Форкните репозиторий и работайте в своей ветке: `artifacts/` отслеживаются,
поэтому решения попадут в историю и останутся портфолио. При обновлении
курса конфликтов не будет — в апстриме эти папки пустые.

`make progress` считает по факту: серия пройдена, если в её `artifacts/`
лежит ваша работа и тест на ней зелёный. Наличие `solution/` не
засчитывается.

### Типы серий

| Метка | Что делаете | Что проверяет тест |
|---|---|---|
| `Type A — Automation` | пишете `.sh` | поведение скрипта на фикстуре |
| `Type B — Configuration` | правите конфиг | свойства конфига, идемпотентность |
| `Type C — Investigation` | работаете в CLI | воспроизводимость находки |
| `Type D — Code` | пишете `.py` | поведение программы |

Баланс типов — часть критериев приёмки сезона: сезон, целиком состоящий из
`Type A`, не принимается.

**Подсказок становится меньше.** S1–S3 — полный каркас и эталон; S4–S5 —
каркас, эталон после попытки; S6–S7 — интерфейсы; S8 — только договор
вызова. Это совмещено с сюжетом, а не введено молча.

## Сквозные артефакты

Каждый сезон не решает разрозненные упражнения, а собирает работающую
систему:

| Сезон | Артефакт | Что это |
|---|---|---|
| S4 | `shadow_iac` | репозиторий инфраструктуры: git, образы, конвейер, Ansible |
| S6 | `shadow_mesh` | сеть edge-узлов: плата, дрон, MQTT, модуль ядра |
| S7 | `aurora` | контур эксплуатации: манифесты, метрики, оповещения, SLO |
| S8 | `shadow_core` | приёмка: 12 фаз, по одной на навык каждого сезона |

Финал (`s08e12`) не вводит новую тему — он **принимает** всё построенное.
Курс заканчивается не поздравлением, а прогоном, который возвращает ноль
или не возвращает.

Подробнее — [docs/PROJECTS.md](docs/PROJECTS.md).

## Сюжет и LILITH

Виктор Петров поручает вам построить и защитить распределённую систему.
Полковник Крылов и организация «Новая Эра» пытаются взломать серверы,
перехватить трафик, внедрить закладки. За 60 дней вы проходите путь от
`pwd` до приёмки инфраструктуры на пятидесяти узлах.

**LILITH** — наставник внутри сюжета и внутри текста серий. Она задаёт
вопрос раньше, чем даёт ответ, и разбирает, почему решение именно такое.
Она **не** следит за вашей машиной и **не** решает задачу за вас.

В конце каждой серии есть **красные промпты** — вопросы, которые задавать
не надо, с объяснением почему: там готовый ответ выглядит убедительно и
вредит. Границы — [docs/LILITH.md](docs/LILITH.md).

Сюжетный канон (спойлеры): [docs/SCENARIO.md](docs/SCENARIO.md),
[docs/CHARACTERS.md](docs/CHARACTERS.md), [docs/LOCATIONS.md](docs/LOCATIONS.md).

## Что курс даёт

Профессии, к которым он готовит: системный администратор, инженер
эксплуатации и DevOps, инженер по безопасности, сетевой инженер, работа со
встраиваемым Linux, разбор инцидентов.

**Что разбирается в заданиях:**

| Область | Что именно |
|---|---|
| текст и оболочка | `grep`, `awk`, `sed`, конвейеры, `find`, права, `sudo` |
| конфигурация | `sshd_config`, юниты и таймеры systemd, `fstab`, `nftables`/`ufw`, `logrotate` |
| сети | TCP/IP, сокеты, DNS, фильтрация, туннели SSH, WireGuard |
| контейнеры и IaC | образы и слои, Compose, конвейеры сборки, Ansible |
| безопасность | аудит, `auditd`, целостность, AppArmor, SELinux, CIS |
| встраиваемое | device tree, GPIO, MQTT, модули ядра, символьные устройства |
| эксплуатация | манифесты Kubernetes, Prometheus и PromQL, перцентили, SLO |
| языки | `.sh` везде; `.py` с Season 6; C — там, где Linux и есть C |

**Чего в курсе нет** (чтобы не искали): администрирования СУБД, Terraform
как предмета, ассемблера, eBPF. Они встречаются в тексте как контекст, но
заданий по ним нет. Писать на C курс тоже не учит — для этого есть
[OPERATION MOONLIGHT](https://github.com/gfazzz/moonlight-course).

## Требования

- **ОС:** Ubuntu 20.04 LTS или новее; подойдёт WSL2 или виртуальная машина
- **Инструменты:** `bash`, `awk`, `grep`, `python3`, `git`
- **Опыт:** не требуется, курс начинается с `pwd`

Больше ничего не нужно: **ни один тест не требует root, сети, Docker,
кластера или железа**. Всё, что в жизни требует живой инфраструктуры,
проверяется по снимкам и фикстурам.

## Инструменты

```bash
make check                    # ссылки + инструменты + хронология + тесты (как в CI)
make test                     # тесты всех серий
make test SERIES=s03e07       # одна серия
make test SEASON=season-03-system-administration
make progress                 # где я остановился
make test-repeat              # два прогона подряд: воспроизводимость
make test-locale              # прогон под другой локалью и часовым поясом
make clean-clone              # приёмка на чистом клоне
```

Документы, которые собираются из самих серий, а не пишутся руками:

```bash
bash tools/gen_index.sh          # указатель серий  -> docs/CURRICULUM.md
bash tools/gen_bibliography.sh   # библиография     -> docs/RESOURCES.md
bash tools/gen_timeline.sh       # хронология сюжета
```

Помощник в терминале: `./tools/lilith.sh hint s03e07`,
`./tools/lilith.sh check s03e07`. Подробнее — [tools/README.md](tools/README.md).

`.vscode/` содержит настройки и задачи для Cursor и VSCode: рекомендуемые
расширения, запуск тестов, проверка скриптов.
