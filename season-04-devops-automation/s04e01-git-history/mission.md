## Обстановка

Дмитрий две недели складывал конфигурации операции в репозиторий. Двенадцать
коммитов, две ветки, одно слияние. Ханс предлагает начать не с того, чтобы
писать, а с того, чтобы читать: «половина работы DevOps — археология».

И добавляет, что у него будет один вопрос по этому репозиторию. Неприятный.

## Приказ

Разобрать историю и **сдать отчёт** — заполненный
`artifacts/history_report.txt`.

```bash
bash ../data/build_shadow_iac.sh /tmp/shadow_iac
cd /tmp/shadow_iac
```

```bash
cp starter/history_report.txt artifacts/history_report.txt
bash tests/test.sh
```

Репозиторий собирается с фиксированными датами и авторами, поэтому получается
**побитово одинаковым** при каждом запуске — включая хеши коммитов. Пересобрать
можно сколько угодно раз: удалите каталог и запустите сборщик снова.

| Файл | Что это |
|---|---|
| [`data/build_shadow_iac.sh`](../data/build_shadow_iac.sh) | сборщик учебного репозитория; ничего не скачивает |

## Чем добывать

| Что нужно | Как |
|---|---|
| граф истории | `git log --oneline --graph --all` |
| счёт коммитов | `git rev-list --count HEAD`, `--no-merges` |
| авторы | `git log --format='%an' \| sort \| uniq -c \| sort -rn` |
| корневой коммит | `git rev-list --max-parents=0 HEAD` |
| дата коммита | `git log -1 --format=%ad --date=short <хеш>` |
| коммит слияния | `git rev-list --merges -1 HEAD` |
| точка расхождения | `git merge-base "$M^1" "$M^2"`, где `M` — слияние |
| отслеживаемые файлы | `git ls-files \| wc -l` |
| когда файл добавлен/удалён | `git log --all --oneline --diff-filter=A\|D -- путь` |
| содержимое из прошлого | `git show <хеш>:путь` |
| объём изменений | `git log --numstat` или `--shortstat` |
| короткий хеш | `git rev-parse --short=7 <хеш>` |

## Критерии приёмки

- [ ] `artifacts/history_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Коммиты посчитаны и со слияниями, и без них — числа разные.
- [ ] Автор с наибольшим числом коммитов определён сортировкой по числу.
- [ ] Найден корневой коммит и его дата.
- [ ] Точка расхождения ветки найдена через родителей коммита слияния, а не через `merge-base main monitoring`.
- [ ] Число отслеживаемых файлов взято из `git ls-files`, а не из `ls`.
- [ ] Найден файл с паролем, коммит его появления и коммит удаления.
- [ ] **Пароль выписан** — то есть добыт из коммита, где файла уже нет в дереве.
- [ ] Найден коммит с наибольшим числом изменённых строк.
- [ ] Короткие хеши записаны семью символами.
- [ ] `bash tests/test.sh` → 24 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils |
| Сеть | **не нужна** — сборщик ничего не скачивает |
| Внешние пакеты | **`git`** — для серии про git это предмет изучения |
| Изоляция теста | тест сам собирает репозиторий во временном каталоге и вычисляет по нему все ответы |

Тест дополнительно проверяет, что репозиторий воспроизводим (повторная сборка
даёт тот же хеш), что секрета нет в рабочем дереве, но он есть в истории, и что
наивный `merge-base main monitoring` даёт не тот ответ.

## Выполнение

```bash
cd season-04-devops-automation/s04e01-git-history
cp starter/history_report.txt artifacts/history_report.txt
bash ../data/build_shadow_iac.sh /tmp/shadow_iac
cd /tmp/shadow_iac && git log --oneline --graph --all
cd -                     # вернуться в каталог серии
bash tests/test.sh
```

Заодно стоит посмотреть на свой собственный репозиторий теми же командами:

```bash
git shortlog -sn | head
git log -S 'password' --oneline | head
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «коммитов всего» на 1 меньше | посчитано без слияния | `git rev-list --count HEAD` |
| точка расхождения — вершина ветки | `merge-base main monitoring` после слияния | брать родителей коммита слияния |
| «отслеживаемых файлов» больше | посчитан `ls` вместе с `.git` | `git ls-files` |
| хеш не принят | скопирован длинный или шестизначный | ровно 7 символов |
| пароль не найден | искали в рабочем дереве | `git show <коммит>:.env` |
| дата не та | взята дата коммиттера | `--date=short` от автора |
| «коммит с наибольшими изменениями» не тот | посчитаны файлы, а не строки | `--numstat`, сумма добавленных и удалённых |

## После выполнения

Зелёный тест означает, что вы умеете задавать репозиторию вопросы. Это
половина работы с инфраструктурой как кодом: вторая половина — писать так,
чтобы на такие вопросы можно было ответить.

И главное, что стоит унести: **удалить файл — не значит убрать его из
репозитория.** Пароль, найденный вами в истории, надо считать
скомпрометированным независимо от того, что с ним делали дальше.

## Кумулятивность

Пароль от базы операции, найденный в истории, — от той самой базы
`10.50.1.102`, которая описана в
[`s02e01`](../../season-02-networking/s02e01-tcpip-addressing/) и до которой
строился туннель в [`s02e10`](../../season-02-networking/s02e10-ssh-tunnels/).

[`s01e15`](../../season-01-shell-foundations/s01e15-permissions-basics/):
на диске он был защищён правами, а в репозитории права не значат ничего.
Приёмы `sort | uniq -c | sort -rn` и `grep -c` — из
[`s01e11`](../../season-01-shell-foundations/s01e11-awk-stats/); привычка
считать «наивным» и «правильным» способом и сравнивать — из
[`s02e12`](../../season-02-networking/s02e12-firewall-log/).
