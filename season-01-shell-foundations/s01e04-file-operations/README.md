## II. Теория: пять команд и одна привычка

### Пять команд, которыми делается всё

```bash
mkdir intel               # создать каталог
mkdir -p ws/intel/raw     # создать всю цепочку сразу (и не ругаться, если есть)
touch operation.log       # создать пустой файл (или обновить время правки)
cp brief.txt intel/       # скопировать: оригинал остаётся
cp -r data/ backup/       # скопировать каталог целиком (-r = recursive)
mv draft.txt final.txt    # переместить ИЛИ переименовать — это одна операция
rm tmp.txt                # удалить файл
rm -r old/                # удалить каталог с содержимым
```

Две вещи, которые стоит понять сразу.

**`mv` — это и «переместить», и «переименовать».** Отдельной команды переименования в Unix нет: имя файла — это запись в каталоге, и смена имени есть перемещение внутри того же каталога. Одна операция вместо двух.

**`cp` копирует, `mv` переносит.** Разница безобидна, пока ты работаешь со своими файлами, и критична, когда с чужими: `mv` **удалит файл у источника**. На боевом сервере это означает, что ты незаметно унёс чужой конфиг.

### `rm` не спрашивает и не кладёт в корзину

```bash
rm file.txt        # файл исчез. Насовсем.
rm -r dir/         # каталог со всем содержимым. Тоже насовсем.
rm -i file.txt     # -i = спросить перед удалением
```

Корзины в Unix нет. Восстановление удалённого — это либо бэкап, либо дорогая криминалистика. Поэтому у опытных администраторов рука сама набирает `rm -i` или сначала `ls` того, что собирается удалить.

Особая осторожность с `rm -rf` и подстановками: `rm -rf * .bak` — лишний пробел, и вместо `*.bak` удаляется **всё** в каталоге, а потом ещё `.bak`. Классика, стоившая людям продакшена.

> **LILITH:** *«Перед `rm` со звёздочкой замени `rm` на `ls` и посмотри, что попадёт под удаление. Две секунды против невосстановимого. Я видела, чем заканчивается вторая половина этого выбора.»*

### `man` — справка, которая всегда под рукой

В каждой серии этого курса есть строчка «см. `man ls`». Пора сказать, как ею пользоваться.

```bash
man cp            # справка по команде
man 5 crontab     # раздел 5 — форматы файлов (а не команда crontab из раздела 1)
man -k copy       # поиск по описаниям: «какая команда умеет копировать?»
```

`man` открывается в `less` — том самом, что из прошлой серии: пробел листает, `/текст` ищет, `q` выходит.

Разделы нумерованы: `1` — команды, `5` — форматы файлов и конфиги, `8` — команды администратора. Отсюда `man 5 passwd` (формат файла `/etc/passwd`) и `man 1 passwd` (команда смены пароля) — разные страницы про разное.

Структура страницы всегда одинакова: NAME, SYNOPSIS (краткий синтаксис), DESCRIPTION, OPTIONS, EXAMPLES, SEE ALSO. Начинать читать стоит с SYNOPSIS и EXAMPLES — обычно этого хватает. Подробнее про разделы, `apropos` и почему `man` надёжнее поисковика — в [`theory.md`](theory.md).

**LILITH:** *«Тебе нужно забрать конфиг с чужого сервера. `cp` или `mv`?»*

<details>
<summary>Подумай 20 секунд</summary>

`cp`. `mv` **удалит** файл у источника — на чужой машине это порча чужих данных, а в контексте операции ещё и заметный след: пропавший файл видно сразу.

Правило простое: с чужого — только копировать. Убирать за собой можно лишь то, что создал сам.
</details>

**LILITH:** *«Что сделает `rm -rf * .bak` и чем это отличается от `rm -rf *.bak`?»*

<details>
<summary>Ответ</summary>

`rm -rf *.bak` удалит файлы с расширением `.bak`.

`rm -rf * .bak` — с пробелом — это **два аргумента**: `*` (всё в текущем каталоге) и `.bak`. Первый уничтожит содержимое каталога целиком.

Отсюда привычка: перед удалением по шаблону выполнить `ls` с тем же шаблоном и посмотреть на список глазами.
</details>

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Скопировать скрытый файл под новым именем — обычное `cp`: точка в имени ни на что не влияет. Эталонная сборка — в `solution/build_workspace.sh`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Использовать `mv` вместо `cp`.** Файл переезжает, а на «сервере» пропадает. Тест ловит это отдельной проверкой — и это единственная ошибка серии, которая портит данные, а не только результат.

**Создавать каталоги по одному без `-p`.** `mkdir a/b/c` без `-p` упадёт, если `a` ещё нет: команда создаёт только последний уровень. Флаг `-p` делает всю цепочку и молчит, если часть уже существует.

**Считать, что `touch` — это «обновить дату».** Он и создаёт файл, если того нет. Пустой файл-заготовка под лог — обычный приём: он сразу существует с нужными правами, и приложению есть куда писать.
