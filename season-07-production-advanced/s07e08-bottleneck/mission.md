## Обстановка

Соседняя команда жалуется: `aurora-api` отвечает по полсекунды. Порог
оповещения — триста миллисекунд, фактический 95-й перцентиль — шестьсот
двадцать, но держится десять минут при выдержке в пятнадцать, и потому
молчит.

Процессор узла простаивает на три четверти, диск занят на двенадцать
процентов, доступной памяти четыре с половиной гигабайта из семи восьми.
Аппаратные ресурсы в порядке — и приложение всё равно медленное.

## Приказ

Заполнить `artifacts/bottleneck_report.txt` — 23 значения: по каждому
ресурсу утилизация, насыщение, приговор, и единственное узкое место.

```bash
cp starter/bottleneck_report.txt artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `vmstat.txt` | `vmstat 1 10` — процессор, очередь, подкачка |
| `iostat.txt` | `iostat -x` — диск |
| `free.txt` | `free -m` — память узла |
| `nstat.txt` | счётчики сетевого стека за минуту |
| `cadvisor.txt` | троттлинг и память контейнера |
| `app_metrics.txt` | перцентили приложения и пул соединений |
| `use_thresholds.txt` | пороги, за которыми ресурс считается узким местом |

## Чем добывать

| Что нужно | Как |
|---|---|
| утилизация процессора | `100` минус **наименьший** `id` в `vmstat` |
| насыщение процессора | наибольшее `r` |
| память | `available` к `total` в `free` |
| диск | наибольший `%util` |
| троттлинг | `throttled_periods` к `periods`, в процентах |
| память контейнера | `working_set` к `spec_memory_limit` |
| утилизация пула | занято к потолку |
| доля ожидания | `pool_wait_p95_ms` к `request_p95_ms` |
| приговор | утилизация **строго больше** порога → `saturated` |

## Критерии приёмки

- [ ] Все 23 ключа заполнены целыми числами или словами `ok`/`saturated`.
- [ ] Память считается по `available`, а не по `free`.
- [ ] Утилизация процессора взята по наименьшему простою, а не по среднему.
- [ ] Троттлинг контейнера посчитан отдельно от загрузки узла.
- [ ] Пул соединений разобран как ресурс: потолок, занято, очередь.
- [ ] Ровно один ресурс получил приговор `saturated`.
- [ ] Названное узкое место — не аппаратный ресурс.
- [ ] Комментарии в файле сохранены.
- [ ] `bash tests/test.sh` → 30 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep |
| Сеть | не нужна |
| **доступ к машине** | **не нужен** — снимки в `data/` |
| Внешние пакеты | нет |
| Изоляция теста | снимки только читаются |

Тест пересчитывает каждое значение из снимков теми же приёмами. Отдельно
проверяется, что данные не выродились: что за порогом ровно один ресурс,
что процессор, память и диск в норме (иначе разбор свёлся бы к чтению
одной колонки), что ожидание пула объясняет больше половины времени
ответа и что очередь к пулу длиннее самого пула.

Все сравниваемые величины целые: проценты и доли секунды с плавающей
точкой между машинами и локалями не сравнивают.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `cpu_util_max_pct` не проходит | посчитано среднее | нужен наименьший `id` |
| `mem_available_pct` мал | взята колонка `free` | смотреть `available` |
| `disk_util_max_pct` дробный | не отброшена дробь | все величины целые |
| `cpu_throttled_pct` из `vmstat` | взята загрузка узла | у контейнера свои счётчики |
| `pool_util_pct` не 100 | занято сравнили не с потолком | `pool_in_use_max` к `pool_max` |
| `bottleneck=cpu` | остановились на аппаратных ресурсах | ни один из них не за порогом |
| «приговоров saturated больше одного» | порог применён не к тому числу | у памяти это `100 - available` |

## После выполнения

Зелёный тест означает, что пять ресурсов честно исключены, а шестой
найден: пул соединений к базе занят полностью, в очереди к нему сорок
семь запросов, и две трети времени ответа уходит на ожидание в ней.

Главное, что стоит унести: **ресурс — это не обязательно то, что можно
потрогать.** Пул соединений, очередь потоков, `backlog` сокета, файловые
дескрипторы — у каждого есть потолок, и почти всегда его назначил
человек. Аппаратные ресурсы покупают с запасом; узкое место оказывается в
очереди, которую настроили однажды и забыли.

И второе: **сто процентов утилизации значимы только вместе с
насыщением.** Диск на ста процентах с пустой очередью здоров, пул на ста
процентах с очередью в сорок семь — стена.
