## Обстановка

Внутреннее имя `shadow-05.ops.internal` резолвится в публичный адрес из Tor-сети,
хотя сервер стоит в московской стойке с приватным адресом `10.50.1.20`. Запрос
выполняется успешно: ошибки нет, предупреждения нет, ответ выглядит нормальным.

Отравлен кеш резолвера — подделка успела прийти раньше настоящего ответа и осела
на весь TTL. Инструмент честен, данные ложны, и отличить одно от другого можно
только сравнением с тем, что известно наверняка.

## Приказ

Собрать `dns_guard.sh` — читает файл эталонов, резолвит каждый домен и ловит
расхождения:

```
  ✓ shadow-01.ops.internal → 10.50.1.10 (совпадает с эталоном)
  ⚠️ shadow-05.ops.internal → 185.220.101.52 (ОЖИДАЛОСЬ 10.50.1.20) — ВОЗМОЖНА ПОДМЕНА!
---
Проверено: OK=2 SPOOFED=1
ALERT: обнаружена возможная подмена DNS (1)
```

Использование: `./dns_guard.sh BASELINE_FILE`, строка — `домен ожидаемый_IP`.

## Данные

| Что | Как |
|---|---|
| файл эталонов | `"${1:?…}"`, проверить `[ -f … ]` |
| чтение | `while IFS= read -r line; … done < "$baseline"` (s01e08) |
| домен / эталон | `domain="${line%% *}"`, `expected="${line##* }"` |
| текущий адрес | `dig "$domain" A +short 2>/dev/null \| head -1` |
| сравнение | `[ "$actual" = "$expected" ]` |
| нет ответа | пустой `actual` — расхождение, но с другой причиной |
| тревога | `ALERT` в `stderr` при `spoofed > 0` |

Пустой эталон в строке — не «совпало», а ошибка формата: пустое, сравненное с
пустым, даёт тихое «всё хорошо».

## Критерии приёмки

- [ ] `artifacts/dns_guard.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Совпавший домен помечается как совпавший, расходящийся — как возможная подмена.
- [ ] Отравленный домен обнаружен, и в выводе видны **оба** адреса: полученный и ожидаемый.
- [ ] Домен, который вообще не резолвится, считается расхождением, а не совпадением.
- [ ] Строка эталона без адреса не превращается в «совпало».
- [ ] Итог `OK=N SPOOFED=M` соответствует напечатанным строкам.
- [ ] При `SPOOFED > 0` выдаётся `ALERT` в stderr.
- [ ] Комментарии и пустые строки не считаются доменами.
- [ ] Отсутствующий файл эталонов → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 12 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash; для реального запуска — `dig` |
| Сеть | **не нужна** — тест подменяет `dig` |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `dig`; в тесте подменяется |
| Изоляция теста | мок-`dig` в `PATH` + файл эталонов во временном каталоге |

Мок воспроизводит четыре ситуации: совпадение, отравленный домен, домен без
ответа и домен с несколькими адресами. Ожидаемые счётчики тест вычисляет,
прогоняя мок по файлу эталонов.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| всё «совпадает», хотя адреса разные | сравниваются не те поля | `${line%% *}` и `${line##* }` |
| домен без ответа считается совпавшим | пустое сравнивается с пустым | проверять `[ -z "$actual" ]` отдельно |
| строка эталона без адреса даёт «ОК» | `expected` пуст | проверять формат строки до сравнения |
| `ALERT` не виден в конвейере | ушёл в stdout | писать в stderr: `>&2` |
| счётчики нулевые при верных строках | цикл в подоболочке | читать через `done < "$baseline"` |
| ложные тревоги на внешних доменах | у домена несколько меняющихся адресов | эталон применим к фиксированным адресам |
