## Обстановка

Дмитрий прислал дамп машины, которую операции передают. Перед подключением надо
понять её состав: сколько файлов, сколько конфигов, что спрятано и что занимает
больше всего места.

Дерево большое и незнакомое — обойти его `ls`-ом и `cd`-ом нельзя: на третьем
уровне теряешь нить, а машин таких будет не одна.

## Приказ

Собрать `audit_tree.sh` — инструмент, который принимает каталог и печатает четыре
факта о дереве. Формат вывода строгий, по строке на факт:

```
files=<число>
configs=<число>
hidden=<число>
largest=<имя файла без пути>
```

Инструмент должен работать на **любом** дереве, а не только на присланном дампе.

## Данные

| Факт | Условие | Подсказка |
|---|---|---|
| `files` | обычные файлы, рекурсивно | `-type f` |
| `configs` | из них с именем `*.conf` | `-name '*.conf'` в кавычках |
| `hidden` | имя начинается с точки | `-name '.*'` |
| `largest` | самый большой по размеру | `-exec du -k {} +`, затем `sort -rn`, `basename` |

Каталоги в счёт файлов не входят. Размер берётся переносимым способом:
GNU-расширения `find -printf` в решении быть не должно — на macOS/BSD его нет.

## Критерии приёмки

- [ ] `artifacts/audit_tree.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Принимает каталог первым аргументом; несуществующий → сообщение и ненулевой exit.
- [ ] Четыре строки вывода в формате `ключ=значение`.
- [ ] Числа верны для дерева любой глубины (рекурсия, а не верхний уровень).
- [ ] `configs` считает только файлы `*.conf`, не каталоги.
- [ ] `hidden` считает скрытые файлы на всех уровнях.
- [ ] `largest` — имя без пути.
- [ ] Работает на другом дереве с другим составом (проверяется отдельно).
- [ ] `bash tests/test.sh` → 10 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + find + coreutils (Linux / macOS / WSL) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`find`, `du`, `sort`, `wc`, `basename`) |
| Изоляция теста | фикстура-дерево во временном `TEST_ROOT`, удаляется автоматически |

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| числа равны нулю | не указан каталог или неверный путь | проверить аргумент, `pwd` |
| `files` больше ожидаемого | посчитаны каталоги | добавить `-type f` |
| `configs` = 0 при явных `.conf` | шаблон раскрыла оболочка | взять в кавычки: `-name '*.conf'` |
| считает только верхний уровень | добавлен `-maxdepth 1` | убрать ограничение глубины |
| `largest` с полным путём | не отрезан путь | `basename` или `${p##*/}` |
| `find: -printf: unknown primary` | GNU-расширение на macOS/BSD | размер через `du -k` |

## После выполнения

Если тест зелёный — у тебя инструмент, который отвечает на вопросы о незнакомой
машине за долю секунды. Дмитрий получит состав дампа, а ты — первый признак
неладного: приватный ключ, забытый кем-то в `.ssh`.

Если числа сходятся на фикстуре, но не на другом дереве — значит, в скрипте
что-то захардкожено. Инструмент, который верен только для одного случая, хуже
отсутствующего: он создаёт ощущение проверки там, где её нет.
