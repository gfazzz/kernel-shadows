## Теория: блокировка списком (один концепт: список IP → стена)

Заблокировать один IP просто:

```bash
sudo ufw deny from 185.220.101.47
```

Но их 847. Собираем правила **из файла**, генерируя скрипт (а не применяя на лету):

```bash
while IFS= read -r line; do
    ip="${line%% *}"
    echo "ufw deny from $ip"
done < botnet_ips.txt > block_rules.sh
```

**Почему генерировать, а не применять сразу:** ошибка в данных — и ты заблокируешь свой же SSH. Сгенерированный файл можно проверить глазами и применить осознанно (`sudo bash block_rules.sh`). Про масштаб (`ipset` вместо тысяч правил), rate limiting и `fail2ban` — в [`theory.md`](theory.md).

> **LILITH:** *«847 отдельных правил — медленно; для больших списков есть `ipset`. Но сейчас важнее остановить флуд. Сгенерируй, проверь, применяй.»*

## Проверка «в мире сюжета»

**Алекс:** *«Почему скрипт ГЕНЕРИРУЕТ правила, а не сам вызывает `ufw` на каждый IP?»*

<details>
<summary>Подумай 30 секунд</summary>

Безопасность и контроль. Если в списке окажется твой собственный IP (или строка-мусор превратится в кривое правило), скрипт, применяющий на лету, заблокирует тебя мгновенно и без предупреждения. Сгенерированный файл ты проверяешь глазами перед `sudo bash`, и он повторяем/версионируется.
</details>

**Дмитрий:** *«847 правил iptables — почему это может само стать проблемой?»*

<details>
<summary>Ответ</summary>

Каждый входящий пакет проверяется по списку правил сверху вниз — 847 правил на каждый из 52 000 пакетов/сек = лишняя нагрузка на CPU (частично играет на руку атакующему). Для больших списков используют `ipset` (хеш-таблица, проверка за O(1)) — одно правило на весь набор.
</details>
