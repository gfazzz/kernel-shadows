## 2. `cd` меняет состояние, а не «открывает папку»

В графическом интерфейсе «открыть папку» — это показать окно. В оболочке `cd` **меняет свойство процесса**: тот самый рабочий каталог (CWD) из s01e01. Никакого окна не появляется, зато меняется точка отсчёта для всех последующих относительных путей.

```bash
cd documents        # относительный путь: от того места, где стоишь
cd /etc/nginx       # абсолютный: от корня, работает откуда угодно
cd ..               # к родителю
cd ../../var/log    # цепочка: два уровня вверх, потом вниз
cd                  # без аргумента — домой, эквивалент cd ~
cd -                # в предыдущий каталог (и печатает, куда попал)
```

Про `cd -` стоит знать отдельно: оболочка помнит предыдущий каталог в переменной `OLDPWD`, и `cd -` прыгает туда. Когда правишь конфиг в `/etc/nginx`, а логи смотришь в `/var/log/nginx`, эти прыжки экономят десятки набранных символов.

`cd` — **встроенная команда оболочки**, а не программа. Иначе и быть не могло: внешняя программа поменяла бы каталог у себя и завершилась, не затронув родителя. Проверить: `type cd` скажет `cd is a shell builtin`.

## 3. `cat` и его семья

```bash
cat file                 # весь файл на экран
cat a b > c              # склеить два файла в третий (отсюда и название)
cat -n file              # с номерами строк
less file                # листалка: пробел вперёд, b назад, /текст поиск, q выход
head -n 20 file          # первые 20 строк
tail -n 50 file          # последние 50
tail -f /var/log/syslog  # следить за дописыванием в реальном времени
```

`cat` расшифровывается как *concatenate* — «склеить». Печать файла на экран — частный случай: склеили один файл и вывели в stdout.

**Когда `cat` — плохая идея.** Файл на гигабайт заполнит буфер терминала, а прокрутка вверх упрётся в его ограничение. Для больших файлов `less`; для «посмотреть начало» — `head`; для «что там в конце» — `tail`.

**Антипаттерн `cat file | grep x`.** Работает, но запускает лишний процесс и лишает `grep` знания об имени файла (он не сможет напечатать его в выводе при поиске по нескольким файлам). Правильно: `grep x file`. Это настолько распространённая привычка, что у неё есть имя — *useless use of cat*.

## 4. Чем `less` лучше `more` (и почему это смешно)

Исторически первым был `more` — он показывал файл постранично, но только вперёд. Потом появился `less`, умеющий листать в обе стороны и искать. Отсюда шутка, ставшая мнемоникой: **less is more** — «`less` — это улучшенный `more`».

Полезные клавиши в `less`: `/шаблон` — поиск вперёд, `?шаблон` — назад, `n`/`N` — следующее/предыдущее совпадение, `G` — в конец файла, `g` — в начало, `q` — выход. `man` внутри тоже использует `less`, так что эти клавиши работают и в документации.

## 5. Пути с пробелами и другие ловушки имён

```bash
cd my documents        # ошибка: два аргумента
cd "my documents"      # верно
cd my\ documents       # тоже верно
cat -- -weird-file     # -- прекращает разбор флагов
cat ./-weird-file      # или так: путь, а не флаг
```

Файл с именем `-rf` существует ровно для того, чтобы испортить кому-то день: команда примет его за флаг. Отсюда привычка писать `./` перед именами из недоверенного источника.

## 6. Компромиссы чтения

| Инструмент | Когда | Ограничение |
|---|---|---|
| `cat` | маленькие файлы, склейка, конвейеры | гигабайт вывалит целиком |
| `less` | большие файлы, поиск, чтение глазами | интерактивен, не годится в скрипт |
| `head`/`tail` | заглянуть в начало/конец | не видит середины |
| `tail -f` | следить за живым логом | держит терминал занятым |
| `grep` | найти строку в большом файле | покажет строки, а не контекст (лечится `-A`/`-B`) |

## 7. Метанавык: имя — это гипотеза

Файл `backup_final_2024.tar.gz` не обязан быть бэкапом, финальным и от 2024 года. Имя пишет человек, а человек ошибается, спешит и врёт.

Профессиональная привычка: **проверять содержимое, а не доверять подписи.** `file` скажет реальный тип, `head` покажет первые строки, `tar -tzf` перечислит содержимое архива, не распаковывая. На чужом сервере это не паранойя, а гигиена: файл `.secret_location` в этой серии оказался тем, чем назван, но `.next_server` вполне мог бы содержать приманку.

Дальше в курсе то же самое повторится крупнее: в Season 5 подозрительный бинарник проверяют не по имени, а по контрольной сумме; в Season 3 конфиг, который «точно рабочий», сверяют с тем, что реально прочитала служба.
