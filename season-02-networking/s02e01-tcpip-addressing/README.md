## Теория: IPv4-адрес + модель TCP/IP (один концепт: адрес в сети)

**IP-адрес** — это почтовый адрес устройства. IPv4 = 4 октета (0-255):

```
10.50.1.100
│  │  │  └ хост (конкретный сервер)
│  │  └ подсеть (rack)
│  └ подсеть (ЦОД)
└ сеть (класс A, private)
```

Ключевое различие — **private vs public**:

- `10.x`, `172.16–31.x`, `192.168.x` — **private** (внутренние, не видны из интернета, RFC 1918);
- `127.x` — **loopback** (сам с собой); всё остальное — **public**.

Класс определяется первым октетом (A `<128`, B `<192`, C `<224`). А сам адрес живёт на слое **Internet** модели TCP/IP («конверт в конверте»: Application → Transport → Internet → Link). Диапазоны, CIDR и 4 слоя подробно — в [`theory.md`](theory.md).

> **LILITH:** *«Private IP — твоя квартира, public — офисное здание, видимое всем. Атакующий узнал твой public IP — он знает, где ты. Первое правило обороны: понимать карту адресов.»*

## Проверка «в мире сюжета»

**Анна:** *«`172.16.5.20` и `172.32.5.20` — оба private?»*

<details>
<summary>Подумай 20 секунд</summary>

Нет. Private-диапазон класса B — это только `172.16.0.0`–`172.31.255.255` (`/12`). `172.16.5.20` — private, а `172.32.5.20` — уже **public**. Границу `16–31` легко забыть — и принять чужой публичный адрес за «свой внутренний».
</details>

**Дмитрий:** *«Зачем модель TCP/IP, если можно просто отправить пакет?»*

<details>
<summary>Ответ</summary>

Слои разделяют ответственность: IP отвечает «куда» (адрес), TCP — «как» (надёжность, порты), Link — «физически чем». Когда что-то ломается, ты знаешь, на каком слое искать: нет пинга — слой Internet; порт закрыт — Transport; кабель — Link. Это карта для диагностики (следующие серии).
</details>
