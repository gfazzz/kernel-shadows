## Обстановка

За восемь дней инфраструктура операции переехала из голов и с пятидесяти
машин в один репозиторий. Двадцать седьмая пересобрана из него за
тридцать четыре минуты — и завтра из него же соберутся остальные сорок
девять.

Это значит, что репозиторий стал самой большой поверхностью атаки в
операции. И единственным, кого за эти восемь дней никто не проверял.

## Приказ

Написать `artifacts/iac_audit.sh` — аудит описания, восемь разделов.

```bash
cp starter/iac_audit.sh artifacts/
bash tests/test.sh
```

```
iac_audit.sh --repo /путь [--quiet]
```

## Требования

| Раздел | Что искать | Откуда правило |
|---|---|---|
| `secrets` | значение, похожее на секрет, в отслеживаемом файле | `s04e03` |
| `history` | `.env`, `*.pem`, `id_rsa`, `vault_pass.txt` в любом коммите | `s04e01` |
| `gitignore` | не закрывает секреты — или закрывает `.env.example` | `s04e03` |
| `docker` | база без точной версии, работа от root, ключ в `COPY` | `s04e05` |
| `compose` | `privileged: true`, `docker.sock`, порт вида `N:N`, тег `latest` | `s04e06` |
| `ci` | незакреплённое действие, `\|\| true`, `continue-on-error`, нет `permissions` | `s04e07` |
| `ansible` | пароль в инвентаре, `ansible_user: root`, `StrictHostKeyChecking=no`, пароль vault в репозитории | `s04e09` |
| `perms` | закрытый ключ с правами шире `600` | `s01e15` |

| Требование к самому скрипту | Почему |
|---|---|
| состав берётся из `git ls-files` | предмет — то, что уедет к другим, а не рабочий каталог |
| история проверяется отдельно | удаление файла не отменяет утечку |
| у каждой находки важность (`ВЫСОКАЯ`/`СРЕДНЯЯ`), раздел и путь | иначе находку негде исправлять и нечем приоритизировать |
| файлы `*.example` не считаются находкой, и об этом сказано в итоге | одно ложное срабатывание — и отчёт перестанут читать |
| в итоге — сколько проверено и сколько найдено | «чисто» без объёма ничем не подтверждено |
| код 2, если проверять оказалось нечего | этот случай обязан отличаться от чистого |
| ничего не изменяется в репозитории | аудит, который правит, — уже не аудит |
| `--quiet` оставляет находки и итог | для запуска из конвейера |
| ни одного зашитого пути | `build/Dockerfile` — тоже Dockerfile |
| ни docker, ни ansible не запускаются | проверяется описание, а не машины |

Коды возврата: `0` — находок нет и было что проверять, `1` — есть находки,
`2` — ошибка вызова или нечего проверять.

## Чем добывать

| Что нужно | Как |
|---|---|
| состав репозитория | `git -C "$REPO" ls-files` |
| все пути в истории | `git log --all --pretty=format: --name-only \| sort -u` |
| коммит, где файл был | `git log --all --oneline -1 -- ПУТЬ` |
| закрыт ли путь правилами | `git check-ignore -q ПУТЬ` |
| регулярка для секретов | уже написана в `prepush_check.sh` из `s04e02` |
| убрать комментарии, сохранив номера строк | `sed -e 's/^[[:space:]]*#.*$//' -e 's/[[:space:]]#[^"]*$//'` |
| пропустить двоичные файлы | `grep -Iq . ФАЙЛ` |
| права файла | `ls -l ФАЙЛ \| cut -c1-10` |

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + git + awk + coreutils |
| Сеть | не нужна |
| `docker`, `ansible` | **не нужны** — и не должны вызываться |
| Внешние пакеты | нет |
| Изоляция теста | полигон собирается во временном каталоге из файлов сезона |

Тест строит два настоящих git-репозитория: «чистый» — из эталонов
`s04e03`, `s04e05`, `s04e06`, `s04e07` и `s04e09`, «грязный» — из их
стартеров. Ожидаемых чисел в тесте не зашито: находки берутся из того, что
реально лежит в полигоне. Отдельно проверяются пустой репозиторий, секрет
только в истории, ключ с открытыми правами, пароль vault и раскладка с
другими именами каталогов. `docker`, `ansible` и `curl` подменены
заглушками-ловушками: любой их вызов — провал.

```bash
cd season-04-devops-automation/s04e11-iac-audit

```

Стоит натравить готовый скрипт на собственный репозиторий — не курсовой,
а рабочий. Опыт показывает, что первая находка обычно есть, и обычно она
в истории.

```bash
bash artifacts/iac_audit.sh --repo ~/мой-проект
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| находки в чистом репозитории | проверяются комментарии | убирать комментарии перед разбором |
| «раздел history: 0 находок» | смотрится только рабочее дерево | `git log --all --name-only` |
| ложное срабатывание на `.env.example` | образцы не исключены | пропускать `*.example` и сказать об этом |
| пустой репозиторий даёт 0 | нет проверки объёма | код 2, если `git ls-files` пуст |
| «аудит потерял файлы» | путь зашит | искать по имени, а не по каталогу |
| «скрипт вызвал docker» | попытка проверить образ по-настоящему | предмет — текст, а не машина |
| «после аудита репозиторий изменился» | временные файлы внутри репозитория | работать в `mktemp -d` |
| код 1 при чистом репозитории | `set -e` и `grep` без `\|\| true` | `grep`, ничего не нашедший, возвращает 1 |

## После выполнения

Зелёный тест означает, что описание инфраструктуры теперь проверяет само
себя — восемью правилами, каждое из которых вы за этот сезон видели
сломанным своими глазами.

Стоит запомнить последнюю мысль сезона: **у проверки всегда две цифры —
сколько найдено и сколько просмотрено**. Зелёная галочка конвейера,
`Up (healthy)`, `changed=0` и «находок нет» — четыре разных способа сказать
«я не нашёл проблем», и ни один из них не означает «проблем нет». Разница
каждый раз в том, что именно было в области видимости, и назвать её —
работа автора проверки, а не читателя отчёта.
