## Теория: `xargs` + отчёт (один концепт: пакетно и с отчётом)

**Batch-установка** — список превращается в один вызов `apt` через `xargs`:

```bash
grep -v '^#' tools.txt | awk '{print $1}' | xargs sudo apt install -y
#   убрать комментарии    взять имя         поставить все разом
```

Один `apt install pkg1 pkg2 pkg3` лучше трёх отдельных: зависимости считаются один раз.

**Отчёт** — из тех же one-liner'ов: статус (`dpkg -l | grep '^ii'`), версия (`awk '/^ii/{print $3}'`), счётчики. bash — только цикл по списку и сборка в файл. Флаги `xargs`, cleanup (`autoremove`, `apt clean`) — в [`theory.md`](theory.md).

> **LILITH:** *«apt = инструмент администратора. Не bash-скрипты. Инструмент. Season 1 учил тебя мыслить как админ: используй готовое, автоматизируй разумно.»*

## Проверка «в мире сюжета»

**Виктор:** *«Почему `xargs sudo apt install` лучше, чем `while read p; do apt install $p; done`?»*

<details>
<summary>Подумай 30 секунд</summary>

Цикл вызывает `apt` по разу на пакет: N раз пересчитываются зависимости, N раз трогается база dpkg, N раз обновляется индекс. `xargs` собирает все имена и делает ОДИН `apt install pkg1 pkg2 …`: apt один раз строит план зависимостей — быстрее и целостнее.
</details>

**Виктор:** *«В отчёте по `dpkg -l` пакет показал `rc`. Считать его установленным?»*

<details>
<summary>Ответ</summary>

Нет — `rc` значит «удалён, остались конфиги». Установлен только `ii`. Поэтому в отчёте статус проверяем строго по `^ii`, иначе насчитаешь «готовность», которой нет.
</details>
