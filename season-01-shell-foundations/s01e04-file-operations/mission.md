## Обстановка

Разведданные добыты, но лежат на чужой машине под чужими именами. Доступ к ней
временный: сегодня есть, завтра нет. Работать с этими данными предстоит два месяца.

Нужна своя структура — с понятными именами, журналом и местом под инструменты.
Копировать так, чтобы на «сервере» ничего не изменилось: пропавший файл заметят.

## Приказ

Собрать рабочее пространство `artifacts/workspace/`:

```
workspace/
├── intel/
│   ├── briefing.txt     копия documents/briefing.txt
│   ├── meeting.txt      копия documents/.secret_location
│   └── access.txt       копия .next_server
├── tools/               пока пусто — под инструменты
└── logs/
    └── operation.log    пустой журнал
```

Черновик `tmp_draft.txt`, если создашь его по ходу, — удалить.
Оригиналы на «сервере» должны остаться на месте.

## Данные

| Что нужно | Команда | Замечание |
|---|---|---|
| каталоги | `mkdir -p` | `-p` создаёт всю цепочку и не ругается на существующие |
| копии файлов | `cp источник назначение` | оригинал остаётся; для каталогов нужен `-r` |
| новое имя копии | `cp a b/new_name.txt` | переименование делается прямо при копировании |
| пустой журнал | `touch` | создаёт файл, если его нет |
| удалить черновик | `rm` | без подтверждения и без корзины |
| забыл флаг | `man <команда>` | раздел SYNOPSIS и EXAMPLES |

Скрытые файлы копируются как обычные: точка в имени влияет только на вывод `ls`.

## Критерии приёмки

- [ ] Создан `artifacts/workspace/` с каталогами `intel/`, `tools/`, `logs/`.
- [ ] `intel/briefing.txt` — побайтовая копия `documents/briefing.txt`.
- [ ] `intel/meeting.txt` — копия `documents/.secret_location` (под новым именем).
- [ ] `intel/access.txt` — копия `.next_server`.
- [ ] `logs/operation.log` существует и пуст.
- [ ] `tmp_draft.txt` отсутствует.
- [ ] **Файлы на «сервере» целы** — копирование, а не перенос.
- [ ] `bash tests/test.sh` → 10 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils (Linux / macOS / WSL) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`mkdir`, `cp`, `mv`, `touch`, `rm`, `man`) |
| Изменяется | только `artifacts/` внутри этой серии |

Тест сверяет копии с источником побайтово (`cmp`) и отдельно проверяет, что
источник не пострадал.

## Выполнение

```bash
mkdir -p artifacts/workspace/{intel,tools,logs}
SRV=../data/test_environment
cp "$SRV/documents/briefing.txt" artifacts/workspace/intel/briefing.txt
# ... остальные копии
touch artifacts/workspace/logs/operation.log
bash tests/test.sh
```

Забыл флаг — `man cp`. Не помнишь, какая команда нужна, — `man -k copy`.
LILITH подскажет, но команды выполняешь ты.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `нет каталога intel/` | создан только верхний уровень | `mkdir -p` создаёт цепочку целиком |
| `mkdir: cannot create ...: No such file or directory` | нет родительского каталога | добавить `-p` |
| `содержимое не совпадает с источником` | скопирован не тот файл | сверить путь; `cmp a b` покажет расхождение |
| `нет файла logs/operation.log` | журнал не создан | `touch artifacts/workspace/logs/operation.log` |
| **`на «сервере» пропали файлы`** | использован `mv` вместо `cp` | восстановить: `git checkout -- ../data/`, повторить через `cp` |
| `rm: cannot remove ...: Is a directory` | `rm` без `-r` на каталоге | `rm -r` (сначала посмотреть `ls`, что удаляется) |

## После выполнения

Если тест зелёный — у операции появилась своя территория: данные скопированы,
структура заведена, журнал ждёт первых записей, а «сервер» выглядит нетронутым.
Дальше в `tools/` переедет твой `shadow_toolkit`, а в `logs/` пойдут записи
мониторинга из следующих серий.

Если тест сообщил, что на «сервере» пропали файлы, — это самая дорогая ошибка
серии, и починить её надо сразу: `git checkout -- ../data/`. Разница между `cp`
и `mv` в одну букву, а последствия несимметричны: первая команда обратима,
вторая — нет.
