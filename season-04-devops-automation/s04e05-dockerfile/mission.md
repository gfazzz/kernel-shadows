## Обстановка

Четыре находки из [`s04e04`](../s04e04-images-layers/) — ключ в слое, пароль
в переменных, работа от root и база на гигабайт — все происходят из одного
файла на двенадцать строк. Ни одна из этих строк не является ошибкой: каждая
делает ровно то, что написано.

Задача — написать тот же образ, зная цену каждой строки.

## Приказ

Переписать два файла в `artifacts/`: `Dockerfile` и `dockerignore`
(в репозитории — `.dockerignore`).

```bash
cp starter/Dockerfile starter/dockerignore artifacts/
bash tests/test.sh
```

## Требования

| Что | Почему |
|---|---|
| облегчённая база, версия до patch | 9 уязвимостей вместо 61; сборка через месяц даст то же |
| `COPY requirements` → `RUN pip` → `COPY .` | правка кода не должна пересобирать зависимости |
| `apt-get` с `--no-install-recommends` и `rm -rf /var/lib/apt/lists/*` **в той же инструкции** | иначе кеш остаётся в слое |
| `pip` с `--no-cache-dir` | то же самое |
| ни одного `ENV` с секретом | его печатает `docker inspect` |
| ни одного `COPY` ключа и никаких «скопировали и удалили» | файл остаётся в слое |
| создать пользователя и переключиться на него до `CMD` | контейнеру сборщика root не нужен |
| `CMD` или `ENTRYPOINT` массивом | иначе `docker stop` не останавливает |
| `WORKDIR` задан | относительные пути должны быть определены |
| `.dockerignore` закрывает `.git`, `.env`, ключи | `COPY .` иначе затянет их в образ |

## Чем добывать

| Что нужно | Как |
|---|---|
| создать пользователя | `RUN useradd --system --create-home --uid 10001 имя` |
| владелец при копировании | `COPY --chown=имя:имя . /app` |
| одна инструкция из нескольких команд | `RUN a \` + перенос + `    && b` |
| exec-форма | `CMD ["python", "/app/collector.py"]` |
| проверить на своей машине | `docker build .`, затем `docker history` |

## Критерии приёмки

- [ ] `artifacts/Dockerfile` и `artifacts/dockerignore` созданы на основе `starter/`.
- [ ] База облегчённая, версия задана до patch, тега `latest` нет.
- [ ] Нет `ENV` с паролем, токеном или ключом.
- [ ] В образ не копируются `.env`, `*.pem`, `*.key`, `deploy_key`.
- [ ] Нет пары «скопировали и удалили следующей инструкцией».
- [ ] Порядок: `COPY requirements` → `RUN pip` → `COPY .`.
- [ ] `apt-get` с `--no-install-recommends` и очисткой в той же инструкции (если пакеты вообще ставятся).
- [ ] `pip` с `--no-cache-dir`.
- [ ] Пользователь создан, `USER` не root и стоит до `CMD`.
- [ ] Запуск в exec-форме; `WORKDIR` задан.
- [ ] `.dockerignore` закрывает `.git`, `.env`, `*.pem` и заполнен не менее чем восемью правилами.
- [ ] `bash tests/test.sh` → 20 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| `docker` | **не нужен** — файл проверяется как текст |
| Внешние пакеты | нет |
| Изоляция теста | инструкции разбираются по порядку, с учётом переносов строк: порядок здесь и есть предмет |

Тест дополнительно проверяет, что в стартере остались обе ловушки — секрет
в `ENV` и ключ в `COPY`, — и что зависимости там не выделены отдельным слоем.

## Выполнение

```bash
cd season-04-devops-automation/s04e05-dockerfile
cp starter/Dockerfile starter/dockerignore artifacts/
$EDITOR artifacts/Dockerfile
bash tests/test.sh
```

Если docker есть на твоей машине, стоит увидеть эффект порядка своими глазами:
собрать, поменять строку в коде, собрать снова и сравнить время.

```bash
docker build -t t:1 . && time docker build -t t:2 .
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «полная база на гигабайт» | `FROM python:3.11` | `-slim` и точная версия |
| «версия задана неточно» | нет patch-версии | `3.11.6-slim` |
| «не найдено разделение» | нет отдельного `COPY requirements` | вынести зависимости выше кода |
| «кеш apt не удалён в той же инструкции» | `rm` отдельным `RUN` | объединить через `&&` |
| «пользователь нигде не создан» | есть `USER`, нет `useradd` | контейнер не стартует |
| «USER должен стоять до CMD» | переключились слишком рано или поздно | root ставит → `USER` → `CMD` |
| «запуск строкой» | `CMD python …` | массив: `CMD ["python", "…"]` |
| «в `.dockerignore` не хватает» | пустой файл | `.git`, `.env`, `*.pem` минимум |

## После выполнения

Зелёный тест означает, что тот же образ теперь весит вдвое меньше, не
содержит ключа ни в одном слое и не работает от root — и всё это без единой
правки кода приложения.

Стоит обратить внимание, что ни одна из четырёх исходных строк не была
синтаксически неверной. Ошибки в декларативных языках — не синтаксические,
а **ценовые**: строка делает то, что написано, а платишь ты за это в другом
месте и позже.

## Кумулятивность

Четыре находки, которые здесь закрываются, сделаны в
[`s04e04`](../s04e04-images-layers/). `.dockerignore` — тот же приём, что
`.gitignore` из [`s04e03`](../s04e03-gitignore-secrets/), только для контекста
сборки, и он же не пускает внутрь `.git` со всей историей из
[`s04e01`](../s04e01-git-history/). Работа не от root продолжает
[`s03e05`](../../season-03-system-administration/s03e05-systemd-service/), где
та же задача решалась директивой `User=`, и
[`s01e16`](../../season-01-shell-foundations/s01e16-sudo-basics/), где
выяснялось, что пустое поле пользователя означает root. Разница между
`SIGTERM` и `SIGKILL`, из-за которой нужна exec-форма, — из
[`s03e04`](../../season-03-system-administration/s03e04-processes/).
