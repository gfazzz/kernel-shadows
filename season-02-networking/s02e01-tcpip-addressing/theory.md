## IPv4-адрес

```
   192   .   168   .    1    .   100
  network    subnet   subnet   host
```

- 4 октета (0-255), разделены точками. 32 бита всего.
- Примеры: `10.0.0.42`, `192.168.1.1`, `8.8.8.8`.

## Private (RFC 1918) vs Public

| Диапазон | Класс | Назначение |
|----------|-------|------------|
| `10.0.0.0 – 10.255.255.255` | A | внутренние сети (`/8`) |
| `172.16.0.0 – 172.31.255.255` | B | корпоративные (`/12`) |
| `192.168.0.0 – 192.168.255.255` | C | домашние (`/16`) |
| всё остальное | — | public (виден из интернета) |

Граница `172`: private только `172.16`–`172.31`; `172.32.x` — уже public.

## Спец-адреса

- `127.0.0.1` — loopback («разговор с собой», тест: `ping 127.0.0.1`).
- `255.255.255.255` — broadcast («крик на всю сеть»).
- `0.0.0.0` — «любой адрес» (в конфигах — «слушать на всех интерфейсах»).

## Классы по первому октету

`A` `<128` · `B` `128–191` · `C` `192–223` · `D` `224–239` (multicast) · `E` `240+` (reserved).
Классовая схема историческая; сейчас адресацию задаёт **CIDR** (`10.50.1.0/24` —
префикс `/24` = первые 24 бита сеть, последние 8 — хосты). Подсети и маски — тема дальше.

## Модель TCP/IP (4 слоя) — «конверт в конверте»

Каждый слой добавляет свой заголовок:

```
4. Application  ЧТО?  HTTP, SSH, DNS — твои данные
3. Transport    КАК?  TCP (надёжно) / UDP (быстро); порты 22, 80, 443
2. Internet     КУДА? IP-адреса (source → destination), ICMP; маршрутизация
1. Link         ГДЕ?  Ethernet/Wi-Fi, MAC-адреса, физика
```

Отправка: данные спускаются 4→1, каждый слой «упаковывает» предыдущий в свой конверт.
Приём: разворачивается 1→4. IPv4-адрес живёт на слое Internet (2) — это «адрес на конверте».

## IPv4 vs IPv6

IPv4 — 32 бита (~4.3 млрд адресов, почти исчерпаны). IPv6 — 128 бит
(`2001:db8::1`, практически бесконечно). В курсе работаем с IPv4, IPv6 — по месту.
