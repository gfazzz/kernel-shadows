## Кодекс поведения

Уважительное общение, конструктивная критика, терпимость к разному уровню
подготовки. Личные выпады, дискриминация и травля недопустимы.

Курс учит в том числе безопасности. Материалы наступательного характера
допустимы только в учебной рамке (см. `season-05-security-pentesting/labs/`) и
только со стороны следов и защиты. PR с работающим вредоносным кодом,
инструментами для атак на чужие системы или обходом чужой защиты закрывается
без обсуждения.

## Чем помочь

| Что | Куда |
|---|---|
| **Ошибка в серии** (неверный факт, битая команда, красный тест) | issue с меткой `bug`, приложите вывод теста |
| **Опечатка, стиль, ссылка** | PR сразу, обсуждение не нужно |
| **Новая серия или переработка существующей** | сначала issue с замыслом: концепт, тип, артефакт, чем проверяется |
| **Перевод** | issue: обсуждаем объём до начала, курс большой |
| **Инструменты и CI** | PR с описанием, что именно ломалось без этого |

Для баг-репорта полезно приложить: серию, команду, ожидаемое и фактическое
поведение, вывод `bash tests/test.sh`, версию ОС и bash.

## Устройство серии

Каталог `season-NN-<тема>/sNNeNN-<slug>/`:

```
sNNeNN-slug/
├── README.md      # 180–300 строк: шапка → «Ранее» → сцена (место, время) →
│                  # теория одного концепта → «Проверка» (2–3 <details>) →
│                  # задание → разбор ошибок → развязка → ссылки → навигация
├── mission.md     # 60–160 строк: брифинг-рамка, обстановка, приказ, дано,
│                  # критерии приёмки чек-листом, требования среды,
│                  # диагностика, «после выполнения», кумулятивность
├── theory.md      # 110–200 строк: история вопроса, компромиссы, подводные
│                  # камни, «Спросить у LILITH», «Куда смотреть дальше»
├── starter/       # каркас артефакта — всегда папка
├── solution/      # рабочий эталон, не заглушка
├── data/          # снимки и фикстуры, если нужны
├── tests/test.sh  # воспроизводимый тест
└── artifacts/     # рабочая папка студента (в репозитории — .gitkeep)
```

**Одна серия — один концепт — одна задача.** Если README перевалил за 300
строк, это кандидат на дробление, а не на сокращение шрифта.

### Тип серии обязателен

| Метка | Что делает студент | Что проверяет тест |
|---|---|---|
| `Type A — Automation` | пишет `.sh` | поведение скрипта на фикстуре |
| `Type B — Configuration` | правит конфиг | свойства конфига, идемпотентность |
| `Type C — Investigation` | работает в CLI, отвечает на вопросы | воспроизводимость находки |
| `Type D — Code` | пишет `.py` | поведение программы |

Баланс типов — критерий приёмки **сезона**, а не серии. Сезон, целиком
состоящий из `Type A`, не принимается: курс про Linux, а не про
shell-скриптинг.

### Прогрессивная автономия

Чем дальше по курсу, тем меньше подсказок, и это совмещено с сюжетом:

| Сезоны | Что даёт каркас |
|---|---|
| S1–S3 | полный `starter/`, эталон доступен |
| S4–S5 | каркас, эталон «после попытки» |
| S6–S7 | интерфейсы и ТЗ |
| S8 | только договор вызова: как называется, что на входе, что на выходе |

## Требования к тесту

Тест — не формальность, а то, что делает серию серией. Обязательное:

1. **Зелёный без root, без сети, без живой инфраструктуры.** Всё нужное —
   фикстуры в `data/` или дерево, которое тест строит сам в `mktemp -d`.
2. **Проверяет свойство, а не константу.** `hash(x) == hash(x)` вместо
   `hash == 7572827489583`; «бюджет не превышен» вместо «бюджет равен 87».
3. **Не меняет хост.** Всё создаётся во временном каталоге и убирается в `trap`.
4. **Сообщает, чей код проверяет** — артефакт студента или запасной эталон.
5. **Пропуск по отсутствию окружения — это `SKIP` с объяснением**, а не `PASS`.
6. **Не зависит от утилит, которых нет на части платформ**, либо проверяет их
   наличие (`command -v`).
7. **Сравнивает только `stdout`.** Величины «для глаз» идут в `stderr`, куда
   тест не смотрит.
8. **Воспроизводим:** два прогона подряд и прогон с другой локалью дают тот же
   результат. Ни одна сверяемая величина не находится на уровне шума.
9. **Данные не выродились.** Отдельный раздел проверок: что в фикстуре есть
   что искать, что задача не сводится к чтению одной строки.

Хороший приём для Type A и D: **тест строит стенд сам** (см.
`s08e05`, `s08e06`, `s08e07`). Тогда решение, подогнанное под `data/`, не
проходит — в стенде теста ответы другие.

### Числа в тексте получаются кодом

Любое число, названное в README, должно получаться запуском кода серии. При
написании прозы `expected.txt` (или вывод эталона) открыт рядом, и каждое
число сверяется глазами при вставке, а не после.

## Стандарт текста

**Сцена вместо ярлыка.** Не «## Сцена», а «## Москва, 23:47», и дальше проза.

**Теория отвечает на «почему».** Проверочный вопрос к каждому разделу: что
здесь есть такого, чего студент не получит из `man` за минуту? Нет ответа —
раздел не нужен. Ценность добавляют: история решения, честная цена, таблицы
компромиссов, связки с соседними сериями.

**Связность.** Каждая серия открывается «Ранее» на 2–3 строки и закрывается
развязкой с крючком. Числа и объекты возвращаются между сезонами.

**Русский язык.** Термины на русском там, где есть устоявшийся перевод;
английские — в коде и в именах файлов. Не «сделать deploy», а «выкатить». Не
«зафейлился тест», а «тест красный».

**Эмодзи** — в шапках документов и сезонных README, в сериях их нет.

**Красные промпты.** В конце README — раздел «Как работать с LILITH» с
зелёными вопросами (можно спрашивать) и красными (нельзя, и объяснено почему).
Красный промпт — не запрет ради запрета, а место, где готовый ответ навредит.

## Процесс

```bash
# 1. Форк и ветка от актуальной линии
git checkout v2.0-refactor
git pull
git checkout -b feat/s03e07-journal-priorities

# 2. Работа. Перед коммитом — проверки (ниже)

# 3. Коммит: Conventional Commits, тело на русском
git commit -m "feat(s03e07): приоритеты journald и восстановление хронологии"

# 4. PR в v2.0-refactor с описанием: что меняется и чем проверено
```

**Правила коммитов:**

- один коммит — одно осмысленное изменение;
- префиксы: `feat`, `fix`, `docs`, `test`, `refactor`, `ci`, `chore`;
- область — идентификатор серии (`s03e07`) или подсистема (`ci`, `tools`);
- в теле: что было не так, что стало, чем проверено.

**Ветку для PR заводите от чистой линии.** `git add -A` в грязном дереве
утаскивает в PR чужие решения из `artifacts/` — в CI есть работа
`artifacts-guard`, которая такой PR роняет и печатает команду исправления.

## Проверки перед PR

```bash
make check                    # все тесты + ссылки + инструменты
make test SERIES=s03e07       # одна серия
make test-repeat              # два прогона подряд: детерминизм
make test-locale              # прогон под другой локалью и TZ
make clean-clone              # приёмка на чистом клоне
bash tools/check_links.sh     # битые внутренние ссылки
bash tools/check_tools.sh     # forward-deps по инструментам
shellcheck path/to/*.sh       # если правили bash
```

**Приёмка на чистом клоне обязательна.** Рабочая копия — не репозиторий:
файл, съеденный `.gitignore` или забытый в `git add`, обнаружится только у
того, кто клонирует с нуля.

Если добавили инструмент, которого в курсе не было, `check_tools.sh` об этом
скажет: его нужно либо ввести в серии, либо заменить на уже известный.

## Сюжетный канон

Правки, затрагивающие сюжет, сверяются с ведущими документами:

| Документ | За что отвечает |
|---|---|
| [SCENARIO.md](docs/SCENARIO.md) | хронология операции по дням, кроссовер с MOONLIGHT |
| [CHARACTERS.md](docs/CHARACTERS.md) | биографии, роли, кто что знает и когда |
| [LOCATIONS.md](docs/LOCATIONS.md) | локации и их атмосфера |
| [LILITH.md](docs/LILITH.md) | голос и границы ИИ-наставника |

**Три вещи, которые ломаются чаще всего** и которые стоит проверять руками:

1. **имя персонажа** — один человек, одно имя во всех документах;
2. **дата и время** — сквозная хронология: серия не может кончаться в 03:10 в
   Москве и продолжаться в 04:12 в Петербурге;
3. **числа** — гонорар, сроки, счёт узлов: они называются в нескольких местах.

LILITH задаёт вопросы и объясняет «почему», но **не решает задачу за
студента**. Это техническое требование, а не пожелание: правило записано в
`.cursorrules`, который читает редактор, и в `LILITH.md`.

---

## Документы, которые генерируются

Не правьте руками — они собираются из самих серий:

```bash
bash tools/gen_index.sh          # указатель серий → CURRICULUM.md
bash tools/gen_bibliography.sh   # библиография → RESOURCES.md
```

Если нужно изменить строку в указателе — меняйте шапку серии, а не указатель.
