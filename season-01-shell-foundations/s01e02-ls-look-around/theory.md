# Теория — s01e02

## 1. Точка, которой не должно было быть

> *Второй год в «Сибирь-Телекоме». Клиент жалуется: «сайт сожрал диск». Я захожу, смотрю каталог — сорок мегабайт, всё чисто. Иду к Палычу с докладом: у клиента паранойя.*
>
> *Он не отрывается от своего чая.*
>
> — Ты смотрел `ls`?
> — Ну да.
> — А теперь `ls -A` и посмотри ещё раз.
>
> *Я возвращаюсь. Двенадцать гигабайт в каталоге `.cache`, который обычный `ls` мне вежливо не показал. Точка в начале имени — и файла для меня как будто нет.*
>
> — Почему оно вообще так работает?
> — Случайность. Полвека назад кто-то поленился написать три строки кода. Мы с тобой до сих пор с этим живём.

История с ленью — не фигура речи. Правило точки появилось не как решение о приватности, а как **побочный эффект неаккуратного кода**, и об этом стоит знать: половина «странностей» Unix объясняется не замыслом, а тем, что так однажды получилось и прижилось.

## 2. Откуда взялось правило точки

В ранних Unix в каждом каталоге есть две служебные записи: `.` (он сам) и `..` (родитель). Когда писали `ls`, их надо было как-то скрыть из вывода — иначе они мозолили бы глаза в каждом листинге.

Правильный способ — сравнить имя с `.` и `..` и пропустить ровно эти две записи. Реализованный способ — пропустить всё, что начинается с точки. Три строки кода вместо десяти.

Так у файловой системы, ничего об этом не знающей, появилось «скрытие файлов». Дальше произошло то, что происходит всегда: программы начали этим пользоваться — конфиги стали складывать в `~/.bashrc`, `~/.ssh/`, `~/.config/`, чтобы не захламлять домашний каталог. Случайность превратилась в соглашение, соглашение — в стандарт (XDG Base Directory).

**Вывод, который переживёт эту серию:** скрытость файла — свойство *утилиты*, а не файла. В файловой системе нет флага «скрытый», как в Windows. `ls` просто не печатает такие имена по умолчанию.

## 3. `-a` против `-A`: маленькая разница с последствиями

```console
$ ls
documents
$ ls -a
.  ..  .next_server  documents
$ ls -A
.next_server  documents
```

| Флаг | Что показывает |
|---|---|
| (без флага) | всё, кроме имён на точку |
| `-a` | вообще всё, включая `.` и `..` |
| `-A` | всё скрытое, **кроме** `.` и `..` |

Практическое следствие: любой подсчёт через `ls -a | wc -l` даёт на два больше правды. Ошибка живучая — она не выглядит ошибкой, просто число «немного не такое». Для счёта берут `-A`.

## 4. Длинный формат: паспорт объекта

```console
$ ls -l
total 12
drwxr-xr-x 2 max max 4096 окт  3 09:30 documents
-rw-r--r-- 1 max max  156 окт  3 09:25 notes.txt
```

```
-rw-r--r--   1   max  max   156  окт 3 09:25  notes.txt
│└┬┘└┬┘└┬┘   │    │    │     │        │           └ имя
│ │  │  │    │    │    │     │        └ время изменения
│ │  │  │    │    │    │     └ размер в байтах
│ │  │  │    │    │    └ группа-владелец
│ │  │  │    │    └ владелец
│ │  │  │    └ число жёстких ссылок
│ │  │  └ права для остальных
│ │  └ права для группы
│ └ права владельца
└ тип: '-' файл, 'd' каталог, 'l' симлинк
```

Полезные детали, которые обычно узнают позже, чем стоило бы:

- **`total 12`** — это не число файлов и не сумма их размеров, а объём в блоках, занятый на диске содержимым каталога.
- **Размер каталога** (`4096`) — размер служебной структуры, а не того, что внутри. Каталог с гигабайтом видео покажет те же 4096 байт. Чтобы узнать реальный объём, нужен `du -sh`.
- **Число ссылок** у каталога всегда не меньше двух: сам он и запись `.` внутри него. Каждый вложенный каталог добавляет ещё одну — через свой `..`.

## 5. Порядок вывода: не то, что кажется

`ls` сортирует по алфавиту, но алфавит зависит от локали. В `LC_ALL=C` заглавные идут перед строчными (`Z` раньше `a`), в русской или английской UTF-8-локали — регистр обычно игнорируется. Один и тот же каталог на двух машинах даёт разный порядок строк.

Отсюда правило для скриптов и тестов: **если порядок важен — задай его явно** (`| sort`) и зафиксируй локаль (`LC_ALL=C sort`). В этой серии отчёт требует алфавитного порядка именно поэтому: иначе «правильный» ответ зависел бы от настроек машины.

Ещё пара флагов сортировки, которые пригодятся: `-t` (по времени, свежие сверху), `-S` (по размеру), `-r` (обратный порядок). Связка `ls -lt | head` — первое, что делают, когда ищут «что тут менялось последним».

## 6. Почему `ls` не годится для скриптов

`ls` создан для человека. Его вывод меняется в зависимости от терминала (колонки против одной строки), локали, версии утилиты. Разбирать его в скриптах — классическая ловушка: имя с пробелом или переводом строки ломает всё.

```bash
for f in $(ls); do ...        # сломается на "my file.txt"
for f in *; do ...            # правильно: раскрытие шаблона оболочкой
find . -maxdepth 1 -type f    # правильно для более сложных условий
```

Здесь мы разбираем вывод `ls` руками — глазами, в разведке, и это нормально. Как только результат нужен программе, переходят на `*` или `find`.

## 7. Компромиссы

| Приём | Что даёт | Чем платишь |
|---|---|---|
| `ls` | быстро, читаемо | не видит скрытое, вывод нестабилен |
| `ls -A` | полная картина каталога | только верхний уровень |
| `ls -la` | + права и размеры | много строк, тяжело читать в большом каталоге |
| `find` | рекурсия и условия | многословнее, легко перегрузить систему на больших деревьях |
| `tree -a` | наглядная структура | обычно не установлен по умолчанию |

## 8. Метанавык: «пусто» — это гипотеза

Разведка, которая остановилась на первом взгляде, обычно ошибается в ту сторону, которая удобнее наблюдателю. Пустой каталог, чистый лог, «нет ошибок» — это не факты, а результат конкретного способа смотреть.

Правило простое: прежде чем доложить «ничего нет», спроси себя, **чем именно ты смотрел** и что этот инструмент показывает по умолчанию. `ls` прячет точку. `grep` без `-i` не видит `ERROR`, если искал `error`. `ps` без `-e` показывает только твои процессы. `docker ps` без `-a` — только запущенные контейнеры.

Дальше в курсе это вернётся почти дословно: в S3 — процессы, которых «нет», пока не добавишь флаг; в S5 — файлы, которых «нет», пока не посмотришь с нужными правами.
