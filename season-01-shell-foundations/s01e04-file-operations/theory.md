## 2. Файл — это запись в каталоге

Чтобы понять, почему `mv` одновременно «переместить» и «переименовать», надо знать, как устроено имя файла.

Само содержимое живёт в **inode** — структуре с данными, правами, владельцем и временем. Имени файла в inode нет. Имя — это запись в каталоге: пара «строка → номер inode».

Отсюда всё остальное:

- **Переименование** = замена записи в том же каталоге. Данные не двигаются.
- **Перемещение внутри одной файловой системы** = удаление записи в одном каталоге и создание в другом. Данные снова не двигаются — поэтому `mv` большого файла мгновенен.
- **Перемещение между файловыми системами** (`/home` → флешка) — другое дело: там `mv` вынужден скопировать данные и удалить оригинал, и это уже долго.
- **Жёсткая ссылка** (`ln a b`) — вторая запись на тот же inode. Оба имени равноправны; файл исчезнет, когда исчезнет последняя запись.

`ls -l` показывает число ссылок вторым полем — теперь понятно, что это счётчик имён, ведущих к одному содержимому.

## 3. `cp`: копия и что именно копируется

```bash
cp file.txt copy.txt          # содержимое
cp -r dir/ backup/            # каталог целиком (recursive)
cp -a dir/ backup/            # archive: + права, владелец, время, симлинки
cp -i file.txt existing.txt   # спросить перед перезаписью
cp -u src dst                 # копировать, только если источник новее
```

Обычный `cp` создаёт **новый** файл: у него свой inode, своё время создания, права по умолчанию (с поправкой на `umask`), владелец — ты. Для резервной копии конфига это плохо: `cp sshd_config sshd_config.bak` даст файл с другими правами.

Поэтому у бэкапа конфига правильная форма — `cp -a` или `cp -p`: они сохраняют метаданные. Разница всплывает ровно тогда, когда бэкап понадобится восстановить.

## 4. `rm`: почему нет корзины

`rm` удаляет запись в каталоге и уменьшает счётчик ссылок inode. Когда счётчик доходит до нуля и файл никем не открыт, место помечается свободным. Никакой промежуточной «корзины» в файловой системе нет — она есть только у графических оболочек, и это их собственная выдумка (перемещение в скрытый каталог).

Практические следствия:

- **Восстановление после `rm` — не рутинная операция.** Это либо бэкап, либо снапшот файловой системы, либо криминалистика по сырому диску (и то при условии, что поверх ещё не записали).
- **Файл, открытый процессом, продолжает жить** после `rm`: запись из каталога исчезла, но inode держит открытый дескриптор. Классика: удалили огромный лог, а место не освободилось, потому что его пишет работающий сервис. Лечится перезапуском сервиса (или `truncate -s 0` вместо `rm`).

Приёмы, снижающие цену ошибки:

```bash
ls   *.bak      # сначала посмотреть, ЧТО попадёт под шаблон
rm   *.bak      # потом то же самое, но rm
rm -i *.bak     # либо с подтверждением
```

Про `alias rm='rm -i'` мнения расходятся: он выручает новичка, но вырабатывает опасную привычку — на чужой машине алиаса нет, а рука уже приучена «жать Enter не глядя».

## 5. `man`: почему справка надёжнее поисковика

`man` показывает документацию **той версии, которая установлена у тебя**. Ответ в интернете — про какую-то версию, на каком-то дистрибутиве, возможно, пятилетней давности. Для флагов это решает: `ls --time-style`, `sed -i` и половина опций `find` различаются между GNU и BSD (macOS).

```bash
man cp             # раздел 1 по умолчанию — команды
man 5 crontab      # раздел 5 — форматы файлов
man 8 mount        # раздел 8 — команды администратора
man -k copy        # поиск по описаниям (он же apropos)
man -f cp          # какие разделы есть для этого имени (он же whatis)
```

| Раздел | Что там |
|---|---|
| 1 | пользовательские команды |
| 2 | системные вызовы (интерфейс ядра) |
| 3 | функции библиотек (C) |
| 5 | форматы файлов и конфигов |
| 7 | разное: соглашения, `man 7 hier`, `man 7 regex` |
| 8 | команды системного администратора |

Разделы 2 и 3 — это уже про C: `man 2 open` описывает системный вызов, которым пользуется всё, что открывает файлы. Именно там курс по Linux встречается с сестринским курсом по C.

Читать страницу целиком незачем: `SYNOPSIS` даёт форму команды, `EXAMPLES` (если есть) — рабочие примеры, `SEE ALSO` — куда смотреть дальше. Внутри работает `less`: `/шаблон` ищет, `q` выходит.

## 6. Компромиссы

| Приём | Что даёт | Чем платишь |
|---|---|---|
| `cp` | оригинал цел, ошибка обратима | занимает место, копии расходятся со временем |
| `mv` | мгновенно, без дублей | необратимо; на чужом сервере — порча данных |
| `rm` | освобождает место | без корзины; восстановление — из бэкапа |
| `rm -i` | защита от опечатки | привычка «жать Enter не глядя» |
| `mkdir -p` | не падает, создаёт цепочку | молча создаст и опечатку в имени |

## 7. Метанавык: разделять своё и чужое

Правило, которое старше Linux: **на чужой территории — только копии.** Читать можно, копировать можно, изменять и уносить — нет.

За этим стоит не только вежливость. Пропавший файл — это заметное событие: его хватятся, по логам найдут время, по времени — сессию. Скопированный файл не оставляет следа в структуре, только в логах доступа (если они ведутся).

Дальше в курсе тот же принцип станет техническим требованием: тесты серий не трогают живой хост и работают на фикстурах (правило курса); Ansible применяет изменения через `--check` перед боевым прогоном; форензика в Season 5 начинается с того, что образ диска **копируют** и исследуют копию — потому что исследование оригинала его изменяет.
