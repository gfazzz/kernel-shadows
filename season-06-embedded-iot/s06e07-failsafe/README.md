## I. Ноль, который означает «продолжай»

Ли Вэй выводит на экран параметры вчерашнего аппарата.

```
FS_GCS_ENABLE,0
FS_THR_ENABLE,1
BATT_LOW_VOLT,14.0
BATT_CRT_VOLT,14.5
RTL_ALT,60
```

> — Найди здесь три способа потерять дрон.

Макс смотрит.

> — Первый: отказ по связи выключен.

> — Верно. Ноль здесь не «нет реакции». Ноль — это «продолжать делать то, что делал». Аппарат теряет станцию и невозмутимо летит по последней команде. Дальше.

> — Пороги батареи... критический выше низкого?

> — И значит, критический сработает первым. Ты задумал: сначала мягко — возвращайся, потом жёстко — садись. А получил: сразу садись, где бы ты ни был. Мягкой реакции не будет никогда, потому что до неё дело не дойдёт. Третье?

Макс молчит.

> — `RTL_ALT` в **сантиметрах**. Шестьдесят сантиметров. При возврате аппарат снизится до полуметра и пойдёт домой, подстригая кусты. Ты хотел шестьдесят метров — надо было написать шесть тысяч.

Он закрывает экран.

> — Ни одна из трёх ошибок не даёт ошибки при загрузке. Автопилот принял всё. Файл выглядит правильным. Он и есть правильный — синтаксически.

> **LILITH:** *«Параметр отказоустойчивости — это ответ на вопрос, который задаётся, когда спросить уже некого. Проверить ответ можно только заранее, и проверять надо не значения по отдельности, а связи между ними: порог против порога, потолок против высоты возврата, радиус против маршрута.»*

## II. Теория: чем аппарат отвечает на отказ

### Четыре отказа и реакция на каждый

| Отказ | Параметр | Разумная реакция |
|---|---|---|
| пропал сигнал пульта | `FS_THR_ENABLE` | вернуться домой |
| пропала наземная станция | `FS_GCS_ENABLE` | вернуться домой |
| развалилась оценка положения | `FS_EKF_ACTION` | сесть на месте |
| села батарея | `BATT_FS_LOW_ACT` / `BATT_FS_CRT_ACT` | вернуться → сесть |

Логика реакции не произвольна. При потере связи аппарат исправен и знает, где находится, — можно лететь домой. При развале оценки положения он **не знает, где находится**, и «домой» для него — случайное направление; садиться на месте безопаснее. Это тот же принцип, что `nofail` в [`s06e04`](../s06e04-readonly-root/): реакция должна соответствовать тому, что ещё работает.

`0` в любом из этих параметров означает не «не реагировать», а «продолжать выполнение». Разница важна: не реагировать — значит зависнуть; продолжать — значит улететь по последней команде.

### Два порога батареи

```
16.8 В  полный заряд
14.0 В  BATT_LOW_VOLT  → BATT_FS_LOW_ACT = 2 (возврат домой)
13.4 В  BATT_CRT_VOLT  → BATT_FS_CRT_ACT = 1 (посадка на месте)
13.2 В  физический низ: 4 банки × 3.3 В
```

Смысл двух порогов — дать аппарату шанс вернуться, прежде чем сажать его где придётся. Отсюда два жёстких требования:

- **критический строго ниже низкого**, иначе мягкая реакция никогда не наступит;
- **низкий выше физического низа**, иначе предупреждение придёт, когда банки уже сели.

Это связь между параметрами, а не свойство каждого. По отдельности `14.0` и `14.5` — совершенно нормальные напряжения.

### Геозона: битовая маска

```
FENCE_TYPE = 1 (потолок) │ 2 (радиус) │ 4 (многоугольник)
FENCE_TYPE = 3           → потолок + радиус
```

Значение — не выбор из списка, а **сумма битов**. `FENCE_TYPE=2` ограничивает радиус и оставляет открытым верх; `FENCE_TYPE=1` — наоборот. Ошибка здесь выглядит как обычное число и не вызывает подозрений.

### Связи, из-за которых ломается всё остальное

```
маршрут 780 м  <  FENCE_RADIUS 1500 м        ← иначе штатный полёт срабатывает
препятствие 45 м < RTL_ALT 60 м < FENCE_ALT_MAX 110 м < регламент 120 м
```

Три величины в одной цепочке. Если `RTL_ALT` выше потолка геозоны — возврат сам нарушает геозону, и аппарат попадает в петлю: срабатывает геозона → начинается возврат → возврат поднимает выше потолка → снова срабатывает геозона. Если `RTL_ALT` ниже препятствия — возврат приведёт в вышку связи.

**Каждое значение по отдельности допустимо. Неверна их комбинация.**

### Единицы измерения

| Параметр | Единицы |
|---|---|
| `RTL_ALT`, `RTL_ALT_FINAL` | сантиметры |
| `FENCE_ALT_MAX`, `FENCE_RADIUS` | метры |
| `BATT_*_VOLT` | вольты |
| `FS_THR_VALUE` | единицы PWM |
| `LAND_SPEED` | см/с |

Единого правила нет — они складывались годами. Держать их в голове нельзя; смотреть в справочник обязательно. `RTL_ALT=60` и `RTL_ALT=6000` одинаково валидны и отличаются в сто раз.

Про `FS_OPTIONS`, отказ по GPS, поведение при нескольких одновременных отказах, `SITL` и рекомендованные значения — в [`theory.md`](theory.md).

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«Почему при потере связи — домой, а при развале оценки положения — сесть на месте? Разве домой не безопаснее?»*

<details>
<summary>Подумай 30 секунд</summary>

Домой безопаснее только если аппарат знает, где он и где дом. При потере связи навигация исправна: координаты есть, курс есть, маршрут возврата вычислим. Лететь домой — правильно.

При развале оценки положения аппарат **потерял представление о своём местоположении**. Команда «лети домой» превращается в «лети в направлении, которое я считаю домом», а считает он неверно — иначе оценка бы не развалилась. Возврат в таком состоянии — это полёт в случайную сторону на полной скорости.

Общее правило: **реакция на отказ должна опираться только на то, что ещё работает.** Оно же стоит за `nofail` в [`s06e04`](../s06e04-readonly-root/) (поднимаемся без раздела данных, раз данных нет) и за выбором «сесть, а не вернуться» здесь. Реакция, которая требует исправности отказавшей подсистемы, — не реакция, а вторая авария.
</details>

**LILITH:** *«Все параметры в допустимых диапазонах, автопилот их принял. Что ещё проверять?»*

<details>
<summary>Ответ</summary>

Связи между ними. Диапазон проверяет каждое значение в одиночку, а ломаются комбинации:

- `BATT_CRT_VOLT` 14.5 и `BATT_LOW_VOLT` 14.0 — оба корректных напряжения, вместе отменяют мягкую реакцию;
- `RTL_ALT` 6000 см и `FENCE_ALT_MAX` 50 м — оба в диапазоне, вместе дают петлю срабатываний;
- `FENCE_RADIUS` 500 м и маршрут на 780 м — оба разумны, вместе означают, что штатный полёт постоянно нарушает геозону.

Ни одну из этих ошибок нельзя увидеть, глядя на одну строку. Нужна проверка, которая знает **отношения**: этот порог ниже того, эта высота между этими двумя, этот радиус больше того маршрута.

Это общая черта всех конфигураций из настоящей эксплуатации: `sshd_config`, где `PermitRootLogin` осмыслен только вместе с настройкой ключей; `fstab`, где сумма размеров `tmpfs` должна помещаться в память ([`s06e04`](../s06e04-readonly-root/)); `mosquitto.conf`, где ACL имеет смысл только вместе с аутентификацией. **Валидатор, проверяющий поля по одному, пропускает именно те ошибки, ради которых его писали.**
</details>

## IV. Задание: `failsafe.params`

Артефакт — `artifacts/failsafe.params`, 18 параметров.

```bash
cp starter/failsafe.params artifacts/
bash tests/test.sh
```

| Блок | Требование |
|---|---|
| отказы | пульт, станция, оценка положения, геозона — все включены |
| порог газа | ниже минимума канала из `data/rc_calibration.txt` |
| батарея | критический строго ниже низкого; низкий не ниже банок × `cell_min_volt` |
| реакции | низкий заряд → возврат (2), критический → посадка (1) |
| геозона | маска с битами потолка и радиуса; радиус больше маршрута с запасом |
| высоты | препятствие < `RTL_ALT` < `FENCE_ALT_MAX` ≤ регламент |
| возврат | `RTL_ALT_FINAL=0` — садиться, а не висеть |
| набор | все обязательные параметры, ни одного неизвестного |

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Список обязательных параметров, единицы и диапазоны — в `data/param_reference.txt`.

Физический низ батареи: `battery_cells × cell_min_volt` из `data/airframe.txt`.

Радиус маршрута, регламентный потолок и высота препятствия — в `data/site_limits.txt`.

`RTL_ALT` в сантиметрах, `FENCE_ALT_MAX` в метрах — сравнивать после перевода.

`FENCE_TYPE` — сумма битов, а не номер варианта.

Эталон — в `solution/`, там у каждого параметра написано, что он предотвращает.
</details>

### Три ошибки, которые здесь делают

**Оставить ноль в параметре отказа.** Это не «без реакции», а «продолжать полёт» — аппарат уходит по последней команде.

**Перепутать порядок порогов батареи.** Критический выше низкого отменяет возврат: аппарат сядет там, где застало.

**Написать `RTL_ALT` в метрах.** Число примется, файл загрузится, и возврат пойдёт на высоте полуметра.
