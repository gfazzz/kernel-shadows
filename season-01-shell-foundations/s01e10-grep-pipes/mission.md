## Обстановка

Ночью сервер Виктора принял поток запросов, среди которых были следы того, кто
искал вход, пока все смотрели на график нагрузки. Журнал доступа за сутки —
больше четырёх тысяч строк.

Читать это глазами невозможно и не нужно. Нормальный запрос отвечает статусом
`200`; всё остальное — `401`, `403`, `404`, `5xx` — заслуживает счёта.

## Приказ

Провести разбор журнала и **сдать отчёт** — заполненный
`artifacts/attack_report.txt`. Не инструмент, а числа: сколько всего запросов,
сколько ненормальных, каких именно статусов, сколько попыток инъекции, сколько
запросов пришло от сканера и сколько уложилось в минуту пика.

```bash
cp starter/attack_report.txt artifacts/attack_report.txt
# заполнять, добывая каждое число командами
bash tests/test.sh
```

## Объект разбора

| Файл | Что это |
|---|---|
| [`data/access.log`](../data/access.log) | журнал доступа за 4 октября, 4400 строк |

Формат строки — Apache Combined:

```
IP - - [дата] "МЕТОД /путь HTTP/1.1" статус размер "referer" "user-agent"
```

Статус стоит **сразу после закрывающей кавычки** запроса, за ним — размер ответа.

## Чем добывать

| Что нужно | Как |
|---|---|
| всего строк | `wc -l < "$L"` |
| по статусу | `grep -c '" 404 ' "$L"` — с кавычкой, иначе поймается размер |
| всё, кроме статуса | `grep -vc '" 200 ' "$L"` |
| по подстроке | `grep -c 'UNION SELECT' "$L"` |
| по времени | `grep -c '04/Oct/2025:03:47' "$L"` |
| посмотреть глазами | `grep '" 403 ' "$L" \| head -5` — перед тем как верить числу |

## Критерии приёмки

- [ ] `artifacts/attack_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Общее число запросов совпадает с числом строк журнала.
- [ ] Успешные и подозрительные в сумме дают общее число.
- [ ] Счётчики статусов посчитаны с привязкой к кавычке: `404` — 806, а не 807.
- [ ] Найдены попытки SQL-инъекции и запросы от инструмента, назвавшегося сканером.
- [ ] Посчитаны запросы в минуту пика `04/Oct/2025:03:47`.
- [ ] `bash tests/test.sh` → 15 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + grep + coreutils |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`grep`, `wc`) |
| Изоляция теста | эталон вычисляется из того же `data/access.log`, констант в тесте нет |

Тест дополнительно проверяет, что ловушка в данных на месте: наивный шаблон
без кавычки завышает `404` и `500` ровно на единицу.

## Выполнение

```bash
cd season-01-shell-foundations/s01e10-grep-pipes
cp starter/attack_report.txt artifacts/attack_report.txt
L=../data/access.log
wc -l < "$L"
grep -c '" 200 ' "$L"
bash tests/test.sh
```

Перед тем как записать число — посмотри строки, которые его дали:
`grep '" 403 ' "$L" | head -5`. Пять секунд, которые один раз уберегут от
отчёта, где всё сходится, кроме сути.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `404` = 807 вместо 806 | шаблон без кавычки ловит размер ответа | `grep -c '" 404 '` |
| сумма не сходится с общим числом | часть строк посчитана дважды | проверить, что фильтры не пересекаются |
| `grep -c` вернул 0 и ненулевой код | совпадений нет | это ответ, а не ошибка; записать 0 |
| в конвейере с `set -e` всё оборвалось | `grep` без совпадений завершает цепочку | `\|\| true` либо убрать `-e` |
| число запросов за минуту слишком велико | шаблон захватил соседние минуты | указывать время целиком: `03:47` с датой |
| тест «значение не заполнено» | потерян `=` или переименован ключ | брать шаблон из `starter/` без правок |

## После выполнения

Зелёный тест означает, что четыре тысячи строк превратились в одиннадцать чисел,
и эти числа можно показать человеку, который журнал не открывал.

Анне этого не хватит: ей нужны не количества, а **адреса** — кто именно стучался
и как часто. Для этого строку надо разложить на поля и посчитать повторы, а `grep`
работает со строкой целиком. Инструмент, который видит в строке колонки, — в
следующей серии.
