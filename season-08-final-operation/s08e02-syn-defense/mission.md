## Обстановка

Разбор [`s08e01`](../s08e01-first-wave/) закончен: исчерпана очередь
полуоткрытых соединений, полоса свободна, адреса источников подделаны.

В канале лежит найденная статья с девятью строками `sysctl`. Один параметр из
девяти удалён из ядра четыре версии назад, один вредный, два бессмысленных.
Проверить это можно, не выходя из терминала: список ключей, существующих в
этом ядре, лежит в `data/`.

Узел работает. Правки применяются на живой системе, к которой у тебя есть
доступ только по SSH.

## Приказ

Написать два файла в `artifacts/`:

- **`99-syn-defense.conf`** — параметры стека, каждый с причиной;
- **`syn-defense.nft`** — набор правил фильтра, где порядок значит не меньше
  содержания.

```bash
cp starter/99-syn-defense.conf starter/syn-defense.nft artifacts/
$EDITOR artifacts/99-syn-defense.conf artifacts/syn-defense.nft
bash tests/test.sh
```

## Дано

| Файл в `data/` | Что в нём |

## Что решить

| Вопрос | Где ответ |
|---|---|
| включать syn-cookies всегда или по переполнению | `man 7 tcp`, разница между `1` и `2` |
| какой размер очередей | обычный темп новых соединений в `conn_baseline.txt` |
| сколько повторов SYN+ACK | сколько секунд держать запись о том, кого нет |
| какой предел на источник | поведение обычного клиента: перцентиль и максимум |
| что оставить открытым | `services.txt` и `mgmt_net.txt` |
| в каком порядке | что проверяется для каждого пакета, а что для немногих |

Тест сверяет **свойства**, а не значения: любой набор, следующий из
наблюдений, проходит. Единственное значение, заданное однозначно, —
`tcp_syncookies`, и однозначно оно потому, что двух правильных вариантов там
нет.

## Критерии приёмки

- [ ] Все параметры существуют в этом ядре (проверено по `available_sysctl.txt`).
- [ ] Каждый параметр снабжён комментарием, из которого видна причина.
- [ ] Очереди больше прежних и не ниже наблюдаемого темпа новых соединений.
- [ ] `somaxconn` не меньше очереди полуоткрытых: узкое место не переезжает.
- [ ] `tcp_abort_on_overflow` выставлен сознательно, а не забыт.
- [ ] Входная цепочка и пересылка — политика `drop`.
- [ ] Установленные соединения принимаются **до** ограничителя темпа.
- [ ] Доступ дежурной смены — **выше** ограничителя темпа.
- [ ] Ограничитель считает на источник, применяется к SYN и разрешает всплеск.
- [ ] Предел выведен из наблюдений, а не назначен.
- [ ] У динамического множества есть `timeout` и `size`.
- [ ] Списка блокировки по адресам источников нет.
- [ ] `bash tests/test.sh` → 41 passed, 0 failed.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «ядро не знает таких параметров» | ключ из статьи для старого ядра | сверить с `available_sysctl.txt` |
| «параметров без комментария» | значения скопированы | написать, откуда взялось число |
| `somaxconn` ниже очереди | правили только одну очередь | узкое место переехало на шаг |
| «ограничитель выше established» | правила писались по порядку мысли | сначала дешёвое и частое |
| «доступ дежурного ниже ограничителя» | про SSH вспомнили последним | правило управляющей сети выше |
| «предел общий» | `limit rate` без `ip saddr` | считать на источник |
| «множество без size» | взят пример из вики | под подделкой адресов это утечка |
| «списка блокировки» | адреса из `s08e01` попали в правила | они подделаны |
| порт 443 закрыт | политика `drop` и забытое правило | узел перестал делать то, ради чего стоит |

## После выполнения

Зелёный тест означает, что защита следует из измерений этого узла, а не из
статьи про какой-то сервер вообще, и что при её применении ты не отрезал себя
от машины.

Главное, что стоит унести: **чужая конфигурация — это ответ на чужой вопрос.**
Совпадение вопросов проверяется, а не предполагается. Половина параметров в
популярных подборках относится к ядрам, которых больше нет, и молча не
применяется.

И второе: **у аварийного режима есть цена, и она оправдана только в аварии.**
`tcp_syncookies=2` выглядит как «то же самое, но надёжнее», а означает потерю
опций TCP у всех соединений навсегда.

## Кумулятивность

Default-deny и правило «сначала разреши себе доступ, потом закрывай» —
из [`s02e06`](../../season-02-networking/s02e06-firewall-ufw/) и
[`s05e11`](../../season-05-security-pentesting/s05e11-hardening/). Здесь то же
правило действует под нагрузкой, где цена ошибки — выезд на площадку.

«Параметр без измерения — суеверие» — прямое продолжение
[`s07e10`](../../season-07-production-advanced/s07e10-tuning/). Отличие в том,
что там измеряли задержку в спокойной системе, а здесь — очередь под атакой,
и замер «до и после» лежит в `data/after_apply.txt`.

Очередь принятия и `somaxconn` разбирались в
[`s07e08`](../../season-07-production-advanced/s07e08-bottleneck/): узкое место,
которое переезжает, если расширить только одну очередь из двух.

Подделка адресов и бесполезность списка блокировки — находка
[`s08e01`](../s08e01-first-wave/); здесь она превращается в требование к
конфигурации.

Атака, которая на узле не лечится, приходит в `s08e03`: одиннадцать гигабит и
пакеты по полторы тысячи байт — это уже не про очередь.
