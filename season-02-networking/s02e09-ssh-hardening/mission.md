## Обстановка

Команда перешла на ключи, но на серверах ничего не изменилось: парольный вход
разрешён, root пускают напрямую. В журналах — четыре тысячи неудачных попыток
входа под root за сутки, и это только по одной машине.

Пока сервер предлагает парольную аутентификацию, перебор имеет смысл. После её
отключения он теряет смысл целиком — метод просто не предлагается.

## Приказ

Собрать `sshd_harden_check.sh` — аудит конфигурации SSH-сервера по ключевым
директивам, с учётом только активных строк:

```
=== Аудит закалки sshd_config: /etc/ssh/sshd_config ===
  ⚠️ PermitRootLogin = yes — root-логин должен быть запрещён
  ⚠️ PasswordAuthentication = yes — парольный вход выключить, оставить только ключи
  ⚠️ PermitEmptyPasswords = <не задано> — пустые пароли недопустимы
  ✓ X11Forwarding = no (ок)
---
Проблем: 3
```

Использование: `./sshd_harden_check.sh SSHD_CONFIG`. Аудит только читает файл и
ничего не меняет.

## Данные

| Что | Как |
|---|---|
| конфигурация | `"${1:?…}"`, проверить `[ -f … ]` |
| активное значение | `grep -iE "^[[:space:]]*ДИРЕКТИВА[[:space:]]"` + `grep -vE '^[[:space:]]*#'` |
| само значение | `awk '{print $2}'` |
| проверяемые директивы | `PermitRootLogin`, `PasswordAuthentication`, `PermitEmptyPasswords`, `X11Forwarding` |
| безопасное значение | ровно `no` (сравнение без учёта регистра) |
| не задано | тоже проблема — действует умолчание, а оно менялось между версиями |
| тревога | `ALERT` в stderr при `issues > 0` |

Директивы `sshd_config` нечувствительны к регистру и допускают отступ в начале
строки — и то и другое встречается в реальных файлах.

## Критерии приёмки

- [ ] `artifacts/sshd_harden_check.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Небезопасное значение директивы помечается проблемой.
- [ ] Закомментированная строка активным значением **не** считается.
- [ ] Директива, записанная в другом регистре (`permitrootlogin`), распознаётся.
- [ ] Отступ перед директивой не мешает её найти.
- [ ] Отсутствующая директива помечается как «не задано» и считается проблемой.
- [ ] `prohibit-password` у `PermitRootLogin` не принимается за `no`.
- [ ] Полностью закалённая конфигурация даёт ровно `0` проблем.
- [ ] Счётчик проблем согласован с числом предупреждений.
- [ ] При `N > 0` выдаётся `ALERT` в stderr.
- [ ] Отсутствующий файл → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 14 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен для аудита (нужен, чтобы применить изменения) |
| ОС | любая с bash |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны (перезапуск службы — Season 3) |
| Внешние пакеты | нет |
| Изоляция теста | фикстуры-конфигурации во временном каталоге |

Фикстуры: небезопасная конфигурация с закомментированной строкой рядом с
активной, вариант с отступами и другим регистром, вариант с
`prohibit-password` и полностью закалённая конфигурация.

## Выполнение

```bash
cp starter/sshd_harden_check.sh artifacts/sshd_harden_check.sh
# заменить TODO
bash artifacts/sshd_harden_check.sh /etc/ssh/sshd_config
bash tests/test.sh
```

На реальном сервере сравни результат с тем, что скажет сама программа:

```bash
sudo sshd -T | grep -iE 'permitrootlogin|passwordauthentication'
```

Расхождение между файлом и `sshd -T` объясняется `Include`, блоками `Match` или
правилом «побеждает первое вхождение» — разобрано в [`theory.md`](theory.md).

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| закомментированная строка засчитана | нет исключения комментариев | `grep -vE '^[[:space:]]*#'` |
| директива не найдена при отступе | якорь без пробелов | `^[[:space:]]*` в шаблоне |
| `permitrootlogin` не распознан | учитывается регистр | `grep -i` |
| `prohibit-password` принят за безопасное | проверка «не yes» | сравнивать ровно с `no` |
| отсутствующая директива не помечена | пустое значение считается ок | пустое → «не задано» и проблема |
| аудит расходится с поведением сервера | `Include` / `Match` / первое вхождение | сверять с `sshd -T` |

## После выполнения

Зелёный тест закрывает Episode 08 и Season 2. На реальных конфигурациях аудит
найдёт шестнадцать незакалённых серверов из тридцати четырёх и четыре с
`prohibit-password` — формально не ошибка, но не то, о чём договаривались.

Правки применяются с проверкой синтаксиса (`sshd -t`), перезагрузкой службы и
обязательной второй открытой сессией: уже установленные соединения при `reload`
не рвутся, и это единственный путь назад, если новая конфигурация не пускает.
