## sed — потоковый редактор

```bash
sed 's/pattern/replacement/'  file    # заменить ПЕРВОЕ вхождение в строке
sed 's/pattern/replacement/g' file    # заменить ВСЕ (g = global)
sed 's/error/ERROR/gi' file           # + i = игнор регистра
```

`sed` пишет результат в stdout — **файл не меняется** (если не `-i`).

**Удаление строк:**

```bash
sed '/test/d' file      # удалить строки, содержащие test
sed '/^$/d' file        # удалить пустые строки
sed '1,10d' file        # удалить строки 1-10
```

**In-place (осторожно!):**

```bash
sed -i 's/old/new/g' file        # изменить файл на месте
sed -i.bak 's/old/new/g' file    # + backup file.bak
```

**Практика для логов:**

```bash
# вычистить квадратные скобки из [04/Oct/2025:03:47:23]
awk '{print $4}' access.log | sed 's/[][]//g'

# убрать весь таймстамп в скобках
sed 's/\[.*\]//g' access.log

# анонимизировать последний октет IP (сложно — обычно берут спец-инструменты)
sed -E 's/([0-9]{1,3}\.){3}[0-9]{1,3}/\1XXX/' access.log
```

> `[][]` в классе символов означает «символ `]` или `[`»: первый `]` сразу после
> `[` трактуется как литерал. Так одним `s/[][]//g` убираем обе скобки.

## Подход Type B (важно для этого капстоуна)

Курс различает две педагогические метки:

- **Type A — Bash Automation:** результат серии — скрипт-оркестратор (как `server_monitor.sh`).
- **Type B — Linux Configuration/Tools:** акцент на готовых инструментах; bash — только клей.

`log_analyzer.sh` — эталон **Type B**: 70% работы делают `grep/awk/sort/uniq/sed`
в виде ONE-LINERS, а bash лишь собирает их вывод в отчёт. Единственный цикл — сверка
с базой угроз. Это и есть образ мышления Linux-администратора: не писать 200 строк
bash там, где хватает пяти команд в конвейере.
