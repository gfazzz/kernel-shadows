## Обстановка

Восемь закреплений найдены, вопрос «когда» открыт. Журналов пять, форматов
времени четыре, и три из них неполны: syslog не знает года, журнал ядра
считает от загрузки, местное время не знает своего смещения.

Недостающее снято вместе с журналами и лежит в `sources.conf`.

## Приказ

Написать `artifacts/timeline.py`: свести пять журналов к одной оси и
напечатать хронологию.

```bash
cp starter/timeline.py artifacts/
python3 artifacts/timeline.py data data/sources.conf
bash tests/test.sh
```

## Договор

```
timeline.py <каталог-журналов> <sources.conf>

EVENT <epoch> <источник> <хост> <текст>
SUMMARY first=<epoch> last=<epoch> events=<n> sources=<k>

код возврата: 0 — разобрано, 2 — вход не разобран
```

Имена источников: `auth`, `nginx`, `audit`, `k8s`, `firewall`. Порядок — по
времени; при совпадении меток порядок обязан быть определён чем-то ещё,
иначе вывод начнёт зависеть от порядка чтения файлов.

## Дано

| Файл в `data/` | Формат времени |
|---|---|
| `auth.log` | `Nov 22 14:32:21` — местное, года нет |
| `nginx_access.log` | `[22/Nov/2025:14:43:18 +0100]` — смещение в строке |
| `audit.log` | `msg=audit(1763819511.601:266)` — эпоха UTC |
| `k8s_events.log` | `2025-11-22T14:19:18Z` — RFC 3339, UTC |
| `firewall.log` | `[ 88194.277]` — секунды с загрузки узла |
| `sources.conf` | `year`, `boot_epoch`, `tz` и список источников |

## Что здесь легко пропустить

**Год, момент загрузки и смещение берутся из конфигурации.** Не из системных
часов машины, где запущена программа. Тест меняет каждое из трёх и
проверяет, что вывод сдвинулся ровно на предсказанную величину: 365 суток,
1000 секунд, −3600 секунд.

**Знак смещения.** `+01:00` — часы впереди UTC, значит смещение вычитается.
Ошибка даёт сдвиг на два часа и правдоподобную неверную хронологию.

**`calendar.timegm`, а не `time.mktime`.** Вторая трактует набор как местное
время машины и делает результат зависимым от того, у кого считали.

**Строки в журналах перемешаны.** Полагаться на то, что файл отсортирован,
нельзя.

**Тест не проверяет `data/`.** Он порождает свои журналы из событий с
известным временем и сравнивает вывод с истиной побайтово.

## Критерии приёмки

- [ ] Договор вызова соблюдён, неверный вход даёт код 2 без трассировки.
- [ ] Все пять форматов разобраны, ни одно событие не потеряно и не задвоено.
- [ ] Хронология отсортирована, порядок при совпадении меток определён.
- [ ] Итоговая строка совпадает с содержимым хронологии.
- [ ] Год, момент загрузки и смещение читаются из конфигурации.
- [ ] Смещение применяется в верную сторону.
- [ ] Два прогона и два разных набора журналов — совпадение с истиной.
- [ ] `stdout` — только отчёт; диагностика в `stderr`.
- [ ] `bash tests/test.sh` → 25 passed, 0 failed.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| все события сдвинуты на 2 часа | знак смещения | вычитать, а не прибавлять |
| syslog уехал на год | год взят из системных часов | `year` из конфигурации |
| журнал ядра в 1970-х | `boot_epoch` не прибавлен | эпоха = загрузка + счётчик |
| «расхождение с истиной» на одну строку | потерялась строка комментария или пустая | пропускать их явно |
| «хронология не отсортирована» | сортировка по строке, а не по числу | ключ — целое |
| «вывод меняется между прогонами» | сортировка только по времени | доопределить сравнение |
| результат разный на двух машинах | `time.mktime` или `datetime.now()` | `calendar.timegm` |
| код 0 при пустом разборе | не проверено, что события есть | ни одного события — код 2 |

## После выполнения

Зелёный тест означает, что у вас есть хронология, а не пять мнений, и её
можно показать на совещании.

Главное, что стоит унести: **внутрь — эпоха, наружу — местное время.** Все
сравнения, вычитания и сортировки делаются над числом; перевод в
человеческий вид — последняя операция перед печатью, а не первая после
чтения.

И второе: **всё, чего нет в строке журнала, — часть описания системы, а не
знание программы.** Год, момент загрузки, смещение снимаются вместе с
журналами. Через неделю узел перезагрузят, и восстановить их будет неоткуда.

## Кумулятивность

Разбор журналов `awk`-ом вводился в
[`s01e11`](../../season-01-shell-foundations/s01e11-awk-stats/); здесь его
не хватает — форматов пять, арифметика календарная, и это ровно та граница,
за которой берут Python
([`s06e10`](../../season-06-embedded-iot/s06e10-sensor-client/),
[`s07e09`](../../season-07-production-advanced/s07e09-latency-percentiles/)).

`auditd` как источник — [`s05e08`](../../season-05-security-pentesting/s05e08-auditd/);
журнал фаервола — [`s02e12`](../../season-02-networking/s02e12-firewall-log/);
события кластера — [`s07e01`](../../season-07-production-advanced/s07e01-cluster-recon/).
Три сезона сходятся в одну ось.

Независимость вывода от среды запуска — то же сквозное правило курса, что и в
[`s07e09`](../../season-07-production-advanced/s07e09-latency-percentiles/):
результат, зависящий от локали, часового пояса или порядка обхода, не
воспроизводится.

Восемь закреплений из [`s08e05`](../s08e05-persistence/) получают время. Ключ,
принятый в 14:32, никто не добавлял на узле — откуда он взялся, разбирается
в `s08e07`.
