## Обстановка

Веб-сервер на архивном узле не отдаёт файлы. Предложение — выключить
SELinux. В журнале три отказа, и все три разные: метки файлов, порт,
соединение с базой.

Плюс два отказа, которых в журнале **нет**: правила `dontaudit` запрещают
и не записывают. Один из них — причина, по которой архиватор третий день
не пишет во временный каталог.

Плюс одна служба, у которой отказов не будет никогда, потому что политики
для неё не написано.

## Приказ

Заполнить `artifacts/selinux_report.txt` — 20 значений: состояние
подсистемы, счёт отказов, разбор трёх случаев и то, чего в отказах не
видно.

```bash
cp starter/selinux_report.txt artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `sestatus.txt` | режим и политика |
| `ps_z.txt` | контексты процессов |
| `ls_z.txt` | контексты файлов |
| `audit_avc.txt` | отказы за час |

## Чем добывать

| Что нужно | Как |
|---|---|
| тип из контекста | третье поле: `system_u:system_r:httpd_t:s0` → `httpd_t` |
| разные отказы | разные четвёрки «домен, тип, класс, действие» |
| скрытые отказы | разность числа строк в двух снимках |
| ожидаемый тип по пути | `semanage fcontext -l`, шаблон `(/.*)?` |
| тип для веб-портов | в `semanage port -l` он один |
| переключатель про базу | тот, в имени которого есть `_db` |

- [ ] Все 20 ключей заполнены.
- [ ] Отказы посчитаны по четвёркам, а не по строкам.
- [ ] Скрытые `dontaudit` отказы посчитаны.
- [ ] Три случая получили **три разных** лечения; ни одно не «выключить» и ни одно не свой модуль политики.
- [ ] Для меток предложено восстановление, а не добавление правила: правило в политике уже есть.
- [ ] Названа служба в неограниченном домене.
- [ ] Комментарии в файле сохранены.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + grep |
| Сеть | не нужна |
| **SELinux** | **не нужен** — снимки в `data/` |
| `semanage`, `getsebool` | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | снимки только читаются |

Тест пересчитывает каждое значение из снимков. Отдельно проверяется, что
данные не выродились: что снимок без `dontaudit` действительно содержит
больше отказов, что среди строк есть повторы, что служба в неограниченном
домене присутствует и что режим — `enforcing` (в `permissive` отказы не
отказы, а записи).

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `denials_distinct` равен `denials_total` | посчитаны строки | считать четвёрки |
| `hidden_denials=0` | второй снимок не открывали | `dontaudit` скрывает отказы |
| тип с двоеточиями | взят весь контекст | нужно третье поле |
| `case_label_fix=policy-module` | предложен свой модуль | правило в политике уже есть |
| `case_port_expected_type` не проходит | взят `unreserved_port_t` | это текущий, а не нужный |
| «разным отказам одно лечение» | всё сведено к `permissive` | три случая — три штатные команды |
| `unconfined_service` пуст | искали в отказах | у него отказов и не будет |

## После выполнения

Зелёный тест означает, что три отказа разобраны до причин и каждый получил
своё штатное лечение, а два скрытых и одна служба вне политики — названы.

Главное, что стоит унести: **отсутствие записи в журнале означает только
отсутствие записи в журнале.** Пустой журнал у одной службы и пустой
журнал у другой означают разное: у первой — разрешено политикой, у второй
— политики нет. Утверждение «ничего не было» требует, чтобы кто-то
гарантировал: всё, что было, записывается.

И второе: **любая защита делит мир на «проверено» и «не покрыто», и
второе никогда не бывает пустым.** Принять риск законно. Не знать о нём —
нет.
