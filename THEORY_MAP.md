# THEORY_MAP — карта зависимостей концептов

**Назначение.** Единая карта «какой концепт где вводится» — чтобы ловить
**зависимости «вперёд»** (forward-deps): ситуации, когда инструмент/концепт
используется в зачётном коде раньше, чем объясняется. Это прямое требование
плана v2.0 (§8): «Ввести `THEORY_MAP.md` — чтобы ловить forward-deps как T1–T4».

**Правило.** Концепт X можно использовать в серии N только если X введён в серии ≤ N.
Исключение — **осознанный «предпросмотр»**: тогда в README серии ставится явная пометка
«предпросмотр, разберём в sNNeNN», и X **не попадает в зачётный код** (тест не должен
требовать неизученного).

> Нумерация ниже — текущая (`epNN`); после Этапа 1 (миграция на `sNNeNN`) колонка
> «серия» обновляется на посезонные идентификаторы. Соответствие — в релизе v2.0.

## 3. Дубли справочников (T6) — свести в единый источник

Повторяющиеся справочные блоки должны жить в одном месте (`RESOURCES.md`
или общий `theory.md`-раздел), а серии — **ссылаться**, а не копировать.

| Справочник | Где дублируется (тек.) | Каноничный дом |
|------------|------------------------|----------------|
| sysctl-hardening (`tcp_syncookies`, ASLR…) | ≥6 мест: ep20, ep27, ep28×3, ep29, ep07 | `RESOURCES.md` → раздел hardening |
| SSH-hardening (`sshd_config`) | ep17, ep20, ep21, ep28 | `RESOURCES.md` → раздел SSH |
| cheatsheet-файлы | перекрывают hardening-эпизоды | ссылка из серии |
