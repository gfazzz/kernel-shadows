## Обстановка

Серверы разворачивались в три захода за полгода, последняя инвентаризация была в
июле. Никто в команде не может перечислить, какие сервисы подняты на каждой
машине и какие из них видны из сети.

Одновременно снаружи идёт медленный перебор портов — по несколько за час, чтобы
не сработали пороги обнаружения. Кто-то ищет забытую открытую дверь, и найдёт он
её быстрее, чем команда вспомнит, что её открывала.

## Приказ

Собрать `check_ports.sh` — показывает слушающие TCP-сокеты и сверяет номера портов
со списком согласованных:

```
=== Слушающие TCP (адрес:порт) ===
0.0.0.0:22
127.0.0.1:3306
[::]:80
0.0.0.0:4444
--- Проверка по allowlist (allow.txt) ---
  ✓ 22 — разрешён
  ⚠️ 4444 — НЕ в allowlist (неожиданный порт!)
Неожиданных портов: 2
```

Использование: `./check_ports.sh allow.txt` — по номеру порта на строку,
комментарии `#` допускаются.

## Данные

| Что | Как |
|---|---|
| список сокетов | `ss -tln 2>/dev/null \| awk 'NR>1{print $4}'` |
| номер порта | `sed 's/.*://'` — после **последнего** двоеточия (работает и для `[::]:80`) |
| отбросить мусор | `grep -E '^[0-9]+$'` |
| уникальные, по порядку | `sort -un` |
| сверка со списком | `grep -qxF "$p" "$allow"` — совпадение строки **целиком** |
| счётчик | увеличивать в ветке «не найден» |

`-n` у `ss` обязателен: без него команда попытается резолвить адреса в имена и на
машине с недоступным DNS будет ждать таймаута.

## Критерии приёмки

- [ ] `artifacts/check_ports.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Выводятся все слушающие сокеты в виде `адрес:порт`.
- [ ] Номер порта извлекается корректно как для `0.0.0.0:22`, так и для `[::]:80`.
- [ ] Заголовок вывода `ss` не принимается за сокет.
- [ ] Порт из allowlist помечается разрешённым, остальные — неожиданными.
- [ ] Порт `44` **не** считается разрешённым из-за строки `443` (сверка по целой строке).
- [ ] Дубликаты (один порт на разных адресах) в отчёте не удваиваются.
- [ ] Счётчик неожиданных совпадает с числом помеченных строк.
- [ ] `bash tests/test.sh` → 12 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен (без root не видны чужие процессы, но сокеты видны) |
| ОС | любая с bash; `ss` из пакета `iproute2` для реального запуска |
| Сеть | **не нужна** — тест подменяет `ss` |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `ss`; в тесте подменяется |
| Изоляция теста | мок-`ss` в `PATH` + allowlist во временном каталоге |

Мок отдаёт реалистичный вывод: IPv4 и IPv6-сокеты, порт-дубликат на разных
адресах, порт `443` рядом с проверкой на `4` и «временный сервис» на `4444`.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| порт из `[::]:80` не извлёкся | режется по первому `:` | `sed 's/.*://'` — по последнему |
| в список портов попало слово `Port` | не пропущен заголовок `ss` | `awk 'NR>1'` или фильтр `^[0-9]+$` |
| порт `4` объявлен разрешённым | сверка по подстроке | `grep -qxF` — точное совпадение строки |
| один порт в отчёте дважды | не убраны дубликаты | `sort -un` |
| `ss` подвисает | нет `-n`, идёт резолв имён | добавить `-n` |
| счётчик не совпадает со строками | увеличивается не в той ветке | считать там же, где печатается предупреждение |

## После выполнения

Зелёный тест означает, что у тебя есть список дверей — и он получен наблюдением,
а не по памяти. Расхождение между этим списком и ожиданиями команды и есть
результат работы.

про то, как отличить мёртвый хост от обрыва по пути.
