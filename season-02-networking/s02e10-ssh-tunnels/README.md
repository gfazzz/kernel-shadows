## «Сервер есть, дороги нет»

Алекс разворачивает схему, которую ты вместе рисовал вчера.

```
интернет ──► bastion.ops.local  (единственная машина с белым адресом)
                   │
       ┌───────────┼───────────┐
       ▼           ▼           ▼
   db.internal  10.0.7.10   devbox.ops.local
   (5432, только localhost)
```

> — Мы закрыли всё правильно, — говорит он. — Наружу смотрит один бастион. База слушает `127.0.0.1:5432` и снаружи невидима вообще. Теперь объясни, как Анна будет с ней работать.

> — Зайти на бастион, оттуда на базу?

> — И запускать `psql` в терминале через две сессии. Можно. А если у неё графический клиент? А если ей нужно выгрузить дамп к себе на ноутбук?

Он ждёт. Ты понимаешь, к чему он ведёт, но формулировки нет.

> — SSH умеет не только давать оболочку, — говорит Алекс. — Он умеет переносить **порты**. Соединение уже зашифровано и уже аутентифицировано — остаётся сказать, какой порт куда положить.

Он пишет одну строку:

```bash
ssh -L 15432:127.0.0.1:5432 -J bastion db
```

> — С этого момента `localhost:15432` на её ноутбуке — это `127.0.0.1:5432` на сервере базы. Для клиента разницы нет никакой.

> **LILITH:** *«Туннель не пробивает стену. Он пользуется дверью, которая уже есть, — и проносит через неё то, для чего дверь не предназначалась.»*

## Чему ты научишься

- Четырём направлениям туннеля: `ProxyJump`, `-L`, `-R`, `-D` — и тому, какой вопрос решает каждый.
- `~/.ssh/config`: почему `Host *` обязан стоять последним и как ssh собирает итоговые настройки.
- Тому, чем `ProxyJump` лучше «зайти и оттуда»: ключ не покидает твою машину.
- Метанавыку: **спрашивать программу, а не файл**. Действует не текст конфига, а то, что из него вывел клиент.

Подробнее, с историей и подводными камнями, — в [`theory.md`](theory.md).

## Теория: четыре способа

### `ProxyJump` — дойти через посредника

```bash
ssh -J bastion db              # в командной строке
ProxyJump bastion              # то же в ~/.ssh/config
ProxyJump bastion,relay        # цепочка
```

Твоя машина открывает соединение с бастионом и просит его **переслать байты** до `db`. Шифрование при этом — от тебя до `db`; бастион видит только зашифрованный поток и не может ни прочитать его, ни подменить.

Старый способ — `ProxyCommand ssh -W %h:%p bastion` — делает то же самое; `ProxyJump` появился, чтобы это не приходилось помнить.

### `-L` — локальный порт сюда

```
LocalForward 15432 127.0.0.1:5432
              │         │
              │         └ куда идти С ТОЙ СТОРОНЫ (адрес с точки зрения сервера)
              └ какой порт слушать У СЕБЯ
```

Слушаем `15432` на своей машине, всё пришедшее туда уходит по туннелю и открывается уже на сервере как соединение с `127.0.0.1:5432`. Именно поэтому база, слушающая только localhost, становится доступна: подключение к ней происходит **изнутри**.

### `-R` — обратно, наружу

```
RemoteForward 127.0.0.1:9000 127.0.0.1:3000
                     │              │
                     │              └ что отдаём: наш локальный сервис
                     └ где слушать НА СЕРВЕРЕ
```

Обратное направление: порт открывается на сервере, а трафик приходит к нам. Так показывают коллеге локальную сборку, не выкладывая её никуда.

**Явный `127.0.0.1:` слева обязателен.** Без него порт может открыться на всех интерфейсах сервера — если там `GatewayPorts yes` — и твой отладочный сервис окажется доступен из интернета.

### `-D` — SOCKS-прокси

```
DynamicForward 127.0.0.1:1080
```

Не один порт, а прокси: приложение (браузер) отправляет туда любые соединения, и они выходят в сеть **со стороны сервера**. Один параметр вместо десятка `-L`.

### Где это писать

Всё перечисленное можно набирать ключами в командной строке. Но набирать придётся каждый раз, а туннелей четыре — поэтому их держат в `~/.ssh/config`, и дальше достаточно `ssh db`.

**Правило чтения, из-за которого ломается половина конфигов:** ssh просматривает блоки сверху вниз и для каждого параметра берёт **первое найденное значение**. Значит, блок `Host *` должен стоять **последним** — наверху он перекроет всё, что написано ниже.

Про `ForwardAgent`, `IdentitiesOnly`, `ControlMaster` и проверку `ssh -G` — в [`theory.md`](theory.md).

## Проверка: LILITH задаёт вопросы

**LILITH:** *«В `~/.ssh/config` первым идёт блок `Host *` с `User dmitry`, ниже — `Host db` с `User max`. Под каким именем пойдёт `ssh db`?»*

<details>
<summary>Подумай 30 секунд</summary>

Под `dmitry`. Действует **первое** найденное значение, а `Host *` совпадает с чем угодно и стоит выше.

Это не опечатка в редком случае, а полная противоположность интуиции: файл выглядит так, будто частная настройка «уточняет» общую, а на деле она мертва.

Проверяется без догадок: `ssh -G db | grep '^user '` покажет, что ssh на самом деле собирается делать.
</details>

**LILITH:** *«Чем `ProxyJump` лучше, чем зайти на бастион и оттуда запустить ssh?»*

<details>
<summary>Ответ</summary>

Тем, что ключ не покидает твою машину, а бастион не видит содержимое сессии.

При «зайти и оттуда» тебе нужен ключ **на бастионе** (или проброс агента, что ещё хуже: root на бастионе сможет им пользоваться). При `ProxyJump` соединение шифруется от тебя до конечной машины, а бастион только пересылает байты.

Побочно: работают `scp`, `rsync`, туннели и графические клиенты — всё, что умеет ssh, а не только интерактивная оболочка.
</details>

## Задание: собрать конфигурацию клиента

Артефакт — `artifacts/config`, файл для `~/.ssh/config`:

```bash
cp starter/config artifacts/config
bash tests/test.sh
```

| Хост | Что нужно |
|---|---|
| `bastion` | единственная машина с внешним адресом |
| `db` | через бастион; локальный порт к базе `5432` |
| `moscow` | через бастион; SOCKS для браузера |
| `devbox` | через бастион; наш локальный `3000` отдать туда |

Плюс общие настройки клиента: не отдавать ключ чужому серверу, не перебирать все ключи подряд, не отключать проверку хоста, не терять туннель за NAT.

Стартер — конфиг Дмитрия. Он работает: Дмитрий ходит на все машины и не вводит пароль. И в нём почти каждая строка либо лишний риск, либо мёртвая настройка.

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Порядок блоков: сначала частные (`Host bastion`, `Host db`, …), в самом конце — `Host *`. Внутри блока — отступ и пары «ключ значение».

Ключи, которые понадобятся: `HostName`, `User`, `IdentityFile`, `ProxyJump`, `LocalForward`, `RemoteForward`, `DynamicForward`, `ForwardAgent`, `IdentitiesOnly`, `StrictHostKeyChecking`, `ServerAliveInterval`.

На своей машине: `ssh -G db` покажет, что ssh реально прочитал. Эталон — в `solution/`, там же комментарий к каждому решению.
</details>

## Разбор типичных ошибок

**Оставить `Host *` наверху.** Ошибки не будет ни при разборе, ни при подключении — просто все частные настройки перестанут действовать, и ты будешь ходить под чужим именем, гадая почему.

**Включить `ForwardAgent yes`.** Выглядит удобно: ключ «доступен» на бастионе, и оттуда можно идти дальше. На деле это означает, что тот, кто получил root на бастионе, ходит твоим ключом куда угодно — и в журналах это ты. `ProxyJump` решает ту же задачу, ничего не отдавая.

**Открыть `RemoteForward` без адреса.** `RemoteForward 9000 127.0.0.1:3000` при `GatewayPorts yes` на сервере откроет твой отладочный сервис всему интернету. Явный `127.0.0.1:` слева стоит одну строку и закрывает вопрос.

## Debriefing

**Четыре трубы**

Ты сдаёшь конфиг. Алекс проверяет его не глазами, а командой:

```
$ ssh -G db | grep -E '^(user|proxyjump|forwardagent|localforward)'
user max
proxyjump bastion
forwardagent no
localforward 15432 127.0.0.1:5432
```

> — Вот это правильный способ читать такой файл, — говорит он. — Не «что я написал», а «что ssh понял». Разница между этими двумя вещами и есть весь `Host *` наверху.

Он показывает на `forwardagent no`.

> — И вот это. Знаешь, как чаще всего уводят ключи? Не взломом. Человек включает проброс агента, чтобы было удобно ходить через бастион, и заходит на скомпрометированную машину. Всё. Пока сессия открыта, его ключом можно подписать что угодно.

> — А ProxyJump?

> — А ProxyJump тем и хорош, что решает ту же задачу, не задавая вопроса о доверии. Бастиону нечего доверять — он видит поток байт.

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   Четыре туннеля, и до всех машин операции есть дорога.      │
│                                                              │
│   Но каждый из них живёт, пока открыта сессия. Анна          │
│   закрыла ноутбук — базы нет. А завтра команда работает      │
│   из трёх городов, и трафик между ними нужен весь,           │
│   а не по одному порту.                                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```
