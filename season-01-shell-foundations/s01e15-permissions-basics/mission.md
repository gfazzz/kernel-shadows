## Обстановка

Всю неделю работа шла на своей машине, где единственный пользователь — ты,
и всё принадлежит тебе. Послезавтра — общий сервер, где сидят ещё четверо.

Виктор просит собрать рабочий каталог операции так, чтобы ключи в нём не
читались посторонними, а скрипты запускались. Не «чтобы работало» —
чтобы было правильно.

## Приказ

Написать `artifacts/setup_workspace.sh` — скрипт, который создаёт структуру
каталога и выставляет права.

```bash
cp starter/setup_workspace.sh artifacts/setup_workspace.sh
bash artifacts/setup_workspace.sh --root /tmp/ops
ls -l /tmp/ops
bash tests/test.sh
```

## Что должно получиться

| Путь | Права | Почему |
|---|---|---|
| `scripts/` | `700` | свои инструменты: читать, писать и запускать только владельцу |
| `secrets/` | `700` | туда лягут ключи; посторонним нечего даже перечислять |
| `reports/` | `755` | отчёты отдают другим, значит их читают |
| `logs/` | `750` | журналы читает группа, посторонние нет |
| файлы в `secrets/` | `600` | секрет читает только владелец |
| `*.sh` в `scripts/` | `700` | исполняемый и только для владельца |
| файлы в `reports/` | `644` | их должны прочитать |

**Главное требование.** Скрипт не только создаёт, но и **приводит к нужному
виду**: каталог, где кто-то поставил `777`, он обязан починить, а то, что
уже правильно, — не трогать. Запускать его можно сколько угодно раз.

## Чем добывать

| Что нужно | Как |
|---|---|
| текущие права | `stat -c '%a' путь` (GNU) или `stat -f '%Lp' путь` (macOS) |
| сравнить как числа | `[ "$(( 8#$have ))" -ne "$(( 8#$want ))" ]` — восьмеричные |
| выставить права | `chmod 700 путь` |
| создать каталог, если его нет | `mkdir -p путь` |
| обойти файлы внутри | `find "$dir" -type f -print \| while IFS= read -r f; do …` |
| перебрать пары «каталог права» | `for pair in "scripts 700" "logs 750"; do set -- $pair; …` |

Переносимость `stat`: попробовать GNU-форму, при неудаче — BSD:
`stat -c '%a' "$1" 2>/dev/null || stat -f '%Lp' "$1" 2>/dev/null`.

## Критерии приёмки

- [ ] `artifacts/setup_workspace.sh` создан на основе `starter/`, с шебангом и `set -euo pipefail`.
- [ ] Создаются все четыре каталога с указанными правами.
- [ ] Файлы внутри приводятся к нужным правам: `secrets/` → `600`, `*.sh` → `700`, `reports/` → `644`.
- [ ] Повторный запуск проходит без ошибок и ничего не ломает.
- [ ] Каталог с правами `777` и файл `666` исправляются; слишком узкие права — тоже.
- [ ] Файлы за пределами `--root` не изменяются.
- [ ] `chmod 777` в скрипте нет.
- [ ] `sudo` не вызывается ни разу.
- [ ] Путь к обычному файлу вместо каталога и запуск без `--root` отвергаются с ненулевым кодом.
- [ ] Результат не зависит от локали и часового пояса.
- [ ] `bash tests/test.sh` → 23 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | **не нужен** — и тест проверяет, что ты его не звал |
| ОС | любая с bash + coreutils (`stat`, `chmod`, `find`) |
| Сеть | не нужна |
| Внешние пакеты | нет |
| Изоляция теста | всё во временном каталоге; `sudo` подменён заглушкой-регистратором |

Тест дополнительно проверяет, что права выставлены скриптом, а не совпали
случайно со значением `umask`.

## Выполнение

```bash
cd season-01-shell-foundations/s01e15-permissions-basics
cp starter/setup_workspace.sh artifacts/setup_workspace.sh
$EDITOR artifacts/setup_workspace.sh
bash artifacts/setup_workspace.sh --root /tmp/ops && ls -l /tmp/ops
chmod 777 /tmp/ops/secrets                       # испортить нарочно
bash artifacts/setup_workspace.sh --root /tmp/ops && ls -ld /tmp/ops/secrets
bash tests/test.sh
```

Заодно стоит посмотреть на свою машину — почти наверняка там найдётся
что-нибудь доступное всем на запись:

```bash
ls -ld ~/.ssh 2>/dev/null
find ~ -maxdepth 2 -perm -002 -type f 2>/dev/null | head
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| права `755` вместо `700` | `mkdir` отдал права по `umask` | после создания нужен `chmod` |
| «каталог 777 не приведён обратно» | скрипт только создаёт | проверять и выставлять на каждом запуске |
| «слишком узкие права тоже исправляются» | сравнение «не меньше чем» | нужно **ровно** заданное значение |
| `stat: illegal option` | BSD-версия `stat` | `stat -c … 2>/dev/null \|\| stat -f …` |
| сравнение прав не срабатывает | `0700` и `700` как строки разные | сравнивать числа: `$(( 8#$m ))` |
| «скрипт вызвал sudo» | привычка | файлы твои, root не нужен |
| «файлы вне --root изменены» | путь собран неверно | все операции только внутри `${ROOT}` |
| `set -e` роняет на `find` | пустой результат или ошибка доступа | обходить через `while read`, а не `for` |

## После выполнения

Зелёный тест означает, что каталог операции готов к общему серверу: у каждого
подкаталога свой ответ на вопрос «кому это видно», и ответ этот выставлен
намеренно, а не достался от `umask`.

Посмотри на вывод `ls -l` ещё раз и произнеси вслух, что означает каждая
строка. Эти девять букв встречались в каждой серии сезона — теперь они
что-то говорят.
