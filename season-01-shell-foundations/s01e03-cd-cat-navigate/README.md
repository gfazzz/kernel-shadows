## Чему ты научишься

## Теория: `cd` и `cat`

**`cd`** (**c**hange **d**irectory) переносит тебя по дереву. Не «открывает папку» — меняет текущий рабочий каталог оболочки, тот самый, что печатает `pwd`:

```bash
cd documents      # вниз, в подкаталог (относительный путь)
cd ..             # вверх, к родителю
cd /etc           # в конкретное место от корня (абсолютный путь)
cd ~              # домой
cd -              # обратно, туда, где был только что
```

`cd -` — недооценённая команда: возвращает в предыдущий каталог, как кнопка «назад» в браузере. Мотаться между двумя далёкими точками дерева ею удобнее, чем набирать пути заново.

**`cat`** (от *concatenate*) печатает содержимое файла:

```bash
cat briefing.txt              # весь файл в терминал
cat documents/briefing.txt    # можно и не переходя — прямо по пути
```

Отсюда важное следствие: **чтобы прочитать файл, не обязательно к нему идти.** Путь в аргументе работает так же, как переход. `cd` нужен, когда ты собираешься работать в этом месте, а не заглянуть один раз.

Для больших файлов вместо `cat` берут `less` (листается, ищет по `/`, выходит по `q`), для быстрого взгляда — `head` и `tail`. Разбор `less`, `tail -f` и того, почему `cat file | grep` — плохая привычка, в [`theory.md`](theory.md).

> **LILITH:** *«`cat` на файл в гигабайт — это заявка на минуту скролла и полное отсутствие пользы. Смотри `head`, ищи `grep`, листай `less`. „Прочитать" не значит „вывалить на экран".»*

## Проверка: LILITH задаёт вопросы

**LILITH:** *«Ты в `~`. Файл — в `/var/log/nginx/error.log`. Обязательно ли делать `cd`, чтобы его прочитать?»*

<details>
<summary>Подумай 20 секунд</summary>

Нет. `cat /var/log/nginx/error.log` прочитает файл из любого места: путь в аргументе полностью заменяет переход.

`cd` осмыслен, когда работать в этом каталоге ты собираешься долго — тогда короткие относительные пути экономят время. Для одного взгляда переход лишний, и он оставляет тебя не там, где ты думаешь, что находишься.
</details>

**LILITH:** *«`cd ..` из `/home/max/projects/web` — куда попадёшь? А `cd ../..`?»*

<details>
<summary>Ответ</summary>

`cd ..` → `/home/max/projects`, `cd ../..` → `/home/max`.

Каждая пара точек — шаг вверх по дереву, и их можно составлять в цепочку: `../../etc` значит «на два уровня вверх, затем вниз в `etc`». Работает не только в `cd`, но и в аргументах любых команд: `cat ../notes.txt`.
</details>

## Разбор типичных ошибок

**Искать «специальную команду для скрытых файлов».** Её нет: `cat .next_server` работает ровно как `cat briefing.txt`. Точка влияет только на вывод `ls`, а не на чтение.

**Переписать значение «примерно».** `55.7558°N` — это не `55.7558 N` и не `55,7558°N`. Разведданные с потерянным символом — координаты, по которым никто не придёт. Тест сверяет посимвольно, и это не придирка: конфиги и ключи в реальной работе ведут себя так же.
