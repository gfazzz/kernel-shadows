## Обстановка

Есть ордер: две сети, два разрешённых действия, три запрещённых прямо,
окно до восьми вечера, вычистка персональных данных при раскрытии. Есть
девять заявок от команды — часть за пределами ордера, часть — разрушительные.

Решение о каждом действии должен принимать файл правил, а не человек в
разгар операции.

## Приказ

Написать `artifacts/engagement.conf`: перенести ордер в правила так, чтобы
каждая заявка получала верное решение.

```bash
cp starter/engagement.conf artifacts/
$EDITOR artifacts/engagement.conf
bash tests/test.sh
```

## Дано

| Источник в `data/` | Что в нём |
|---|---|
| `authorization.txt` | ордер: сети, разрешённые и запрещённые действия, политика PII |
| `targets.txt` | девять заявок: адрес, действие, обоснование |
| `evidence_fields.txt` | поля доказательств: техническое против персонального |

## Что перенести в правила

| Из ордера | В правила |
|---|---|
| разрешённые сети | `allow_scope <CIDR>` на каждую |
| умолчание | `default deny` |
| разрешённые действия | `allow_action <имя>` |
| запрещённые действия | `deny_action <имя>` — явно, хотя default и так запрещает |
| политика PII | `disclosure_redact_pii yes` |
| порядок раскрытия | `disclosure_channel <кому сначала>` |
| незаявленное | `on_unlisted deny` |

## Что здесь легко пропустить

**Область не может быть шире ордера.** Сеть, которой нет в ордере, не
появляется в правилах, даже если «это же их сервер».

**Запреты выписываются явно.** При default-deny они и так не пройдут, но
запрет должен быть виден тому, кто читает файл.

**PII вычищается, раскрытие идёт сначала координатору.** Не сразу в прессу.

## Критерии приёмки

- [ ] `default deny` и `on_unlisted deny` присутствуют.
- [ ] Область правил совпадает с ордером и не шире его.
- [ ] Все разрешённые действия перенесены, все запрещённые выписаны явно.
- [ ] `disclosure_redact_pii yes` и задан канал раскрытия.
- [ ] Прогон девяти заявок совпадает с ордером: 4 разрешено, 5 отклонено.
- [ ] Ни одно разрушительное действие не проходит правила.
- [ ] Комментарии в файле сохранены.
- [ ] `bash tests/test.sh` → 16 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | **не нужна** — никаких активных действий, всё на снимках |
| Внешние пакеты | нет |
| Изоляция теста | снимки только читаются |

Тест независимо переносит ордер в решение и прогоняет через ваши правила
все девять заявок. Отдельно проверяется, что данные не выродились: среди
заявок есть цели вне области и есть запрещённые действия.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «в конфигурации сети вне ордера» | добавлена сеть «на всякий случай» | только сети ордера |
| «пропущены сети ордера» | перенесена не вся область | по строке на каждую |
| «разрушительная заявка прошла» | нет `deny_action` и/или `default deny` | оба обязательны |
| «PII уйдёт в раскрытие» | нет `disclosure_redact_pii yes` | добавить |
| заявка вне области разрешена | нет `default deny` | умолчание — запрет |
| решение не совпало с ордером | область или действия расходятся с `authorization.txt` | сверить построчно |

## После выполнения

Зелёный тест означает, что активные действия ограничены ордером на уровне
файла, а не обещания, и что раскрытие не превращает жертв в пострадавших
повторно.

Главное, что стоит унести: **оправданное — это не разрешённое.** Виновность
цели не даёт полномочий; полномочия даёт ордер, и действие за его пределами
не становится законным от силы оправдания.

И второе: **граница — единственное, что отличает оборону от того, с чем она
борется.** Сотрёшь её один раз «по-честному» — и доказательства станут
негодными, а разница исчезнет.

## Кумулятивность

Default-deny — тот же принцип, что у фаервола в
[`s05e11`](../../season-05-security-pentesting/s05e11-hardening/) и
[`s02e07`](../../season-02-networking/s02e07-block-botnet/): запрещено всё,
что не разрешено явно; здесь он применён к активным действиям.

Вычистка PII перед раскрытием опирается на различение технического и
персонального — то же, что в разборе доказательств
[`s05e02`](../../season-05-security-pentesting/s05e02-audit-report/).

«Точно принадлежит им» как ненадёжный вывод — прямое продолжение
[`s08e09`](../s08e09-weber-case/): принадлежность адреса устанавливается, а
не предполагается.

Проверка каждого действия конфигурацией, а не в моменте, — то же, что во
всех сериях Type B этого курса: решение принимает проверяемый файл.
