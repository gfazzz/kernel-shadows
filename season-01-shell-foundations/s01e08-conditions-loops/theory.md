## 1. Счётчик, который обнулялся

> *Пишу отчёт по ночному обходу: сколько машин ответило, сколько нет. Скрипт печатает каждую строку правильно, а в конце — «UP=0 DOWN=0». Проверяю глазами: тридцать строк «UP» прямо над итогом, и ноль в итоге.*
>
> *Час сижу. Переписываю счётчик тремя способами. Ноль.*
>
> *Палыч смотрит на экран секунд десять.*
>
> — Как ты читаешь файл?
> — `cat servers.txt | while read host`.
> — Вот и ответ. Труба порождает подоболочку. Твой цикл считает честно — в отдельном процессе, который умирает вместе с последней строкой и уносит счётчики с собой.
> — А как надо?
> — `done < servers.txt`. Тот же цикл, только он остаётся у себя дома.
>
> *Он уходит, потом оборачивается:*
>
> — И запомни ощущение. Ты искал ошибку в счётчике, а она была в способе чтения. Ошибка почти никогда не там, куда ты смотришь.

## 2. `[` — это команда, а не синтаксис

Главное недоразумение с условиями в bash: квадратная скобка выглядит как часть языка, а на деле это исполняемая команда со своими аргументами.

```console
$ type [
[ is a shell builtin
$ ls -l /usr/bin/[
-rwxr-xr-x 1 root root 60416 /usr/bin/[
```

Отсюда всё остальное:

- **Пробелы обязательны.** `[ "$a" = "$b" ]` — команда `[` с четырьмя аргументами. Написав `[$a = $b]`, ты просишь запустить программу с именем `[значение`.
- **Кавычки нужны.** Если `$a` пуст и не в кавычках, команда получает меньше аргументов, чем ждёт: `[ = b ]` — синтаксическая ошибка.
- **Закрывающая скобка — тоже аргумент**, поэтому её нельзя приклеивать к предыдущему слову.

| Проверка | Числа | Строки |
|---|---|---|
| равно | `-eq` | `=` |
| не равно | `-ne` | `!=` |
| больше / меньше | `-gt` / `-lt` | `>` / `<` (в `[[ ]]`) |
| пусто / не пусто | — | `-z` / `-n` |

Числовые и строковые операторы не взаимозаменяемы: `[ "10" = "10.0" ]` — ложь (строки разные), `[ 10 -eq 10 ]` — истина.

**`[[ ]]` против `[ ]`.** Двойные скобки — расширение bash: внутри не нужно кавычить переменные, работают `&&`, `||`, сравнение по шаблону (`==` с `*`) и регулярки (`=~`). Но это **не POSIX**: скрипт с `#!/bin/sh` на них упадёт. Правило простое: пишешь под bash — `[[ ]]` удобнее и безопаснее; пишешь переносимо — `[ ]` с кавычками.

## 3. Циклы: три формы и одна ловушка

```bash
for host in web1 web2 web3; do ... done      # по списку слов
for i in {1..5}; do ... done                 # по диапазону (bash-расширение)
for f in *.conf; do ... done                 # по шаблону — раскрывает оболочка
while [ "$n" -lt 10 ]; do ... done           # пока условие истинно
until [ "$n" -ge 10 ]; do ... done           # пока условие ложно
while IFS= read -r line; do ... done < file  # по строкам файла
```

Ловушка — **подоболочка**. Всё, что стоит справа или слева от `|`, выполняется в отдельном процессе:

```bash
cat file | while read -r line; do n=$((n+1)); done
echo "$n"        # 0 — изменения остались в подоболочке
```

Три способа обойти:

```bash
while read -r line; do n=$((n+1)); done < file        # перенаправление (лучший)
while read -r line; do n=$((n+1)); done < <(command)  # подстановка процесса, если нужен вывод команды
shopt -s lastpipe                                      # bash умеет иначе, но требует отключённого job control
```

Первый вариант покрывает 90 % случаев и не требует пояснений в код-ревью.

## 4. Почему `IFS=` и `-r`

```bash
while IFS= read -r line; do
```

`read` по умолчанию делает две вещи, которые почти никогда не нужны при чтении файла построчно:

1. **Срезает ведущие и хвостовые пробелы** — из-за значения `IFS` по умолчанию (пробел, табуляция, перевод строки). Пустое присваивание `IFS=` перед командой отключает это только для неё.
2. **Трактует `\` как экранирование** — строка `path\to\file` превратится в `pathtofile`, а `C:\new` — в строку с переводом строки. Флаг `-r` (raw) это выключает.

Формула `while IFS= read -r line` — идиома, которую пишут не думая. Думать надо, когда её нарушаешь.

## 5. Разбор строки без внешних команд

```bash
line="shadow-server-07 185.192.45.124 prod"
echo "${line%% *}"      # shadow-server-07  — отрезать всё от первого пробела
echo "${line#* }"       # 185.192.45.124 prod — отрезать до первого пробела
echo "${line##* }"      # prod — оставить после последнего пробела
echo "${#line}"         # длина строки
```

| Форма | Что делает |
|---|---|
| `${v#шаблон}` | убрать кратчайшее совпадение с начала |
| `${v##шаблон}` | убрать длиннейшее с начала |
| `${v%шаблон}` | убрать кратчайшее с конца |
| `${v%%шаблон}` | убрать длиннейшее с конца |
| `${v/старое/новое}` | заменить первое вхождение |
| `${v//старое/новое}` | заменить все |

Зачем это, если есть `awk` и `cut`? Затем, что параметрическое расширение выполняется **внутри** оболочки, без запуска процесса. На пятидесяти строках разница неощутима, на пятидесяти тысячах — это разница между секундой и минутой. Плюс в этой серии `awk` ещё не введён (он будет в s01e11), а обходиться без него полезно уметь всегда.

## 6. Как читать чужой список

Реальный файл со списком узлов почти никогда не бывает чистым:

```
# прод, обновлено 04.10
shadow-server-01 185.192.45.118

shadow-server-07 185.192.45.124   # временно выключен
```

Минимальная гигиена цикла:

```bash
[ -z "$line" ] && continue                   # пустые строки
case "$line" in \#*) continue ;; esac        # комментарии
line="${line%%#*}"                           # хвостовые комментарии
host="${line%% *}"
[ -z "$host" ] && continue                   # строка была только из комментария
```

Пропускать мусор — не перфекционизм: скрипт, который пингует строку `# прод`, портит статистику и подрывает доверие к отчёту.

## 7. Компромиссы

| Приём | Плюс | Минус |
|---|---|---|
| `while read < file` | счётчики живут, память не расходуется | нельзя брать вход из конвейера напрямую |
| `for f in $(cat file)` | коротко | ломается на пробелах, шаблонах, больших файлах |
| `mapfile -t arr < file` | весь файл в массиве, удобен индекс | bash 4+, файл целиком в памяти |
| `xargs -a file -I{}` | параллельность (`-P`) | сложнее отлаживать, вывод перемешивается |

## 8. Метанавык: цикл — это про внимание, а не про скорость

Кажется, что автоматизация экономит время. На пятидесяти хостах она экономит минуты — не так много. Настоящая причина в другом: **человек деградирует на повторениях, машина — нет**.

К тринадцатому однотипному запуску ты перестаёшь читать вывод. К тридцатому — не заметишь `DOWN` среди `UP`. Цикл не устаёт, не отвлекается и обрабатывает пятидесятую строку так же, как первую.

Тот же принцип дальше в курсе: систематическая проверка вместо выборочной (аудит в S5), декларативная конфигурация вместо ручных правок (Ansible в S4), автотесты вместо «я посмотрел глазами» (весь курс). Везде одна мысль: рутину отдают машине не потому, что она быстрее, а потому что она внимательнее.
