## Обстановка

База операции удалена — 4.3 ГБ. Копия трёхчасовой давности есть локально и
на офсайте. Из копий ни разу не восстанавливались.

Восстанавливать «поверх» нельзя, пока копия не проверена: если она битая,
частично уцелевшая система остаётся единственным источником данных, и
развёртывание уничтожит и её.

## Приказ

Написать `artifacts/restore_check.sh` — скрипт, который разворачивает снимок
во временный каталог и отвечает, годится ли он.

```bash
cp starter/restore_check.sh artifacts/restore_check.sh
bash tests/test.sh
```

## Что должен уметь скрипт

| Требование | Почему |
|---|---|
| ключи `--backup`, `--into`, `--report`, `--quick`, `--force` | скрипт вызывают и вручную, и из расписания |
| разворачивать во временный каталог | оригинал и остатки системы трогать нельзя |
| сверять каждый файл с манифестом | «каталог не пуст» — не проверка |
| называть **испорченные** файлы поимённо | иначе искать придётся вручную |
| называть **пропавшие** файлы | исключение в конфигурации незаметно годами |
| называть **лишние** файлы | подсадка в бэкап надёжнее подсадки в систему |
| не изменять сам бэкап | это может быть единственная копия |
| не затирать непустой каталог назначения без `--force` | там могут быть чужие данные |
| `--quick` — сверка на месте, без восстановления | быстрая ежедневная проверка |
| машиночитаемый отчёт по `--report` | его читает мониторинг, а не человек |
| ненулевой код при любом расхождении | из расписания видно только код |
| понятная ошибка при отсутствии манифеста | проверять было бы нечем |

## Чем добывать

| Что нужно | Как |
|---|---|
| строка манифеста | сумма до первого пробела, путь после; `sha256sum` ставит **два** пробела |
| переносимый sha256 | `sha256sum` в GNU, `shasum -a 256` в macOS — выбрать через `command -v` |
| список из манифеста | `awk '{ sub(/^[0-9a-f]+ +/,""); print }' | LC_ALL=C sort` |
| список в дереве | `cd "$T" && find . -type f | LC_ALL=C sort` |
| лишние файлы | `comm -13 <(список из манифеста) <(список в дереве)` |
| копия с сохранением прав | `cp -p` |
| проверка «каталог не пуст» | `[ -n "$(ls -A "$D" 2>/dev/null)" ]` |

## Критерии приёмки

- [ ] `artifacts/restore_check.sh` создан на основе `starter/`, с шебангом и `set -euo pipefail`.
- [ ] Целая копия принимается с кодом 0, восстановление содержит все файлы, включая вложенные.
- [ ] Отчёт по `--report` записан и содержит итог.
- [ ] Испорченный файл: ненулевой код и имя файла в выводе.
- [ ] Пропавший файл: ненулевой код и имя файла в выводе.
- [ ] Лишний файл: ненулевой код и имя файла в выводе.
- [ ] Сам бэкап после проверки не изменён.
- [ ] Снимок без манифеста отвергнут, причина названа.
- [ ] Непустой каталог назначения не затирается молча.
- [ ] `--quick` работает и находит порчу так же, как полная проверка.
- [ ] Несуществующий снимок отвергнут, сообщение — в stderr.
- [ ] Отчёт не зависит от локали и часового пояса.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — работа во временном каталоге |
| ОС | любая с bash + coreutils + `sha256sum` или `shasum` |
| Сеть | не нужна |
| Внешние пакеты | нет |
| Изоляция теста | тест строит настоящий бэкап с манифестом и портит его тремя способами: подменяет файл, удаляет файл, дописывает лишний |

## Выполнение

```bash
cd season-03-system-administration/s03e13-restore-check
cp starter/restore_check.sh artifacts/restore_check.sh
$EDITOR artifacts/restore_check.sh

# собрать себе учебный бэкап скриптом из s03e11
mkdir -p /tmp/rc-src /tmp/rc-bk && echo проба > /tmp/rc-src/f.txt
bash ../s03e11-backup-rsync/solution/backup.sh --source /tmp/rc-src --dest /tmp/rc-bk --name t1
bash artifacts/restore_check.sh --backup /tmp/rc-bk/t1 --into /tmp/rc-out

bash tests/test.sh
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «лишний файл не обнаружен» | проверка идёт только по манифесту | сравнить и в обратную сторону, `comm -13` |
| «в выводе нет имени» | печатается только счётчик | перечислять поимённо |
| «целая копия отвергнута» | лишний пробел при разборе строки | `sha256sum` ставит два пробела |
| «проверка изменила бэкап» | восстановление идёт поверх | разворачивать в `--into` |
| «чужие файлы удалены» | каталог назначения очищается | отказ без `--force` |
| «снимок без манифеста принят» | нет проверки существования файла | сообщить и выйти с ненулевым кодом |
| «--quick не работает» | режим не реализован | сверять на месте, не копируя |
| код 0 при расхождениях | итог не влияет на `exit` | `exit 1`, если найдено хоть что-то |

## После выполнения

Зелёный тест означает, что на третий вопрос Лийзы теперь есть ответ, и его
даёт не память, а запуск.

Стоит обратить внимание, что скрипт не делает ничего сложного: копирует
файлы и считает суммы. Вся его ценность в том, что он существует и
запускается — а стартер, который «проверял» бэкап полгода, отвечал «да»
каждый день и не проверял ничего.

## Кумулятивность — весь сезон

Манифест, с которым идёт сверка, создаёт скрипт из
[`s03e11`](../s03e11-backup-rsync/); относительные пути в нём нужны именно
для этой серии. Правило «не трогать повреждённую систему до снятия
состояния» — из [`s03e04`](../s03e04-processes/), где то же самое
формулировалось про процессы (`kill -STOP` вместо `kill -9`). Удалённый файл,
который ещё можно вытащить из повреждённой системы, — из
[`s03e08`](../s03e08-disks-fs/). Глубина хранения журналов, позволяющая
разобрать инцидент, — из [`s03e12`](../s03e12-logrotate/). Ограничение прав
ключа на приёмнике копий — та же логика, что в
[`s03e03`](../s03e03-sudo/). Хронология атаки, восстановленная по журналу
в [`s03e07`](../s03e07-journalctl/), — то, что делают **параллельно**
восстановлению, а не после него.
