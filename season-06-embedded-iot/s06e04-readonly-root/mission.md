## Обстановка

Узлы стоят на улице, питание им рубят без предупреждения, носитель — SD-карта.
Замер показал 478 МБ записи в сутки, из которых пережить перезагрузку обязаны
два. Остальное убивает карту дважды: изнашивает ячейки и подставляет файловую
систему под сбой питания.

Из двенадцати узлов прошлого проекта через восемь месяцев работали пять.

## Приказ

Собрать `artifacts/fstab` для узла с корнем только для чтения.

```bash
cp starter/fstab artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `write_paths.txt` | что пишется, сколько и в каком режиме должно жить |
| `partitions.txt` | разделы карты с `PARTUUID` |
| `board_facts.txt` | объём ОЗУ, идентификаторы разделов, ресурс карты |

## Требования

| Требование | Почему |
|---|---|
| `/` и `/boot` — `ro`, по `PARTUUID` | нечего портить сбоем питания, нечего изнашивать |
| каждому пути — режим из `write_paths.txt` | решение принимается по смыслу данных |
| tmpfs: `size=` не меньше суточной записи | без предела съест память, с малым — переполнится |
| суммарный tmpfs ≤ половины `ram_mb` | свопа на узле нет, придёт OOM |
| overlay: `lowerdir` = сам путь | иначе система не увидит исходное содержимое |
| overlay: `upperdir` и `workdir` в памяти (`/run`) | иначе запись снова идёт на карту |
| persist: отдельный раздел по `PARTUUID`, `nofail` | узел должен подняться и с побитым разделом |
| `noatime` везде | иначе каждое **чтение** порождает запись |
| `nosuid,nodev` на записываемом | сокращение прав, как в s05e11 |
| у tmpfs поле `pass` = `0` | проверять `fsck` нечего |

## Чем добывать

| Что нужно | Как |
|---|---|
| режим пути | `awk '!/^#/ {print $1, $3}' data/write_paths.txt` |
| суточная запись | вторая колонка того же файла |
| `PARTUUID` разделов | `data/partitions.txt`, `data/board_facts.txt` |
| объём ОЗУ | `grep '^ram_mb=' data/board_facts.txt` |

## Критерии приёмки

- [ ] `artifacts/fstab` создан на основе `starter/`.
- [ ] `/` и `/boot` смонтированы `ro` по `PARTUUID`, с `noatime`.
- [ ] Каждый путь из `write_paths.txt` смонтирован тем способом, который указан в колонке «режим».
- [ ] Ни один `persist`-путь не оказался в tmpfs или overlay.
- [ ] У каждого tmpfs есть `size=`, и сумма не превышает половины ОЗУ.
- [ ] `upperdir` и `workdir` overlay лежат в памяти.
- [ ] Раздел данных смонтирован с `nofail`.
- [ ] Ни одной ссылки на `/dev/…` — только `PARTUUID` и виртуальные ФС.
- [ ] `bash tests/test.sh` → 28 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | не нужна |
| **плата** | **не нужна** — `fstab` проверяется как текст |
| Внешние пакеты | нет |
| Изоляция теста | требования вычисляются из `data/` |

Тест не содержит зашитых путей. Что монтировать и каким способом, он берёт
из `data/write_paths.txt`: поменяй режим у пути — и тест будет ждать другой
тип монтирования. Предел суммарного tmpfs считается от `ram_mb`, минимальный
`size=` — от замеренной суточной записи, идентификаторы разделов — из фактов
платы.

Отдельно проверяется, что `persist`-путь не оказался в памяти: это ошибка,
которая не проявляется до первой перезагрузки, а потом проявляется потерей
всего состояния узла.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «корень монтируется на запись» | нет `ro` в опциях | `ro,noatime` |
| «tmpfs без size=» | не задан предел | `size=` с запасом от замера |
| «суммарный tmpfs > половины ОЗУ» | размеры взяты «на глаз» | сумма против `ram_mb` |
| «size меньше суточной записи» | запас не заложен | не меньше второй колонки замера |
| «upperdir должен быть в памяти» | верхний слой на карте | `/run/...` |
| «данные исчезнут» | persist-путь в tmpfs | отдельный раздел по `PARTUUID` |
| «нет nofail» | побитый раздел остановит загрузку | добавить `nofail` |
| «ссылается на /dev/…» | взято имя устройства | `PARTUUID` из `partitions.txt` |

## После выполнения

Зелёный тест означает, что на карту уходит 2 МБ в сутки вместо 478, а
внезапное отключение питания больше не застаёт систему за записью. Карту
можно тиражировать на все двадцать семь узлов.

Стоит запомнить принцип, который в embedded звучит буквально, а на серверах
метафорически: **запись — это расход ресурса, а не бесплатная операция.**
Прежде чем что-то записать, полезно спросить, обязаны ли эти данные пережить
перезагрузку. Ответ «нет» встречается заметно чаще, чем принято думать, и
каждое такое «нет» снимает нагрузку с носителя, убирает точку отказа и
сокращает поверхность, которую можно испортить.

## Кумулятивность

Синтаксис `fstab`, `PARTUUID` и поля `dump`/`pass` — из
[`s03e10`](../../season-03-system-administration/s03e10-fstab/); здесь та же
таблица решает другую задачу: не «куда что подключить», а «что вообще не
писать». `nosuid,nodev` на записываемых точках — сокращение прав из
[`s05e11`](../../season-05-security-pentesting/s05e11-hardening/).

Неизменяемый корень закрывает два шага атаки, разобранной в
[`s05e09`](../../season-05-security-pentesting/s05e09-forensics-snapshot/):
бэкдор в `/tmp` и закрепление через файлы не переживают перезагрузку.
Сама идея «состояние описано, а не накоплено» — прямое продолжение
[`s04e11`](../../season-04-devops-automation/s04e11-iac-audit/) и
[`s04e12`](../../season-04-devops-automation/s04e12-ansible-playbook/).
Механизм слоёв overlayfs — тот же, что под образами контейнеров в
[`s04e04`](../../season-04-devops-automation/s04e04-images-layers/).
