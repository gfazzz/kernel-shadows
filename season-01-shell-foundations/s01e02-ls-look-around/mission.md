## Обстановка

Ориентироваться ты научился. Теперь надо найти три файла, о которых говорил Виктор:
брифинг, координаты встречи, адрес следующего узла.

Обычный `ls` показывает в корне «сервера» ровно один каталог. Это не значит, что
остальное отсутствует, — это значит, что часть объектов не попадает в вывод по
умолчанию. Прежде чем что-либо читать или запускать, нужна полная картина: что
здесь есть на самом деле.

## Приказ

Провести разведку каталога `../data/test_environment` и сдать отчёт `recon.txt`:
состав корня, скрытые объекты, содержимое `documents/`.

Скрипт писать **не нужно**. Результат этой серии — не файл кода, а достоверное
знание об объекте, добытое командами. Это законная работа администратора: сначала
разведка, потом действия.

## Данные

| Поле отчёта | Что означает |
|---|---|
| `total_entries` | объектов в корне (файлы + каталоги), без `.` и `..` |
| `hidden_entries` | из них скрытых (имя начинается с точки) |
| `dirs` | каталогов в корне |
| `hidden_names` | имена скрытых объектов через запятую, по алфавиту |
| `documents_entries` | объектов внутри `documents/`, без `.` и `..` |
| `documents_hidden_name` | имя скрытого файла внутри `documents/` |

Инструменты: `ls` (`-a`, `-A`, `-l`), `wc -l`, `grep '^\.'`. Ни одно значение не
угадывается — каждое выясняется командой.

## Критерии приёмки

- [ ] Файл `recon.txt` создан в корне серии (`cp starter/recon.txt ./recon.txt`).
- [ ] Все шесть полей заполнены — пустых значений нет.
- [ ] Числа совпадают с реальным содержимым объекта (тест вычисляет их заново).
- [ ] `hidden_names` — через запятую, без пробелов, по алфавиту.
- [ ] Учтено, что каталог `documents` — тоже объект корня.
- [ ] `bash tests/test.sh` → 8 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils (Linux / macOS / WSL) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`ls`, `wc`, `grep`) |
| Объект разведки | `season-01-shell-foundations/data/test_environment` — в репозитории |

Тест не хранит эталонных чисел: он пересчитывает их из каталога при каждом запуске.
Если учебные данные однажды изменятся, задание останется верным, а не «сломается».

## Выполнение

```bash
cp starter/recon.txt ./recon.txt
cd ../data/test_environment && ls -A && cd -
# заполни recon.txt значениями, которые увидел
bash tests/test.sh
```

Застрял — спроси LILITH в чате Cursor. Она объяснит флаги, но считать за тебя не будет:
цифры в отчёте должны быть добыты, а не получены.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `значение не заполнено` | поле осталось пустым | заполнить справа от `=`, без пробелов |
| число больше на 2 | считал через `ls -a` вместе с `.` и `..` | использовать `ls -A` |
| `hidden_names` не совпало | пробелы или другой порядок | через запятую, без пробелов, по алфавиту (`sort`) |
| `documents_entries` = 1 | посчитан только видимый файл | внутри есть и скрытый — `ls -A documents` |
| объект разведки не найден | запуск не из каталога серии | запускать `bash tests/test.sh` из корня серии |

## После выполнения

Если тест зелёный — картина полная: два объекта в корне, два внутри `documents`,
три из них те самые файлы Виктора. Дальше их надо прочитать, а для этого — научиться
перемещаться по дереву.

Если числа не сходятся, не правь отчёт наугад. Расхождение на два почти всегда
означает `.` и `..`; расхождение на один — что каталог не посчитан как объект либо
что скрытый файл внутри `documents/` остался незамеченным. Разведка с цифрами,
подогнанными под ожидание, хуже отсутствующей: на неё потом опираются.
