## Обстановка

От партнёров пришло сообщение «у вас всё лежит» — без адреса, времени и деталей.
Проверить его нечем: базовой картины сети не существует, и никто в команде не
скажет, какие хосты отвечают в нормальном состоянии и с какой задержкой.

Нужен замер, который делается одной командой и даёт таблицу по всем машинам:
кто отвечает, кто нет, с какой задержкой. Он же станет отправной точкой — тем
самым «нормально», с которым сравнивают всё последующее.

## Приказ

Собрать `net_diag.sh` — читает список хостов, проверяет каждый и печатает таблицу
с итогом:

```
HOST                   STATUS  RTT
----                   ------  ---
shadow-server-02       UP      12.3 ms
shadow-server-31       DOWN    -
---
Итог: UP=2 DOWN=1
```

Использование: `./net_diag.sh HOSTS_FILE`. Имя хоста — первое поле строки;
комментарии и пустые строки пропускаются.

## Данные

| Что | Как |
|---|---|
| список | первый аргумент, проверить `[ -f … ]` |
| чтение | `while IFS= read -r line; … done < "$list"` (s01e08) |
| имя хоста | `host="${line%% *}"` |
| проверка | `out="$(ping -c 1 -W 2 "$host" 2>/dev/null)"`, статус — по коду возврата |
| RTT | `sed -n 's/.*time=\([0-9.]*\).*/\1/p' \| head -1` (s01e12) |
| неизвестный RTT | `${rtt:-?}` — не ноль, а явный признак «не разобрано» |
| таблица | `printf '%-22s %-7s %s\n'` |

Статус определяется **кодом возврата** `ping`, а не текстом вывода: формат
сообщений различается между Linux, macOS и BusyBox и зависит от локали.

## Критерии приёмки

- [ ] `artifacts/net_diag.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Доступный хост → `UP`, недоступный → `DOWN` (по коду возврата).
- [ ] Для доступных RTT разбирается из вывода `ping` и совпадает с ним.
- [ ] Разные хосты показывают **разные** RTT (значение не захардкожено).
- [ ] Хост, ответивший без поля `time=`, помечается `UP` с `?`, а не нулём.
- [ ] Итог `UP=N DOWN=M` соответствует напечатанным строкам.
- [ ] Комментарии и пустые строки списка не считаются хостами.
- [ ] Отсутствующий список → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 12 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash (для реального запуска — `ping`) |
| Сеть | **не нужна** — тест подменяет `ping` |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `ping`; в тесте подменяется |
| Изоляция теста | мок-`ping` в `PATH` + фикстура-список во временном каталоге |

Мок отдаёт разные задержки для разных хостов и один ответ **без** поля `time=`.
Ожидаемые счётчики тест вычисляет по фикстуре.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| все хосты `DOWN` при рабочей сети | статус берётся из текста вывода | использовать код возврата |
| RTT одинаковый у всех | значение захардкожено или взято не из вывода | разбирать `time=` каждого ответа |
| в колонке RTT пусто или « ms» | поле `time=` не разобралось | подставлять `${rtt:-?}` |
| скрипт падает на сравнении RTT | пустая строка в числовом сравнении | сравнивать только когда значение разобрано |
| счётчики нулевые при верных строках | цикл в подоболочке | читать через `done < "$list"` |
| комментарий пингуется как хост | нет фильтров цикла | пропускать пустые и `#` |
| проверка идёт минутами | последовательный обход с таймаутом | уменьшить `-W`, позже — `xargs -P` (s01e14) |

## После выполнения

Зелёный тест означает, что у команды появилась базовая картина сети — не мнение,
а измерение. С этого момента «стало хуже» можно доказать, а не почувствовать.

`net_diag.sh` — ядро мониторинга `netshield` (см. [`PROJECTS.md`](../../docs/PROJECTS.md)).
