## II. Теория: правила и порядок

### Default-deny

Фаервол — это список правил и **политика по умолчанию** для всего, что под правила не подошло. Правильная политика для входящих — запрет:

```bash
sudo ufw default deny incoming     # всё входящее запрещено
sudo ufw default allow outgoing    # исходящее разрешено
sudo ufw allow 22/tcp              # ...и точечно то, что нужно
sudo ufw allow 80,443/tcp
```

Обратный подход — «разрешить всё и запрещать плохое» — не работает по арифметической причине: перечислить нужное можно (три-четыре порта), перечислить всё плохое нельзя.

### Как не отрезать себя

Порядок действий имеет значение, и цена ошибки — поездка в дата-центр:

```bash
sudo ufw allow 22/tcp     # СНАЧАЛА разрешить SSH
sudo ufw enable           # и только ПОТОМ включать
```

При включённом `default deny incoming` команда `enable` немедленно применит политику к текущим соединениям. Правило для SSH, добавленное после, уже некому будет добавить.

Приём на случай неуверенности — отложенный откат: перед изменением ставится задание, которое через десять минут вернёт прежние правила. Успел проверить связь и отменить — хорошо; потерял доступ — правила откатятся сами.

### Что видно в `ufw status`

```bash
sudo ufw status numbered
```

```
To                         Action      From
--                         ------      ----
22/tcp                     ALLOW       Anywhere
3306                       ALLOW       Anywhere
6379                       ALLOW       127.0.0.1
```

Колонка `From` важнее колонки `To`. `Anywhere` означает «из интернета», конкретный адрес или подсеть — ограничение. Порт базы данных, открытый на `Anywhere`, — это приглашение, независимо от того, есть ли на ней пароль.

Под `ufw` работает `iptables` с цепочками `INPUT`, `OUTPUT`, `FORWARD`; правила просматриваются сверху вниз, побеждает первое совпавшее. Детали, `nftables`, сохранение правил и то, почему Docker обходит `ufw`, — в [`theory.md`](theory.md).

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«Почему „разрешить всё и блокировать плохое" — проигрышная стратегия?»*

<details>
<summary>Подумай 30 секунд</summary>

Потому что список нужного конечен, а список плохого — нет. Разрешить три порта можно и нужно; перечислить все адреса ботнета, все будущие уязвимости и все ещё не изобретённые способы обращения к сервису — нельзя.

Default-deny переворачивает задачу так, что незакрытых дыр не остаётся по построению: всё, что не разрешено явно, запрещено. Ошибка в такой конфигурации проявляется как «что-то не работает» — неприятно, но заметно. Ошибка в обратной проявляется как тишина.
</details>

**LILITH:** *«В правилах строка `3306 ALLOW Anywhere`. Чем это грозит прямо сейчас, во время атаки?»*

<details>
<summary>Ответ</summary>

Двумя вещами сразу. Во-первых, это открытая в интернет база данных: перебор паролей, попытки эксплуатации, а при неудачной конфигурации — прямой доступ к данным.

Во-вторых — то, что важно именно сейчас: каждое соединение к MySQL дороже, чем к веб-серверу. Ботнет, долбящий в открытый порт базы, уронит машину быстрее, чем тот же трафик по HTTP.

Место такого сервиса — на `127.0.0.1` либо с правилом `From` для конкретной подсети.
</details>


ТЗ и критерии — в [`mission.md`](mission.md). Фикстура теста воспроизводит реальный вывод: порт со слэшем и без, чувствительный порт на `Anywhere`, тот же порт на `127.0.0.1`, правило `(v6)` и строка `DENY` — всё это надо различать.

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

```bash
case "$line" in *ALLOW*) ;; *) continue ;; esac
port="${line%% *}"; port="${port%%/*}"
for s in $sensitive; do
    if [ "$port" = "$s" ] && printf '%s' "$line" | grep -qi 'Anywhere'; then
        issues=$((issues + 1))
    fi
done
```

`${port%%/*}` отрезает `/tcp`. Сравнение портов — по точному совпадению, а не по вхождению: `3306` не должен «находиться» внутри `33060`. Эталон — в `solution/`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Смотреть только на порт.** `3306 ALLOW 10.50.0.0/24` и `3306 ALLOW Anywhere` — это правила с противоположным смыслом. Аудит, который флагует порт независимо от источника, завалит отчёт ложными тревогами, и его перестанут читать.

**Ловить порт вхождением подстроки.** `grep -q "$port"` найдёт `3306` в строке про порт `33060` и в адресе `10.33.6.1`. Порт — это поле, и сравнивать его надо целиком.

**Считать `DENY`-строки разрешениями.** В выводе `ufw status` есть и запрещающие правила; они содержат тот же номер порта. Фильтр по `ALLOW` обязателен, иначе аудит объявит проблемой ровно то, что уже закрыто.
