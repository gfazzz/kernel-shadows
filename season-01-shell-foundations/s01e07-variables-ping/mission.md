## Обстановка

У операции пятьдесят серверов и никакого мониторинга. Дмитрию нужна проверка
доступности каждые пять минут, с записью результатов.

Начинать с пятидесяти бессмысленно: сначала надо научиться достоверно проверять
**один** узел и отличать «отвечает» от «молчит» — не по тому, что команда
напечатала, а по тому, что она сообщила.

## Приказ

Собрать `check_host.sh` — принимает имя хоста, пингует его и печатает три строки:

```
HOST: <имя из аргумента>
STATUS: UP | DOWN
EXIT_CODE: <код возврата ping>
```

Это первый кирпич будущего мониторинга: в следующих сериях он вырастет
до обхода списка и журнала.

## Данные

| Что | Как получить |
|---|---|
| имя хоста | первый аргумент скрипта — `$1` |
| факт доступности | `ping -c 1 -W 2 "$host" >/dev/null 2>&1` |
| результат проверки | `code=$?` **сразу** после `ping` |
| статус | `code` равен `0` → `UP`, иначе `DOWN` |

Вывод `ping` не разбирается: он зависит от локали и версии. Решение принимается
по коду возврата.

## Критерии приёмки

- [ ] `artifacts/check_host.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Имя хоста берётся из аргумента и печатается в выводе.
- [ ] Код возврата `ping` сохраняется в переменную и печатается.
- [ ] Доступный хост → `STATUS: UP`, `EXIT_CODE: 0`.
- [ ] Недоступный → `STATUS: DOWN` (статус не захардкожен).
- [ ] Переменные используются в кавычках.
- [ ] `bash tests/test.sh` → 8 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash (Linux / macOS / WSL) |
| Сеть | **не нужна** — тест подменяет `ping` |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `ping`; в тесте заменяется заглушкой |
| Изоляция теста | мок-`ping` в отдельном `PATH`, временный каталог |

Заглушка отвечает по правилу: хосты `up-*` доступны, остальные молчат. Поэтому
результат одинаков на любой машине и не зависит от чужого файрвола.

## Выполнение

```bash
cp starter/check_host.sh artifacts/check_host.sh
# заменить TODO
bash artifacts/check_host.sh 8.8.8.8      # на своей машине, если есть сеть
bash tests/test.sh
```

Застрял — спроси LILITH или загляни в `man ping`. Скрипт пишешь сам.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `EXIT_CODE` всегда 0 | `$?` взят не сразу после `ping` | перенести `code=$?` вплотную к команде |
| всегда `UP` | статус захардкожен | статус вычислять из `code` |
| скрипт молча завершается на первом мёртвом хосте | включён `set -e` | убрать `-e`: неответ здесь штатная ситуация |
| `unbound variable` | `set -u` и необъявленная переменная | задать значение по умолчанию либо `${1:?сообщение}` |
| вывод `ping` мешает | не заглушён | добавить `>/dev/null 2>&1` |
| на macOS ждёт непривычно долго | `-W` там в миллисекундах | для переносимости — `-W 2000` или проверка платформы |

## После выполнения

Если тест зелёный — у тебя первый инструмент, который **принимает решение**, а не
просто печатает. Дальше он научится обходить список машин и вести журнал, а пока
проверь его на заведомо мёртвом адресе: инструмент, который не умеет сказать
«плохо», бесполезен именно в тот момент, когда плохо.

Если `STATUS` всегда `UP` — скрипт не проверяет, а сообщает. Такая «проверка»
опаснее отсутствия мониторинга: она создаёт уверенность, что всё в порядке,
и ночью никто не проснётся.
