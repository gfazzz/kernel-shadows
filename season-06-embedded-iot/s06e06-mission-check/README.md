## Точка, которую забыли заполнить

Ли Вэй открывает план вчерашнего полёта — обычный текстовый файл, который наземная станция загружает в аппарат.

```
QGC WPL 110
0	1	0	16	0	0	0	0	22.5410000	114.0520000	0	1
1	0	3	16	0	0	0	0	22.5463890	114.0520000	60	1
…
7	0	3	16	0	0	0	0	0.0000000	0.0000000	60	1
```

> — Седьмая точка. Ноль, ноль. Кто-то добавил строку и не заполнил координаты.

> — И что сделает дрон?

> — Полетит. Ноль-ноль — это Гвинейский залив, точка Нуль. Он развернётся туда и будет лететь, пока не кончится батарея или пока не сработает возврат. Он не знает, что это ошибка: для него это координаты.

Он листает дальше.

> — А вот восьмая. Кадр высоты ноль, у остальных три. Три — это «шестьдесят метров над точкой взлёта». Ноль — «шестьдесят метров над уровнем моря». Мы стоим на высоте сорок. Значит, между седьмой и восьмой точкой аппарат снизится на сорок метров, и никто этого не планировал.

> — Почему станция это не проверила?

> — Потому что станция проверяет синтаксис, а не смысл. Файл разобрался — значит, файл правильный. То, что маршрут уходит за пределы связи, задевает аэродром и не влезает в батарею, — не её забота. Это **твоя** забота, и проверить это можно ровно один раз: до вылета.

> **LILITH:** *«Есть два вида проверок: „файл разобрался" и „план осмыслен". Первую делает любой парсер, вторую — только тот, кто знает пределы конкретного аппарата и конкретной площадки. Первая защищает от опечатки, вторая — от аварии.»*

## Чему ты научишься

- Формату QGC WPL 110 и системам отсчёта высоты — они не взаимозаменяемы.
- Считать расстояние на сфере и не ломаться о мусор в координатах.
- Проверять план на земле: пределы высоты, нулевые координаты, отсутствие посадки, запретные зоны.
- Метанавыку: **в воздухе проверять поздно**. Валидатор дешевле полигона.

Подробнее, с историей и подводными камнями, — в [`theory.md`](theory.md).

## Теория: план полёта как данные

### Формат QGC WPL 110

```
INDEX CURRENT FRAME COMMAND P1 P2 P3 P4 LAT LON ALT AUTOCONTINUE
  $1     $2     $3     $4               $9 $10 $11     $12
```

| Поле | Смысл |
|---|---|
| `INDEX` | номер точки, начиная с 0; нулевая — дом |
| `CURRENT` | 1 у стартовой точки |
| `FRAME` | система отсчёта высоты: `0` — над уровнем моря, `3` — над точкой взлёта |
| `COMMAND` | `16` — точка маршрута, `20` — возврат домой, `21` — посадка |
| `LAT`/`LON`/`ALT` | координаты и высота |
| `AUTOCONTINUE` | продолжать ли автоматически |

Обычный текст с табуляциями — то есть план полёта можно проверять теми же инструментами, что и любой другой текстовый формат. В этом и смысл серии: **безопасность полёта здесь сводится к `awk`.**

### Что проверяет валидатор

| Правило | Что предотвращает |
|---|---|
| нумерация подряд с нуля | пропущенную или задвоенную строку |
| первая точка — дом (`16`, `current=1`) | план без точки старта |
| последняя команда — `20`/`21` | маршрут, который заканчивается зависанием в воздухе |
| нет координат `0,0` | полёт в точку Нуль |
| единый `FRAME` у путевых точек | необъявленное снижение на разницу высот |
| высота в `[alt_min, alt_max]` | нарушение регламента и полёт по земле |
| точка вне запретных зон | заход на аэродром |
| точка внутри геозоны | уход за пределы связи |
| плечо ≤ `leg_max` | перелёт вне зоны приёма |
| маршрут ≤ `total_max` | посадку на разряженной батарее |

Все пределы — **в файле, а не в коде**: у другого аппарата другая батарея, у другой площадки другие зоны. Проверки одинаковы, числа разные.

### Расстояние на сфере

```awk
function dist(la1, lo1, la2, lo2,   p1, p2, dp, dl, h) {
    p1 = rad(la1); p2 = rad(la2)
    dp = p2 - p1;  dl = rad(lo2 - lo1)
    h = sin(dp/2)^2 + cos(p1)*cos(p2)*sin(dl/2)^2
    return 2 * 6371000.0 * atan2(sqrt(h), sqrt(1-h))
}
```

Формула гаверсинуса — расстояние по дуге большого круга. Для маршрутов в километры разница с плоским приближением невелика, но плоское приближение требует помнить про сжатие меридианов с широтой (`cos(lat)`), и именно там ошибаются. Формула на сфере ошибиться не даёт.

### Как считать длину, когда в данных мусор

Нулевая точка ломает расчёт: расстояние до неё — двенадцать тысяч километров, и общая длина маршрута теряет смысл. Два варианта поведения:

1. посчитать честно и выдать абсурдное число;
2. исключить заведомо испорченные точки из расчёта и сказать об этом отдельно.

Второй лучше: **отчёт не должен маскировать одну ошибку другой.** «Маршрут 24 941 км» скрывает настоящую находку — незаполненную точку. Список из «точка 7 не заполнена» и «маршрут 8 640 м без неё» полезнее.

Про `.plan` в JSON, `MAV_CMD` целиком, `DO_JUMP` и условные команды, `SITL` и предполётные проверки самого автопилота — в [`theory.md`](theory.md).

## Проверка: LILITH задаёт вопросы

**LILITH:** *«Наземная станция загрузила план без ошибок. Разве это не проверка?»*

<details>
<summary>Подумай 30 секунд</summary>

Это проверка формата, а не смысла. Станция убедилась, что в каждой строке двенадцать полей, что числа — числа, а команды ей известны. Файл, где все точки лежат в Гвинейском заливе, разберётся так же успешно.

Разница фундаментальная: **синтаксическая проверка не знает предметной области.** Она не в курсе, какая у аппарата батарея, где стоит аэродром и на какой высоте площадка. Всё это — внешние знания, которые надо принести и применить.

Тот же зазор существует везде: YAML-файл Ansible из [`s04e10`](../../season-04-devops-automation/s04e10-ansible-check/) разбирается корректно и при этом описывает неверную конфигурацию; конфигурация `sshd` проходит `sshd -t` и оставляет вход по паролю. Проверка «разобралось» никогда не заменяет проверку «правильно».
</details>

**LILITH:** *«Почему пределы обязательно выносить в файл — их же можно вписать в скрипт?»*

<details>
<summary>Ответ</summary>

Можно, и работать будет — ровно на одном аппарате и одной площадке. Дальше начинается: второй дрон с батареей побольше, вторая площадка на другой высоте, третья с аэродромом рядом. Скрипт с зашитыми числами придётся копировать и править, и через месяц копий будет пять с разными правилами и одинаковым именем.

Разделение отвечает на два разных вопроса. **Код отвечает „как проверять"** — это логика, она одна. **Данные отвечают „что допустимо"** — это факты о конкретной технике и месте, и их много. Смешивать их — значит дублировать логику ради разных фактов.

Побочная выгода видна в этой серии: тест проверяет, что скрипт действительно читает пределы, а не делает вид. Он подставляет ослабленные ограничения и требует, чтобы часть нарушений исчезла. Скрипт с зашитыми числами это не пройдёт — и это правильно, потому что такой скрипт **выглядит** работающим, а на другом аппарате молча даёт неверный ответ.
</details>

## Задание: `check_mission.sh`

Артефакт — `artifacts/check_mission.sh`.

```bash
cp starter/check_mission.sh artifacts/
bash tests/test.sh
```

```
check_mission.sh [--limits ФАЙЛ] [--nofly ФАЙЛ] ПЛАН.waypoints
```

| Требование | Почему |
|---|---|
| заголовок `QGC WPL` проверяется **до** разбора | разбирать чужой формат как свой опаснее, чем отказаться |
| десять правил из таблицы выше | каждое закрывает свой класс аварии |
| все пределы — из `--limits`, зоны — из `--nofly` | у другого аппарата они другие |
| по строке на нарушение + итог `Нарушений: N` | отчёт должен называть точку, а не только факт |
| коды `0` / `1` / `2` / `3` | вызывающий конвейер различает причины |
| нулевые точки исключаются из расчёта длины | одна ошибка не должна маскировать другую |

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Ограничения и зоны удобно читать в `BEGIN` через `getline line < FILE`.

План — в массивы: `idx[++m]=$1; frame[m]=$3; cmd[m]=$4; lat[m]=$9; lon[m]=$10; alt[m]=$11`.

Гаверсинус — в подсказке внутри стартера, вместе с `rad()`.

Точка внутри зоны, если расстояние до центра ≤ радиуса.

Эталон — в `solution/`, там у каждой проверки написано, что она предотвращает.
</details>

## Разбор типичных ошибок

**Вписать пределы в скрипт.** Работает на одном аппарате; на втором молча даёт неверный ответ — а это хуже, чем не работать вовсе.

**Разбирать файл, не проверив заголовок.** CSV с координатами «разберётся» как план полёта, и вердикт будет выдан по мусору.

**Посчитать длину вместе с нулевой точкой.** Абсурдное число в итоге прячет настоящую находку.

## Debriefing

**Он летел туда, куда его послали**

Макс прогоняет вчерашний план: десять нарушений. Незаполненная точка, разные системы отсчёта высоты, заход в зону аэродрома, два плеча за пределом связи, маршрут в полтора раза длиннее запаса батареи и никакой посадки в конце.

> — Вот теперь картина целиком, — говорит Ли Вэй. — Аппарат не сломался. Он честно выполнял то, что ему дали. Возврат по потере навигации спас его от нас же.

Он подшивает отчёт к папке полигона.

> — И последнее на сегодня. Валидатор проверяет план. Но аппарат должен уметь принять правильное решение и тогда, когда планировать уже некогда: связь пропала, батарея кончается, его уносит ветром. Это уже не проверка на земле — это настройки, которые он унесёт с собой в воздух.
