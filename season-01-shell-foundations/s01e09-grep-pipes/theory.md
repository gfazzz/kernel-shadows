## grep — поиск по шаблону

```bash
grep "ERROR" app.log          # строки, содержащие ERROR
```

| Флаг | Действие |
|------|----------|
| `-i` | игнорировать регистр |
| `-v` | инверсия (строки БЕЗ шаблона) |
| `-c` | только количество совпадений |
| `-n` | номера строк |
| `-E` | extended regex (`|`, `+`, `{}`) |
| `-o` | вывести только совпавшую часть |
| `-A/-B/-C N` | N строк после/до/вокруг |

## Regex (базовый уровень)

| Шаблон | Значение |
|--------|----------|
| `.` | любой символ |
| `*` | 0+ повторов предыдущего |
| `+` | 1+ (с `-E`) |
| `^` / `$` | начало / конец строки |
| `[0-9]` | класс символов (цифра) |
| `[^0-9]` | отрицание класса |
| `a|b` | ИЛИ (с `-E`) |

```bash
grep -E '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log   # похожее на IP
grep -E 'ERROR|WARN' app.log                           # ERROR или WARN
grep '^[0-9]' file                                     # строки, начинающиеся с цифры
```

## Pipes — конвейер

`|` направляет stdout одной команды в stdin следующей:

```bash
grep -v ' 200 ' access.log | wc -l      # отфильтровать → посчитать
grep ' 404 ' access.log | head -5        # найти → взять первые 5
```

**Unix-философия «Do One Thing Well»:** маленькие специализированные инструменты
(`grep` фильтрует, `awk` извлекает поля, `sort` сортирует, `uniq` считает,
`wc` считает строки) соединяются в мощные цепочки как LEGO.

```
[файл] → grep (фильтр) → awk (поля) → sort → uniq → [результат]
```

> Pipe придуман в 1970-х и всё ещё работает. Одна команда — одна задача; сила — в комбинации.

## Про статус-фильтр

`grep -vE ' 200 '` — грубый, но наглядный приём: «нормальный» ответ веб-сервера —
`200 OK`; во время атаки растут `401/403/404/5xx`. Точную привязку к полю статуса
(`$9` в Apache Combined) сделаем `awk`'ом в следующей серии.
