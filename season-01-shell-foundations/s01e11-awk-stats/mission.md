## Обстановка

Подозрительные запросы отделены от нормальных, но их всё ещё сотни. Глаз не
считает: он видит адреса, а не частоты, и после тридцатой строки перестаёт
различать даже адреса.

Вопрос Анны звучит иначе, чем предыдущий. Не «какие запросы», а «кто и сколько
раз». Это уже не фильтрация, а агрегация: строку надо разложить на поля, взять
одно и посчитать повторы.

## Приказ

Собрать `top_attackers.sh` — принимает журнал и число N, печатает N самых
активных адресов с количеством запросов, по убыванию:

```
=== Топ-3 IP по числу запросов ===
      5 66.66.66.66
      3 77.77.77.77
      1 10.0.0.5
```

Использование: `./top_attackers.sh access.log 5`. Без второго аргумента — топ-5.

## Данные

| Что | Как |
|---|---|
| журнал / N | `log="${1:?…}"`, `n="${2:-5}"` |
| проверка файла | `[ -f "$log" ]` до работы, иначе stderr + `exit 1` |
| адрес из строки | `awk '{print $1}' "$log"` — **одинарные** кавычки |
| сгруппировать | `sort` (без него `uniq` посчитает неверно) |
| посчитать | `uniq -c` |
| ранжировать | `sort -rn` — по числу, по убыванию |
| ограничить | `head -n "$n"` |

Формат Apache Combined: адрес — первое поле, статус — девятое, размер — десятое.

## Критерии приёмки

- [ ] `artifacts/top_attackers.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Адрес извлекается через `awk` (или эквивалент), а не вырезанием подстроки.
- [ ] Количество запросов у каждого адреса посчитано верно.
- [ ] Первая строка рейтинга — действительно самый активный адрес (есть `sort -n`).
- [ ] Порядок строго по убыванию: `10` не может стоять выше `9`.
- [ ] `head -n N` ограничивает вывод; N берётся из аргумента.
- [ ] Отсутствующий файл → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 10 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils (Linux / macOS / WSL) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`awk`, `sort`, `uniq`, `head`) |
| Изоляция теста | фикстура-журнал во временном каталоге |

Записи в фикстуре намеренно перемешаны: без `sort` перед `uniq -c` один адрес
распадётся на несколько групп, и тест это увидит. Ожидаемые числа тест
**считает по фикстуре**, а не хранит константами.

собирается.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| выводятся пустые строки | двойные кавычки вокруг программы `awk` | одинарные: `awk '{print $1}'` |
| один адрес встречается в рейтинге дважды | нет `sort` перед `uniq -c` | добавить `sort` |
| `10` стоит выше `9` | сортировка как текст | `sort -rn`, а не `sort -r` |
| рейтинг по возрастанию | нет `-r` | `sort -rn` |
| в топе обычные пользователи | считается нефильтрованный журнал | сначала `grep -vE ' 200 '` |
| выводится весь журнал | нет `head -n "$n"` | добавить ограничение |
| нет файла → пустой вывод и код 0 | нет проверки входа | `[ -f "$log" ]`, иначе `exit 1` |

## После выполнения

Зелёный тест означает, что сотни строк свернулись в короткий список, который
понимает человек, никогда не открывавший терминал. `top_attackers.sh` — второе
звено конвейера анализа логов в `shadow_toolkit` (см. [`PROJECTS.md`](../../PROJECTS.md)).

Дальше Анне нужен не вывод команды, а документ: объём, распределение статусов,
топ адресов и сверка со списком известных угроз — в одном файле. Это капстоун
эпизода и первый случай, когда скрипт не выполняет работу сам, а **склеивает**
готовые инструменты.
