## II. Теория: список превращается в стену

### Блокировка одного адреса

```bash
sudo ufw deny from 185.220.101.47              # один адрес
sudo ufw deny from 185.220.101.0/24            # целая подсеть
sudo iptables -A INPUT -s 185.220.101.47 -j DROP   # то же уровнем ниже
```

Для подсети правило одно вместо двухсот пятидесяти шести — если атакующие адреса группируются, блокировать стоит блоками. Но осторожно: в подсети может оказаться и что-то нужное.

### Генерация вместо применения

```bash
{
    echo '#!/usr/bin/env bash'
    while IFS= read -r line; do
        case "$line" in \#*|'') continue ;; esac
        echo "ufw deny from ${line%% *}"
    done < botnet_ips.txt
} > block_rules.sh
```

Получается файл, который можно прочитать, сохранить в репозиторий, показать коллеге и применить осознанно: `sudo bash block_rules.sh`.

Три причины, по которым так делают с любыми массовыми изменениями:

**Проверяемость.** Ошибка в исходных данных видна до того, как что-то произошло. `grep` по собственному адресу в сгенерированном файле занимает секунду.

**Повторяемость.** Файл можно применить на второй машине, положить в систему контроля версий, сравнить с прошлой версией и понять, что изменилось.

**Обратимость.** Из того же списка тривиально генерируется файл отмены (`ufw delete deny from …`), а из скрипта, который применял на лету, — ничего.

### Про масштаб

Восемьсот сорок семь отдельных правил — рабочее, но не лучшее решение: каждый входящий пакет проверяется по цепочке сверху вниз. Для больших списков существует `ipset` — хеш-набор адресов, который проверяется одним правилом за постоянное время:

```bash
sudo ipset create botnet hash:ip
sudo ipset add botnet 185.220.101.47
sudo iptables -A INPUT -m set --match-set botnet src -j DROP
```

Про `ipset`, ограничение частоты, SYN cookies и `fail2ban` — в [`theory.md`](theory.md).

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«Почему скрипт генерирует правила, а не вызывает `ufw` сам?»*

<details>
<summary>Подумай 30 секунд</summary>

Потому что на входе — данные, которые ты не составлял, а на выходе — необратимое изменение доступа к машине. Если в списке окажется твой адрес, адрес шлюза или строка мусора, скрипт, применяющий на лету, сделает это мгновенно и без предупреждения.

Сгенерированный файл разрывает эту цепочку: между «прочитали данные» и «изменили систему» появляется момент, когда можно посмотреть. Плюс файл повторяем и версионируется — то есть из разового действия получается инструмент.
</details>

**LILITH:** *«Восемьсот сорок семь правил в цепочке — чем это плохо?»*

<details>
<summary>Ответ</summary>

Тем, что цепочка просматривается для каждого пакета сверху вниз до первого совпадения. При пятидесяти тысячах пакетов в секунду это заметная работа процессора — и часть её оплачивает как раз атакующий трафик, ради которого правила и добавлялись.

Решение — `ipset`: набор адресов в хеш-таблице и одно правило, ссылающееся на него. Проверка за постоянное время независимо от размера набора.
</details>

```bash
{
  echo '#!/usr/bin/env bash'
  while IFS= read -r line; do
```

Сборка в группу `{ … } > файл` — из s01e12, фильтры цикла — из s01e08. Эталон — в `solution/`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Пропускать во входе всё подряд.** Строка `не знаю чей это адрес` превратится в правило `ufw deny from не` — синтаксически валидное для bash и бессмысленное для `ufw`. Минимальная проверка формата отсеивает мусор до того, как он попадёт в файл, который кто-то запустит под root.

**Не отделять комментарий от адреса.** `185.220.101.47     # Tor exit node` без обрезки даст правило с лишними словами. Первое поле строки — `${line%% *}`, остальное игнорируется.

**Считать нулевой результат успехом.** Пустой список, неверный путь, файл в другой кодировке — во всех случаях получится файл правил без единого правила, и он будет успешно применён. Ноль правил при непустом входе означает, что что-то не так, и код возврата должен это сообщать.

## V. Двадцать минут

Ты генерируешь файл и первым делом ищешь в нём то, чего там быть не должно.

```
$ grep -cE 'ufw deny from' block_rules.sh
847
$ grep -E '10\.50\.|172\.20\.' block_rules.sh
$ grep -E 'ufw deny from [^0-9]' block_rules.sh
```

Пусто, пусто. Алекс просматривает первые тридцать строк, кивает, применяет.

Графики реагируют через полторы минуты: входящий трафик падает с четырёхсот восьмидесяти мегабит до сорока, нагрузка сползает к трём. Двадцать минут от звонка до отбоя.

Ты откидываешься на спинку и только сейчас замечаешь, что за окном светло.
