## Полсотни машин и одна находка

На доске три строки — то, что режим проверки нашёл на двадцать седьмой:

чужой ключ в authorized_keys

> — Одна **найденная**, — поправляет Клаус. — Прогон был по боевому контуру. В стенде мы не смотрели, а ключ, который добавили на двадцать седьмую, добавить на другие было ровно так же легко. Приводите к описанию все пятьдесят.

Макс открывает редактор и делает то, что кажется очевидным: переписывает вчерашние команды в YAML.

```yaml
- name: закрыть каталог ключей
  ansible.builtin.shell: chmod 700 /etc/ssl/private
```

Клаус смотрит на это секунд десять.

> — Запусти с `--check`.

```
TASK [закрыть каталог ключей] **************************************************
skipping: [prod-web01.shadow.io]
skipping: [prod-web02.shadow.io]
```

> — Помнишь вчерашние две задачи, которые молчали в режиме проверки? Ты только что сделал такую же. Своими руками, добровольно, на ровном месте.

> **LILITH:** *«Декларативно — это не „в YAML". Playbook из команд оболочки — это скрипт с отступами: без diff, без режима проверки, без ответа на вопрос „изменится ли что-нибудь".»*

## Чему ты научишься

- Тому, что модуль знает целевое состояние: `ansible.builtin.package` вместо `apt-get install`.
- Handlers: перезапуск как следствие изменения, а не отдельный шаг списка.
- Области видимости `become` и тому, зачем `changed_when` у неизбежного `command`.
- Метанавыку: **описание состояния против списка действий**. Проверяемый признак один: можно ли спросить систему, что изменится, ничего не меняя.

Подробнее, с историей и подводными камнями, — в [`theory.md`](theory.md).

## Теория: чем задача отличается от команды

### Модуль знает состояние

```yaml
- name: каталог закрытых ключей закрыт
  ansible.builtin.file:
    path: /etc/ssl/private
    state: directory
    mode: "0700"
```

Модуль `file` умеет три вещи, которых не умеет `chmod`: сказать, отличается ли текущее состояние от описанного; показать разницу; ничего не делать, если всё уже так. Отсюда и `ok:` вместо `changed:` на втором прогоне.

| Вместо команды | Модуль |
|---|---|
| `chmod`, `chown`, `mkdir`, `ln -s` | `file` |
| `apt-get install` | `apt` (`package`) |
| `systemctl restart/enable` | `systemd` |
| `useradd`, `usermod` | `user`, `group` |
| `echo … > файл` | `copy` (`content:`) |
| `sed -i` по строке | `lineinfile` (с `regexp:`) |
| `cp` с подстановкой | `template` |

`command` остаётся для того, для чего модуля нет, — и тогда его нужно **объявить безвредным явно**:

```yaml
- name: контрольные суммы системных файлов
  ansible.builtin.command: debsums -c
  register: sums
  changed_when: false        # эта задача только смотрит
  check_mode: false          # и её можно выполнять даже в режиме проверки
```

Без этой пары аудит целостности молчит ровно там, где он нужен, — как в [`s04e10`](../s04e10-ansible-check/).

### Перезапуск — следствие, а не шаг

```yaml
  handlers:
    - name: перезапустить sshd
      ansible.builtin.systemd: { name: sshd, state: restarted }

  tasks:
    - name: вход root по ssh запрещён
      ansible.builtin.lineinfile:
        path: /etc/ssh/sshd_config
        regexp: '^[#[:space:]]*PermitRootLogin[[:space:]]'
        line: PermitRootLogin no
        validate: /usr/sbin/sshd -t -f %s
      notify: перезапустить sshd
```

Три вещи в этих семи строках, и каждая закрывает свой способ навредить полусотне машин. **`notify` + handler** — служба трогается только если файл изменился; задача с `state: restarted` перезапускала бы sshd каждый прогон. **`regexp:`** — строка заменяется, а не дописывается: без него после десяти прогонов в файле десять строк `PermitRootLogin no`. **`validate:`** — результат проверяется до подмены файла; сломанный `sshd_config` на пятидесяти машинах означает, что чинить их придётся через консоль машинного зала.

### Область видимости прав

```yaml
- hosts: production
  become: false          # подключаемся как ops
  tasks:
    - name: …
      become: true       # root просит та задача, которой он нужен
```

`become: true` на уровне плея выдаёт root всем задачам сразу, включая те, что просто читают. Это то же решение, что `User=` в юните из [`s03e05`](../../season-03-system-administration/s03e05-systemd-service/) и `user:` в [`s04e06`](../s04e06-compose/), только на пятидесяти машинах.

Про роли, шаблоны Jinja2, `loop`, `ansible-vault` и `ansible-lint` — в [`theory.md`](theory.md).

## Проверка: LILITH задаёт вопросы

**LILITH:** *«Задача `shell: chmod 700 /etc/ssl/private` делает ровно то, что нужно. Чем она плоха?»*

<details>
<summary>Подумай 30 секунд</summary>

Тем, что делает. Модуль `file` не делает, а **приводит к состоянию** — и потому умеет ответить на вопрос «а нужно ли».

Практических последствий четыре: в режиме проверки задача пропускается (слепая зона, созданная своими руками); `--diff` ничего не покажет — показывать нечего; каждый прогон отчитается `changed`, и настоящие изменения утонут в шуме; на машине, где каталога нет, `chmod` вернёт ошибку, а `file: state=directory` создаст его.

Признак, по которому это ловится в чужом playbook: **вторая подряд строка `changed` при неизменившейся системе**.
</details>

**LILITH:** *«Перезапуск службы сделан обычной задачей, а не handler. Что произойдёт?»*

<details>
<summary>Ответ</summary>

Служба будет перезапускаться при каждом прогоне — включая те, где не изменилось ничего.

На одной машине это незаметно. На пятидесяти, в рабочее время, при регулярном прогоне из конвейера — это плановый разрыв всех соединений по расписанию, причину которого будут искать в сети.

Handler выполняется один раз в конце плея и только если его позвали. Это и есть разница между «сделай» и «сделай, если понадобилось».
</details>

## Задание: привести пятьдесят машин к описанию

Артефакт — `artifacts/harden.yml`.

```bash
cp starter/harden.yml artifacts/
bash tests/test.sh
```

| Требование | Почему |
|---|---|
| плей адресован группе, а не `all` | в инвентаре есть и стенд |
| `become` у задач, а не у плея | root просит тот, кому он нужен |
| у каждой задачи `name` | иначе прогон нечитаем |
| не больше одной задачи на `command`/`shell` | остальное умеют модули |
| у команды `changed_when` или `creates` | иначе ansible не знает, что изменится |
| перезапуск — только через handler и `notify` | иначе служба падает каждый прогон |
| `lineinfile` с `regexp:` и `validate:` | иначе строка дублируется, а ошибка уезжает на все машины |
| `no_log: true` у задачи с секретом | иначе значение попадёт в вывод и в diff |
| ни одного `ignore_errors: true` | это «`\|\| true`» из [`s04e07`](../s04e07-ci-pipeline/) |
| `tags` не меньше чем у трёх задач | прогон должен ограничиваться темой |
| закрыты все три находки [`s04e10`](../s04e10-ansible-check/) | ключи, `PermitRootLogin`, права `0700` |

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

`authorized_keys` приводится к описанию не добавлением, а заменой файла целиком: `template` со списком доверенных ключей. Иначе чужой ключ останется.

Секрет в playbook не пишут: `content: "{{ registry_password }}"`, а само значение — в зашифрованном `group_vars`.

Эталон — в `solution/`, там прокомментировано, что именно закрывает каждая строка.
</details>

## Разбор типичных ошибок

**Перевести команды в YAML и решить, что это Ansible.** Формат сменился, свойства — нет: ни идемпотентности, ни diff, ни режима проверки.

**Поставить `become: true` на плей, потому что «всё равно нужно».** Нужно четырём задачам из восьми. Остальные получают root бесплатно и навсегда.

**Забыть `validate` у правки `sshd_config`.** Единственная ошибка в этом файле, разъехавшаяся по пятидесяти машинам, закрывает вход на все пятьдесят одновременно. Именно поэтому `validate` придуман.
