## Теория: `awk` + `sort`/`uniq` (один концепт: извлечь и посчитать)

**`awk`** разбивает строку на поля (по пробелам) и печатает нужное:

```bash
awk '{print $1}' access.log        # $1 = первое поле = IP
awk '{print $1, $9}' access.log    # IP и HTTP-статус (Apache Combined)
awk -F':' '{print $1}' /etc/passwd # -F: свой разделитель
```

> Это первое «официальное» появление `awk` в курсе — раньше он по ошибке использовался до объяснения (forward-dep T1). Теперь он на своём месте.

**`sort | uniq -c`** считает повторы (`uniq` видит только соседей → сначала `sort`), а `sort -rn` ранжирует по числу:

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
```

Это золотой идиом анализа логов. Детали полей, `$NF`, флаги `sort`/`uniq` — в [`theory.md`](theory.md).

> **LILITH:** *«`sort` видит строки, не числа. Забудешь `-n` — получишь 100 перед 20. И помни: `uniq` считает только соседние повторы, поэтому перед ним всегда `sort`.»*

## Проверка «в мире сюжета»

**Ольга:** *«Почему `uniq -c` без `sort` перед ним даст неправильную статистику?»*

<details>
<summary>Подумай 30 секунд</summary>

`uniq` схлопывает только **соседние** одинаковые строки. Если один IP разбросан по логу вперемешку с другими, без предварительной `sort` он попадёт в несколько отдельных групп и посчитается неверно. `sort` собирает одинаковые строки вместе — тогда `uniq -c` считает правильно.
</details>

**Ольга:** *«Рейтинг вышел `10 100.0.0.5`, `9 66.66.66.66`… но 66-й явно активнее. Что не так с `sort`?»*

<details>
<summary>Ответ</summary>

Забыт `-n`: `sort` сравнил числа как строки, и «10» встало выше «9». Нужен `sort -rn` — числовая сортировка по убыванию. Классическая ошибка, которая ломает любой топ.
</details>
