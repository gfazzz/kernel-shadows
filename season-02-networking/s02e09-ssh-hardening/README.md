## II. Теория: конфигурация и каналы

### Что закрывают в `sshd_config`

```
PermitRootLogin no             # root — только через sudo от обычного пользователя
PasswordAuthentication no      # только ключи
PermitEmptyPasswords no
X11Forwarding no               # на сервере не нужен
MaxAuthTries 3
AllowGroups ssh-users          # явный список тех, кому можно
```

Каждая строка убирает конкретный способ войти. `PermitRootLogin no` лишает смысла перебор самой ценной учётной записи; `PasswordAuthentication no` обесценивает перебор паролей целиком — сервер просто не предложит такой метод.

**Закомментированная строка настройкой не является.** `#PermitRootLogin no` — это документация значения по умолчанию, а не запрет. Значение по умолчанию, к тому же, менялось между версиями OpenSSH. Аудит должен смотреть на активные строки, иначе конфигурация «выглядит закалённой», а поведение остаётся прежним.

Порядок применения:

```bash
sudo sshd -t                       # проверить синтаксис — обязательно
sudo systemctl reload ssh          # применить (systemd — Season 3)
```

Перед выключением паролей стоит убедиться, что ключ работает, **и держать вторую открытую сессию**: уже подключённые сессии не разрываются, и через них можно откатить ошибку.

### Как прячут трафик

SSH умеет пробрасывать порты внутри своего шифрованного соединения:

```bash
ssh -L 8080:localhost:80 user@server   # локальный порт → сервис на той стороне
ssh -R 9000:localhost:3000 user@server # порт на сервере → сервис на твоей машине
ssh -D 1080 user@server                # SOCKS-прокси: весь трафик приложения через сервер
```

Снаружи видно единственное SSH-соединение — не то, что внутри него.

VPN решает ту же задачу шире: шифрует **весь** трафик машины, а не отдельный канал. Современный выбор — WireGuard: пара ключей, короткий конфиг, шифр ChaCha20-Poly1305. Детали туннелей, VPN и остальных директив — в [`theory.md`](theory.md).

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«В конфигурации есть `PermitRootLogin no`, но строка закомментирована. Она работает?»*

<details>
<summary>Подумай 20 секунд</summary>

Нет. Символ `#` делает строку комментарием, а не настройкой — обычно так в поставке отмечают значение по умолчанию. Действовать будет именно умолчание, а оно менялось: в старых версиях OpenSSH это `yes`, в новых — `prohibit-password`.

Отсюда правило аудита: читать только активные строки. Конфигурация, где нужные значения присутствуют исключительно в комментариях, — самый неприятный случай, потому что выглядит она правильной.
</details>

**LILITH:** *«Фаервол настроен, вход по ключам. Зачем ещё шифровать канал?»*

<details>
<summary>Ответ</summary>

Потому что это три разные задачи. Фаервол решает, кого пускать. Ключи решают, кто именно вошёл. Ни то, ни другое не влияет на то, что видит наблюдатель на пути между узлами.

При перехвате трафика видно, кто с кем и когда соединяется, какие имена запрашивает, какого объёма данные передаёт, — и всё содержимое, если протокол не шифрован. Туннель или VPN оставляют наблюдателю только факт соединения.

Слои независимы и не заменяют друг друга: убери любой — исчезнет именно та защита, которую он давал.
</details>

## IV. Задание: капстоун сезона

Здесь артефакт — не скрипт, а **сама конфигурация**. В `starter/sshd_config` лежит то, что стоит на боевых машинах прямо сейчас: пароли включены, root пускают напрямую, попыток шесть, список допущенных не задан. Твоя задача — закалить её, не сломав.

```bash
cp starter/sshd_config artifacts/sshd_config
# править artifacts/sshd_config
bash tests/test.sh
```

Тест читает файл **так же, как его читает `sshd`**: берёт первое активное вхождение директивы, игнорирует комментарии, не смотрит на регистр и допускает отступ. Поэтому «дописать правильную строку в конец» не сработает — проверка это увидит и объяснит почему.

Что должно получиться (полный список — в [`mission.md`](mission.md)):

```
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
MaxAuthTries 3
AllowGroups ssh-users
LogLevel VERBOSE
```

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Проверить, как твой файл прочитает сервер:

```bash
grep -iE '^[[:space:]]*PermitRootLogin([[:space:]]|=)' artifacts/sshd_config \
  | grep -vE '^[[:space:]]*#' | head -1
```

На живой машине то же самое делает `sudo sshd -T | grep -i permitrootlogin` — он показывает не то, что ты написал, а то, что сервер понял. Эталон — в `solution/`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Закомментировать опасную строку вместо исправления.** `#PermitRootLogin yes` не запрещает root-вход — он убирает настройку, и начинает действовать умолчание, которое менялось между версиями OpenSSH. Правильное значение должно быть задано **явно**.

**Дописать нужное в конец файла.** В отличие от большинства конфигураций Unix, `sshd_config` берёт **первое** вхождение директивы. Строка, добавленная ниже старой, не переопределит её и создаст ровное ощущение, что всё исправлено.

**Выключить пароли, забыв про `KbdInteractiveAuthentication`.** На системах с PAM это второй путь к парольному входу: `PasswordAuthentication no` сам по себе закрывает не всё. Пара директив работает только вместе.

## V. Двадцать три ноль-ноль

Правки применяются по одной, с проверкой синтаксиса и второй открытой сессией. Первым идёт `PermitRootLogin no`, последним — `PasswordAuthentication no`, и после каждого шага Дмитрий из соседнего окна подтверждает, что зашёл по ключу.

На двух машинах из тридцати четырёх правка не срабатывает. Разбираешься: в обоих случаях нужная строка была дописана в конец файла, а выше стояла старая. `sshd -T` показывает `yes`, хотя в файле ниже написано `no`.

> — Это единственная конфигурация в системе, которая берёт первое значение, а не последнее, — говорит Алекс. — Один раз обжигаешься и запоминаешь навсегда.

К девяти вечера пароли выключены везде. К одиннадцати Дмитрий поднимает VPN-узел в Цюрихе, и все пятеро подключаются через него.

> **Анна:** — Он пробовал смотреть последние два часа. Видел поток шифротекста и ничего больше.
> **Виктор:** — Значит, теперь мы разговариваем.

Ты сидишь у окна с видом на мокрый Цюрих и считаешь: шестнадцать дней назад ты не знал, что такое TCP, и всерьёз думал, что «сервер лежит» — это диагноз, а не вопрос.
