## Обстановка

Одиннадцать восемьсот мегабит в канал на десять тысяч. Шестнадцать процентов
пакетов теряется до узла, отклик вырос с двенадцати миллисекунд до девятисот
сорока. Средний размер пакета — тысяча четыреста восемьдесят байт, источники
настоящие: это усиление через отражение.

Фильтр на узле бесполезен: трафик умирает в канале, до правил доезжает то, что
влезло. Единственная доступная мера — попросить провайдера перестать передавать
трафик к части адресов. Он перестанет передавать **весь** трафик к ним,
включая законный.

Девять префиксов. У каждого свой трафик, своя доля законного и своя ценность,
согласованная с заказчиком заранее. Три из девяти отдавать нельзя по договору.

## Приказ

Написать `artifacts/blackhole.py`: выбрать набор префиксов, после сброса
которых остаток укладывается в допустимую занятость канала, а потеря ценности
наименьшая.

```bash
cp starter/blackhole.py artifacts/
python3 artifacts/blackhole.py data/prefixes.txt data/policy.txt
bash tests/test.sh
```

## Дано

| Файл в `data/` | Что в нём |
|---|---|
| `prefixes.txt` | префикс, служба, трафик, из него законный, ценность, неприкосновенность |
| `policy.txt` | ёмкость канала и допустимая занятость в процентах |
| `uplink.txt` | что с каналом сейчас: занятость, потери, отклик |

## Формат вывода

```
PREFIX <cidr> service=<имя> total_mbps=<n> legit_mbps=<n> value=<n> action=<keep|blackhole>
TOTAL before_mbps=<n> after_mbps=<n> capacity_mbps=<n> limit_mbps=<n> headroom_pct=<n>
LOST value=<n> legit_mbps=<n> prefixes=<n>
GREEDY value=<n> worse_by=<n>
VERDICT <fits|impossible>
```

Строки `PREFIX` идут в порядке входного файла — так отчёт сверяется с ним
построчно. `LOST` и `GREEDY` печатаются только при `fits`.

Код возврата: `0` — остаток влезает, `1` — не влезает ни при каком допустимом
выборе, `2` — вход не разобран.

## Что решить

| Вопрос | Условие |
|---|---|
| предел | `max_util_pct` от ёмкости, целочисленно |
| что можно отдавать | всё, кроме `critical=yes` |
| критерий | наименьшая потеря ценности |
| при равной потере | воспроизводимый выбор одного набора из нескольких |
| для сравнения | что дал бы жадный выбор — сначала дешёвое за мегабит |
| когда решения нет | неприкосновенное само по себе шире предела |

Прежде чем писать эвристику, посчитай, сколько у задачи вариантов. Это тот
случай, когда думать про приближение дороже, чем посчитать точно.

## Критерии приёмки

- [ ] Остаток укладывается в предел.
- [ ] Потеря ценности — наименьшая возможная при данных ограничениях.
- [ ] Неприкосновенные префиксы не отданы ни при каких настройках политики.
- [ ] Набор минимален: без любого из отданных остаток уже не влезает.
- [ ] `after_mbps` и `LOST` сходятся с построчными значениями в самом выводе.
- [ ] Жадный вариант посчитан и его разница с наилучшим показана.
- [ ] Порядок строк `PREFIX` совпадает с входным файлом.
- [ ] Неверный вызов, битая строка и неположительная ёмкость дают код `2`.
- [ ] Два прогона подряд дают побайтово одинаковый вывод.
- [ ] `bash tests/test.sh` → 38 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| Python | 3.8+ |
| Сеть | не нужна |
| Доступ к маршрутизатору | **не нужен** — решение считается, а не применяется |
| Внешние пакеты | нет |
| Изоляция теста | свои файлы в `mktemp -d`, данные только читаются |

Тест решает ту же задачу независимым перебором в `awk` и требует совпадения
потери ценности с наименьшей возможной. Любой набор с такой же потерей
принимается: проверяется свойство решения, а не его форма.

Отдельно проверяется, что данные не выродились: трафик не влезает в предел
(иначе решать нечего), жадный выбор хуже наилучшего (иначе сравнивать нечего),
а неприкосновенные сами по себе в канал влезают.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| потеря больше наименьшей | написана жадность | посчитать точно: вариантов 512 |
| «лишних префиксов отдано» | сброшено с запасом | набор обязан быть минимальным |
| вывод меняется между прогонами | наборов с равной потерей несколько | доопределить порядок предпочтения |
| неприкосновенные в blackhole | признак не прочитан | шестая колонка `prefixes.txt` |
| `impossible` на основных данных | предел посчитан в мегабайтах | `max_util_pct` — проценты от ёмкости |
| трассировка вместо кода 2 | вход не проверен | ловить ошибки чтения и разбора |
| деление на ноль | ёмкость взята как есть | неположительная ёмкость — испорченный вход |
| `after_mbps` не сходится с строками | итог посчитан отдельно от решения | считать по тому же набору |

## После выполнения

Зелёный тест означает, что решение можно назвать провайдеру и объяснить
заказчику: вот что отдано, вот сколько это стоило, вот почему не иначе.

Главное, что стоит унести: **точка фильтрации должна быть выше точки
насыщения.** Когда переполнен канал, на узле не лечится ничего, и вся
изобретательность в правилах — потерянное время.

И второе: **очевидное решение здесь неверно.** Жадный выбор выглядит
естественно, даёт правдоподобный ответ и теряет на четверть больше. Разницу
видно только тогда, когда посчитаны оба варианта, — поэтому программа печатает
и тот, и другой.

## Кумулятивность

Различение «что именно исчерпано» — метод из
[`s08e01`](../s08e01-first-wave/) и [`s07e08`](../../season-07-production-advanced/s07e08-bottleneck/):
здесь исчерпана полоса, и это меняет не выбор лечения, а место, где лечение
вообще возможно.

Ценность служб, названная **заранее**, — та же конструкция, что бюджет ошибок
в [`s07e12`](../../season-07-production-advanced/s07e12-slo/): число,
согласованное до того, как понадобилось, превращает спор в вычитание.

Целочисленная арифметика и воспроизводимость вывода — правило §4.3
[плана курса](../../V2.0_UPGRADE_PLAN.md), действующее с
[`s07e09`](../../season-07-production-advanced/s07e09-latency-percentiles/).

Разбор алгоритмической стороны — первый в курсе случай, когда решение не в
том, какую команду выполнить, а в том, какой ответ считать правильным. Это
задел на `s08e12`, где приёмка тоже считается, а не
объявляется.

Найденное Алексом в конце серии — расписание, работающее на семи узлах до
сегодняшнего дня, — разбирается в `s08e04` и дальше: атака в канале была
шумом, за которым не смотрели внутрь.
