## II. Теория: что говорит режим проверки

### Что такое `--check`

Ansible не выполняет задачи, а спрашивает у каждого модуля: «если бы я применил это состояние — что-нибудь изменилось бы?» Модуль сравнивает описанное с существующим и отвечает `ok` или `changed`. Ничего не пишется.

`--diff` добавляет к ответу построчную разницу. Читается она **слева направо от машины к описанию**:

```
--- before: /etc/ssh/sshd_config     ← как сейчас на машине
+++ after:  /etc/ssh/sshd_config     ← как описано в playbook
-PermitRootLogin yes
+PermitRootLogin no
```

Строка со знаком минус — это не «что ansible уберёт из вашего файла». Это **то, что сейчас на сервере**.

### Три исхода и один, который выглядит как исход

| Строка | Что означает |
|---|---|
| `ok:` | описанное совпадает с существующим |
| `changed:` | не совпадает; ansible изменил бы |
| `fatal: … UNREACHABLE!` | машина не ответила; задачи на ней не выполнялись вообще |
| `skipping:` | задача не выполнялась — и причина бывает разной |

Недоступные хосты выпадают из всех задач, но остаются в `PLAY RECAP`. Поэтому считать машины по строкам задач нельзя: двоих недосчитаетесь именно там, где они важнее всего.

### Где режим проверки молчит

```yaml
- name: checksums
  ansible.builtin.command: debsums -c    # не умеет предсказывать результат
```

Модули `command` и `shell` запускают произвольную программу. Предсказать её действие невозможно, поэтому в режиме проверки они **не запускаются вовсе** и печатают `skipping:`.

Отсюда главное свойство `--check`, о котором легко забыть: **чистый прогон проверки не означает, что на машинах всё в порядке**. Он означает, что всё в порядке с тем, что ansible умеет предсказать.

Обойти это можно явно:

```yaml
  check_mode: false      # выполнять даже в режиме проверки (для безопасных команд)
```

Про идемпотентность, `changed_when`, `--limit`, `--tags` и `--diff` для шаблонов — в [`theory.md`](theory.md).

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«Прогон в режиме проверки чистый: ноль изменений, ноль ошибок. Машины настроены правильно?»*

<details>
<summary>Подумай 30 секунд</summary>

Правильный ответ: «правильно настроено всё, что описано и что ansible умеет проверять». Три оговорки, каждая существенная:

1. **Что описано.** Файл, о котором в playbook нет ни слова, может содержать что угодно.
2. **Что предсказуемо.** Задачи на `command`/`shell` пропущены — в этом прогоне их две, и обе про целостность системы.
3. **Кто ответил.** Недоступные машины не проверялись вообще; в `PLAY RECAP` они выглядят спокойно.

«Ноль изменений» — это утверждение об области видимости, а не о мире.
</details>

**LILITH:** *«Тридцать одна машина из тридцати четырёх изменится. Это дрейф?»*

<details>
<summary>Ответ</summary>

Нет. Это движение описания, а не машин: вчера в инвентарь добавили `ntp_servers`, и теперь playbook хочет записать их на все машины, где их ещё нет.

Различает два случая вопрос «что изменилось последним». Меняется почти у всех — вперёд ушло описание. Меняется у одной машины из тридцати — в сторону ушла машина. Меняется у группы целиком — группа настроена иначе, чем описана.

Выброс — это не «ошибка», а **вопрос**: почему именно эта.
</details>

## IV. Задание: прочитать прогон

Артефакт — `artifacts/plan_report.txt`, четырнадцать значений из
`data/ansible_check_prod.txt`.

```bash
cp starter/plan_report.txt artifacts/
bash tests/test.sh
```

| Блок | Что нужно узнать |
|---|---|
| масштаб | хостов в `PLAY RECAP`, недоступных, изменяющихся, уже совпадающих, задач всего |
| слепые зоны | сколько задач пропущено на всех хостах и каким модулем они написаны |
| фон | какая задача меняется чаще всего и на скольких хостах |
| выброс | на какой машине изменится больше всего задач и сколько |
| находки | чужой ключ, директива `sshd_config`, права каталога с ключами |

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

Только строки итога:

```bash
awk '/^PLAY RECAP \*/ {r=1; next} r' data/ansible_check_prod.txt | grep 'changed='
```

Считать по задачам:

```bash
awk '/^TASK \[/{t=$0} /^changed: \[/{c[t]++} END{for (k in c) print c[k], k}' \
    data/ansible_check_prod.txt | sort -rn
```

Эталон — в `solution/`, там над каждым значением стоит команда, которой оно получено.
</details>

### Три ошибки, которые здесь делают

**`grep -c changed`.** Даёт 77 вместо 31: слово встречается и в `changed=0` каждой строки итога, и в JSON недоступного хоста (`"changed": false`). Считать надо строки, а не слово.

**Считать хосты по строкам задач.** Получится 34 вместо 36. Недоступные машины в задачах не участвуют — а именно про них стоит спросить отдельно.

**Принять `skipped=2` за хорошую новость.** В строке итога это выглядит как «две задачи не понадобились». На деле это «две задачи режим проверки выполнить не может», и обе — про целостность системных файлов.

## V. Двадцать седьмая

Макс открывает `--diff` по `prod-web27` и читает вслух.

```
-ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIP2wKdN7bQxS4mVcE8hTrY1oZjG6aLuF root@kali
```

> — Ключ, которого нет в описании. Ansible убрал бы его.

```
-PermitRootLogin yes
-    "mode": "0755",
```

> — Вход root разрешён. Каталог с закрытыми ключами открыт на чтение всем.

В комнате тихо. Дмитрий проверяет журнал входов на этой машине:

```
root   pts/0   185.220.101.52   Nov 20 03:42 - 03:55  (00:13)
```

> — Этот адрес Анна находила в четырнадцатом эпизоде. Выходной узел Tor.

Клаус наконец говорит:

> — Тринадцать минут с правами root три недели назад. И заметили мы это не потому, что кто-то проверял серверы, а потому, что впервые спросили у них, совпадают ли они с описанием.

Он показывает на две строки `skipping:` в конце вывода.

> — А теперь то, что мне не нравится больше всего. Две задачи, которые проверяют контрольные суммы системных файлов и срок сертификата, в режиме проверки не выполняются. Запускайте их по-настоящему, только на этой машине.

Через восемь минут:

```
TASK [audit : checksums] *******************************************************
fatal: [prod-web27.shadow.io]: FAILED! => {"changed": false, "stdout": "debsums: checksum mismatch openssl file /usr/bin/openssl"}
```

> — Подменён `openssl`. Эту машину не чинят, её пересобирают. — Клаус уже открывает консоль машинного зала. — И вот теперь, Макс, главный вопрос сезона.

> — Какой?

> — Через полчаса эта машина будет настроена заново из вашего описания. Из одного файла, который применится к пятидесяти машинам сразу. Кто проверял **его**?

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   Двадцать седьмая нашлась потому, что описание              │
│   спросили у реальности.                                     │
│                                                              │
│   Реальность теперь будет строиться из описания.             │
│   Спросить его больше не у кого.                             │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```
