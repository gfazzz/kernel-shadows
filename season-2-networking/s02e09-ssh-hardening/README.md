## Теория: hardening + туннели (один концепт: закрыть и спрятать)

**Закалка `sshd_config`** — запретить опасное:

```
PermitRootLogin no             # root напрямую — нельзя
PasswordAuthentication no      # только ключи, пароли выключены
PermitEmptyPasswords no
X11Forwarding no
```

sshd берёт **активные** (незакомментированные) строки. После правки — `sudo sshd -t` (проверка) и перезапуск (это systemd — Season 3).

**SSH-туннели** прячут трафик в шифрованном канале: `-L` (local), `-R` (remote), `-D` (SOCKS-прокси). Снаружи виден только SSH, не содержимое. VPN (WireGuard/ChaCha20) шифрует **весь** трафик машины. Детали — в [`theory.md`](theory.md).

> **LILITH:** *«Перед `PasswordAuthentication no` проверь, что ключ работает, и держи вторую сессию. Закрыть себе единственный вход — классическая ошибка. sshd не прощает.»*

## Проверка «в мире сюжета»

**Алекс:** *«У нас `PermitRootLogin no`, но строка закомментирована `#`. Она работает?»*

<details>
<summary>Подумай 20 секунд</summary>

Нет. Закомментированная строка — это дефолт, а не активная настройка. sshd её игнорирует, и реальное поведение может быть `yes` (или зависеть от версии). Аудит должен брать только **активные** (незакомментированные) директивы — иначе «выглядит закалённым, а дыра открыта».
</details>

**Анна:** *«Firewall + ключи уже есть. Зачем ещё VPN?»*

<details>
<summary>Ответ</summary>

Firewall блокирует нежелательные подключения, ключи защищают вход — но сам **трафик** между узлами всё ещё может читаться (DPI Крылова). VPN/туннель шифрует содержимое: атакующий видит поток, но не то, что внутри (пароли, планы, координаты). Оборона слоями: firewall + доступ по ключам + шифрование канала.
</details>
