## Обстановка

Ключ в `authorized_keys` появился без события «ключ добавлен» — значит,
приехал внутри чего-то. Образы собираются своим конвейером и тянутся из
внутреннего реестра, и это считалось достаточным основанием им доверять.

Есть два списка: что запущено на узлах и что опубликовал издатель. Разница
между ними — работа этой серии.

## Приказ

Написать `artifacts/verify_supply.sh`: сверить запущенное с опубликованным и
назвать все расхождения по категориям.

```bash
cp starter/verify_supply.sh artifacts/
bash artifacts/verify_supply.sh data/deployed_images.txt data/official_digests.txt data/allowed_registries.txt
bash tests/test.sh
```

## Договор

```
verify_supply.sh <инвентарь> <перечень-издателя> <разрешённые-реестры>

FINDING <категория> <образ> <подробность>
TOTAL <n>

код возврата: 0 — чисто, 1 — есть находки, 2 — вход не разобран
```

## Четыре категории

| Категория | Когда |
|---|---|
| `MISMATCH` | отпечаток не совпал с опубликованным |
| `UNPINNED` | образ подтянут по метке, отпечатка нет вовсе |
| `UNKNOWN` | издатель такого образа не публиковал |
| `MIRROR` | реестр не входит в список разрешённых |

Образ без отпечатка — `UNPINNED`, а не `MISMATCH`: сравнивать нечего. Образ
из чужого реестра даёт **две** находки: он и не в списке, и у издателя такого
пути нет.

## Дано

| Файл в `data/` | Что в нём |
|---|---|
| `deployed_images.txt` | узел, образ, отпечаток; прочерк — тянули по метке |
| `official_digests.txt` | образ и отпечаток из подписанного индекса реестра |
| `allowed_registries.txt` | закрытый список: всё остальное — находка |

## Что здесь легко пропустить

**Один образ на пятидесяти узлах — одна находка.** Интересует образ, а не
число узлов, на которых он запущен.

**Реестр — это всё до первой косой черты.** `registry-aurora.internal` и
`registry.aurora.internal` различаются одним символом и являются разными
источниками.

**Вывод отсортирован.** Порядок строк инвентаря наружу не просачивается.

**Тест порождает собственный инвентарь.** В каждом прогоне портятся другие
образы; ответы из `data/` не подойдут.

## Критерии приёмки

- [ ] Договор вызова соблюдён, коды 0/1/2 различаются по смыслу.
- [ ] Неверный вызов и отсутствующие файлы дают код 2.
- [ ] Найдены все заложенные расхождения, лишнего не названо.
- [ ] Категории не смешиваются: `UNPINNED` не выдаётся за `MISMATCH`.
- [ ] Чужой реестр даёт две независимые находки.
- [ ] На чистом инвентаре — `TOTAL 0` и код 0.
- [ ] Повторы по узлам не задваивают находку.
- [ ] Вывод отсортирован и воспроизводим.
- [ ] `bash tests/test.sh` → 27 passed, 0 failed.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| находок в разы больше заложенного | считаются строки инвентаря | свести к различным образам |
| «UNPINNED выдан за MISMATCH» | прочерк сравнили как отпечаток | проверять прочерк до сравнения |
| «по чужому реестру одна находка» | одна проверка вместо двух | реестр и наличие у издателя независимы |
| ложные срабатывания на чистом списке | сравнение по подстроке | сравнивать полный путь образа |
| «вывод не отсортирован» | печать по ходу обхода | накопить и отсортировать |
| «на втором инвентаре расхождение» | имена образов зашиты в скрипт | работать с любыми именами |
| код 1 на чистом списке | код не связан с числом находок | 0 при `TOTAL 0` |

## После выполнения

Зелёный тест означает, что перед очисткой известно, что именно чистить: не
«что-то не то с образами», а пять конкретных строк с категориями.

Главное, что стоит унести: **метка — это указатель, отпечаток — содержимое.**
Ссылка по метке означает, что ты не знаешь, что у тебя запущено, и узнать
задним числом будет неоткуда.

И второе: **подпись отвечает на вопрос «то ли это», а не «тот ли издатель».**
Второй вопрос решается закрытым списком источников, и без него проверка
подписи не значит почти ничего.
