## Теория: `grep` + pipes (один концепт: фильтровать поток)

**`grep`** печатает только строки, содержащие шаблон:

```bash
grep "ERROR" app.log          # строки с ERROR
grep -v " 200 " access.log    # -v: строки БЕЗ " 200 " (не-успешные = подозрительные)
grep -c " 404 " access.log    # -c: только количество
```

`grep` понимает regex: `^` начало строки, `$` конец, `[0-9]` цифра, `-E` для `|` (ИЛИ). Полная таблица флагов и regex — в [`theory.md`](theory.md).

**Pipe `|`** соединяет команды в конвейер: stdout одной → stdin следующей.

```bash
grep -v " 200 " access.log | wc -l    # отфильтровать → посчитать
```

Это Unix-философия: маленькие инструменты («одна задача — одна команда»), соединённые как LEGO, дают мощную обработку.

> **LILITH:** *«Unix создан в 1970-х. Pipe — гениальное решение: комбинируй простые команды. 50 лет спустя всё ещё работает. Это не баг, это feature.»*

## Проверка «в мире сюжета»

**Ольга:** *«Тебе нужны строки, где НЕ статус 200. Какой флаг `grep`?»*

<details>
<summary>Подумай 20 секунд</summary>

`grep -v " 200 "` — флаг `-v` инвертирует: печатает строки, которые НЕ содержат шаблон. Во время атаки нормальный ответ — `200 OK`, а всплеск `401/403/404/5xx` — след атакующих.
</details>

**Ольга:** *«`grep -c` и `grep … | wc -l` дают одно число. Зачем тогда pipe?»*

<details>
<summary>Ответ</summary>

`grep -c` умеет только считать свои совпадения. Pipe же соединяет ЛЮБЫЕ команды: `grep | awk | sort | uniq -c | sort -rn | head` — так из лога рождается рейтинг атакующих. `-c` — частный случай; конвейер — общий принцип.
</details>
