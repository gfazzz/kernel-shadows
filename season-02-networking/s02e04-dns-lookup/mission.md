## Обстановка

Панель мониторинга дата-центра показывает 47 % неуспешных разрешений имён и два
десятка зафиксированных попыток отравления кеша. Прежде чем ловить подмену, надо
уверенно читать сам DNS.

Эрик снял с резолвера ответы по доменам операции — восемь запросов с полными
заголовками. Сеть больше не нужна: ответы уже получены, осталось их разобрать.

## Приказ

Провести разбор снимка и **сдать отчёт** — заполненный
`artifacts/dns_report.txt`: адреса зоны, почтовые серверы и приоритеты, серверы
имён, политика SPF, цель алиаса, адрес и TTL подозрительного узла и — отдельно —
два разных случая «нет ответа».

```bash
cp starter/dns_report.txt artifacts/dns_report.txt
bash tests/test.sh
```

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/dig_capture_ops.txt`](../data/dig_capture_ops.txt) | восемь записанных ответов `dig` с заголовками |
| [`data/dns_zones.txt`](../data/dns_zones.txt) | список внутренних доменов операции (справочно) |

Снимок разбит на секции строками `;; ===== dig <домен> <тип> =====`.
Строка ответа устроена так:

```
ops.internal.        300    IN    A     10.50.1.100
имя                  TTL  класс  тип   значение
```

## Чем добывать

| Что нужно | Как |
|---|---|
| одна секция | `awk -v h=";; ===== dig ops.internal MX =====" '$0==h{f=1;next} /^;; =====/{f=0} f' "$C"` |
| записи типа | `awk '$4=="MX"'` |
| приоритет MX | пятое поле; **меньшее число важнее** |
| значение записи | последнее поле строки ответа |
| TTL | второе поле |
| статус ответа | строка `;; ->>HEADER<<- … status: …` |
| число ответов | строка `;; flags: … ANSWER: N` |

## Критерии приёмки

- [ ] `artifacts/dns_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Адреса зоны взяты из своей секции, а не поиском по всему файлу.
- [ ] Число записей MX и приоритетный сервер определены верно (не по порядку строк).
- [ ] Цель `CNAME` для `www` указана вместе с завершающей точкой, как в снимке.
- [ ] Для `shadow-05` записаны и адрес, и TTL.
- [ ] Найдено имя, по которому пришёл `NXDOMAIN`.
- [ ] Найден тип записи, по которому пришёл `NOERROR` с нулём ответов.
- [ ] Эти два случая записаны как **разные** — они и есть разные.
- [ ] `bash tests/test.sh` → 15 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils |
| Сеть | **не нужна** — ответы записаны заранее |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`dig` понадобится только для практики на своей машине) |
| Изоляция теста | эталон вычисляется из того же снимка, констант в тесте нет |

Тест дополнительно проверяет, что ловушки в данных на месте: первым в ответе MX
стоит не приоритетный сервер, а TTL у одной записи заметно короче остальных.

## Выполнение

```bash
cd season-02-networking/s02e04-dns-lookup
cp starter/dns_report.txt artifacts/dns_report.txt
C=../data/dig_capture_ops.txt
grep -n '=====\|status:' "$C"      # с этого удобно начать: карта снимка
bash tests/test.sh
```

На машине с сетью повтори то же вживую и сравни три ответа для одного имени:
`dig +short`, `getent hosts` и `resolvectl query`. Расхождение между ними —
тема, к которой серия ещё вернётся.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| адресов зоны получилось три | искали по всему файлу | вырезать секцию `ops.internal A` |
| основным вышел `mail-backup` | взята первая строка ответа | сравнивать приоритеты численно |
| `www_cname_target` без точки | точка отброшена вручную | писать значение ровно как в снимке |
| `nxdomain_name` и пустой тип совпали | оба взяты из одной секции | это разные запросы, ищи по заголовкам |
| TTL перепутан с классом | сбит порядок полей | имя, TTL, класс, тип, значение |
| тест «значение не заполнено» | потерян `=` или переименован ключ | брать шаблон из `starter/` без правок |

## После выполнения

Зелёный тест означает, что ответ DNS перестал быть непрозрачным: видно, сколько
записей, какого типа, с каким приоритетом и сроком жизни — и видно разницу между
«имени нет» и «записи такого типа нет».

Отчёт становится базовой картой имён `netshield` (см. [`PROJECTS.md`](../../docs/PROJECTS.md)).

И в нём остаётся одна строка, которая не объясняется ничем нормальным: у
`shadow-05` публичный адрес при внутреннем сервере и TTL в пять раз короче
обычного. Ответ пришёл успешно — но правдив ли он, снимок не говорит. Это
капстоун эпизода.
