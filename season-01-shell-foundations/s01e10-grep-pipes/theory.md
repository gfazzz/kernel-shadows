# Теория — s01e10

## 1. Человек, которого я обвинил по ошибке

> *Второй курс, я подрабатываю у Палыча в лаборатории. У нас общий выход в сеть через шлюз, и кто-то ночами качает торренты, забивая канал.*
>
> *Я нахожу лог, знаю адрес подозреваемой машины — `10.0.0.1`. Пишу:*
>
> ```console
> $ grep 10.0.0.1 gateway.log | wc -l
> 84213
> ```
>
> *Восемьдесят четыре тысячи запросов за ночь. Иду к Палычу с распечаткой и фамилией.*
>
> *Он берёт лист, смотрит секунд пять и спрашивает:*
>
> — А кто у нас `10.0.0.12`?
> — При чём тут двенадцатый?
> — При том, что ты его тоже посчитал. И `10.0.0.100`, и `10.0.0.199`. Твой шаблон — это подстрока, а не адрес. `10.0.0.1` есть внутри `10.0.0.123`.
> — …
> — И точка в шаблоне — это «любой символ». `10.0.0.1` совпадёт и с `10a0b0c1`, если такое встретится. Ты искал не то, что думал, что ищешь.
>
> *Он берёт карандаш и пишет на полях: `grep -E '(^| )10\.0\.0\.1( |$)'`.*
>
> — Экранируй точки. Ставь границы. И прежде чем нести кому-то фамилию, посмотри **сами строки**, а не только их количество. Число ничего не доказывает — оно только выглядит убедительно.
>
> *Я пересчитал. Восемьдесят четыре тысячи превратились в шестьсот, и это была не та машина. Настоящим виновником оказался `10.0.0.123` — тот самый, кого я приплюсовал по ошибке.*
>
> *С тех пор первое, что я делаю после `grep`, — смотрю десяток строк глазами. `| head`. Пять секунд, которые один раз спасли человека от разбирательства.*

## 2. `grep` — флаги, которые действительно нужны

| Флаг | Действие |
|---|---|
| `-i` | игнорировать регистр |
| `-v` | инверсия: строки БЕЗ совпадения |
| `-c` | только количество совпавших строк |
| `-n` | номера строк |
| `-l` / `-L` | только имена файлов, где есть / где нет |
| `-r` | рекурсивно по каталогу |
| `-o` | печатать только совпавшую часть, по одной на строку |
| `-w` | совпадение как целое слово |
| `-F` | шаблон — обычная строка, не regex (быстро и безопасно) |
| `-A/-B/-C N` | N строк после / до / вокруг совпадения |
| `-E` | расширенный regex (`|`, `+`, `?`, `{}`) |

Три из них решают большинство проблем новичка:

- **`-w`** — избавляет от истории выше в простых случаях: `grep -w 10.0.0.1` не совпадёт внутри `10.0.0.123`, потому что цифра рядом считается частью слова.
- **`-F`** — когда ищешь буквальную строку с точками, скобками или `$`, не думая об экранировании.
- **`-o`** — превращает `grep` из фильтра строк в извлекатель кусков: `grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' access.log` вытащит все адреса.

## 3. Регулярные выражения: минимум, который окупается

| Шаблон | Значение |
|---|---|
| `.` | любой символ |
| `*` | 0 и более повторов предыдущего |
| `+` | 1 и более (нужен `-E`) |
| `?` | 0 или 1 (нужен `-E`) |
| `{n,m}` | от n до m повторов (нужен `-E`) |
| `^` / `$` | начало / конец строки |
| `[0-9]` / `[^0-9]` | класс символов / его отрицание |
| `\.` | буквальная точка |
| `a\|b` (BRE) / `a|b` (ERE) | или |

```bash
grep -E '^[0-9]{1,3}(\.[0-9]{1,3}){3} ' access.log    # строка начинается с IP
grep -E ' (4[0-9]{2}|5[0-9]{2}) ' access.log          # статусы 4xx и 5xx
grep -E 'ERROR|FATAL' app.log                          # два уровня сразу
grep -v '^#' /etc/ssh/sshd_config | grep -v '^$'       # конфиг без комментариев и пустых
```

**BRE против ERE.** Обычный `grep` использует базовый синтаксис, где `|`, `+`, `?`, `{}` — обычные символы, и чтобы получить их особый смысл, нужен обратный слэш: `grep 'a\|b'`. Флаг `-E` (или команда `egrep`, ныне устаревшая) включает расширенный синтаксис, где всё наоборот. Практическое правило: пишешь что-то сложнее подстроки — сразу `-E`.

**Жадность.** `.*` захватывает максимум возможного: в строке `"GET /a" 200 "GET /b"` шаблон `".*"` совпадёт целиком от первой кавычки до последней, а не с первой парой. В `grep` регулировать это неудобно — если нужна точность, берут `[^"]*` вместо `.*` (то есть «что угодно, кроме кавычки»).

## 4. Конвейер: что происходит физически

```bash
grep -v ' 200 ' access.log | wc -l
```

Оболочка запускает **обе** программы одновременно и соединяет их трубой в ядре: `stdout` первой становится `stdin` второй. Данные текут потоком, а не «сначала всё, потом всё» — поэтому `grep огромный.log | head -3` отвечает мгновенно: `head` получает три строки, закрывает трубу, `grep` получает `SIGPIPE` и завершается, не дочитав файл.

Отсюда следствия:

- **Память не расходуется на объём.** Стомегабайтный лог проходит через конвейер, не оказываясь в памяти целиком. Именно поэтому `cat file | grep x` — лишнее звено (`grep x file` делает то же и на один процесс меньше), но не катастрофа.
- **Код возврата конвейера — код последней команды.** `grep нет_такого file | wc -l` завершится успешно, хотя `grep` ничего не нашёл. Спасает `set -o pipefail` или `${PIPESTATUS[0]}`.
- **`grep` возвращает 1, когда совпадений нет.** Это не ошибка, а ответ «нет». В скрипте с `set -e` такой ответ убивает процесс — типичная причина «скрипт молча остановился на середине».

Стандартный набор звеньев, из которых собирают почти любой разбор лога:

```
[файл] → grep (фильтр) → awk (поле) → sort → uniq -c (счёт) → sort -rn → head
```

`grep` здесь — только первое звено; остальные появятся в следующей серии.

## 5. Про фильтр по статусу

`grep -vE ' 200 '` — приём наглядный, но грубый: он смотрит на всю строку, а не на конкретное поле. В логе формата Apache Combined статус — девятое поле, и правильный фильтр адресуется именно к нему. Это делает `awk` (s01e11):

```bash
awk '$9 != 200' access.log
```

Пока `awk` не введён, пробелы вокруг числа — минимальная защита от ложных совпадений: они отсекают `1200` в размере ответа и `10.0.200.5` в адресе. Не идеально, но честно, и разница между «грубо, зато понимаю, где грубо» и «точно, но не знаю почему» — в пользу первого.

## 6. Быстродействие и локаль

На больших файлах `grep` зависит от локали: в UTF-8 он разбирает многобайтные символы, в `C` — сравнивает байты. Разница бывает в разы:

```bash
LC_ALL=C grep -F 'ERROR' huge.log      # быстрее, если шаблон — ASCII
```

Тот же приём делает вывод предсказуемым в тестах — поэтому в проверках курса иногда встречается `LC_ALL=C`. Обратная сторона: с `LC_ALL=C` диапазоны вроде `[а-я]` и регистр для кириллицы работать перестанут.

Отдельно про `grep -r` по каталогу: наткнувшись на бинарный файл, он напишет «Binary file … matches» и не покажет строк. Флаг `-a` заставит обработать его как текст, `-I` — вовсе пропускать бинарники.

## 7. Метанавык: сначала вопрос, потом инструмент

Сто мегабайт логов — это не «много текста». Это набор данных, к которому задают вопрос. Пока вопрос не сформулирован («какие запросы не вернули 200 в интервале с 03:45 до 03:50»), никакая команда не поможет: пролистывать можно бесконечно и ничего не увидеть.

Отсюда же порядок работы, который дальше не изменится: сузить выборку фильтром, посмотреть глазами десяток строк (`| head`), убедиться, что фильтр отсекает то, что должен, и только потом считать. Числа, полученные до этой проверки, — самый удобный способ уверенно ошибиться.
