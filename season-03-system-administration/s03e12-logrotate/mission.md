## Обстановка

Десять гигабайт, найденные в [`s03e08`](../s03e08-disks-fs/), появились не от
чьих-то действий вручную. Их создавала действующая конфигурация `logrotate`,
каждую ночь, полгода подряд: журнал поворачивался, `rsyslogd` об этом не
уведомлялся и продолжал писать в переименованный, а затем удалённый файл.

Побочный эффект: файл `/var/log/ops/audit.log` полгода был пустым, и это
никто не заметил — смотрели через `journalctl`.

## Приказ

Переписать `artifacts/ops` — файл для `/etc/logrotate.d/` — так, чтобы
поворот журналов не ломал пишущие службы и чтобы записи хранились дольше,
чем время обнаружения инцидента.

```bash
cp starter/ops artifacts/ops
bash tests/test.sh
```

## Требования

| Что | Зачем |
|---|---|
| описаны оба набора журналов: `/var/log/ops` и `/var/log/nginx` | в стартере есть только один |
| служба узнаёт о повороте | иначе повторится история с десятью гигабайтами |
| `sharedscripts` при пути с шаблоном | иначе сигнал уйдёт по разу на каждый файл |
| `rotate` не меньше 7 | три дня меньше времени обнаружения инцидента |
| задана периодичность | иначе неизвестно, когда поворачивать |
| `compress` вместе с `delaycompress` | свежий файл ещё пишется — сжимать рано |
| `create` с правами не шире `0640` | журнал не должен читаться посторонними |
| `missingok`, `notifempty` | иначе ошибка при каждом запуске, и её перестают читать |

Сигналы у служб разные: `rsyslog` — `/usr/lib/rsyslog/rsyslog-rotate`,
`nginx` — `kill -USR1` по PID-файлу. Альтернатива обоим — `copytruncate`,
но он несовместим с `create` и теряет строки.

## Чем добывать

| Что нужно | Как |
|---|---|
| блок конфигурации | `путь { директивы }`, путь может содержать шаблон |
| уведомление службы | `sharedscripts` + `postrotate … endscript` |
| безопасный `kill` | `[ -f /run/nginx.pid ] && kill -USR1 "$(cat /run/nginx.pid)"` |
| проверить разбор (на своей машине) | `logrotate -d artifacts/ops` |
| посмотреть, что уже настроено | `ls /etc/logrotate.d/`, `cat /var/lib/logrotate/status` |

## Критерии приёмки

- [ ] `artifacts/ops` создан на основе `starter/`, фигурные скобки сбалансированы.
- [ ] Описаны блоки для `/var/log/ops` и `/var/log/nginx`.
- [ ] В каждом блоке есть `postrotate` с сигналом службе (или `copytruncate`).
- [ ] `copytruncate` не смешан с `create`.
- [ ] При пути с шаблоном и `postrotate` задан `sharedscripts`.
- [ ] `rotate` не меньше 7 в обоих блоках.
- [ ] Периодичность задана.
- [ ] `compress` идёт вместе с `delaycompress`.
- [ ] `create` задаёт права не шире `0640` и владельца.
- [ ] `missingok` и `notifempty` заданы.
- [ ] `bash tests/test.sh` → 23 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — `logrotate` не запускается, конфигурация проверяется как текст |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| `logrotate` | не нужен для теста |
| Внешние пакеты | нет |
| Изоляция теста | конфигурация разбирается на блоки, каждый проверяется отдельно |

Тест дополнительно проверяет, что задание не выродилось: в стартере
сохранились поворот без уведомления службы и отсутствие второго блока.

## Выполнение

```bash
cd season-03-system-administration/s03e12-logrotate
cp starter/ops artifacts/ops
$EDITOR artifacts/ops
bash tests/test.sh
```

На своей машине стоит посмотреть, что настроено уже сейчас, и убедиться,
что конфигурации вообще читаются:

```bash
ls /etc/logrotate.d/
sudo logrotate -d /etc/logrotate.conf 2>&1 | grep -E 'reading|considering'
cat /var/lib/logrotate/status | head
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «нет ни postrotate, ни copytruncate» | служба не уведомляется | добавить сигнал или `copytruncate` |
| «путь с шаблоном и postrotate без sharedscripts» | скрипт выполнится на каждый файл | добавить `sharedscripts` |
| «compress без delaycompress» | свежий файл сожмут во время записи | добавить `delaycompress` |
| «rotate 3 — меньше недели» | глубина хранения из стартера | не меньше 7, обычно 14 |
| «create 0644 — права шире» | скопировано умолчание | `0640` и группа `adm` |
| «copytruncate вместе с create» | смешаны два подхода | выбрать один |
| «нет блока для /var/log/nginx» | описана одна служба | второй блок со своим сигналом |
| «скобки не сбалансированы» | пропущена `}` или `endscript` | `logrotate -d` покажет строку |

## После выполнения

Зелёный тест означает, что ротация больше не ломает пишущие службы и что
журналов хватит на разбор двухнедельной давности.

Стоит задержаться на том, что именно было не так в стартере. Ни одна из трёх
строк не была ошибкой: `daily`, `rotate 3`, `compress` — всё корректно.
Проблема была в **отсутствующей** строке, а отсутствие не подсвечивается
ни линтером, ни проверкой синтаксиса, ни `logrotate -d`. Единственный способ
его заметить — знать, что она должна быть.

## Кумулятивность

Десять гигабайт без имени найдены в [`s03e08`](../s03e08-disks-fs/), а
механизм — дескриптор против имени — разобран в
[`s03e04`](../s03e04-processes/) (`/proc/PID/fd`) и в теории
[`s03e08`](../s03e08-disks-fs/) (`unlink` удаляет имя, а не файл). Сигнал
`HUP` как «перечитай конфигурацию» — из
[`s03e04`](../s03e04-processes/). Права `0640` и группа `adm` — из
[`s03e01`](../s03e01-users-groups/) и [`s03e02`](../s03e02-permissions/).
Логика «настройка без обратной связи, проверяй сразу» — та же, что у `fstab`
в [`s03e10`](../s03e10-fstab/).
