## Обстановка

`sshd-helper.service` отключён и удалён — вместе с ним ушли оба процесса из
[`s03e04`](../s03e04-processes/). Заодно ушёл и мониторинг: Дмитрий держал его
тем же способом, что и злоумышленник, — службой от root без единого ограничения.

Виктор просит вернуть мониторинг так, чтобы новая служба не стала следующей
`sshd-helper`.

## Приказ

Довести `artifacts/ops-monitor.service` до состояния, которое не стыдно
оставить на сервере после инцидента.

```bash
cp starter/ops-monitor.service artifacts/ops-monitor.service
bash tests/test.sh
```

Скрипт уже написан и лежит по пути `/usr/local/bin/ops-monitor.sh`: он читает
состояние серверов и печатает результат в stdout. Ему нужен каталог для
своего состояния — `/var/lib/ops-monitor`.

## Требования к службе

| Что | Зачем |
|---|---|
| стартует **после появления сети** | иначе падает на первом же запросе |
| перезапускается при падении, с паузой | но не после штатного завершения |
| работает не от root | ей нужно только читать состояние |
| корень только на чтение, свой `/tmp`, `/home` не виден | компрометация службы не должна давать доступ к системе |
| не может получить новых привилегий | в системе есть SUID-файлы (см. `s03e02`) |
| ограничена по памяти, процессору и числу процессов | служба сбора состояния не должна уметь съесть сервер |
| пишет в журнал | разбирать инцидент будут по нему |
| включается в автозагрузку | иначе не вернётся после перезагрузки |

## Чем добывать

| Что нужно | Как |
|---|---|
| порядок и наличие зависимости | `Wants=` **и** `After=network-online.target` |
| команда запуска | `ExecStart=` с абсолютным путём, без конвейера |
| перезапуск | `Restart=on-failure`, `RestartSec=` |
| от кого | `User=`, `Group=` |
| ограничение прав | `NoNewPrivileges=`, `ProtectSystem=strict`, `ProtectHome=`, `PrivateTmp=` |
| куда всё-таки можно писать | `ReadWritePaths=` или `StateDirectory=` |
| ресурсы | `MemoryMax=`, `CPUQuota=`, `TasksMax=` |
| автозагрузка | секция `[Install]`, `WantedBy=multi-user.target` |

Проверить на своей машине, ничего не устанавливая:
`systemd-analyze verify ./artifacts/ops-monitor.service`.

## Критерии приёмки

- [ ] `artifacts/ops-monitor.service` создан на основе `starter/`.
- [ ] Все три секции на месте, включая `[Install]`.
- [ ] `Description=` сообщает, что это за служба, а не повторяет её имя.
- [ ] `After=network-online.target` подкреплён `Wants=` (или `Requires=`).
- [ ] `ExecStart=` — абсолютный путь без конвейеров и `;`.
- [ ] `Type=` указан явно.
- [ ] `Restart=on-failure` и `RestartSec=` заданы.
- [ ] `User=` задан и это не root.
- [ ] `NoNewPrivileges=yes`, `ProtectSystem=strict|full`, `ProtectHome=`, `PrivateTmp=yes`.
- [ ] При `ProtectSystem=strict` указано, куда службе разрешено писать.
- [ ] `MemoryMax=`, `CPUQuota=`, `TasksMax=` заданы.
- [ ] Вывод уходит в журнал.
- [ ] `WantedBy=` задан в `[Install]`.
- [ ] Ни одна настройка не сброшена пустым присваиванием ниже по файлу.
- [ ] `bash tests/test.sh` → 24 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — systemd не запускается, unit проверяется как текст |
| ОС | любая с bash + awk + coreutils (systemd не требуется) |
| Сеть | не нужна |

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «After без Wants» | задан только порядок | `After` не запускает цель, добавить `Wants=` |
| «network.target вместо network-online» | сеть настраивается, адреса ещё нет | ждать `network-online.target` |
| «символ оболочки в ExecStart» | конвейер или `;` | оболочки нет; вывод и так идёт в журнал |
| «Restart=always не годится» | перезапуск после кода 0 | `on-failure` |
| «strict без ReadWritePaths» | корень только на чтение | `ReadWritePaths=` или `StateDirectory=` |
| «пустое присваивание сбрасывает» | ключ задан дважды, второй раз пусто | убрать вторую строку |
| «нет секции [Install]» | нечего включать | `WantedBy=multi-user.target` |
| «Description ничего не сообщает» | описание повторяет имя юнита | его читают в `systemctl status` и в журнале |

## После выполнения

Зелёный тест означает, что служба описана целиком: что запускается, от кого,
с какими правами и что будет, если она упадёт. Проверьте себя одним вопросом
по каждой строке — «что сломается, если её убрать». Строки, на которые ответа
нет, в юните лишние.

Сравни свой файл с `sshd-helper.service` из README. Разница между ними не в
том, что один вредоносный, а другой нет: в вредоносном просто нет ни одного
ограничения — как и в черновике из `starter/`.

## Кумулятивность

Ограничение `NoNewPrivileges` закрывает ровно тот способ закрепиться, что
найден в [`s03e02`](../s03e02-permissions/) (SUID-копия оболочки), а `PrivateTmp`
— тот каталог, из которого запускалась закладка в
[`s03e04`](../s03e04-processes/). Логика «конфиг как артефакт» и правило про
порядок чтения директив — из [`s03e03`](../s03e03-sudo/) и
[`s02e09`](../../season-02-networking/s02e09-ssh-hardening/); в systemd
побеждает последнее присваивание, в `sshd_config` — первое, в `sudoers` —
последнее совпавшее правило.
