## Теория: порты и `ss` (один концепт: что слушает)

Один IP — много сервисов; их различают **порты** (`IP:PORT`). Диапазон well-known — `0–1023` (SSH 22, HTTP 80, HTTPS 443, MySQL 3306…).

**`ss`** показывает сокеты изнутри хоста:

```bash
ss -tln     # TCP, только LISTEN, числовой вывод
```
```
State   Local Address:Port
LISTEN  0.0.0.0:22          # SSH слушает на ВСЕХ интерфейсах
LISTEN  127.0.0.1:3306      # MySQL только на localhost
```

Ключ к безопасности — **где** слушает порт: `0.0.0.0` = доступен извне, `127.0.0.1` = только локально. Состояния `ss`, `nmap` (взгляд снаружи) и `/etc/services` — в [`theory.md`](theory.md).

> **LILITH:** *«`0.0.0.0` — дверь открыта для всех. `127.0.0.1` — только изнутри. База данных на `0.0.0.0:3306`? Крылов говорит спасибо.»*

## Проверка «в мире сюжета»

**Анна:** *«`ss` показал `LISTEN 0.0.0.0:6379`. Чем это опасно?»*

<details>
<summary>Подумай 30 секунд</summary>

`6379` — Redis, по умолчанию без пароля. На `0.0.0.0` он доступен из интернета — любой может читать/писать данные и часто выполнить команды. Такие сервисы держат на `127.0.0.1` или за firewall. Открытый Redis — классический вектор взлома.
</details>

**Дмитрий:** *«Чем `ss` отличается от `nmap` для проверки портов?»*

<details>
<summary>Ответ</summary>

`ss` смотрит **изнутри** хоста (что реально слушает локально). `nmap` сканирует **снаружи** (что видно атакующему через сеть/firewall). Изнутри порт может слушать, но снаружи быть закрыт фаерволом — обе точки зрения нужны.
</details>
