## Перенаправление вывода

| Оператор | Действие |
|----------|----------|
| `>` | перезаписать файл (**опасно** для логов) |
| `>>` | дописать в конец (append) |
| `2>` | перенаправить stderr |
| `&>` | перенаправить stdout + stderr |
| `2>&1` | stderr → туда же, куда stdout |
| `\| tee -a file` | и на экран, и в файл (append) |

Три потока: `stdin (0)`, `stdout (1)`, `stderr (2)`.

```bash
echo "строка"  > file     # перезаписать
echo "строка" >> file     # дописать
команда 2> errors.log      # только ошибки
команда > out.log 2>&1     # всё вместе в один файл
команда | tee -a run.log   # на экран И в лог
```

> Перепутал `>` и `>>` — стёр production-логи. Правило: `>` для создания, `>>` для логов.

## Таймстамп: `date`

```bash
date '+%Y-%m-%d %H:%M:%S'   # 2025-10-04 16:23:45
date -Iseconds             # 2025-10-04T16:23:45+07:00
```

| Код | Значение |
|-----|----------|
| `%Y %m %d` | год, месяц, день |
| `%H %M %S` | час, минута, секунда |

Логирование с таймстампом:

```bash
echo "[$(date '+%Y-%m-%d %H:%M:%S')] Сервер проверен" >> monitor.log
# [2025-10-04 16:23:45] Сервер проверен
```

Удобно вынести в функцию, чтобы формат был единым:

```bash
ts() { date '+%Y-%m-%d %H:%M:%S'; }
echo "[$(ts)] [UP] $host" >> "$log"
```

## Production-привычки (заявка на будущее)

- `set -euo pipefail` — строгий режим (падать на ошибке, ловить необъявленные переменные).
- Функции (`ts()`, позже — `check()`, `log()`) вместо копипаста.
- `local` для переменных внутри функций (Season 3+).
- Проверка входных данных условиями до основной работы.

Полноценная ротация логов (`logrotate`) и системные таймеры (`systemd timer` вместо
`while true; sleep`) — это Type B и Season 3. Здесь достаточно `>>` + `date`.
