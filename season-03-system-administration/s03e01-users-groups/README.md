## III. Теория: три файла и одно число

### `/etc/passwd` — кто заведён

Файл читается всеми, и пароля в нём давно нет. Семь полей через двоеточие:

```
max:x:1000:1000:Maxim Sokolov:/home/max:/bin/bash
 │  │  │    │        │            │         └ оболочка
 │  │  │    │        │            └ домашний каталог
 │  │  │    │        └ комментарий (GECOS)
 │  │  │    └ GID основной группы
 │  │  └ UID
 │  └ пароль хранится не здесь (x)
 └ логин
```

**Права определяет UID, а не имя.** Учётная запись с UID 0 — это root, как бы она ни называлась. Проверка `whoami` покажет её имя, а ядро при каждой операции будет смотреть на число.

Диапазоны условны, но соблюдаются повсеместно: `0` — root, `1–999` — служебные учётки демонов, `1000+` — люди, `65534` — `nobody`.

### `/etc/group` — кто с кем

```
sudo:x:27:max,viktor
 │   │  │     └ дополнительные члены
 │   │  └ GID
 │   └ пароль группы (практически не используется)
 └ имя
```

Ловушка: **основная группа пользователя здесь не перечисляется**. Она задана четвёртым полем в `/etc/passwd`. Ответ на вопрос «кто входит в группу» из одного `/etc/group` бывает неполным.

### `/etc/shadow` — чем входят

Читается только root. Нас интересует второе поле:

| Значение | Что означает |
|---|---|
| `$6$…` | пароль задан (SHA-512) |
| `*` | вход по паролю невозможен — обычная запись служебной учётки |
| `!` или `!$6$…` | учётная запись заблокирована |
| пусто | **пароля нет вообще** — вход без пароля |

Разница между `*` и пустым полем — это разница между «сюда не входят» и «сюда входит кто угодно». Выглядят они одинаково безобидно.

Подробнее про NSS, `getent`, теневые файлы и почему `useradd` не то же самое, что `adduser`, — в [`theory.md`](theory.md).

## IV. Проверка: LILITH задаёт вопросы

**LILITH:** *«Учётная запись называется `devops`, а не `root`. Почему это всё равно root?»*

<details>
<summary>Подумай 20 секунд</summary>

Потому что проверка прав в ядре сравнивает **числа**, а не строки. Все привилегии суперпользователя привязаны к UID 0; имя — просто ярлык, который подставляет `getpwuid()` при выводе.

Отсюда следствие, которое стоит запомнить: две записи с одинаковым UID — это один и тот же пользователь с точки зрения системы, просто с разными именами, домашними каталогами и паролями. Именно так и прячут второй вход.
</details>

**LILITH:** *«В `/etc/shadow` у одной учётки во втором поле звёздочка, у другой пусто. Что опаснее?»*

<details>
<summary>Ответ</summary>

Пусто. Звёздочка означает, что ни один введённый пароль не совпадёт с хешем — вход по паролю невозможен, и так помечают служебные учётки.

Пустое поле означает, что пароля нет: проверять нечего, и вход выполняется без него. На машине с включённым парольным входом это открытая дверь. Разница в один символ, и оба варианта в файле выглядят одинаково незаметно.
</details>

## V. Задание: составить список жильцов

Это **расследование**. Анна сняла три файла со скомпрометированной машины до того, как что-либо на ней трогали, — они лежат в [`data/`](../data/). Твоя задача — прочитать их и ответить на вопросы.


```bash

```

Вопросы и критерии — в [`mission.md`](mission.md). Подсадок в снимке **две**, и вторая заметно тише первой.

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

```bash
D=../data
noc() { grep -vE '^[[:space:]]*(#|$)' "$1"; }   # отбросить шапку файла

noc $D/passwd_shadow-01.txt | awk -F: '$3 == 0 {print $1}'          # все UID 0
noc $D/passwd_shadow-01.txt | awk -F: '$3 < 1000 {print $1, $7}'    # служебные и их оболочки
noc $D/group_shadow-01.txt  | awk -F: '$1=="sudo" {print $4}'       # состав sudo
noc $D/shadow_shadow-01.txt | awk -F: '{print $1, $2}'              # чем входят
```

Разделитель полей у всех трёх файлов один — двоеточие, поэтому `awk -F:` работает везде. Эталон — в `solution/`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Искать root по имени.** `grep '^root'` найдёт одну строку и создаст ощущение порядка. Искать надо по третьему полю: `awk -F: '$3 == 0'`. Имя учётной записи не говорит о её правах ничего.

**Считать «не nologin» признаком служебной учётки.** У `sync` оболочка `/bin/sync` — это не `nologin`, но и не вход в систему: такая запись выполняет одну команду и завершается. Вопрос стоит про интерактивные оболочки — `bash`, `sh`, `zsh`.

**Считать членство в группе только по `/etc/group`.** Основная группа пользователя там не значится. Если спрашивают «кто состоит в группе», надо смотреть и четвёртое поле `/etc/passwd` — иначе половина ответа теряется молча.
