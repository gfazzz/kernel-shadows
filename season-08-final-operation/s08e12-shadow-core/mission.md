## Обстановка

Атака отбита, узлы очищены, задержание проведено. Осталось доказать, что всё
построенное за шестьдесят дней работает, — не словами, а прогоном, который
возвращает ноль или не возвращает.

Двенадцать фаз, по одной на навык сезона. Каждая проверяет свойство, а не
сверяет число.

## Приказ

Написать `artifacts/shadow_core.py`: прогнать план приёмки и вернуть код,
по которому принимают решение «принято или нет».

```bash
cp starter/shadow_core.py artifacts/
python3 artifacts/shadow_core.py data/acceptance.txt data/state
bash tests/test.sh
```

## Договор

```
shadow_core.py <acceptance.txt> <каталог-состояния>

PHASE <N> <сезон> <pass|FAIL> <описание> [<деталь>]
SUMMARY passed=<n> failed=<n> of=<N>

код возврата: 0 — все прошли, 1 — есть провал, 2 — вход не разобран
```

## Виды проверок

| Проверка | Свойство |
|---|---|
| `kv <файл> <ключ> <значение>` | ключ равен значению |
| `max <файл> <ключ> <n>` | целое не больше n |
| `min <файл> <ключ> <n>` | целое не меньше n |
| `present <файл>` | файл существует |
| `absent <файл>` | файла нет |
| `same <A> <B>` | списки совпадают |
| `subset <A> <B>` | каждая строка A есть в B |

Пути в аргументах — относительно каталога состояния.

## Дано

| Файл в `data/` | Что в нём |
|---|---|
| `acceptance.txt` | двенадцать фаз в фиксированном порядке |
| `state/` | состояние инфраструктуры, которое проверяют фазы |

## Что здесь важно

**Свойство, а не константа.** Фаза проверяет инвариант, который переживёт
обновление сезона. Тест это гарантирует тем, что ломает состояние и ждёт
провала — программа со «знанием ответов» не пройдёт.

**Порядок фаз фиксирован.** По номерам. Это одна операция.

**Один провал роняет всё.** Ноль — только если прошли все фазы.

**Нет файла — это `FAIL`, а не трассировка.** Отсутствие проверяемого
состояния — провал фазы, а не сбой программы.

## Критерии приёмки

- [ ] Договор вызова соблюдён, коды 0/1/2 различаются по смыслу.
- [ ] Все двенадцать фаз проходят на исправном состоянии, код 0.
- [ ] Каждая фаза ловит свою поломку: сломай одну — провалится ровно она.
- [ ] Один провал → код возврата 1.
- [ ] Порядок фаз в выводе — по возрастанию номера.
- [ ] Отсутствующий файл состояния даёт `FAIL`, а не исключение.
- [ ] `stdout` — только отчёт; диагностика в `stderr`.
- [ ] Два прогона дают один вывод.
- [ ] `bash tests/test.sh` → 14 passed, 0 failed.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| приёмка падает после изменения состояния | сверяется константа | проверять свойство (`<=`, `>=`, `same`) |
| код 0 при проваленной фазе | код не связан с итогом | 1, если хоть одна `FAIL` |
| трассировка на отсутствующем файле | исключение не поймано | нет файла → `FAIL` |
| фазы в случайном порядке | нет сортировки по номеру | сортировать перед прогоном |
| тест «фаза N не поймала поломку» | проверка слишком мягкая | свойство должно ломаться при поломке |
| `stdout` засорён отладкой | печать не туда | диагностика в `stderr` |

## После выполнения

Зелёный тест означает, что курс пройден: всё построенное собрано в одну
проверку, и она возвращает ноль.

Главное, что стоит унести из шестидесяти дней: **проверяемое утверждение
сильнее уверенного.** «Работает» — мнение; «возвращает ноль, вот команда» —
факт, который может перепроверить кто угодно.

И последнее, ради чего был весь Season 8: **зелёная приёмка — не гарантия
безопасности, а честная граница знания.** Известное проверено и выполнено;
неизвестное осталось неизвестным. Инженер, который держит эту границу в
голове, надёжнее того, кто верит в галочку.

- S5 — [`s05e12`](../../season-05-security-pentesting/s05e12-cis-check/) счёт CIS;

код 0 вместо „скрипт отработал"» — сквозная линия всех тестов курса.
