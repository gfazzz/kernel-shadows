## Обстановка

Идёт объёмная атака: около 50 000 пакетов в секунду с 847 адресов, нагрузка на
машинах в тридцать раз выше нормы. Менять правила вслепую нельзя — половина
команды работает через тот же SSH, который можно закрыть одной командой.

Первый шаг — прочитать, что открыто сейчас. Не по памяти и не по вики, а по
действующим правилам.

## Приказ

Собрать `fw_audit.sh` — читает сохранённый вывод `ufw status` и помечает опасные
разрешения: чувствительные сервисы, доступные из интернета.

```
=== ALLOW-правила ===
  ALLOW: 22/tcp                     ALLOW       Anywhere
  ALLOW: 3306                       ALLOW       Anywhere
    ⚠️ чувствительный порт 3306 открыт наружу (Anywhere)!
---
Проблем: 1
```

Использование: `./fw_audit.sh UFW_STATUS_FILE`, где файл получен командой
`sudo ufw status > file`. Сам аудит root не требует и ничего не меняет.

## Данные

| Что | Как |
|---|---|
| файл правил | `"${1:?…}"`, проверить `[ -f … ]` |
| только разрешения | `case "$line" in *ALLOW*) ;; *) continue ;; esac` |
| порт | `port="${line%% *}"`, затем `port="${port%%/*}"` |
| чувствительные | `3306 5432 6379 27017 9200 11211` |
| открыт наружу | в строке есть `Anywhere` |
| счётчик | увеличивать там же, где печатается предупреждение |
| тревога | `ALERT` в stderr при `issues > 0` |

Сравнение портов — по **точному совпадению**: `3306` не должен находиться внутри
`33060`, а `9200` — внутри адреса `10.92.0.1`.

## Критерии приёмки

- [ ] `artifacts/fw_audit.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] В отчёт попадают разрешающие правила; строки `DENY` разрешениями не считаются.
- [ ] Чувствительный порт с источником `Anywhere` помечается проблемой.
- [ ] Тот же порт с источником `127.0.0.1` или конкретной подсетью **не** помечается.
- [ ] Порт распознаётся и со слэшем (`3306/tcp`), и без него.
- [ ] `33060` не принимается за `3306` (сверка целым значением).
- [ ] Правила `(v6)` не удваивают счётчик проблем по одному и тому же порту.
- [ ] `Проблем: N` соответствует числу помеченных строк.
- [ ] При `N > 0` выдаётся `ALERT` в stderr.
- [ ] Отсутствующий файл → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 12 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен для аудита (нужен, чтобы снять `ufw status` на сервере) |
| ОС | любая с bash |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | фикстура — сохранённый вывод `ufw status` во временном каталоге |

Фикстура воспроизводит реальный вывод: порты со слэшем и без, чувствительный
порт наружу и он же на петле, ловушку `33060`, строку `DENY` и правило `(v6)`.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| в проблемы попал порт на `127.0.0.1` | не проверяется источник | искать `Anywhere` в строке |
| `3306/tcp` не распознан | не отрезан протокол | `port="${port%%/*}"` |
| `33060` помечен как `3306` | сравнение по вхождению | сравнивать значения целиком |
| закрытый порт объявлен проблемой | не отфильтрованы `DENY` | брать только строки с `ALLOW` |
| один порт посчитан дважды | правило продублировано для `(v6)` | учитывать порт один раз |
| `ALERT` не виден в конвейере | ушёл в stdout | писать в stderr |

## После выполнения

Зелёный тест означает, что состояние стены известно из наблюдения, а не из
предположений. На реальных правилах операции аудит найдёт три позиции, одна из
которых открыта «на время отладки» ещё в июле.

`fw_audit.sh` — модуль фаервола в `netshield` (см. [`PROJECTS.md`](../../PROJECTS.md)).
