## II. Теория: порт, сокет, привязка

### Порт различает сервисы

На одном адресе живёт много программ, и порт говорит, какой из них адресован пакет. Пара `адрес:порт` называется **сокетом**, а полное соединение задаётся четвёркой: адрес и порт источника, адрес и порт назначения.

| Диапазон | Название | Кто занимает |
|---|---|---|
| 0–1023 | well-known | системные сервисы; слушать на них может только root |
| 1024–49151 | registered | прикладные сервисы |
| 49152–65535 | dynamic | исходящие соединения клиентов |

Знакомые: `22` SSH, `53` DNS, `80` HTTP, `443` HTTPS, `3306` MySQL, `5432` PostgreSQL, `6379` Redis, `9200` Elasticsearch.

### `ss` — что слушает прямо сейчас

```bash
ss -tln        # TCP (-t), только слушающие (-l), без резолва имён (-n)
ss -tuln       # плюс UDP
ss -tlnp       # с именами процессов (чужие — только под root)
```

```
State   Recv-Q Send-Q  Local Address:Port   Peer Address:Port
LISTEN  0      128     0.0.0.0:22           0.0.0.0:*
LISTEN  0      128     127.0.0.1:3306       0.0.0.0:*
LISTEN  0      128     [::]:80              [::]:*
```

Флаг `-n` не косметика: без него `ss` попытается разрешить адреса в имена, и на машине с недоступным DNS команда будет висеть секундами.

### Главное — адрес привязки, а не сам порт

Третья строка вывода важнее первых двух:

- `0.0.0.0:3306` — сервис принимает соединения **со всех интерфейсов**, то есть из сети;
- `127.0.0.1:3306` — только с самой машины;
- `[::]:80` — то же, что `0.0.0.0`, но для IPv6.

Один и тот же MySQL на этих двух привязках — это либо база, доступная только приложению на том же хосте, либо база, до которой может дотянуться любой, кто нашёл адрес. Разница в одной строке конфигурации.

> **Дмитрий:** *«Половина утечек, о которых пишут, — это не взлом. Это сервис, который подняли „временно, для теста" на `0.0.0.0` и забыли.»*

## III. Проверка: LILITH задаёт вопросы

**LILITH:** *«`ss` показал `LISTEN 0.0.0.0:6379`. Чем это опасно?»*

<details>
<summary>Подумай 30 секунд</summary>

`6379` — это Redis, который в конфигурации по умолчанию не требует пароля. На `0.0.0.0` он принимает соединения из сети — то есть любой, кто до него дотянулся, может читать и перезаписывать данные, а через несколько известных приёмов и добиться выполнения кода.

Правильная привязка для базы — `127.0.0.1` либо адрес внутреннего интерфейса, закрытого фаерволом. Открытый Redis — один из самых массовых способов потерять сервер, и находят его именно сканированием портов.
</details>

**LILITH:** *«Чем `ss` отличается от `nmap`, если оба показывают порты?»*

<details>
<summary>Ответ</summary>

Точкой зрения. `ss` смотрит **изнутри** машины и показывает, что на ней действительно слушает. `nmap` смотрит **снаружи** и показывает, до чего можно дотянуться через сеть.

Эти списки почти никогда не совпадают: порт может слушать, но быть закрыт фаерволом, а может не слушать вовсе — тогда снаружи он «закрыт» по другой причине. Нужны обе картины, и расхождение между ними — само по себе полезная информация.

Отдельно: сканировать чужие системы без разрешения — не диагностика, а атака. `nmap` разбираем в Season 5, на своей инфраструктуре.
</details>

## IV. Задание: пересчитать двери

Собери `check_ports.sh` — показывает слушающие TCP-сокеты и сверяет порты со списком разрешённых:

```
=== Слушающие TCP (адрес:порт) ===

127.0.0.1:3306

  ⚠️ 4444 — НЕ в allowlist (неожиданный порт!)
Неожиданных портов: 1
```

```bash

bash artifacts/check_ports.sh ../data/allowed_ports.txt

```

ТЗ и критерии — в [`mission.md`](mission.md). Тест подменяет `ss` заглушкой, в выводе которой есть и IPv6-сокет `[::]:80`, и порт `4444` — тот самый «временный сервис», которого в списке нет.

<details>
<summary>Подсказка (если застрял на 5+ минут)</summary>

```bash
listen=$(ss -tln 2>/dev/null | awk 'NR>1{print $4}')
ports=$(printf '%s\n' "$listen" | sed 's/.*://' | grep -E '^[0-9]+$' | sort -un)
for p in $ports; do
    grep -qxF "$p" "$allow" || echo "  ⚠️ $p — НЕ в allowlist"
done
```

`sed 's/.*://'` берёт всё после **последнего** двоеточия — поэтому работает и на `0.0.0.0:22`, и на `[::]:80`. `sort -un` убирает дубликаты и заодно сортирует по числу. Эталон — в `solution/`, открывай после попытки.
</details>

### Три ошибки, которые здесь делают

**Резать по первому двоеточию.** `cut -d: -f2` на строке `0.0.0.0:22` сработает, а на `[::]:80` вернёт пустоту: в IPv6-адресе двоеточий несколько. Номер порта — это всегда то, что после **последнего** двоеточия.

**Сравнивать порты как подстроки.** `grep -q "$p" allow.txt` для порта `4` найдёт строку `443` и объявит его разрешённым. Список портов сверяют по точному совпадению строки целиком: `grep -qxF`.

**Смотреть только на номер, забыв про адрес.** Порт `3306` в списке разрешённых — это нормально, если база слушает на `127.0.0.1`, и совсем другое дело, если на `0.0.0.0`. Полноценный аудит смотрит на пару целиком; в этой серии мы начинаем с номеров, но привычку смотреть на привязку стоит завести сразу.
