## Обстановка

Разбор в `s06e08` дал шесть находок: открытый обмен на 1883, анонимный
доступ, отсутствие прав по темам, посторонний подписчик на `#`, один пароль
на всех и потеря сессий при перезапуске.

Смена пароля закрывает одну из шести. Нужны три механизма сразу:
шифрование канала, учётные записи и права по темам.

## Приказ

Собрать `artifacts/mosquitto.conf` и `artifacts/acl`.

```bash
cp starter/mosquitto.conf starter/acl artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `findings.txt` | находки s06e08, которые обязана закрыть конфигурация |
| `roles.txt` | кто есть в сети и что каждому нужно |
| `tls_material.txt` | пути к выпущенным сертификатам и минимальная версия TLS |
| `broker_host.txt` | порты, пути к файлам, предел очереди |

## Требования

### `mosquitto.conf`

| Требование | Почему |
|---|---|
| ровно один `listener` — на TLS-порту | лишний слушатель надо защищать отдельно |
| незашифрованного порта нет **вовсе** | путь в обход сводит TLS к нулю |
| `cafile`, `certfile`, `keyfile` из `data/` | пути уже существуют, придумывать нельзя |
| `tls_version` не ниже указанной в `data/` | в 1.0 и 1.1 есть известные слабости |
| `allow_anonymous false` | иначе подключится кто угодно |
| `password_file`, `acl_file` | без учётных записей невозможна авторизация |
| `persistence` + `persistence_location` | иначе перезапуск теряет сессии и очереди |
| `max_queued_messages` не больше предела из `data/` | очередь пропавшего узла съест память |
| `log_dest file`, `log_type`, `connection_messages true` | иначе разбор вроде s06e08 невозможен |

### `acl`

| Требование | Почему |
|---|---|
| ни одной строки `topic` до первого `user`/`pattern` | такие строки достаются анонимным клиентам |
| `pattern write shadow/%u/telemetry/#` | каждый узел пишет **только свою** телеметрию |
| `pattern read shadow/%u/cmd/#` | и читает только свои команды |
| панель: читает телеметрию, пишет команды | и не наоборот |
| архиватор: только чтение телеметрии | права по потребности |
| наблюдатель: чтение `$SYS/#` | эта ветка не покрывается подпиской на `#` |
| ни одного правила на голую `#` | ровно то, что делал посторонний клиент |

## Чем добывать

| Что нужно | Как |
|---|---|
| порты и пути | `data/broker_host.txt` |
| сертификаты и версия TLS | `data/tls_material.txt` |
| роли и потребности | `data/roles.txt` |

## Критерии приёмки

- [ ] Оба файла созданы на основе `starter/`.
- [ ] Слушатель ровно один, на TLS-порту; порта `1883` нет.
- [ ] Все пути TLS совпадают с `data/tls_material.txt`.
- [ ] `allow_anonymous false`, заданы `password_file` и `acl_file`.
- [ ] `persistence true`, задана `persistence_location`, очередь ограничена.
- [ ] В `acl` нет правил анонимных и нет правил на голую `#`.
- [ ] Узел не может писать в чужую телеметрию и читать чужие команды.
- [ ] Панель не может писать в телеметрию; архиватор не может писать вообще.
- [ ] Все шесть находок из `data/findings.txt` закрыты.
- [ ] `bash tests/test.sh` → 45 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | не нужна |
| **брокер** | **не нужен** — конфигурация проверяется как текст |
| Внешние пакеты | нет |
| Изоляция теста | пути, порты и роли берутся из `data/` |

Тест не содержит зашитых путей и портов. Главное отличие от обычной
проверки конфигурации: **правила ACL проверяются не текстуально, а по
смыслу.** Тест проходит по правилам той же логикой, что и брокер, и
отвечает на вопросы вида «может ли `shadow-node-07` писать в
`shadow/shadow-node-12/telemetry/temp`». Правило с `+` вместо `%u`
выглядит почти так же, но модель разрешений сразу показывает разницу.

Отдельно проверяется, что каждая находка из `data/findings.txt` закрыта.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «остался listener 1883» | порт оставлен «на миграцию» | убрать совсем |
| «слушателей 2» | добавлен ещё один | оставить один |
| «узел НЕ пишет чужую телеметрию» провалился | в правиле `+` вместо `%u` | подставлять имя пользователя |
| «панель НЕ пишет телеметрию» провалился | правило `readwrite` | разделить `read` и `write` |
| «правила для анонимных» | `topic` стоит до первого `user` | перенести в нужный блок |
| «правило на голую #» | выдан доступ ко всему | перечислить конкретные ветки |
| «наблюдатель читает $SYS» провалился | нет блока `monitor` | `$SYS` выдаётся отдельно |
| «очередь съест память» | нет `max_queued_messages` | задать не больше предела из `data/` |

## После выполнения

Зелёный тест означает, что все три вопроса закрыты: канал зашифрован,
у каждого своя учётная запись, и каждому доступно ровно то, что нужно.
Взлом одного узла теперь даёт право писать одну температуру.

Стоит запомнить принцип, который в IoT стоит дороже, чем где-либо:
**безопасность определяется самым слабым доступным путём, а не самым
сильным настроенным.** Оставленный «на время» незашифрованный порт
отменяет TLS целиком, и хуже всего то, что конфигурация при этом
выглядит защищённой. Проверять поэтому надо не «включено ли», а
«осталось ли что-то в обход» — вопрос, который формулируется отрицанием
и потому редко попадает в чек-листы.

Второе, что стоит унести: **конфигурацию безопасности проверяют
моделированием, а не чтением.** Текст говорит, что написано; модель
разрешений отвечает, что из этого следует. Разница между `%u` и `+` —
один символ в тексте и вся разница по смыслу.

## Кумулятивность

Шесть находок, которые закрывает эта конфигурация, добыты в
[`s06e08`](../s06e08-mqtt-dump/); `$SYS` как ветка вне `#` — оттуда же.
Секции слушателя — та же семантика положения, что у фильтров `config.txt`
в [`s06e03`](../s06e03-boot-config/): строка относится к тому блоку, после
которого стоит.

Default-deny в ACL — прямое продолжение профиля AppArmor из
[`s05e11`](../../season-05-security-pentesting/s05e11-hardening/):
перечисляется разрешённое, остальное запрещено. Права по потребности —
та же мысль, что в
[`s03e03`](../../season-03-system-administration/s03e03-sudo/). Уход от
общего пароля к именованным учётным записям повторяет переход от паролей
к ключам в [`s02e08`](../../season-02-networking/s02e08-ssh-keys/), а
требование «нет пути в обход» — логику правил брандмауэра из
[`s02e06`](../../season-02-networking/s02e06-firewall-ufw/).

Проверка конфигурации моделированием, а не текстом, продолжает
[`s04e07`](../../season-04-devops-automation/s04e07-ci-pipeline/), где по
графу `needs` проверялась достижимость этапа, а не наличие строк.
