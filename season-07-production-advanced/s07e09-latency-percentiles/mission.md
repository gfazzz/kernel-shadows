## Обстановка

После правки 95-й перцентиль вырос с двухсот двадцати миллисекунд до
двухсот тридцати семи — восемь процентов. Обе величины получены
интерполяцией внутри **одной и той же** корзины `[100, 250]`, то есть
двумя предположениями об одном и том же неизвестном.

Разрешение прибора — сто пятьдесят миллисекунд. Измеряют им семнадцать.

## Приказ

Написать `artifacts/latency.py` — программу, которая считает перцентили по
гистограмме и честно сообщает, можно ли по ним что-то сказать.

```bash
cp starter/latency.py artifacts/
python3 artifacts/latency.py data/base.txt data/noise.txt
bash tests/test.sh
```

| Файл в `data/` | Что это |
|---|---|
| `base.txt` | как было до изменения |
| `regression.txt` | задержка выросла по-настоящему |
| `noise.txt` | «выросла» на восемь процентов внутри одной корзины |

## Договор

```
BEFORE p50=<мс> p95=<мс> p99=<мс>
AFTER  p50=<мс> p95=<мс> p99=<мс>
BOUNDS p50 before=[<мс>,<мс>] after=[<мс>,<мс>]
BOUNDS p95 before=[<мс>,<мс>] after=[<мс>,<мс>]
BOUNDS p99 before=[<мс>,<мс>] after=[<мс>,<мс>]
VERDICT no-change | regression | improvement | inconclusive
```

Код возврата: `0` — разобрано, `1` — регрессия, `2` — вход не понят.

## Чем добывать

| Что нужно | Как |
|---|---|
| перцентиль | найти корзину, где накопленный счёт впервые ≥ `q × total` |
| интерполяция | `lo + (hi − lo) × (target − cum_lo) / (cum_hi − cum_lo)` |
| границы | те самые `lo` и `hi`; у первой корзины `lo` — ноль |
| приговор | сравнить границы: пересекаются — сказать нельзя |
| миллисекунды | `int(x * 1000)` — доли здесь шум интерполяции |

## Критерии приёмки

- [ ] Перцентили совпадают с независимым расчётом по гистограмме.
- [ ] Границы корзин напечатаны для каждого перцентиля.
- [ ] `base` против `noise` → `inconclusive`: одна корзина, разница внутри предположения.
- [ ] `base` против `regression` → `regression` и код возврата 1.
- [ ] `regression` против `base` → `improvement`.
- [ ] `base` против самого себя → `no-change`.
- [ ] Гистограмма без корзины `+Inf` отвергается кодом 2.
- [ ] Порядок строк во входе не влияет на результат.
- [ ] Перцентили не убывают: p50 ≤ p95 ≤ p99.
- [ ] Два прогона дают один вывод; `stderr` пуст на исправном входе.
- [ ] `bash tests/test.sh` → 78 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с python3 (3.8+) |
| Сеть | не нужна |
| **Prometheus** | **не нужен** — снимки в `data/` |
| Внешние пакеты | нет, только стандартная библиотека |
| Изоляция теста | вывод пишется в `mktemp -d`, снимки только читаются |

Тест считает перцентили независимой реализацией на awk и сверяет с
выводом программы. Отдельно проверяется, что данные не выродились: что
снимок `noise` отличается от базового числом, но лежит в той же корзине, и
что `regression` лежит в корзине заведомо выше.

Все сравниваемые величины целые: доли миллисекунды здесь не измерение, а
шум интерполяции.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| перцентиль занижен | корзины взяты как ненакопительные | `le="0.1"` — все, кто быстрее |
| `BEFORE p50` не сходится | целевое число взято от числа корзин | `q × total` |
| нижняя граница первой корзины неверна | взята её собственная граница | у первой `lo` — ноль |
| `VERDICT regression` на `noise` | сравнивались числа | сравнивать надо границы |
| разбор зависит от порядка строк | список не отсортирован | сортировать по границе |
| `+Inf` не отвергается | нет проверки полноты | без хвоста перцентиль не считается |
| «два прогона дают разный вывод» | обход множества вместо списка | зафиксировать порядок |

## После выполнения

Зелёный тест означает, что программа отвечает «сказать нельзя» там, где
сказать действительно нельзя, и «регрессия» там, где корзины не
пересекаются ни при каком распределении внутри них.

Главное, что стоит унести: **у перцентиля по гистограмме есть разрешение,
и оно обычно крупнее того, что пытаются измерить.** Число с тремя знаками
выглядит точным и не содержит ни бита сведений о том, чего в гистограмме
нет, — о распределении внутри корзины. Сравнивать можно только величины
из непересекающихся корзин, а гистограммы с разными границами нельзя
сравнивать вовсе: менялась не задержка, а прибор.

И второе, более общее: **«мы не знаем» — тоже результат**, если сказано с
обоснованием. Ответ «инконклюзивно» непопулярен, но честен, а число,
выданное вместо него, будет использовано как факт.

## Кумулятивность

Гистограмма, по которой всё это считается, приведена в порядок в
[`s07e05`](../s07e05-metrics-exporter/): там чинилась отсутствующая
корзина `+Inf`, без которой хвост неизвестен и перцентиль не считается.

Выражение `histogram_quantile(0.95, sum by (le) (...))` из
[`s07e06`](../s07e06-alert-rules/) написано именно так, потому что
складывать корзины можно, а перцентили — нет.

Весь разбор [`s07e08`](../s07e08-bottleneck/) опирался на одно число —
620 мс по 95-му перцентилю. Эта серия говорит, чего оно стоит.

Проверка свойства вместо сравнения с константой — сквозное правило курса
(§4.3): здесь оно принимает вид «сравнивать границы, а не
интерполированные значения».
