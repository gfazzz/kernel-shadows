## Теория: `find` + первый скрипт (один концепт: автоматический поиск)

Ручной обход — «зашёл в комнату, посмотрел, вышел» — медленно. **`find` — радар**: сканирует всё дерево рекурсивно за долю секунды.

```bash
find . -name "briefing.txt"    # найти по имени, здесь и во всех подпапках
find . -name ".*"              # все скрытые
find . -type f                 # только файлы
```

Теперь превратим команды в **инструмент**. Скрипт — это файл с командами и shebang'ом:

```bash
#!/usr/bin/env bash
set -euo pipefail
briefing="$(find "$base" -name 'briefing.txt' | head -1)"
cat "$briefing"
```

`$(...)` сохраняет вывод команды в переменную; `>`/`>>`/`tee` пишут результат в файл. Флаги `find` (`-type`, `-size`, `-perm`), `-exec` и строгий режим `set -euo pipefail` разобраны в [`theory.md`](theory.md).

> **LILITH:** *«`find .` — твой радар. Скрипт — твоя первая автоматизация: от поиска файлов до CI/CD-пайплайнов. Начни с малого — но начни сегодня.»*

## Проверка «в мире сюжета»

**LILITH:** *«На сервере тысячи файлов. Нужны ВСЕ `.log` больше 100 МБ. Одной командой?»*

<details>
<summary>Подумай 30 секунд</summary>

```bash
find / -name "*.log" -size +100M
```

`find` комбинирует условия: имя (`-name`) И размер (`-size +100M`). Это уже мини-аудит, а не просто поиск.
</details>

**LILITH:** *«Почему скрипт лучше, чем те же команды руками каждый раз?»*

<details>
<summary>Ответ</summary>

Повторяемость и отсутствие ошибок: 10 команд руками — 5 минут и шанс опечататься; `./find_files.sh` — 5 секунд, одинаково каждый раз. Это фундамент автоматизации всего курса.
</details>

ТЗ и «Требования среды» — в [`mission.md`](mission.md). Тест (8 проверок) кладёт `.next_server` **глубоко** во вложенные папки: пройдёт только рекурсивный `find`, «плоский» `cat *` тест отвергает.

<details>
<summary>Подсказка (после попытки)</summary>

```bash
base="${1:-.}"; report="${2:-report.txt}"
briefing="$(find "$base" -name 'briefing.txt' | head -1)"
{ echo "=== briefing ==="; cat "$briefing"; } | tee "$report"
```
