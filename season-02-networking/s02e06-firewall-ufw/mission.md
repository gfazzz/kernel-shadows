## Обстановка

Идёт объёмная атака: около 50 000 пакетов в секунду с 847 адресов, нагрузка в
тридцать раз выше нормы. Менять правила вслепую нельзя — половина команды
работает через тот же SSH, который можно закрыть одной командой.

Первый шаг — понять, что открыто **сейчас**. Не по памяти и не по вики, а по
действующим правилам. Снимок с сервера уже снят.

## Приказ

Провести разведку по снимку и **сдать отчёт** — заполненный
`artifacts/fw_report.txt`. Не инструмент, а находки: какая политика по умолчанию,
что разрешено из интернета, что только для внутренней сети, где стоит правило
«разрешить всё» и что слушает наружу мимо всяких правил.

```bash
cp starter/fw_report.txt artifacts/fw_report.txt
# заполнить каждое значение, добывая его командами
bash tests/test.sh
```

## Объект разведки и источники

| Файл | Что это |
|---|---|
| [`data/ufw_status_moscow1.txt`](../data/ufw_status_moscow1.txt) | снимок `ufw status verbose` — предмет разбора |
| [`data/ss_listen_moscow1.txt`](../data/ss_listen_moscow1.txt) | снимок `ss -tuln` с той же машины (из s02e02) |

Один из вопросов требует сопоставить оба файла: правила говорят, что разрешено,
`ss` говорит, что слушает, и интересное живёт в расхождении.

## Чем добывать

| Что нужно | Как |
|---|---|
| политика по умолчанию | `grep -i '^Default:' "$FW"` — смотреть часть про `incoming` |
| только разрешения | `grep -E '[[:space:]]ALLOW' "$FW"` |
| номер порта | `awk '{print $1}' \| sed 's\|/.*\|\|'` — отрезать `/tcp` |
| источник правила | последнее поле строки |
| из интернета | строки с `Anywhere` |
| из внутренней сети | строки с `10.50.0.0/24` |
| правило «разрешить всё» | строка, где в колонке `To` стоит `Anywhere`, а не порт |
| уникальные, по возрастанию | `sort -un`, список — `paste -sd, -` |

Чувствительными считаем `3306 5432 6379 9200 27017 11211`.

## Критерии приёмки

- [ ] `artifacts/fw_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Политика по умолчанию для входящих определена по строке `Default:`.
- [ ] Число строк `ALLOW` и `DENY` подсчитано отдельно.
- [ ] Порты, открытые из интернета, отделены от открытых только для внутренней сети.
- [ ] Строки `(v6)` не удваивают список портов.
- [ ] Строка `DENY` не попала в разрешения.
- [ ] Найдено правило, разрешающее с подсети **всё**, и указан его источник.
- [ ] Найдены порты, которые слушают наружу, но в правилах не упомянуты.
- [ ] Вывод о действенности фаервола согласован с политикой по умолчанию.
- [ ] `bash tests/test.sh` → 13 passed, 0 failed.

## Выполнение

```bash
cd season-02-networking/s02e06-firewall-ufw
cp starter/fw_report.txt artifacts/fw_report.txt
FW=../data/ufw_status_moscow1.txt
grep -i '^Default:' "$FW"                     # с этого стоит начать
grep -E '[[:space:]]ALLOW' "$FW"
bash tests/test.sh
```

На реальном сервере снимок снимается так: `sudo ufw status verbose > /tmp/ufw.txt`.
Перед любым изменением правил поставь себе отложенный откат — приём разобран
в [`theory.md`](theory.md).

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| политика не найдена | ищется `default` в правилах, а не строка `Default:` | `grep -i '^Default:'` |
| портов больше, чем есть | посчитаны дубли `(v6)` | `sort -un` по номерам |
| `27017` попал в разрешённые | не отфильтрованы `DENY` | брать только строки с `ALLOW` |
| `9100` попал в открытые наружу | не различаются источники | `Anywhere` против `10.50.0.0/24` |
| правило «разрешить всё» пропущено | ищется только по номерам портов | в колонке `To` там слово `Anywhere` |
| нет расхождения ss/ufw | сопоставлен один файл | сравнить публичные порты из `ss` со всеми портами правил |
| тест «значение не заполнено» | ключ переименован или потерян `=` | брать шаблон из `starter/` без правок |

## После выполнения

Зелёный тест означает, что состояние стены известно из наблюдения. И главная
находка не в списке портов: политика по умолчанию — `allow`, то есть все аккуратно
выписанные разрешения не закрывают ничего. Правило, разрешающее с подсети всё,
поставили «на время отладки» ещё в июле, а два слушающих порта не упомянуты
в правилах вовсе.

Отчёт вместе с `ports_report.txt` из [`s02e02`](../s02e02-ports-sockets/) даёт
полную карту поверхности `netshield` (см. [`PROJECTS.md`](../../docs/PROJECTS.md)):
что слушает и что из этого действительно доступно.

Дальше — сама атака: 847 адресов, которые надо заблокировать одним заходом,
а не вносить руками до вечера. Это капстоун эпизода.
