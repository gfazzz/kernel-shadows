## Обстановка

Виктор прислал список инструментов операции — дюжина позиций с пояснениями.
Половина из них на машине уже есть: часть пришла с системой, часть ставилась
раньше и забылась.

Ставить весь список подряд нельзя: переустановка поверх рабочего пакета тянет
новую версию, трогает конфигурацию и ломает то, что работало утром. Сначала
надо посчитать разницу между «должно быть» и «есть».

## Приказ

Собрать `pkg_check.sh` — читает манифест и для каждого пакета сообщает, установлен
он или нет, в конце печатает итог:

```
  ✓ git — установлен
  ✗ htop — НЕ установлен
---
Установлено: 3 | Отсутствует: 2
```

Использование: `./pkg_check.sh required_tools.txt`.

Реальная установка недостающего делается потом руками: `sudo apt install <пакет>`.
Обёртку над `apt` мы не пишем — это ровно то, чему серия учит не делать.

## Данные

| Что | Как |
|---|---|
| манифест | первый аргумент — `"${1:?…}"`, проверить `[ -f … ]` |
| чтение | `while IFS= read -r line; … done < "$list"` (из s01e08) |
| пропуск мусора | пустые строки и строки, начинающиеся с `#` |
| имя пакета | `pkg="${line%% *}"` — комментарий после имени отсекается |
| проверка статуса | `dpkg -l "$pkg" 2>/dev/null \| grep -q '^ii'` |
| счётчики | `installed`, `missing`; объявить до цикла |

Формат манифеста: одна строка — один пакет, дальше произвольный комментарий.
Есть шапка-комментарий и пустые строки.

## Критерии приёмки

- [ ] `artifacts/pkg_check.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Статус проверяется через `dpkg` и **префикс `^ii`**, а не по наличию вывода.
- [ ] Пакет в состоянии `rc` (удалён, конфиги остались) считается **отсутствующим**.
- [ ] Полностью неизвестный пакет считается отсутствующим, скрипт при этом не падает.
- [ ] Комментарии, пустые строки и текст после имени пакета не принимаются за пакеты.
- [ ] Итоговые счётчики соответствуют выведенным строкам.
- [ ] Отсутствующий манифест → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 12 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен (реальная установка — с `sudo`, но она вне теста) |
| ОС | любая с bash — Ubuntu не требуется |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | в реальном запуске `dpkg`; в тесте подменяется |
| Изоляция теста | мок-`dpkg` в `PATH` + фикстура-манифест во временном каталоге |

Мок-`dpkg` воспроизводит три состояния: установлен (`ii`), удалён с оставшимися
конфигами (`rc`) и неизвестен (ненулевой код). Ожидаемые числа тест получает,
прогоняя мок по манифесту, а не хранит константами.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| всё помечено установленным | проверяется код возврата `dpkg`, а не вывод | `\| grep -q '^ii'` |
| удалённый пакет считается установленным | `grep` без якоря `^` ловит `rc`-строку | якорь обязателен |
| в имени пакета оказался комментарий | не отрезано первое поле | `pkg="${line%% *}"` |
| шапка манифеста обработана как пакет | нет фильтра комментариев | `case "$line" in \#*) continue ;; esac` |
| счётчики нулевые при верных строках | цикл в подоболочке | читать через `done < "$list"` |
| `apt install` пишет «пакет не найден» | индекс не обновлён | `sudo apt update` |
| нет манифеста → «Установлено: 0» | нет проверки входа | `[ -f "$list" ]`, иначе `exit 1` |

## После выполнения

Зелёный тест означает, что ты знаешь разницу между желаемым и фактическим
составом системы — и закрываешь только её. `pkg_check.sh` — инвентаризация
окружения `shadow_toolkit` (см. [`PROJECTS.md`](../../docs/PROJECTS.md)).

Дальше манифестов станет несколько, по одному на роль сервера, и ставить по
одному пакету перестанет иметь смысл. Финал сезона — пакетная установка списком
и отчёт о том, что получилось.
