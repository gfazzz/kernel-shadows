## Обстановка

Буфер измерений живёт в ядре, но снаружи к нему не обратиться. Вчерашняя
попытка стажёра кончилась бесконечным `cat`: драйвер каждый раз отдавал
всё с начала и никогда не говорил «конец».

Нужен драйвер символьного устройства, который ведёт себя как файл: отдаёт
столько, сколько просят, помнит позицию, возвращает ноль в конце и
переносит данные через границу пользователь/ядро правильным способом.

## Приказ

Написать два файла:

- `artifacts/shadow_view.c` — представление буфера: форматирование и
  подсчёт «сколько отдать с какой позиции». Без заголовков ядра;
- `artifacts/shadow_dev.c` — драйвер: `file_operations`, регистрация,
  чтение.

`shadow_ring.c` и `shadow_ring.h` перенесены из
[`s06e11`](../s06e11-kernel-module/) **без изменений** — их не
переписывают, ими пользуются.

```bash
cp starter/* artifacts/
bash tests/test.sh
```

| Файл в `data/` | Что в нём |
|---|---|
| `dev_rules.txt` | что обязано быть в драйвере и почему |
| `forbidden.txt` | чего быть не должно |
| `pairs.txt` | парные вызовы: что взял — отдай |

## Требования

### `shadow_view.c`

| Функция | Требование |
|---|---|
| `shadow_format_line` | «`seq=12 t=23.062`»; дробная часть **всегда три цифры**; минус при нулевой целой части; `-1`, если не помещается |
| `shadow_render` | весь буфер от **старого к свежему**; `-1` при нехватке места |
| `shadow_copy_slice` | `min(count, len - pos)` байт с позиции `pos`; `pos >= len` → **0** (конец файла); `-1` при плохих аргументах |
| все | `NULL` не роняет; сборка `-Wall -Wextra -Werror` чиста |

### `shadow_dev.c`

| Требование | Почему |
|---|---|
| `file_operations` с `.owner = THIS_MODULE`, `.open`, `.read`, `.release` | иначе `rmmod` во время чтения оставит указатели на выгруженный код |
| `copy_to_user` и `-EFAULT` при неудаче | указатель из пользовательского пространства нельзя разыменовывать |
| `*ppos` продвигается на число отданных байт | иначе читатель зациклится |
| `shadow_copy_slice` вызывается, а не дублируется | подсчёт должен жить в проверяемом файле |
| пять пар «взял — отдал» из `data/pairs.txt` | незакрытый ресурс живёт до перезагрузки |
| лестница меток `err_*` | частичная инициализация обязана откатываться |
| блокировка и её снятие на **каждом** выходе из `read` | забытое снятие подвешивает всех читателей |
| `MODULE_LICENSE("GPL")` и метаданные | часть символов ядра иначе недоступна |
| нет `memcpy` в пользовательский буфер, `sprintf`, `float`, `malloc` | всё это в ядре запрещено или опасно |

## Чем добывать

| Что нужно | Как |
|---|---|
| требования к драйверу | `data/dev_rules.txt` |
| парные вызовы | `data/pairs.txt` |
| знак и дробная часть | `shadow_scale_milli` из `shadow_ring.c` |
| порядок от старого к свежему | `shadow_ring_peek(r, len-1)` — самое старое |

## Критерии приёмки

- [ ] Оба файла созданы на основе `starter/`; `shadow_ring.c` не изменён.
- [ ] `shadow_view.c` не подключает `<linux/…>`; сборка чиста.
- [ ] `shadow_copy_slice` возвращает `0` за концом данных, а не ошибку.
- [ ] Чтение по кускам собирается в исходные данные и завершается нулём.
- [ ] Дробная часть печатается тремя цифрами: `.005`, а не `.5`.
- [ ] В драйвере есть `copy_to_user`, `-EFAULT` и продвижение `*ppos`.
- [ ] Все пять пар ресурсов симметричны; есть лестница отката.
- [ ] Блокировка снимается на каждом пути выхода из чтения.
- [ ] `bash tests/test.sh` → 62 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | **не нужен** |
| компилятор | `gcc` или `cc` (C99) |
| ОС | любая: логика не зависит от ядра |
| заголовки ядра | **не нужны** для основного теста |
| Сеть | не нужна |
| Изоляция теста | требования и парные вызовы берутся из `data/` |

Основной прогон проверяет представление настоящими юнит-тестами и
разбирает драйвер структурно. Симметрия ресурсов проверяется по
`data/pairs.txt`: если в исходнике есть `class_create`, тест требует
`class_destroy` — и добавить новую пару можно, не трогая тест.

Сборка `.ko`, загрузка модуля и **чтение настоящего `/dev/shadow0`**
вынесены в отдельный тест:

```bash
bash tests/integration.sh          # или make test-integration
sudo bash tests/integration.sh     # с загрузкой модуля
```

Он проверяет то, чего не даст ни один юнит-тест: что `cat` дочитывает
устройство до конца и не зацикливается, что `head -c 8` отдаёт ровно
начало, и что после выгрузки узел в `/dev` исчезает. Без Linux и
заголовков ядра тест честно сообщает, чего не хватает.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «позиция на конце -> 0» | возвращается ошибка | за концом данных — это EOF |
| «чтение по кускам завершается нулём» | нет признака конца | читатель зациклится |
| «`.005`, а не `.5`» | дробная часть без ведущих нулей | ровно три цифры |
| «знак при нулевой целой» | `-0.875` печатается как `0.875` | использовать возврат 1 |
| «порядок от старого к свежему» | `render` идёт от `peek(0)` | начинать с `peek(len-1)` |
| `copy_to_user` не найден | использован `memcpy` | это уязвимость, а не оптимизация |
| «`ppos` не найдено» | позиция не продвигается | `*ppos += n` |
| «класс останется занят» | нет парного `class_destroy` | сверить с `data/pairs.txt` |
| «где-то она останется взятой» | пропущен `mutex_unlock` | снимать на каждом `return` |

## После выполнения

Зелёный тест означает, что устройство ведёт себя как файл: отдаёт не
больше запрошенного, помнит позицию, честно сообщает о конце и переносит
данные через границу правильным способом. Season 6 закончен.

Стоит запомнить три вещи, которые дальше пригодятся вне ядра. Первая:
**у «пусто» должно быть два разных ответа** — «данных больше не будет»
(конец) и «данных пока нет» (подожди или попробуй позже). Смешать их —
значит либо оборвать читателя раньше времени, либо не отпустить его
никогда.

Вторая: **данные, пришедшие из-за границы доверия, проходят её только
через предназначенные для этого средства.** В ядре это `copy_to_user` и
`copy_from_user`; в вебе — валидация ввода; в разборе показаний — проверка
CRC. Граница есть всегда, вопрос только в том, замечена ли она.

Третья: **симметрия «взял — отдай» распространяется на всё** — память,
номера устройств, классы, узлы в `/dev`, блокировки. И проверять её надо
на путях ошибок, потому что на успешном пути её не забывает никто.

## Кумулятивность

`shadow_ring.c` перенесён из [`s06e11`](../s06e11-kernel-module/) без
единого изменения — это и есть накопление: каждая серия добавляет слой
поверх проверенного, а не переписывает его заново. `shadow_scale_milli`
оттуда же решает здесь задачу печати без плавающей точки.

«Всё есть файл» замыкает круг, начатый в
[`s06e02`](../s06e02-gpio-sysfs/): там ядро отдавало железо файлами, здесь
студент сам делает то же самое. Различие «конец» и «пока пусто» — та же
мысль, что `None` вместо нуля в
[`s06e10`](../s06e10-sensor-client/): два разных случая нельзя выражать
одним значением.

Симметрия ресурсов продолжает `export`/`unexport` из
[`s06e02`](../s06e02-gpio-sysfs/) и `kzalloc`/`kfree` из
[`s06e11`](../s06e11-kernel-module/). Проверка границы доверия —
[`s06e06`](../s06e06-mission-check/) (план полёта),
[`s06e07`](../s06e07-failsafe/) (параметры),
[`s06e10`](../s06e10-sensor-client/) (показания датчика) и
[`s06e11`](../s06e11-kernel-module/) (параметр модуля): каждый раз это был
один и тот же вопрос — откуда пришло значение и кто за него отвечает.

Сеть `shadow_mesh` собрана целиком: плата опознана
([`s06e01`](../s06e01-board-recon/)), настроена
([`s06e02`](../s06e02-gpio-sysfs/)–[`s06e04`](../s06e04-readonly-root/)),
дрон проверен
([`s06e05`](../s06e05-mavlink-telemetry/)–[`s06e07`](../s06e07-failsafe/)),
обмен закрыт
([`s06e08`](../s06e08-mqtt-dump/)–[`s06e10`](../s06e10-sensor-client/)),
ядро расширено
([`s06e11`](../s06e11-kernel-module/)–s06e12).
