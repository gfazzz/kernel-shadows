## Порт = квартира в здании (IP)

Один IP — одно «здание», но сервисов на нём много. Порт различает сервисы:
`IP:PORT` → `192.168.1.100:22` (SSH).

| Диапазон | Название | Использование |
|----------|----------|---------------|
| 0–1023 | well-known | системные сервисы (нужен root, чтобы слушать) |
| 1024–49151 | registered | приложения |
| 49152–65535 | dynamic | временные (клиентские соединения) |

Популярные: `22` SSH · `80` HTTP · `443` HTTPS · `25` SMTP · `53` DNS · `3306` MySQL ·
`5432` PostgreSQL · `6379` Redis.

## `ss` — смотрим сокеты

```bash
ss -tln     # TCP (-t), только LISTEN (-l), числовой (-n) — что слушает
ss -tuln    # + UDP (-u)
ss -tp      # с процессами (нужен root для чужих)
```

Вывод (колонка `Local Address:Port`):

```
State   Local Address:Port
LISTEN  0.0.0.0:22          # SSH слушает на ВСЕХ интерфейсах
LISTEN  127.0.0.1:3306      # MySQL только на localhost
ESTAB   192.168.1.100:45678 → 142.250.185.46:443   # активное HTTPS
```

Состояния: `LISTEN` (ждёт подключений), `ESTAB` (активное), `TIME_WAIT` (закрывается).

`netstat -tuln` — старый аналог `ss` (пакет `net-tools`); `ss` быстрее и современнее.

## Security: `0.0.0.0` vs `127.0.0.1`

- `0.0.0.0:PORT` — сервис доступен **извне** (со всех интерфейсов).
- `127.0.0.1:PORT` — только **локально**.

База данных на `0.0.0.0:3306` — открытая дверь для атакующего. Правило: наружу торчит
только то, что должно (обычно 443/80/22), остальное — на `127.0.0.1` или за firewall (S2E06–07).

## `nmap` — взгляд снаружи (превью)

`ss` показывает порты **изнутри** хоста. `nmap` сканирует **снаружи** — как видит тебя атакующий:

```bash
nmap -sT 10.50.1.100        # TCP connect scan
nmap -p 22,80,443 host      # конкретные порты
```

> Сканировать можно только свои системы или с явного разрешения — иначе это атака.
> Полноценно `nmap` и оборона — в Season 5. Здесь достаточно понимать разницу
> «изнутри (`ss`) vs снаружи (`nmap`)».
