## Обстановка

Количества посчитаны, но Анне нужны не количества, а **кто**: какие адреса
работали по серверу и как часто. Это уже вопрос не про строки, а про колонки —
адрес стоит первым полем каждой записи.

Дополнительная сложность в самих данных: часть запросов содержит пробелы внутри
строки запроса, и нумерация полей на таких строках уезжает. Заметить это —
половина задачи.

## Приказ

Провести разбор по полям и **сдать отчёт** — заполненный
`artifacts/attackers_report.txt`: сколько адресов, кто лидер, тройка самых
активных, самый популярный путь, число разных статусов и кто лидировал внутри
минуты пика.

Отдельно требуется посчитать статус `403` **двумя** способами — через `$9` и
через разбор по кавычкам — и записать оба числа.

```bash
cp starter/attackers_report.txt artifacts/attackers_report.txt
bash tests/test.sh
```

## Объект разбора

| Файл | Что это |
|---|---|
| [`data/access.log`](../data/access.log) | тот же журнал, что в s01e10 |

```
IP - - [дата] "МЕТОД /путь HTTP/1.1" статус размер "referer" "user-agent"
$1                                            $9 — но только пока
                                              в запросе ровно два пробела
```

## Чем добывать

| Что нужно | Как |
|---|---|
| уникальные адреса | `awk '{print $1}' "$L" \| sort -u \| wc -l` |
| рейтинг адресов | `awk '{print $1}' "$L" \| sort \| uniq -c \| sort -rn` |
| список через запятую | `head -3 \| awk '{print $2}' \| paste -sd, -` |
| путь запроса | `awk -F'"' '{print $2}' "$L" \| awk '{print $2}'` |
| статус честно | `awk -F'"' '{print $3}' "$L" \| awk '{print $1}'` |
| статус наивно | `awk '{print $9}' "$L"` — для сравнения |
| срез по времени | `grep '04/Oct/2025:03:47' "$L" \| …` |

Программа `awk` всегда в **одинарных** кавычках: в двойных bash подставит свои
`$1`, `$9` до запуска.

## Критерии приёмки

- [ ] `artifacts/attackers_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] Число уникальных адресов и рейтинг посчитаны по первому полю.
- [ ] Тройка лидеров упорядочена по убыванию и начинается с `top_ip`.
- [ ] Путь запроса извлечён из кавычек, а не по номеру поля.
- [ ] `403` посчитан двумя способами, и числа **различаются**.
- [ ] Число разных статусов посчитано правильным способом (мусор не считается статусом).
- [ ] Определён лидер минуты пика и число его запросов.
- [ ] `bash tests/test.sh` → 15 passed, 0 failed.

## Выполнение

```bash
cd season-01-shell-foundations/s01e11-awk-stats
cp starter/attackers_report.txt artifacts/attackers_report.txt
L=../data/access.log
awk '{print $1}' "$L" | sort | uniq -c | sort -rn | head -3
awk '{print $9}' "$L" | sort -u          # посмотри, что тут лишнее
bash tests/test.sh
```

Собирай конвейер по одному звену и после каждого смотри `| head`. Второй
командой выше видно всё, ради чего серия и написана.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| в списке «статусов» слова | поля уехали из-за пробелов в запросе | резать по `-F'"'`, потом брать поля |
| печатаются пустые строки | двойные кавычки вокруг программы `awk` | одинарные |
| один адрес в рейтинге дважды | нет `sort` перед `uniq -c` | добавить |
| `10` выше `9` | сортировка как текст | `sort -rn` |
| топ-путь вышел странным | взят по номеру поля | `awk -F'"' '{print $2}'` затем `awk '{print $2}'` |
| два подсчёта `403` совпали | оба сделаны одним способом | один — через `$9`, второй — через кавычки |

## После выполнения

Зелёный тест означает, что журнал прочитан не только вдоль, но и поперёк: пятнадцать
адресов, один с шестью сотнями запросов, и сорок пять строк, которые наивный разбор
выбрасывал молча.

Дальше Анне нужен не набор чисел из переписки, а документ: объём, распределение
статусов, топ адресов и сверка со списком известных угроз — в одном файле, который
можно приложить к делу. Это капстоун эпизода и первый случай, когда всё сделанное
руками дважды имеет смысл оформить инструментом.
