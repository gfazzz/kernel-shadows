## SSH-ключи вместо паролей

Пароль можно подобрать (`password123` — топ-3 в 2024). Ключ — криптография: 256-битный
ed25519 = 2²⁵⁶ вариантов, brute-force нереален.

```bash
ssh-keygen -t ed25519 -C "max@shadow-ops"          # создать пару
# → ~/.ssh/id_ed25519 (приватный) + id_ed25519.pub (публичный)
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server   # положить публичный на сервер
```

**Приватный ключ никогда не покидает твою машину.** Публичный — кладётся на серверы
(`~/.ssh/authorized_keys`). Подпись приватным проверяется публичным — доступ без пароля.

## Права — критично

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_ed25519        # приватный: только владелец r/w
chmod 644 ~/.ssh/id_ed25519.pub    # публичный: читать всем можно
```

Если у приватного ключа права шире `600` (например, `644` — читают все), **SSH откажется
его использовать** («UNPROTECTED PRIVATE KEY FILE») — потому что ключ, доступный другим
пользователям, скомпрометирован. Проверка прав — первое, что делают при проблемах с ключом.

## ed25519 vs RSA

| | ed25519 | RSA 4096 |
|--|---------|----------|
| Длина ключа | короткий | длинный |
| Скорость | быстрее | медленнее |
| Безопасность | высокая | высокая |
| Совместимость | 2014+ | везде |

Правило: если сервер поддерживает ed25519 (а современный поддерживает) — всегда ed25519.
`id_dsa` — устарел (слабый, отключён в новых OpenSSH), заменять.

## `~/.ssh/config` — автоматизация доступа

Вместо длинных команд — алиасы:

```
Host shadow
    HostName 10.50.1.2
    User max
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host *.ops.internal
    User max
    IdentityFile ~/.ssh/id_ed25519
```

Теперь `ssh shadow` вместо `ssh -i ~/.ssh/id_ed25519 -p 22 max@10.50.1.2`.
Это Type A — автоматизация рабочего процесса.
