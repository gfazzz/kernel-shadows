## Обстановка

Промышленный датчик вибрации отдаёт двести измерений в секунду, драйвера
под Linux для него нет. Читать такой поток из пользовательского
пространства — терять половину; работа для ядра.

Условие Ли Вэя: **никакой отладки перезагрузками.** Всё, что не обязано
жить в ядре, оттуда выносится и проверяется обычным `gcc`.

## Приказ

Написать два файла:

- `artifacts/shadow_ring.c` — логика: кольцевой буфер, обрезка параметра,
  разложение тысячных долей. Ни одного заголовка ядра;
- `artifacts/shadow_mod.c` — обвязка модуля: точки входа, параметры,
  память, сообщения в журнал.

```bash
cp starter/* artifacts/
bash tests/test.sh
```

Интерфейс задан в `shadow_ring.h` (дан готовым), сборка — в `Makefile`
(тоже готов).

| Файл в `data/` | Что в нём |
|---|---|
| `module_rules.txt` | что обязано быть в исходнике модуля и почему |
| `forbidden.txt` | чего в ядре быть не должно и почему |

## Требования

### `shadow_ring.c` — логика

| Функция | Требование |
|---|---|
| `shadow_ring_init` | `capacity` обрезается до `[1, SHADOW_RING_MAX]`; счётчики обнуляются |
| `shadow_ring_push` | буфер **не растёт**; при переполнении вытесняет старейшее, считает `dropped`, возвращает 1 |
| `shadow_ring_pop` | отдаёт **самое старое**; `-1` на пустом |
| `shadow_ring_len` | текущая длина |
| `shadow_ring_peek` | `idx=0` — самое свежее; корректен после оборота головы; `-1` за пределами |
| `shadow_param_clamp` | загоняет в границы, выдерживает `lo > hi` и отрицательные |
| `shadow_scale_milli` | целочисленно; дробная часть неотрицательна; при нулевой целой знак возвращается признаком |
| все | `NULL` не роняет; сборка `-Wall -Wextra -Werror` без единого предупреждения |

### `shadow_mod.c` — обвязка

| Требование | Почему |
|---|---|
| `module_init`/`module_exit`, `__init`/`__exit` | точки входа и освобождение памяти под них |
| `MODULE_LICENSE("GPL")`, `AUTHOR`, `DESCRIPTION`, `VERSION` | иначе ядро `tainted`, а `modinfo` пуст |
| `module_param` с восьмеричными правами + `MODULE_PARM_DESC` | параметр виден в sysfs и в `modinfo` |
| `shadow_param_clamp` **до** использования `depth` | параметр приходит извне |
| `kzalloc` с проверкой и `return -ENOMEM` | выделение может не удаться |
| парный `kfree` в выгрузке | в ядре нет сборщика мусора |
| `pr_info`/`pr_err`/`pr_warn` | сообщения с уровнем |
| ни `float`, ни `double`, ни `printf`, ни `malloc`, ни `stdio.h` | в ядре этого нет |
| арифметика кольца не продублирована | она должна жить в проверяемом файле |

## Критерии приёмки

- [ ] Оба файла созданы на основе `starter/`.
- [ ] `shadow_ring.c` не подключает ни одного `<linux/…>`.
- [ ] Сборка с `-Wall -Wextra -Werror` проходит без предупреждений.
- [ ] Все юнит-тесты логики зелёные, включая границы, оборот и знаки.
- [ ] `shadow_mod.c` удовлетворяет всем правилам из `data/module_rules.txt`.
- [ ] Ни одна конструкция из `data/forbidden.txt` не встречается.
- [ ] `bash tests/test.sh` → 69 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | **не нужен** |
| компилятор | `gcc` или `cc` (C99) |
| ОС | любая: логика не зависит от ядра |
| заголовки ядра | **не нужны** для основного теста |
| Сеть | не нужна |
| Изоляция теста | правила и запреты берутся из `data/` |

Основной прогон проверяет логику настоящими юнит-тестами и разбирает
исходник модуля структурно. Сборка настоящего `.ko`, `insmod`, чтение
`dmesg` и проверка обрезки параметра вынесены в отдельный тест:

```bash
make test-integration          # или: bash tests/integration.sh
sudo make test-integration     # с загрузкой модуля
```

Он требует Linux, заголовков работающего ядра и прав root. Если чего-то
нет, тест честно сообщает, чего именно, и завершается успешно: отсутствие
ядра под рукой — не ошибка студента, а логика к этому моменту уже
проверена.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «не собралось» с `unused parameter` | остались заглушки | реализовать функцию, убрать `(void)` |
| «pop отдаёт самое СТАРОЕ» | отдаётся свежее | старейшее — на `count` назад от `head` |
| «peek верен после оборота» | индекс без модуля | `(head + capacity - 1 - idx) % capacity` |
| «длина не превышает capacity» | `count` растёт без предела | при полном буфере `count` не увеличивается |
| «-4875 -> -4 и 875» | дробная часть отрицательна | взять модуль до деления |
| «знак отмечен признаком» | при целой части 0 знак потерян | вернуть 1 |
| `param_perm` не найден | права заданы не восьмеричным числом | `0444`, а не `S_IRUGO` |
| `float` найден | дробная арифметика в модуле | целые и раздельные части |
| «арифметика продублирована» | кольцо посчитано в `shadow_mod.c` | вызывать функции из `shadow_ring.c` |

## После выполнения

Зелёный тест означает, что тридцать пять свойств логики проверены за
миллисекунды, а в ядро уезжает двадцать строк обвязки, где ломаться почти
нечему.

Стоит запомнить решение, которое здесь важнее любой конкретной строки:
**границу между «обязано быть в ядре» и «может быть проверено снаружи»
проводят до первой строки кода.** Цена цикла «поправил — проверил»
различается на три порядка, и она умножается на число итераций отладки.
Приём не про ядро: так же отделяют код от базы данных, от сети, от
файловой системы — везде, где среда делает проверку дорогой.

Второе: **в ядре нет защиты, которая прощает небрежность.** Нет
изоляции памяти, нет сборщика мусора, нет `SIGSEGV`, который убьёт
только виноватого. Поэтому проверка внешнего ввода на границе,
симметрия «выделил — освободил» и ограниченные буферы здесь не хороший
тон, а условие работоспособности машины.

## Кумулятивность

Кросс-сборка под плату — та же `ARCH`/`CROSS_COMPILE`, что в
[`s06e01`](../s06e01-board-recon/), только применённая к дереву ядра.
Ограниченный буфер, который не растёт, — тот же приём, что `Spool` в
[`s06e10`](../s06e10-sensor-client/); только там переполнение стоило
потери телеметрии, а здесь — порчи памяти ядра.

Проверка внешнего ввода на границе продолжает
[`s06e06`](../s06e06-mission-check/) (пределы плана полёта) и
[`s06e07`](../s06e07-failsafe/) (параметры аппарата). Симметрия «занял —
освободил» — та же, что `export`/`unexport` в
[`s06e02`](../s06e02-gpio-sysfs/). Уровни сообщений `pr_*` устроены как
шкала `severity` из [`s06e05`](../s06e05-mavlink-telemetry/): меньше
значит серьёзнее.

Вынос логики туда, где её дёшево проверять, — прямое продолжение
[`s06e10`](../s06e10-sensor-client/), где время и случайность
передавались параметрами. Пирамида «юнит → сборка → виртуальная машина →
плата» — та же, что в
[`s04e07`](../../season-04-devops-automation/s04e07-ci-pipeline/).
