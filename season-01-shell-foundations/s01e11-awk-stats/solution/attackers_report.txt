# Почему 193 и 238 — разные числа.
#
# Поле $9 считается от начала строки по пробелам. Это работает, пока в запросе
# ровно два пробела: "GET /путь HTTP/1.1". Но в журнале есть такие строки:
#
#   "POST /api/users?id=1' UNION SELECT password HTTP/1.1" 403 1823
#
# Здесь пробелов пять, все поля справа уехали, и $9 попадает не в статус,
# а внутрь запроса. Отсюда мусор в списке «статусов»: SELECT и '1'='1.
# Наивный подсчёт теряет 45 запросов — ровно те, что и есть попытки инъекции
# и прочая разведка, то есть самое интересное.
#
# Правильный разбор: сначала резать по кавычкам (запрос целиком — это $2 при
# -F'"'), и только потом брать поля из остатка. Тогда статусов ровно 6,
# а не 8, и 403 их 238.
#
# Что видно из чисел:
#   - адресов всего 15, но 684 запроса из 4400 — с одного;
#   - он же лидирует и внутри минуты пика: 34 запроса за шестьдесят секунд;
#   - самый популярный путь при этом обычный /index.html — атака пряталась
#     в нормальном трафике, а не заменяла его.
