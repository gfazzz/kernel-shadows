## Обстановка

Анна Ковалёва сообщила о процессе с PID 6623, который называется `sshd`, хотя
настоящий `sshd` имеет PID 1043. Снимок таблицы процессов и подробности `/proc`
сняты сразу, после чего сервер отключён от сети и не перезагружался.

Разбираются копии: живая система недоступна, и это не ограничение задания —
так и работают с уликами.

## Приказ

Разобрать снимки и **сдать отчёт** — заполненный `artifacts/proc_report.txt`:
какой из процессов `sshd` настоящий, чем маскируются остальные, что запущено
из удалённого файла, куда оно ходит, есть ли зомби и кому по этому поводу
слать сигнал.

```bash
cp starter/proc_report.txt artifacts/proc_report.txt
bash tests/test.sh
```

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/ps_shadow-01.txt`](../data/ps_shadow-01.txt) | `ps -eo user,pid,ppid,pcpu,pmem,stat,start,command` |
| [`data/proc_shadow-01.txt`](../data/proc_shadow-01.txt) | `exe`, `cwd`, `cmdline`, `status`, `fd` по четырём PID |

В обоих файлах есть шапка с описанием формата. Строка заголовка `USER PID …`
в подсчёты попадать не должна.

## Чем добывать

| Что нужно | Как |
|---|---|
| только строки процессов | `grep -vE '^#\|^USER' "$F"` |
| поля | `$1` user, `$2` pid, `$3` ppid, `$4` %cpu, `$5` %mem, `$6` stat, `$7` start, дальше команда |
| зомби | `awk '$6 ~ /^Z/'` |
| потоки ядра | `awk '$2==2 \|\| $3==2'` — по родителю `kthreadd`, а не по скобке |
| дети процесса | `awk -v p=6623 '$3==p'` |
| по загрузке CPU | `sort -k4 -nr \| head` |
| разделы `/proc` | `awk '/^=== /{p=$0; gsub(/[^0-9]/,"",p)} /^exe -> /{print p, $0}'` |
| номер сигнала | `kill -l TERM` |

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбираются копии вывода команд |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из тех же снимков; номера сигналов — из `kill -l` |

Тест дополнительно проверяет, что ловушки на месте: зомби с именем в квадратных
скобках, две одинаковые строки запуска `sshd` при разных `exe`, обрезанные
имена пользователей в столбце `USER`.

## Выполнение

```bash
cd season-03-system-administration/s03e04-processes
cp starter/proc_report.txt artifacts/proc_report.txt
D=../data
grep -vE '^#|^USER' $D/ps_shadow-01.txt | awk '$6 ~ /^Z/'
awk '/^=== /{p=$0; gsub(/[^0-9]/,"",p)} /^exe -> /{print p, $0}' $D/proc_shadow-01.txt
bash tests/test.sh
```

На своей машине стоит посмотреть родословную собственных процессов — это
занимает секунду и объясняет половину теории:

```bash
ps -eo user,pid,ppid,stat,command --forest | less
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| потоков ядра на один больше | посчитан `[tar] <defunct>` | это зомби; фильтр по `$3==2` |
| `monitoring` не находится | `ps` обрезал имя до `monitor+` | искать по префиксу: `$1 ~ /^monitor/` |
| настоящим назван не тот `sshd` | сравнивалась строка `ps` | смотреть `/proc/PID/exe` |
| в подсчёты попала строка `USER PID …` | не отфильтрован заголовок | `grep -vE '^#\|^USER'` |
| `masquerade_exe` не принят | в значение попало `(deleted)` | пометка не часть пути |
| зомби «не убивается» | сигнал шлётся зомби | зомби уже мёртв; сигнал родителю |
| сортировка по CPU дала не то | `sort` без `-n` сравнивает как текст | `sort -k4 -nr` |

## После выполнения

Зелёный тест означает, что таблица процессов разобрана и обе маскировки
различены. Существеннее самих находок — порядок, в котором они получены:
сначала спросили ядро (`/proc`), потом читали то, что процессы говорят о себе.

Обрати внимание, что ни одна находка не потребовала ни root, ни запуска чего-либо
на живой машине. Это норма для разбора инцидента, а не особенность задания.
