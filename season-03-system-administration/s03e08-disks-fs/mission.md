## Обстановка

`/var/log` заполнен на 95 %. Через час база данных упрётся в отсутствие места
и остановится. Удалять наугад нельзя: часть журналов — материал расследования
по вечеру 14 октября.

Снимок состояния снят пятью командами и заморожен. Разбираются копии.

## Приказ

Выяснить, **куда делось место**, и сдать отчёт — заполненный
`artifacts/disk_report.txt`: где кончились блоки, где кончились inode, почему
`df` и `du` расходятся, кто держит удалённый файл и что занимает место
на самом деле.

```bash
cp starter/disk_report.txt artifacts/disk_report.txt
bash tests/test.sh
```

Размеры пишутся ровно так, как их печатают команды: `18G`, `980M`, `4.2G`.

## Объект разведки

| Раздел файла | Что это |
|---|---|
| `=== df -h ===` | занятость по блокам |
| `=== df -i ===` | занятость по inode |
| `=== lsblk -f ===` | устройства, файловые системы, точки монтирования |
| `=== du -h --max-depth=1 /var/log ===` | что внутри каталога |
| `=== lsof +L1 ===` | файлы без имён, открытые процессами |

Всё в одном файле: [`data/disk_shadow-01.txt`](../data/disk_shadow-01.txt).

## Чем добывать

| Что нужно | Как |
|---|---|
| вырезать раздел | `awk -v s='df -h' '$0=="=== "s" ===" {f=1; next} /^=== /{f=0} f' "$D"` |
| самая заполненная ФС | `awk 'NR>1 {gsub(/%/,"",$5); ...}'` — сравнивать числа, не строки |
| исчерпание inode | в `df -i` колонка `IUse%` равна `100%` |
| занято по df | пятая колонка — процент, третья — объём |
| итог `du` | строка, где путь равен самому каталогу |
| крупнейший подкаталог | `sort -h` — **не** `sort -n` |
| удалённые файлы | `lsof +L1`; размер — колонка `SIZE/OFF`, путь — последняя без пометки |
| томов LVM | строки `lsblk` с префиксом группы (`ops--vg-`) |

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбирается копия вывода команд |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет (`lsof` на своей машине — по желанию) |
| Изоляция теста | эталон вычисляется из того же снимка, констант в тесте нет |

Тест дополнительно проверяет, что ловушки на месте: единицы измерения в
`du` различаются (иначе `sort -h` не нужен), том с исчерпанными inode занят
меньше чем наполовину, удалённых файлов больше одного.

## Выполнение

```bash
cd season-03-system-administration/s03e08-disks-fs
cp starter/disk_report.txt artifacts/disk_report.txt
D=../data/disk_shadow-01.txt
sec() { awk -v s="$1" '$0=="=== "s" ===" {f=1; next} /^=== /{f=0} f' "$D"; }
sec 'df -i' | awk '$5=="100%"'
sec 'lsof +L1'
bash tests/test.sh
```

На своей машине эти три команды занимают секунду и стоят того, чтобы войти
в привычку:

```bash
df -h; df -i; sudo lsof +L1 2>/dev/null | head
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| крупнейшим вышел `/var/log/apt` | `sort -n` сравнил 120 и 4.2 | `sort -h` понимает суффиксы |
| «самая заполненная» — не та | сравнивались объёмы, а не проценты | пятая колонка `df -h` |
| путь не принят | попала пометка `(deleted)` | это вывод `lsof`, а не имя файла |
| размер удалённого файла не сходится | взята колонка не та | `SIZE/OFF` — седьмая в `lsof +L1` |
| томов LVM посчитано меньше | пропущен `swap` | это тоже логический том |
| `inode_full_fs` совпал с `fullest_fs` | посмотрели только `df -h` | проблемы на разных томах |
| в подсчёт попала строка заголовка | не отброшена первая строка раздела | `NR>1` |

## После выполнения

Зелёный тест означает, что вопрос «куда делось место» закрыт до того, как
что-либо удалено. Это и есть результат: десять гигабайт возвращаются одним
`systemctl reload rsyslog`, и ни один журнал расследования не пострадал.

Обратите внимание на порядок, в котором находки получены: `df -h` → `df -i`
→ `lsof +L1` → `du`. Первые три команды занимают меньше минуты и в
большинстве случаев отвечают на вопрос целиком; самая долгая — последняя.
