## Обстановка

После закалки из [`s02e09`](../s02e09-ssh-hardening/) наружу смотрит один
`bastion.ops.local`. База слушает `127.0.0.1:5432` и снаружи не видна вовсе —
именно так и задумано. Работать с ней при этом нужно.

Конфигурация клиента, которой пользуется команда, досталась от Дмитрия.
Она работает: он ходит на все машины и не вводит пароль. И в ней почти
каждая строка либо лишний риск, либо мёртвая настройка.

## Приказ

Переписать `artifacts/config` — файл для `~/.ssh/config`.

```bash
cp starter/config artifacts/config
bash tests/test.sh
```

## Что должно получиться

| Хост | `HostName` | Что нужно |
|---|---|---|
| `bastion` | `bastion.ops.local` | единственная машина с внешним адресом |
| `db` | `db.internal` | через бастион; локальный порт к базе `5432` |
| `moscow` | `10.0.7.10` | через бастион; SOCKS-прокси для браузера |
| `devbox` | `devbox.ops.local` | через бастион; наш локальный `3000` отдать туда |

Плюс общие настройки клиента:

| Что | Зачем |
|---|---|
| не пробрасывать агент | иначе root на бастионе ходит вашим ключом |
| предлагать только свой ключ | иначе `MaxAuthTries 3` из `s02e09` оборвёт вход |
| не отключать проверку хоста | это единственная защита от подмены сервера |
| напоминать о себе | иначе туннель за NAT умрёт молча |

**Порядок блоков значим.** ssh берёт **первое** найденное значение параметра,
поэтому `Host *` должен стоять **последним**.

## Чем добывать

| Что нужно | Как |
|---|---|
| проход через посредника | `ProxyJump bastion` |
| порт к себе | `LocalForward ПОРТ_У_МЕНЯ адрес:ПОРТ_НА_СЕРВЕРЕ` |
| порт наружу | `RemoteForward 127.0.0.1:ПОРТ_НА_СЕРВЕРЕ 127.0.0.1:ПОРТ_У_МЕНЯ` |
| SOCKS-прокси | `DynamicForward 127.0.0.1:1080` |
| не отдавать ключ | `ForwardAgent no` |
| только указанный ключ | `IdentitiesOnly yes` + `IdentityFile` |
| проверить, что понял ssh | `ssh -G db` (на своей машине) |

Правая часть в `LocalForward` разрешается **сервером**, в `RemoteForward` —
**вашей машиной**. Отсюда `127.0.0.1` в обоих случаях означает разные машины.

## Критерии приёмки

- [ ] `artifacts/config` создан на основе `starter/`, все строки — «ключ значение».
- [ ] Описаны четыре хоста: `bastion`, `db`, `moscow`, `devbox`.
- [ ] Блок `Host *` стоит **последним**.
- [ ] `db`, `moscow`, `devbox` идут через бастион по `ProxyJump` (не `ProxyCommand`).
- [ ] `LocalForward` на `db`: локальный порт **не** `5432`.
- [ ] `RemoteForward` на `devbox` привязан к `127.0.0.1` сервера.
- [ ] `DynamicForward` на `moscow` привязан к `127.0.0.1`.
- [ ] `ForwardAgent no` действует для всех четырёх хостов.
- [ ] `StrictHostKeyChecking` не `no`.
- [ ] `IdentitiesOnly yes` и `IdentityFile` заданы.
- [ ] `ServerAliveInterval` задан в разумных пределах.
- [ ] Эффективный `User` для `db` — тот, что задан в его блоке, а не в `Host *`.
- [ ] `bash tests/test.sh` → 23 passed, 0 failed.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «`Host *` стоит 1-м» | блок наверху | перенести в конец: побеждает первое значение |
| «для db действует User из `Host *`» | то же самое | см. выше |
| «нет ProxyJump» | использован `ProxyCommand` | `ProxyJump bastion` — одна строка |
| «локальный порт должен отличаться от 5432» | взят тот же номер | конфликт со своей базой; берите `15432` |
| «RemoteForward без явного 127.0.0.1» | указан только порт | при `GatewayPorts yes` сервис уйдёт в интернет |
| «ForwardAgent включён» | скопировано из стартера | `no`; задача решается `ProxyJump` |
| «IdentitiesOnly не задан» | агент переберёт все ключи | `yes` + явный `IdentityFile` |
| туннель работает и через час отваливается | нет `ServerAliveInterval` | NAT забывает простаивающее соединение |

## После выполнения

Зелёный тест означает, что до всех машин операции есть дорога, а ключ при
этом никуда не уезжает.

Отдельно стоит осознать разницу между «что написано в файле» и «что понял
ssh». Первое читается глазами, второе — командой `ssh -G`. Блок `Host *`
наверху — ровно тот случай, когда эти две вещи расходятся полностью,
и никакой ошибки при этом не возникает.

## Кумулятивность

Ключи и права на них — из [`s02e08`](../s02e08-ssh-keys/); `MaxAuthTries 3`,
из-за которого нужен `IdentitiesOnly`, задан в
[`s02e09`](../s02e09-ssh-hardening/), там же `GatewayPorts`, делающий
обязательным явный `127.0.0.1` в `RemoteForward`. Подмена сервера, от которой
защищает `StrictHostKeyChecking`, — та же атака, что разбиралась для DNS в
[`s02e05`](../s02e05-dns-spoofing-guard/). То, что база слушает только
`127.0.0.1` и потому невидима снаружи, установлено в
[`s02e02`](../s02e02-ports-sockets/). Права `600` на приватном ключе —
из [`s01e15`](../../season-01-shell-foundations/s01e15-permissions-basics/).
