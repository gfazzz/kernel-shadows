## Обстановка

Виктор прислал одну строку: «Стена стоит. Откуда мы знаем, что она работает?»

`ufw status` показывает `active` и два десятка правил. Это ответ на вопрос
«что мы велели фаерволу», а не «что он сделал». Второй ответ лежит в журнале
ядра, который никто не открывал с того дня, как включили логирование.

## Приказ

Разобрать журнал и **сдать отчёт** — заполненный `artifacts/fwlog_report.txt`:
сколько и чего заблокировано, кто шумел больше всех, куда стучались, где
сработало ограничение частоты, кого пропускали и по какому правилу.

```bash
cp starter/fwlog_report.txt artifacts/fwlog_report.txt
bash tests/test.sh
```

## Объект разведки

| Файл | Что это |
|---|---|
| [`data/ufw_log_moscow1.txt`](../data/ufw_log_moscow1.txt) | `journalctl -k \| grep UFW` за 14–16 октября |
| [`data/ufw_status_moscow1.txt`](../data/ufw_status_moscow1.txt) | правила, действовавшие в это время (из `s02e06`) |

У обоих файлов есть шапка, начинающаяся с `#`. В ней встречаются слова
`BLOCK` и `ALLOW` — в подсчёты она попадать не должна.

## Чем добывать

| Что нужно | Как |
|---|---|
| отбросить шапку | `grep -vE '^[[:space:]]*#\|^[[:space:]]*$'` |
| заблокированные правилом | `grep '\[UFW BLOCK\]'` — **не** `grep BLOCK` |
| отброшенные по частоте | `grep '\[UFW LIMIT BLOCK\]'` |
| пропущенные | `grep '\[UFW ALLOW\]'` |
| адреса | `grep -oE 'SRC=[0-9.]+' \| cut -d= -f2` |
| порт назначения | `grep -oE 'DPT=[0-9]+'` — **не** `PT=` |
| частоты | `sort \| uniq -c \| sort -rn \| head -1` |
| правило пропуска | найти подсеть адреса в `ufw status` |

Три действия фаервола в журнале различаются, и одно из них содержит слово
другого.

## Критерии приёмки

- [ ] `artifacts/fwlog_report.txt` создан на основе `starter/`, все поля заполнены.
- [ ] `[UFW BLOCK]`, `[UFW LIMIT BLOCK]` и `[UFW ALLOW]` посчитаны **раздельно**.
- [ ] Шапка файла в подсчёты не попала.
- [ ] Самый шумный адрес и число его блокировок определены сортировкой по числу.
- [ ] Самый атакуемый порт определён по `DPT`, а не по `PT`.
- [ ] Найдены порт и адрес, по которым сработало ограничение частоты.
- [ ] Найдено сканирование порта VPN — с указанием протокола.
- [ ] Найден адрес, чьи пакеты пропускались, и правило из `ufw status`, по которому он проходит.
- [ ] Назван адрес атакующего и время его последней записи в журнале.
- [ ] `bash tests/test.sh` → 22 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — разбирается копия вывода команд |
| ОС | любая с bash + awk + grep + coreutils |
| Сеть | не нужна |
| `ufw` / `iptables` | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | эталон вычисляется из тех же снимков, констант в тесте нет |

Тест дополнительно проверяет, что ловушки на месте: `LIMIT BLOCK` попадает
под наивный шаблон `BLOCK`, один из сканеров ставит постоянный `SPT=53`
и портит подсчёт по `PT=`, а после 14 октября атакующий в журнале не
появляется.

## Выполнение

```bash
cd season-02-networking/s02e12-firewall-log
cp starter/fwlog_report.txt artifacts/fwlog_report.txt
L=../data/ufw_log_moscow1.txt
noc() { grep -vE '^[[:space:]]*#|^[[:space:]]*$' "$1"; }
noc $L | grep '\[UFW BLOCK\]' | grep -oE 'SRC=[0-9.]+' | sort | uniq -c | sort -rn | head
bash tests/test.sh
```

Если на вашей машине есть `ufw`, стоит посмотреть на то, о чём вся серия:

```bash
sudo iptables -L INPUT -v -n --line-numbers | head -20   # счётчики по правилам
sudo journalctl -k --since '-2 days' | grep -c UFW
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| блокировок на 4 больше | посчитан и `LIMIT BLOCK` | шаблон `\[UFW BLOCK\]` |
| блокировок на 1 больше | посчитана строка шапки | отбросить строки с `#` |
| самый атакуемый порт — 53 | шаблон `PT=` поймал `SPT` | считать по `DPT=` |
| топ-адрес не тот | `sort` без `-n` | `sort -rn` после `uniq -c` |
| «правило, по которому проходит» не принято | указан порт вместо подсети | нужна колонка `From` из `ufw status` |
| время последней записи не принято | взят другой формат | как в журнале: `Oct 14 21:57:35` |
| `unique_sources` меньше | посчитаны только блокировки | адреса встречаются и в `ALLOW` |

## После выполнения

Зелёный тест означает, что на вопрос Виктора есть ответ — и он не «стена
работает».

Обратите внимание на две вещи, которых в журнале **нет**. Первая: адрес
`185.14.29.66` не блокируется никогда, потому что для его подсети открыт
любой порт, — и если бы он делал что-то плохое, журнал бы об этом не узнал.
Вторая: атакующий пропадает 14 октября в 21:57 и больше не появляется.
Через три дня, в Season 3, выяснится, что означала эта тишина.
