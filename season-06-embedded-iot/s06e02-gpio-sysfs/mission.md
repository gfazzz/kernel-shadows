## Обстановка

Сорок контактов без подписей. Часть занята включённой периферией: `i2c1`
держит две ножки, консоль — ещё две, идентификационная память — две.
Запись в занятую ножку ломает то, что на ней работает, и откатить это
нельзя. Управлять железом при этом можно без единой строки на C: ядро
выставило GPIO наружу обычными файлами.

Нужен скрипт-предохранитель между человеком и `echo`.

## Приказ

Написать `artifacts/gpio_ctl.sh` — обёртку над sysfs GPIO.

```bash
cp starter/gpio_ctl.sh artifacts/
bash tests/test.sh
```

```
gpio_ctl.sh [--root КАТАЛОГ] [--map ФАЙЛ] КОМАНДА [АРГУМЕНТЫ]

  export PIN             занять ножку
  unexport PIN           освободить
  direction PIN in|out   задать направление
  write PIN 0|1          выставить уровень (только для out)
  read PIN               напечатать уровень
  status                 показать занятые ножки
```

## Требования

| Требование | Почему |
|---|---|
| занятость ножек читается из карты (`--map`) | у другой платы карта другая |
| `--root` задаёт корень sysfs | иначе скрипт не проверить без платы |
| проверки идут **до** записи | у записи в железо нет отката |
| `write` только при `direction = out` | запись во вход бессмысленна и опасна |
| `export` и `unexport` идемпотентны | повторный запуск — норма, а не ошибка |
| `status` перечисляет занятые ножки с направлением и значением | иначе неизвестно, что осталось занято |
| ошибки — в `stderr`, коды по назначению | вызывающий должен различать причины |

Коды возврата:

| Код | Значение |
|---|---|
| 0 | успех (в том числе «уже сделано») |
| 1 | ошибка использования: аргументы, неизвестная команда, значение не 0/1, направление не in/out |
| 2 | нет sysfs GPIO: каталога или файла `export` |
| 3 | такого пина нет на гребёнке |
| 4 | пин не экспортирован или направление не позволяет операцию |
| 5 | пин занят другой периферией |

## Чем добывать

| Что нужно | Как |
|---|---|
| функция ножки | `awk -v p="$1" '/^#/{next} $1==p {print $2; exit}' "${MAP}"` |
| «уже экспортирован» | `[ -d "${ROOT}/gpio$1" ]` — состояние, а не код `echo` |
| направление | `tr -d '[:space:]' < "${ROOT}/gpio$1/direction"` |
| запись | `printf '%s\n' "${val}" > "${file}"` с проверкой результата |
| перечень занятых | цикл по `"${ROOT}"/gpio[0-9]*` |

## Критерии приёмки

- [ ] `artifacts/gpio_ctl.sh` создан на основе `starter/`, `bash -n` чист.
- [ ] Все пути строятся от `--root`; `/sys` в коде не зашит.
- [ ] Занятость ножек берётся из `--map`: подмена карты меняет ответы скрипта.
- [ ] Отказ по занятой ножке происходит **до** записи в `export`.
- [ ] Повторный `export` и повторный `unexport` возвращают 0 и ничего не пишут.
- [ ] `write` в ножку с `direction = in` возвращает 4 и не меняет `value`.
- [ ] `read` печатает только значение, без пояснений.
- [ ] `status` на пустом корне возвращает 0 и сообщает, что занятых нет.
- [ ] `bash tests/test.sh` → 32 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk |
| Сеть | не нужна |
| **плата** | **не нужна** — sysfs подменяется макетом |
| Внешние пакеты | нет |
| Изоляция теста | временный каталог; реакцию ядра имитирует функция теста |

Тест создаёт макет sysfs во временном каталоге и функцией `sim()` делает
то же, что делает ядро: увидев номер в `export`, создаёт `gpioN/` с
файлами `direction` и `value`; увидев номер в `unexport` — удаляет каталог.
Скрипт работает с настоящими файлами и не знает, что перед ним не ядро.

Ни одного зашитого ответа: свободные и занятые ножки вычисляются из карты.
Отдельная проверка подменяет карту (свободная ножка становится занятой и
наоборот) и требует, чтобы коды возврата поменялись местами — скрипт с
зашитыми номерами её не пройдёт.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «в export записано при отказе» | проверка после действия | сначала карта, потом запись |
| повторный `export` даёт не 0 | ориентируетесь на код `echo` | проверять наличие `gpioN/` |
| «значение не тронуто» не проходит | `direction` читается после записи | читать `direction` до записи в `value` |
| подмена карты ничего не изменила | номера зашиты в коде | все решения — из `--map` |
| нет sysfs даёт не 2 | проверка корня отсутствует | `[ -d "${ROOT}" ] && [ -e "${ROOT}/export" ]` |
| `read` не проходит | печатается лишний текст | только содержимое `value` |
| цикл ломается на втором прогоне | неидемпотентные команды | «уже сделано» — это успех |

## После выполнения

Зелёный тест означает, что между человеком и напряжением на ножке появился
предохранитель: скрипт не даст занять чужую ножку, не даст писать во вход и
не сломается от повторного запуска.

Стоит запомнить принцип, общий далеко за пределами GPIO: **проверка имеет
смысл только до необратимого действия.** Конфигурацию можно откатить,
коммит — вернуть, миграцию — накатить обратно. Поданное на ножку напряжение
отменить нельзя: оно уже случилось. Чем необратимее действие, тем больше
работы делается до него, а не после.
