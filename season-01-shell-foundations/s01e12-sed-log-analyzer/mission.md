## Обстановка

Фильтр и рейтинг существуют в виде команд в истории терминала. Чтобы повторить
вчерашний анализ, нужно помнить, какие именно из девятнадцати черновиков рабочие
и в каком порядке их запускать.

Анне нужен не вывод, а документ: один файл, который читает человек, никогда не
открывавший терминал, и который можно приложить к материалам дела.

## Приказ

Собрать `log_analyzer.sh` — один запуск, один готовый отчёт. Подход **Type B**:
тело отчёта — готовые команды, bash только склеивает их вывод.

Использование: `./log_analyzer.sh ACCESS_LOG [THREATS_FILE] [REPORT_FILE]`.

Отчёт содержит: шапку с датой анализа; общую статистику (всего запросов,
уникальных адресов, время первой и последней записи); топ-10 адресов;
распределение HTTP-статусов; сверку с базой известных угроз; рекомендации.

## Данные

| Раздел отчёта | Чем считается |
|---|---|
| всего запросов | `wc -l < "$log"` |
| уникальных адресов | `awk '{print $1}' "$log" \| sort -u \| wc -l` |
| первая / последняя запись | `awk '{print $4}' "$log" \| head -1 \| sed 's/[][]//g'` |
| топ-10 адресов | `awk '{print $1}' … \| sort \| uniq -c \| sort -rn \| head -10` |
| распределение статусов | `awk '{print $9}' … \| sort \| uniq -c \| sort -rn` |
| сверка с базой | цикл по строкам базы + `grep -c` по журналу |
| сборка в файл | `{ … } > "$report"` — одно перенаправление на группу |

База угроз — текстовый список адресов с комментариями (`#`) и пустыми строками:
их надо пропускать так же, как в s01e08.

## Критерии приёмки

- [ ] `artifacts/log_analyzer.sh` создан, есть shebang, `bash -n` без ошибок.
- [ ] Отчёт записывается в файл, указанный третьим аргументом.
- [ ] Общее число запросов и число уникальных адресов посчитаны верно.
- [ ] Время первой записи выведено **без квадратных скобок** (работа `sed`).
- [ ] Есть топ адресов с количеством запросов и распределение статусов.
- [ ] Адреса из базы, встречающиеся в журнале, помечены `FOUND` с числом запросов.
- [ ] Адреса из базы, которых в журнале нет, в отчёт **не** попадают.
- [ ] Комментарии и пустые строки базы не считаются адресами.
- [ ] Отсутствующий журнал → сообщение в stderr и ненулевой код возврата.
- [ ] `bash tests/test.sh` → 14 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + coreutils + awk + sed |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны |
| Внешние пакеты | нет |
| Изоляция теста | фикстура-журнал и база угроз во временном каталоге |

В базе угроз теста есть адрес, которого в журнале **нет**, и адрес-ловушка,
являющийся префиксом другого. Ожидаемые числа тест считает по фикстуре.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| отчёт содержит только последнюю строку | `>` вместо `>>` в середине | собрать всё в `{ … } > "$report"` |
| `{echo x}` → «команда не найдена» | нет пробела после `{` | `{ echo x; }` |
| в дате остались скобки | `sed` не применён или шаблон неверен | `sed 's/[][]//g'` |
| `sed 's/[[]]//g'` ничего не убирает | неверный класс символов | `]` должна стоять первой: `[][]` |
| в отчёте `FOUND` для адреса, которого нет | совпадение по подстроке | `grep -c -w` или сравнение первого поля |
| комментарий из базы попал в отчёт | нет фильтров цикла | пропускать пустые и `#`-строки |
| скрипт падает, когда угроза не найдена | `set -e` + `grep`, вернувший 1 | `\|\| true` при подсчёте |
| нет журнала → пустой отчёт и код 0 | нет проверки входа | `[ -f "$log" ]`, иначе `exit 1` |

## После выполнения

Зелёный тест закрывает Episode 03: `grep` → конвейер → `awk` → `sort`/`uniq` →
`sed` собраны в один инструмент. Это первый раз, когда результат работы можно
отдать другому человеку, ничего не объясняя.

`log_analyzer.sh` — модуль форензики `shadow_toolkit` (см. [`PROJECTS.md`](../../PROJECTS.md)).
В Season 5 он вернётся против системы, где журналы могли подделать, — и тогда
станет важно, что именно отчёт считает фактом, а что выводом.
