## Обстановка

Режим проверки нашёл на двадцать седьмой три расхождения: чужой ключ
доступа, разрешённый вход root и открытый каталог с закрытыми ключами.
Машина пересобрана, но проверяли только боевой контур, и добавить тот же
ключ на остальные было так же легко.

Приводить к описанию нужно все пятьдесят. Записать вчерашние команды в
YAML недостаточно: такая задача пропускается в режиме проверки — то есть
вы своими руками делаете ещё одну слепую зону.

## Приказ

Написать `artifacts/harden.yml`.

```bash
cp starter/harden.yml artifacts/
bash tests/test.sh
```

## Требования

| Что | Почему |
|---|---|
| плей адресован группе из инвентаря, а не `all` | в инвентаре есть и стенд |
| `become` у задач, которым он нужен; не на уровне плея | root не выдают всем сразу |
| у каждой задачи есть `name` | иначе вывод прогона нечитаем |
| не больше одной задачи на `command`/`shell` | остальное умеют модули: `file`, `apt`, `systemd`, `copy`, `template`, `lineinfile` |
| у команды задан `changed_when` или `creates` (и `check_mode: false`, если она безвредна) | иначе ansible не может сказать, что изменится |
| ни одного `systemctl restart`, `apt-get install`, `chmod`, `useradd`, `echo >` командой | для каждого есть модуль |
| перезапуск службы — только через handler и `notify` | иначе служба перезапускается каждый прогон |
| `notify` совпадает с именем существующего handler | опечатка не ошибка: просто ничего не произойдёт |
| `lineinfile` с `regexp:` | иначе строка дописывается заново при каждом прогоне |
| `lineinfile` с `validate:` | сломанный `sshd_config` закроет вход на все пятьдесят машин |
| файлы раскладываются `template`/`copy` | `authorized_keys` собирается целиком, иначе чужой ключ останется |
| `no_log: true` у задачи с секретом | иначе значение попадёт в вывод и в `--diff` |
| ни одного пароля в самом файле | значение приходит из зашифрованного `group_vars` |
| ни одного `ignore_errors: true` | это то же самое, что `\|\| true` в конвейере |
| `tags` не меньше чем у трёх задач | прогон должен ограничиваться темой |
| закрыты все три находки `s04e10` | ключи, `PermitRootLogin no`, права `0700` |

## Чем добывать

| Что нужно | Как |
|---|---|
| права и каталоги | `ansible.builtin.file: { path: …, state: directory, mode: "0700" }` |
| пакеты | `ansible.builtin.apt: { name: …, state: present }` |
| службы | `ansible.builtin.systemd: { name: sshd, state: restarted }` |
| строка в конфигурации | `lineinfile` с `regexp:` и `validate: /usr/sbin/sshd -t -f %s` |
| файл из шаблона | `ansible.builtin.template: { src: …, dest: …, mode: "0600" }` |
| безвредная команда | `changed_when: false` + `check_mode: false` + `register:` |
| условие по системе | `when: ansible_os_family == "Debian"` |
| посмотреть, что умеет модуль | `ansible-doc file` (на своей машине) |

## Критерии приёмки

- [ ] `artifacts/harden.yml` создан на основе `starter/`, задач не меньше пяти.
- [ ] `hosts:` — группа, не `all`; `become: true` не стоит на уровне плея.
- [ ] Хотя бы одна задача просит `become: true`; у всех задач есть `name`.
- [ ] Задач на `command`/`shell` не больше одной, и у неё есть `changed_when`/`creates`.
- [ ] Ни `systemctl restart`, ни `apt-get install`, ни `chmod`, ни `useradd`, ни `echo >` командой.
- [ ] Объявлены `handlers`; `notify` указывает на существующее имя.
- [ ] Перезапуска службы обычной задачей нет.
- [ ] `lineinfile` с `regexp:` и `validate:`; в файле есть `PermitRootLogin no`.
- [ ] Есть `mode: "0700"` для каталога закрытых ключей и задача `template`/`copy`.
- [ ] Паролей открытым текстом нет; есть `no_log: true`.
- [ ] `ignore_errors` нигде не включён; есть `when`/`failed_when`/`check_mode`.
- [ ] `tags` не меньше чем у трёх задач.
- [ ] `bash tests/test.sh` → 28 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен |
| ОС | любая с bash + awk + coreutils |
| Сеть | не нужна |
| `ansible` | **не нужен** — файл проверяется как текст |
| Внешние пакеты | нет |
| Изоляция теста | файл режется на блоки задач по строкам `- ` внутри `tasks:` |

По каждой задаче тест задаёт один и тот же вопрос: **может ли ansible
сказать, что изменится, не выполняя её**. Задача на `command`/`shell` без
`changed_when` или `creates` ответить не может — и именно она исчезает из
режима проверки, как те две из `s04e10`.

Тест дополнительно проверяет, что в стартере остались исходные ошибки:
`hosts: all`, перезапуск командой, `ignore_errors` и пароль в `vars`.

## Выполнение

```bash
cd season-04-devops-automation/s04e12-ansible-playbook
cp starter/harden.yml artifacts/
$EDITOR artifacts/harden.yml
bash tests/test.sh
```

Если ansible установлен, стоит увидеть главное свойство своими глазами —
на любой локальной машине:

```bash
ansible-playbook -i localhost, -c local harden.yml --check --diff
ansible-playbook -i localhost, -c local harden.yml     # первый прогон
ansible-playbook -i localhost, -c local harden.yml     # второй: changed=0
```

Второй прогон и есть проверка. Всё, что меняется в нём, описано как
действие, а не как состояние.

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «задач на command/shell: 5» | команды переписаны в YAML | заменить модулями |
| «команда без changed_when» | ansible не знает, изменится ли что-то | `changed_when: false` для проверок |
| «systemctl restart вызвано командой» | привычка из скриптов | `ansible.builtin.systemd` в handler |
| «нет handlers» | перезапуск отдельным шагом | `handlers:` + `notify` |
| «notify не совпадает с handler» | опечатка в имени | имена сопоставляются буквально |
| «lineinfile без regexp» | строка дописывается | `regexp:` по имени директивы |
| «нет validate» | нечем поймать сломанный конфиг | `validate: /usr/sbin/sshd -t -f %s` |
| «become: true на уровне плея» | «всё равно нужно» | нужно не всем задачам |
| «секрет открытым текстом» | значение в `vars:` | переменная из vault + `no_log` |
| «меток мало» | `tags` не заданы | размечать по темам: ssh, tls, packages |

## После выполнения

Зелёный тест означает, что пятьдесят машин приводятся к описанию одной
командой, а второй прогон подряд не меняет ничего — единственная проверка,
которая здесь имеет значение.

Стоит запомнить формулировку, которая объясняет половину курса задним
числом: **описание состояния отличается от списка действий тем, что у него
можно спросить, что изменится, ничего не меняя**. Строка в `fstab` вместо
`mount`, юнит вместо скрипта запуска, `compose.yaml` вместо `docker run`,
`.gitignore` вместо «не коммить этот файл», модуль вместо `chmod` — это
один и тот же переход, сделанный пять раз в разных местах.

## Кумулятивность

Три находки, которые здесь закрываются, сделаны в
[`s04e10`](../s04e10-ansible-check/), а группа, к которой адресован плей,
описана в [`s04e09`](../s04e09-ansible-inventory/). Требование объявить
команду безвредной явно — прямое следствие того же `s04e10`: задачи на
`command` пропускаются в режиме проверки. Запрет на `ignore_errors` — то
же правило, что запрет `|| true` и `continue-on-error` в
[`s04e07`](../s04e07-ci-pipeline/). Секрет из vault вместо значения в файле
проверяется аудитом [`s04e11`](../s04e11-iac-audit/). Повышение прав по
месту, а не на входе, продолжает
[`s01e16`](../../season-01-shell-foundations/s01e16-sudo-basics/) и
[`s03e03`](../../season-03-system-administration/s03e03-sudo/), а
`0700` на каталоге ключей —
[`s01e15`](../../season-01-shell-foundations/s01e15-permissions-basics/).
Сам переход «состояние вместо действий» уже делался в
[`s03e10`](../../season-03-system-administration/s03e10-fstab/),
[`s03e05`](../../season-03-system-administration/s03e05-systemd-service/) и
[`s04e06`](../s04e06-compose/) — здесь он назван вслух.
