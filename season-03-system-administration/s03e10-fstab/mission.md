## Обстановка

Том `/var/log` расширен до 520 ГБ. Действующая таблица монтирования при этом:

- монтирует `/var/log` с `/dev/vdb` — это физический том LVM, файловой системы
  на нём нет;
- содержит запись для `/dev/vdb1`, удалённого в марте вместе с разделом;
- адресует разделы именами вида `/dev/vda1` — то есть порядком обнаружения
  дисков при конкретной загрузке;
- не описывает `/var/spool` вовсе;
- монтирует всё с `defaults`.

Сервер не перезагружали с марта. Перезагрузка с этим файлом закончится
запросом пароля root в аварийном режиме.

## Приказ

Переписать `artifacts/fstab` так, чтобы после перезагрузки система поднялась
и все тома оказались на месте.

```bash
cp starter/fstab artifacts/fstab
bash tests/test.sh
```

## Требования

| Что | Зачем |
|---|---|
| адресация по `UUID=` (или `/dev/mapper/…`) | имена `/dev/vdX` меняются при миграции и добавлении дисков |
| каждая запись — существующее устройство | иначе загрузка уходит в аварийный режим |
| тип ФС совпадает с `blkid` | `/dev/vdb` — это `LVM2_member`, а не `ext4` |
| описаны все тома из `df -h` | незаписанное не вернётся после перезагрузки |
| `nodev,nosuid,noexec` на `/var/log` и `/var/spool` | закладка из `s03e02` там работать не будет |
| `noatime` на журналах | иначе чтение порождает запись |
| `pass`: 1 у корня, 2 у прочих ФС, 0 у swap | порядок проверки `fsck` |
| `dump` = 0 везде | утилиты `dump` давно нет |

## Чем добывать

| Что нужно | Как |
|---|---|
| UUID тома | строка `blkid` по нужному устройству |
| точки монтирования | раздел `df -h` второго снимка, строки с `/dev/` |
| имя тома LVM | дефис в имени группы удваивается: `ops-vg` → `ops--vg-log` |
| проверить свой файл | `findmnt --verify --verbose` (на своей машине) |
| применить без перезагрузки | `mount -a`, затем `systemctl daemon-reload` |

## Критерии приёмки

- [ ] `artifacts/fstab` создан на основе `starter/`, в каждой записи шесть полей.
- [ ] Ни одного адреса вида `/dev/vda1`, `/dev/vdb`, `/dev/sdX`.
- [ ] Каждый UUID и каждое устройство есть в снимке `blkid`.
- [ ] Тип файловой системы в каждой записи совпадает со снимком.
- [ ] Описаны все точки монтирования из `df -h`, плюс swap.
- [ ] Записи для `/backup` нет: устройства не существует.
- [ ] Точки монтирования не дублируются.
- [ ] `pass` = 1 у корня, 2 у остальных файловых систем, 0 у swap.
- [ ] `dump` = 0 во всех записях.
- [ ] `/var/log` и `/var/spool` смонтированы с `nodev`, `nosuid`, `noexec`.
- [ ] `/var/log` смонтирован с `noatime`.
- [ ] `bash tests/test.sh` → 18 passed, 0 failed.

На своей машине стоит сделать то, что делают перед каждой перезагрузкой
удалённого сервера, — сравнить, что смонтировано сейчас, с тем, что вернётся:

```bash
findmnt --verify --verbose
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «адрес зависит от порядка обнаружения» | оставлено `/dev/vda1` | взять `UUID=` из `blkid` |
| «запись для несуществующего устройства» | не убрана строка `/backup` | удалить или добавить `nofail` |
| «тип ФС не совпадает» | `/dev/vdb` — это `LVM2_member` | монтировать логический том, а не PV |
| «нет записи для /var/spool» | том забыт | список точек — в `df -h` |
| «не хватает опций» | оставлен `defaults` | `defaults,noatime,nodev,nosuid,noexec` |
| «у корня pass=…» | скопирован `pass` соседней строки | корень проверяется первым: `1` |
| «swap помечен для fsck» | `pass` не обнулён | у swap `dump` и `pass` — нули |
| запись не из шести полей | пропущен `dump` или `pass` | шесть полей обязательны |

## После выполнения

Зелёный тест означает, что таблица описывает систему целиком и не содержит
записей-призраков. Это ровно тот файл, ошибка в котором не проявляется до
перезагрузки — и проявляется недоступностью машины.

Стоит запомнить проверку, которая занимает секунду и снимает почти весь риск:
`findmnt --verify --verbose` перед перезагрузкой, а после правки — `mount -a`
и `systemctl daemon-reload`, пока доступ к серверу ещё есть.

## Кумулятивность

Том `/var/log` расширен в [`s03e09`](../s03e09-lvm/), а его тип и точка
монтирования — из снимка [`s03e08`](../s03e08-disks-fs/). Опции `nosuid` и
`noexec` закрывают именно тот способ закрепиться, что найден в
[`s03e02`](../s03e02-permissions/) (SUID-копия оболочки) и в
[`s03e04`](../s03e04-processes/) (запуск из `/tmp`), — то же самое, что
`NoNewPrivileges` и `PrivateTmp` делают для отдельной службы в
[`s03e05`](../s03e05-systemd-service/), но на уровне всей файловой системы.
Дисциплина «конфиг как артефакт, проверять до применения» — из
[`s03e03`](../s03e03-sudo/).
