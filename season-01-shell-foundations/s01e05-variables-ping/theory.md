## Переменные — коробки с наклейками

```
┌─────────────┐
│  server_ip  │ ← наклейка (имя)
├─────────────┤
│  "8.8.8.8"  │ ← значение
└─────────────┘
```

```bash
server_ip="8.8.8.8"     # положить значение
echo "$server_ip"       # достать через $
```

**Правило: НЕТ пробелов вокруг `=`.**

```bash
name="Max"       # ✅
name = "Max"     # ❌ bash решит, что name — команда
```

**Правило #1: всегда кавычки вокруг переменных.**

```bash
filename="my document.txt"
rm $filename      # ❌ bash видит два аргумента: my и document.txt
rm "$filename"    # ✅ один аргумент
```

Пробел в имени файла без кавычек — и `rm` удалит не то. Кавычки — это выживание.

**Фигурные скобки `${}`** задают границы имени:

```bash
name="Max"
echo "$name_backup"    # ищет переменную name_backup → пусто
echo "${name}_backup"  # Max_backup
```

## Специальные переменные

| Переменная | Значение |
|------------|----------|
| `$0` | имя скрипта |
| `$1 $2 …` | аргументы |
| `$@` | все аргументы |
| `$#` | число аргументов |
| `$?` | **exit code последней команды** |
| `$$` | PID процесса |
| `$USER`, `$HOME`, `$PWD` | окружение |

## `ping` и exit codes

```bash
ping -c 1 -W 2 8.8.8.8    # -c 1: один пакет; -W 2: таймаут 2 сек
echo $?                    # 0 = дошло, 1-2 = нет
```

Exit code — как доклад сотрудника: `0` = «всё ОК», `1–255` = «проблема».
`$?` хранит exit code **последней** команды, поэтому его сохраняют сразу:

```bash
ping -c 1 -W 2 "$host" >/dev/null 2>&1
code=$?     # взяли сразу, пока не затёрла следующая команда
```

> Без exit codes ты слепой. Проверяй `$?` после критичных операций.

**Кросс-платформенная тонкость.** Флаг `-W` на Linux — секунды, на macOS BSD-ping —
миллисекунды. Курс идёт на Ubuntu, поэтому `-W 2` = 2 секунды. (В тесте `ping`
подменяется мок-версией, так что различия не важны для проверки.)
