# Разбор трёх последних происшествий — откуда взялись пороги и выдержки.
#
# Колонка «заметили» — сколько прошло от начала до того, как о проблеме
# узнал человек. Колонка «источник» — как именно узнал.
#
# происшествие              длилось  заметили  источник
# ------------------------  -------  --------  ---------------------------
# 5xx после выката v2.3.8   34 мин   31 мин    жалоба из соседней команды
# деградация базы           2 ч 10 м 1 ч 50 м  еженедельный отчёт
# узел ушёл в перезагрузку  8 мин    никогда   нашли в журнале через сутки
#
# Общее: обо всех трёх узнали не из мониторинга. Оповещений было
# семьдесят четыре за тот же месяц — и ни одно не про эти три случая.

# Что показывали метрики в момент каждого происшествия — это и есть
# исходные данные для порогов. Значения сняты постфактум из хранилища.
#
# key                        value   пояснение
error_ratio_normal           0.004   обычная доля 5xx: примерно 0.4 %
error_ratio_incident         0.180   во время происшествия с выкатом
latency_p95_normal_s         0.082   обычный 95-й перцентиль, секунды
latency_p95_incident_s       1.400   во время деградации базы

# Согласованные пороги (тикет AUR-503). Между обычным и аварийным
# значением взято с запасом от обычного, а не посередине: порог должен
# срабатывать заметно раньше, чем становится плохо.
threshold_error_ratio        0.02
threshold_latency_p95_s      0.3

# Согласованные выдержки. Меньше — и всплеск в одну выборку будит
# человека; больше — и происшествие в восемь минут не будет замечено.
for_error_ratio              10m
for_latency                  15m
for_target_down              5m
for_crashloop                15m
for_absent                   10m
