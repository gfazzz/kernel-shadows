## Обстановка

Команда перешла на ключи, но на серверах ничего не изменилось: парольный вход
разрешён, root пускают напрямую, попыток шесть, список допущенных не задан.
В журналах — четыре тысячи неудачных входов под root за сутки, и это по одной
машине.

Пока сервер предлагает парольную аутентификацию, перебор имеет смысл. После её
отключения он теряет смысл целиком.

## Приказ

Закалить конфигурацию. Артефакт — **сам файл** `artifacts/sshd_config`,
переписанный из `starter/`, а не скрипт, который его проверяет.

```bash
cp starter/sshd_config artifacts/sshd_config
# править artifacts/sshd_config
bash tests/test.sh
```

## Что должно получиться

| Директива | Значение | Зачем |
|---|---|---|
| `PermitRootLogin` | `no` | root — только через `sudo` от именованного пользователя |
| `PasswordAuthentication` | `no` | вход только по ключам |
| `KbdInteractiveAuthentication` | `no` | иначе пароли возвращаются через PAM |
| `PermitEmptyPasswords` | `no` | учётные записи без пароля недопустимы |
| `PubkeyAuthentication` | `yes` | иначе войти станет нечем |
| `X11Forwarding` | `no` | на сервере не нужен |
| `MaxAuthTries` | `1`–`3` | меньше попыток в одном соединении |
| `AllowGroups` или `AllowUsers` | явный список | доступ имеют только перечисленные |
| `LogLevel` | `VERBOSE` | в журнал попадает отпечаток использованного ключа |

`Port` и `Subsystem` должны остаться: конфигурация обязана остаться рабочей.

## Как sshd читает этот файл

Три правила, которые ломают наивную правку:

1. **Побеждает первое вхождение**, а не последнее. Дописать нужное в конец —
   не сработает.
2. **Комментарий не является настройкой.** `#PermitRootLogin no` убирает
   директиву, и начинает действовать умолчание, менявшееся между версиями.
3. **Регистр имени не важен**, отступ допустим — `permitrootlogin` тоже сработает.

Проверить, что получилось, можно тем же способом, каким это делает тест:

```bash
grep -iE '^[[:space:]]*PermitRootLogin([[:space:]]|=)' artifacts/sshd_config \
  | grep -vE '^[[:space:]]*#' | head -1
```

На живой машине — `sudo sshd -T | grep -i permitrootlogin`.

## Критерии приёмки

- [ ] `artifacts/sshd_config` создан из `starter/` и отредактирован.
- [ ] Все девять директив из таблицы имеют требуемые эффективные значения.
- [ ] Ни одна из них не осталась только в комментарии.
- [ ] Ни одна не задана дважды активными строками.
- [ ] `Port` и `Subsystem` на месте — конфигурация рабочая.
- [ ] `bash tests/test.sh` → 14 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — сервер не запускается, правится файл |
| ОС | любая с bash + grep |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны (перезапуск службы — Season 3) |
| Внешние пакеты | нет |
| Изоляция теста | конфигурация читается тем же правилом, что и в `sshd`; констант нет |

Тест дополнительно проверяет, что стартовая конфигурация действительно **не**
закалена, — иначе задание было бы вырожденным.

## Порядок применения на реальном сервере

```bash
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
sudo cp artifacts/sshd_config /etc/ssh/sshd_config
sudo sshd -t                     # синтаксис — обязательно
sudo systemctl reload ssh        # текущие сессии не рвутся
ssh -i ~/.ssh/id_ed25519 user@server   # из ДРУГОГО терминала, не закрыв этот
```

Открытая вторая сессия — единственный путь назад, если новая конфигурация не
пускает. На удалённой машине стоит подстраховаться отложенным откатом — приём
разобран в [`theory.md`](theory.md).

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| правка не действует | нужное дописано ниже старой строки | побеждает первое вхождение — править её |
| «директива не задана» | строка осталась закомментированной | задать значение явно |
| пароли всё ещё принимаются | не выключен `KbdInteractiveAuthentication` | выключить обе директивы |
| после правки не пускает по ключу | выключен `PubkeyAuthentication` | вернуть `yes` |
| не пускает нужного пользователя | он не входит в `AllowGroups` | добавить в группу или в список |
| `sshd -t` ругается на строку | опечатка в имени директивы | имена регистронезависимы, но должны существовать |

## После выполнения
