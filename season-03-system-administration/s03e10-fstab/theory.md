>
> ```
> nofail,x-systemd.device-timeout=10,_netdev
> ```
>
> — `nofail` — «если не смонтировалось, продолжай грузиться». `_netdev` — «это сетевое, дождись сети». Таймаут — чтобы не ждать полторы минуты по умолчанию.

> *А потом сказал то, что я с тех пор повторяю сам:*
>

Ошибиться в эту сторону нельзя: худшее, что даёт лишний `nofail`, — незамеченное отсутствие каталога. Худшее, что даёт его отсутствие, — четыре часа и чужая консоль.

## 2. Шесть полей

```
UUID=1b6e5c40-9af3-4d28-83c7-5e10b742f9a6 /var/log ext4 defaults,noatime,nodev,nosuid,noexec 0 2
```

| Поле | Что означает |
|---|---|
| устройство | `UUID=`, `LABEL=`, `PARTUUID=`, путь `/dev/mapper/…`, `//сервер/шара`, `сервер:/экспорт` |
| точка | абсолютный путь; для swap — `none` или `swap` |
| тип | `ext4`, `xfs`, `swap`, `tmpfs`, `nfs`, `cifs`, `auto` |
| опции | через запятую, без пробелов |
| dump | всегда `0` |
| pass | `1` корень, `2` прочие ФС, `0` остальное |

Поля разделяются пробелами или табуляциями; выравнивание — дело вкуса, парсер его не замечает.

## 3. Чем адресовать устройство

| Форма | Устойчива | Когда применяют |
|---|---|---|
| `/dev/sda1`, `/dev/vdb` | **нет** | нигде в `fstab` |
| `UUID=…` | да | по умолчанию для всего |
| `LABEL=…` | да, если метки уникальны | когда метки осмысленные (`root`, `log`) |
| `PARTUUID=…` | да | загрузочные разделы, GPT |
| `/dev/mapper/vg-lv` | да | тома LVM (имена создаёт LVM) |
| `/dev/disk/by-id/…` | да | когда важен конкретный физический диск |

```bash
blkid                        # UUID, LABEL, TYPE по всем устройствам
lsblk -f                     # то же деревом
ls -l /dev/disk/by-uuid/     # какие ссылки создал udev
```

Имя `/dev/sdb` присваивается в порядке обнаружения. На виртуальных машинах он зависит от порядка подключения дисков в конфигурации гипервизора, на физических — от того, как ядро опросило контроллеры. Совпадение между загрузками — не гарантия, а привычка.

**Дефис в именах LVM удваивается:** группа `ops-vg`, том `log` → `/dev/mapper/ops--vg-log`. Так device-mapper отличает разделитель от дефиса внутри имени.

## 4. Опции, которые стоит знать

```
noatime          не писать время доступа при чтении
relatime         компромисс по умолчанию: пишет не чаще раза в сутки
nodev            игнорировать файлы устройств
nosuid           игнорировать биты SUID/SGID
noexec           запретить запуск программ
ro / rw          только чтение / чтение и запись
nofail           отсутствие устройства не останавливает загрузку
noauto           не монтировать автоматически (только по команде)
user             разрешить монтирование обычному пользователю
_netdev          требуется сеть
x-systemd.automount        монтировать при первом обращении
x-systemd.device-timeout=10  сколько ждать устройство
x-systemd.requires=…       явная зависимость от юнита
```

**`noatime` против `relatime`.** Исторически ядро обновляло время доступа при каждом чтении — то есть писало на диск, когда программа читала. Сейчас по умолчанию `relatime`: запись не чаще раза в сутки. На томе с журналами разница с `noatime` невелика, но она в правильную сторону.

**Тройка `nodev,nosuid,noexec`** имеет смысл везде, где лежат только данные: `/var/log`, `/var/spool`, `/home` (если пользователи не запускают своё), `/tmp`, съёмные носители. На `/var` целиком `noexec` ставить рискованно — часть служб распаковывает туда исполняемые файлы.

**`nofail` для всего, чего может не быть**: съёмное, сетевое, диск с данными на другой машине. Цена ошибки несимметрична: лишний `nofail` даёт пустой каталог, недостающий — аварийный режим.

## 5. tmpfs и bind

```
tmpfs   /tmp        tmpfs  defaults,nodev,nosuid,noexec,size=2G  0 0
/srv/data  /var/www/data  none  bind  0 0
```

`tmpfs` живёт в памяти: быстро, исчезает при перезагрузке, занимает столько, сколько реально записано (до `size=`). Типичное применение — `/tmp` и кеши.

Bind-монтирование делает один каталог видимым в другом месте, без копирования и без символьных ссылок. В отличие от ссылки, работает внутри chroot и для служб с `ProtectHome=`.

## 6. systemd и fstab

systemd не читает `fstab` во время работы — он **генерирует** из него юниты `.mount` на этапе загрузки:

```bash
systemctl daemon-reload            # перечитать fstab, пересоздать юниты
systemctl list-units --type=mount
systemctl status var-log.mount     # точка /var/log → юнит var-log.mount
```

Отсюда неочевидное: после правки `fstab` при работающей системе нужен `daemon-reload`, иначе systemd продолжит работать по старой версии. И отсюда же опции `x-systemd.*` — способ управлять сгенерированным юнитом прямо из `fstab`.

Порядок загрузки: все записи без `noauto` монтируются до `local-fs.target`; запись с `_netdev` — после `network-online.target` и до `remote-fs.target`. Ошибка на первом этапе останавливает загрузку, на втором — обычно нет.

## 7. Проверка и восстановление

```bash
findmnt --verify --verbose     # разбор fstab: синтаксис, существование устройств
mount -a                       # смонтировать всё, что ещё не смонтировано
mount --fake -a                # разобрать, ничего не делая
findmnt                        # что смонтировано СЕЙЧАС и с какими опциями
findmnt /var/log -o OPTIONS
mount -o remount,noexec /var/log   # изменить опции без размонтирования
```

**Если машина уже в аварийном режиме:** корень там смонтирован только для чтения.

```bash
mount -o remount,rw /
nano /etc/fstab            # исправить или закомментировать строку
mount -a                   # проверить
reboot
```

Полезная привычка перед перезагрузкой удалённого сервера: сравнить `findmnt` (что смонтировано сейчас) с `/etc/fstab` (что вернётся). Расхождения — это либо забытая запись, либо ручное монтирование, которое исчезнет.

## 8. Метанавык: конфигурация, у которой нет обратной связи

Почти всё, что администратор настраивает, отвечает сразу: сервис не стартовал, команда вернула ошибку, страница не открылась. `fstab` устроен иначе: он читается один раз, при загрузке, и ошибка проявляется тогда, когда исправлять её труднее всего — при недоступной машине.

Класс таких файлов невелик, и он стоит того, чтобы держать его в голове: `fstab`, `sudoers`, `sshd_config`, конфигурация загрузчика, сетевые настройки. Общее у них одно — сломав их, ты теряешь тот самый доступ, через который собирались чинить.

Приёмы для этого класса одинаковы: проверять до применения (`findmnt --verify`, `visudo -c`, `sshd -t`), держать вторую открытую сессию, менять по одной строке и иметь способ вернуться, не заходя по сети. Не потому что вероятность ошибки высока, а потому что цена её несимметрична.
