## Обстановка

14 октября в данных мониторинга полуторачасовой провал: сервер перезагружался
три минуты, а задача из `crontab` не выполнялась до следующего момента по
расписанию. В этот же промежуток был установлен `sshd-helper.service`.

Проверка состояния должна запускаться раз в пять минут — и догонять пропущенное.

## Приказ

Перенести проверку с cron на таймер systemd. Артефакт — **пара юнитов**
в `artifacts/`: расписание и разовая задача, которую оно запускает.

```bash
cp starter/ops-check.timer starter/ops-check.service artifacts/
bash tests/test.sh
```

Скрипт лежит по пути `/usr/local/bin/ops-check.sh`; ему нужен каталог
состояния `/var/lib/ops-monitor`. Строка, которую переносим:

```
*/5 * * * * /usr/local/bin/ops-check.sh
```

## Требования

| Что | Зачем |
|---|---|
| запуск раз в пять минут | интервал сбора состояния |
| догон пропущенного после простоя | ровно та дыра, что была 14 октября |
| разброс запуска | серверов больше одного, всплеск в :00 не нужен |
| точность лучше минуты по умолчанию | минута — 20 % интервала |
| таймер включается в `timers.target` | иначе не появится в `systemctl list-timers` |
| служба — разовая, с таймаутом | зависшая задача блокирует всё расписание |
| службу отдельно не включать | расписание должно быть описано в одном месте |
| ограничения прав — как у постоянной службы | код тот же самый |

## Чем добывать

| Что нужно | Как |
|---|---|
| расписание | `OnCalendar=` в формате systemd (не crontab) |
| догон пропущенного | `Persistent=` |
| разброс и точность | `RandomizedDelaySec=`, `AccuracySec=` |
| что запускать | `Unit=` (или совпадение имён файлов) |
| включение таймера | `[Install]`, `WantedBy=timers.target` |
| тип задачи | `Type=oneshot`, без `Restart=` |
| защита от зависания | `TimeoutStartSec=` |
| ограничения | `User=`, `NoNewPrivileges=`, `ProtectSystem=`, `PrivateTmp=` |

Проверить календарное выражение, ничего не устанавливая:
`systemd-analyze calendar '*:0/5'`.

## Критерии приёмки

- [ ] В `artifacts/` лежат оба файла: `ops-check.timer` и `ops-check.service`.
- [ ] `OnCalendar=` записан в формате systemd и даёт интервал в пять минут.
- [ ] `Persistent=` включён.
- [ ] `RandomizedDelaySec=` и `AccuracySec=` заданы.
- [ ] `Unit=` либо не задан (имена совпадают), либо указывает на `ops-check.service`.
- [ ] `WantedBy=timers.target` в `[Install]` таймера.
- [ ] `Type=oneshot` в службе; `Restart=` не задан.
- [ ] `TimeoutStartSec=` задан.
- [ ] В службе **нет** секции `[Install]`.
- [ ] `ExecStart=` — абсолютный путь; `User=` не root.
- [ ] `NoNewPrivileges=`, `ProtectSystem=`, `PrivateTmp=` заданы.
- [ ] `Description=` у обоих юнитов сообщает, что это такое.
- [ ] `bash tests/test.sh` → 24 passed, 0 failed.

## Требования среды

| Требование | Значение |
|---|---|
| root / sudo | не нужен — systemd не запускается, юниты проверяются как текст |
| ОС | любая с bash + awk + coreutils (systemd не требуется) |
| Сеть | не нужна |
| systemd / Docker / k8s | не нужны для теста |
| Внешние пакеты | нет (`systemd-analyze` — по желанию, на своей машине) |
| Изоляция теста | юниты читаются по правилам systemd: секции значимы, побеждает последнее присваивание |

Тест дополнительно проверяет, что задание не выродилось: в стартере остались
строка из crontab и `WantedBy=multi-user.target`.

## Выполнение

```bash
cd season-03-system-administration/s03e06-systemd-timers

$EDITOR artifacts/ops-check.service

```

На своей машине стоит посмотреть, что уже работает по расписанию, — почти на
любой системе там найдётся десяток таймеров, о которых вы не знали:

```bash
systemctl list-timers --all
```

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| «это синтаксис crontab» | строка перенесена буквально | формат systemd: `*:0/5` |
| «не даёт интервала в пять минут» | выражение верное, но про другое | проверить `systemd-analyze calendar` |
| «не появится в list-timers» | `WantedBy=multi-user.target` | таймеры включаются в `timers.target` |
| «Restart при Type=oneshot» | служба скопирована из `s03e05` | у разовой задачи перезапуск — работа таймера |
| «в службе есть [Install]» | скопирована целиком | включается таймер, а не служба |
| «TimeoutStartSec не задан» | не задумывались о зависании | пока экземпляр активен, следующий запуск не идёт |
| «Description ничего не сообщает» | скопировано имя юнита | описание видно в `systemctl list-timers` |
| таймер `enabled`, но не срабатывает | цель или календарь | `systemctl show ops-check.timer -p WantedBy -p NextElapseUSecRealtime` |

## После выполнения

Зелёный тест означает, что расписание описано целиком: когда запускать, что
делать с пропущенным, что считать успехом и что произойдёт при зависании.

Стоит отдельно задержаться на `Persistent=true` — это единственная строка,
которой не хватало 14 октября, и она же единственная, чей эффект не виден,
пока всё работает.

## Кумулятивность

Служба и её ограничения — из [`s03e05`](../s03e05-systemd-service/); здесь она
переписывается под другой режим работы, а `Type=` и `Restart=` из той серии
меняют смысл. Провал в данных 14 октября совпал с установкой `sshd-helper`,
найденного через процессы в [`s03e04`](../s03e04-processes/). Дисциплина
«конфиг как артефакт, побеждает последнее присваивание» — из
[`s03e03`](../s03e03-sudo/) и [`s03e05`](../s03e05-systemd-service/).
